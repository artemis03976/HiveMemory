# v0.5.1 基础设施清理规划

**文档状态**: Draft  
**适用范围**: `system/config/`、`engines/artifacts/`、`alice/runtime/`、`patchouli/runtime/`  
**前置版本**: v0.5.0 全部 Phase 完成  
**核心目标**: 清理 v4 架构演进遗留的基础设施技术债，建立清晰的子系统 config 边界，补全 NoOp 组件以消除散落的 None 守卫判断，传递取消信号至 MTP executor。

---

## 1. Config 重分层

### 1.1 现状

当前 `HiveMemoryConfig` 是平坦结构，patchouli 与 alice 的配置字段混在顶层，没有明确的子系统边界。v4 架构演进将 alice 与 patchouli 分离后，config 未随之调整。

### 1.2 文件组织决策

Config 是基础设施关注点，不是领域逻辑，因此**不**在各子系统目录内新建 `config.py`——这会造成 `system/` 反向依赖 `patchouli/` 和 `alice/`，依赖方向倒置。

采用 `system/config/` 目录方案，将单一 `config.py` 拆分为多个文件：

```
system/config/
  shared.py      ← LLMConfig、EmbeddingConfig（跨子系统共用基础设施）
  patchouli.py   ← PatchouliConfig（引用 shared.py 中的类型）
  alice.py       ← AliceConfig
  __init__.py    ← HiveMemoryConfig（组合三者）、load_app_config()
```

依赖方向保持单向：

```
patchouli/runtime/core.py  ──import──► system/config/patchouli.py
alice/runtime/core.py      ──import──► system/config/alice.py
system/config/__init__.py  ──import──► system/config/{patchouli,alice,shared}.py
```

子系统 runtime 只知道自己的 config 类型，不感知 `HiveMemoryConfig` 的组合方式。

### 1.3 目标 Config 结构

```python
# system/config/shared.py
class SharedConfig(BaseModel):
    llm: LLMConfig        # 跨子系统 LLM 服务
    embedding: EmbeddingConfig

# system/config/patchouli.py
class PatchouliConfig(BaseModel):
    storage: QdrantConfig
    perception: PerceptionConfig
    generation: GenerationConfig
    lifecycle: LifecycleConfig
    retrieval: RetrievalConfig
    artifacts: ArtifactStoreConfig

# system/config/alice.py
class AliceConfig(BaseModel):
    runtime: AliceRuntimeConfig

# system/config/__init__.py
class HiveMemoryConfig(BaseModel):
    patchouli: PatchouliConfig
    alice: AliceConfig
    shared: SharedConfig
```

### 1.3 迁移要点

- `PatchouliRuntime` 接收 `PatchouliConfig`，`AliceRuntime` 接收 `AliceConfig`
- `load_app_config()` 继续返回 `HiveMemoryConfig`，向下传递时各自解包子 config
- YAML / 环境变量结构同步调整：`patchouli.qdrant.*`、`alice.runtime.*`
- 所有现有字段**保持原名称**，只改层级路径，最大化兼容
- config 迁移完成后同步更新 `SETUP.md` 中的配置说明

### 1.4 验收

- `PatchouliRuntime.__init__` 接收 `PatchouliConfig`，不接收 `HiveMemoryConfig`
- `AliceRuntime.__init__` 接收 `AliceConfig`
- 现有功能测试全部通过，无配置项丢失

## 2. NoOp 组件补全

### 2.1 现状问题

当前代码中存在大量 `if self._artifact_engine and ...:` 形式的 None 守卫判断。这类模式：
- 使调用方承担"判断是否注入"的责任
- 降低代码可读性
- 不利于后续的测试 mock

### 2.2 目标：已有 NoOp 与需新增 NoOp

| 组件 | 现状 | 操作 |
|---|---|---|
| `NullRuntimeEventSink` | 已有 | 确认实现完整 |
| `NullArtifactEngine` | 无 | 新增：build_and_store / build_for_create / build_for_update 均返回哑 ref |
| `NullPerceptionLayer` | 视情况 | 如果感知层目前有多处 None 守卫则补充 |

### 2.3 NullArtifactEngine 设计

```python
class NullArtifactEngine:
    """当 artifact store 禁用时的哑实现，接口与 ArtifactEngine 一致。"""
    interaction = NullInteractionArtifactBuilder()
    document = NullDocumentArtifactBuilder()
    memory = NullMemoryArtifactBuilder()
```

各 builder 的 `build_and_store` / `build_for_create` / `build_for_update` 返回占位 `ArtifactRef`（`uri=None, sha256=None`），不写磁盘，不抛出异常。

调用方移除 `if self._artifact_engine:` 守卫，直接调用即可。

### 2.4 验收

- `LibrarianCore` 和 `MemoryGenerationTaskController` 的 `_artifact_engine` 字段不再需要 None 检查
- `ArtifactStoreConfig.enabled=false` 时系统注入 `NullArtifactEngine`，正常运行，不写任何 artifact 文件
- 现有测试通过，新增 `NullArtifactEngine` 单元测试

## 3. cancel_event → MTP executor

### 3.1 现状

`MemoryGenerationTask` 中已有 `cancel_event`，TaskController 中已有取消检测。但 Alice 的 MTP executor（Koakuma / `_handle_call` 等）在执行 MTP 指令时，目前没有接收取消信号，导致 agent 运行被 cancel 后，正在执行的 MTP 工具调用可能无法及时感知。

### 3.2 目标

在 agent run 的取消路径上将 `cancel_event` 或等效的 `CancellationToken` 传入 MTP executor 的调用链，使 executor 可在合适时机检查并提前退出。

具体传递路径：

```
AgentRun.cancel()
  → 设置 cancel_event
  → ExecutionFrame / KoakumaRuntime._run_loop()
  → _handle_call() / _execute_mtp_verb()
      └── 每个 verb handler 在适当 checkpoint 检查 cancel_event
```

### 3.3 变更范围

- `alice/runtime/koakuma.py`（或当前等效文件）：`_run_loop` 在每轮迭代前检查
- `MTP executor`：各 verb 耗时操作前加取消检查点
- 取消时以 `SUSPEND`（待 resume）或直接 `CANCELLED` 状态退出，视当前 frame 语义而定

### 3.4 验收

- agent run 被 cancel 后，MTP executor 不再等待当前 verb 完成，在下一个 checkpoint 退出
- 取消行为产生正确的 `agent.run.cancelled` RuntimeEvent
- 现有 agent 相关测试通过

## 4. Done Definition

1. `HiveMemoryConfig` 按 `PatchouliConfig / AliceConfig / SharedConfig` 三层分组，字段名不变。
2. `PatchouliRuntime` 只接收 `PatchouliConfig`，`AliceRuntime` 只接收 `AliceConfig`。
3. `NullArtifactEngine` 实现完成，`artifacts.enabled=false` 时自动注入，系统正常运行。
4. `LibrarianCore` 和 `MemoryGenerationTaskController` 移除 `if self._artifact_engine:` None 守卫。
5. cancel_event 传入 MTP executor 调用链，agent run cancel 在 checkpoint 处提前退出。
6. 所有受影响测试通过。
