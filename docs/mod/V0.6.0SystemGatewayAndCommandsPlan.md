# v0.6.0 System Gateway 与系统指令规划

**文档状态**: Draft  
**适用范围**: `system/`、`patchouli/`、`engines/gateway/`、`core/protocol/`、`server/routers/`、`frontend/src/`  
**前置版本**: v0.5.x 基础设施工作完成  
**核心目标**: 将 Gateway / TheEye 从 Patchouli 记忆系统上移到 System 级，建立全局系统指令库，并增强 TheEye 对复杂用户输入的复合意图分解能力。

---

## 1. 背景

### 1.1 当前状态

当前代码已经把 Gateway 的“纯分析引擎”与 Patchouli Runtime 分开，但还没有把 TheEye 的宿主身份从 Patchouli 中剥离出来。

现状分层如下：

```text
src/hivememory/engines/gateway/
  engine.py            # GatewayEngine，纯数据操作层
  interceptors.py      # RuleInterceptor / create_interceptor
  semantic_analyzer.py # LLMAnalyzer / create_semantic_analyzer
  models.py            # GatewayResult / GatewayIntent / SemanticAnalysisResult
  interfaces.py        # BaseInterceptor / BaseSemanticAnalyzer

src/hivememory/patchouli/
  eye.py               # TheEye，当前仍归属 Patchouli 包
  system.py            # PatchouliSystem 构造 GatewayEngine 与 TheEye
  service.py           # PatchouliService 持有 eye，并暴露 gaze()
```

当前主动 chat 调用链：

```text
ChatApplicationService
  -> GlobalRoutes.PATCHOULI_PREPARE_AGENT_RUN
  -> PatchouliService.prepare_agent_run()
  -> PatchouliLocalRoutes.GATEWAY_GAZE
  -> PatchouliService.gaze()
  -> TheEye.gaze()
  -> GatewayEngine.process()
  -> EyeGazeResult
  -> Topic prepare / Retrieval / Alice run / Patchouli finalize
```

当前被动接入调用链：

```text
PassiveIngressService
  -> PassiveMessageIngressor.route_event()
  -> GlobalRoutes.PATCHOULI_PASSIVE_ANALYZE_AND_RETRIEVE
  -> PatchouliService.analyze_and_retrieve()
  -> PatchouliLocalRoutes.GATEWAY_GAZE
  -> TheEye.gaze()
  -> retrieve_for_gaze()
```

当前职责划分：

- `GatewayEngine` 已经是独立 engine，不直接依赖 Patchouli。
- `TheEye` 负责处理 `GatewayEngine` 的业务包装：topic snapshot 渲染、耗时记录、异常 fallback、`GatewayResult -> EyeGazeResult` 转换。
- `PatchouliSystem._init_gateway()` 仍负责 gateway LLM、interceptor、semantic analyzer、`GatewayEngine` 的装配。
- `PatchouliSystem` 仍直接持有 `self.eye`。
- `PatchouliService` 仍通过构造参数持有 `eye: TheEye`，并将 `service.gaze()` 注册到 Patchouli local bus 的 `gateway.gaze`。
- gateway 配置当前仍位于 `config.patchouli.gateway`，LLM 凭证位于 `config.shared.llm.gateway`。

已知限制：

- TheEye 的包路径与生命周期宿主仍暗示它是 Patchouli 记忆系统的一部分。
- Gateway 装配代码位于 `PatchouliSystem`，导致未来系统指令库、Deep Research、附件任务等非记忆域能力若要复用 TheEye，仍必须经过 Patchouli。
- `PatchouliLocalRoutes.GATEWAY_GAZE = "gateway.gaze"` 是 Patchouli local route，语义上不适合作为全局入口长期存在。
- `EyeGazeResult` 已位于 `core.protocol.models`，但文档注释仍说“数据格式转换由 PatchouliRuntime 负责”，与当前代码不完全一致。

### 1.2 问题陈述

v0.6.0 的第一阶段要解决的是架构归属问题，而不是新增复杂智能行为。

TheEye 当前已经承担“系统入口分析器”的职责，但实现位置仍在 Patchouli 内。这会带来几个实际问题：

1. **依赖方向不清晰**
   - System 级应用服务通过 GlobalBus 请求 Patchouli public route，Patchouli 再转入 local bus 执行 `gateway.gaze`。
   - 从业务语义看，入口分析应发生在 System 层；从代码位置看，它仍被 Patchouli 托管。

2. **后续全局系统指令难以自然扩展**
   - `/clear`、后续 `/research`、`/ingest`、任务队列控制等指令不一定属于记忆域。
   - 若 TheEye 继续在 Patchouli 内，系统指令库会被迫放进 Patchouli 或通过 Patchouli 转发到其他系统能力，形成反向依赖。

3. **复合意图分解的下游不只 Patchouli**
   - 复合意图可能同时包含检索、规划、任务创建、Agent run、文档解析等片段。
   - 这些片段的消费方横跨 Patchouli、Alice、未来 Runtime Job Queue 和前端交互层。
   - TheEye 若仍属于 Patchouli，会让复合意图输出天然偏向记忆域。

4. **测试与文档命名会持续误导**
   - 现有测试集中在 `tests/unit/patchouli/test_eye.py`。
   - 顶层 `hivememory.__getattr__` 也从 `hivememory.patchouli.eye` 导出 `TheEye`。
   - 这些入口会让后续开发继续把 gateway 当作 Patchouli 私有能力。

### 1.3 版本定位

v0.6.0 是后续“全局任务入口”的铺垫版本：

- Phase 1 只解决 TheEye / Gateway 的 System 级归属问题。
- Phase 2 在 Phase 1 的基础上添加全局系统指令库。
- Phase 3 在稳定的 System Gateway 输出契约上扩展复合意图分解。
- v0.6.1 Runtime Job Queue 会消费 Phase 2/3 产生的 task dispatch 信息。
- v0.6.2 附件解析、v0.7.0 Document Ingestion、v0.7.2 Deep Research 都应通过 System Gateway 进入对应任务或工作流，而不是绕进 Patchouli 私有入口。

## 2. 目标与非目标

### 2.1 目标

1. 将 Gateway / TheEye 正式上移到 System 级，脱离 Patchouli 记忆系统。
2. 添加全局系统指令库，由 TheEye 进行拦截、解析与路由转发。
3. 增强 TheEye 解析能力，支持针对复杂用户请求的复合意图分解。
4. 为后续检索、规划、任务队列、Deep Research 提供统一的意图输出契约。

### 2.2 非目标

v0.6.0 不承担以下工作：

- 不实现完整 Alice Phase 3 顶层任务图编排。
- 不实现 Runtime Job Queue，只为后续 task dispatch 预留边界。
- 不实现附件上传、文档解析、Document Ingestion 或 Deep Research。
- 不实现 MTP RUN executable asset、沙箱执行或真取消。
- 不实现完整对话回档或记忆 rollback。
- Phase 1 不改变 GatewayEngine 的 L1/L2 语义分析行为。
- Phase 1 不改变 `EyeGazeResult` 对外字段。

### 2.3 优先级

1. **P0**: Gateway / TheEye 上移到 System 级。
2. **P1**: 全局系统指令库与路由转发。
3. **P2**: 复合意图分解。

## 3. 术语与边界

### 3.1 术语

- **GatewayEngine**: 位于 `engines/gateway/` 的纯分析引擎，负责 L1 规则拦截与 L2 语义分析，不处理业务 fallback、不持有系统状态。
- **TheEye**: System 级入口分析服务，负责调用 `GatewayEngine`，并将结果包装为 `EyeGazeResult`。Phase 1 后不再属于 Patchouli。
- **Gaze**: TheEye 对单条用户输入执行入口分析的动作，输入为 query / topic snapshots / identity，输出为 `EyeGazeResult`。
- **EyeGazeResult**: 当前热路径使用的入口分析协议，承载 intent、rewritten query、search keywords、worth_saving、topic routing 等字段。
- **System Gateway**: System 层对 TheEye、GatewayEngine、配置、未来系统指令库与复合意图路由的总称。
- **System Command**: 全局系统指令，Phase 2 设计；Phase 1 仅预留归属边界。
- **Intent**: 用户输入的单一意图分类，当前主要为 `RAG` / `CHAT` / `SYSTEM`。
- **Composite Intent**: 复合意图分解结果，Phase 3 设计；Phase 1 不实现。
- **Route Target**: 意图或命令的下游目标，Phase 2/3 设计；Phase 1 仅保留 gaze 结果给 Patchouli 消费。
- **Task Spec**: 未来 Runtime Job Queue 可消费的任务描述，v0.6.1 设计；v0.6.0 Phase 1 不生成 task spec。

### 3.2 子系统边界

Phase 1 目标边界：

- `engines/gateway/`：保留为纯引擎层，提供 L1/L2 分析能力，不知道 System、Patchouli、Alice。
- `system/gateway/`：新增 System 级 gateway 宿主层，持有 `TheEye`、gateway factory、未来 command registry / intent router 的扩展点。
- `system/`：负责构造 System Gateway，并通过 GlobalSystemBus 或直接服务注入把 gaze 能力提供给应用服务与子系统。
- `patchouli/`：只消费 `EyeGazeResult`，不构造、不拥有 TheEye。
- `alice/` 与 `agent_runtime/`：Phase 1 不直接接入 TheEye，只保持现有 chat run 调用链。

允许依赖方向：

```text
system/gateway -> engines/gateway
system/gateway -> core.protocol / core.models
system -> system/gateway
patchouli.service -> core.protocol models
patchouli.service -> system-level gaze route or injected gaze callable
```

禁止依赖方向：

```text
system/gateway -> patchouli
engines/gateway -> system
engines/gateway -> patchouli
patchouli.system -> system.gateway concrete composition root
```

说明：Patchouli 可以在类型层面依赖 `EyeGazeResult`、`GatewayIntent` 等协议模型，但不应再负责 TheEye 的创建、配置解析或生命周期托管。

### 3.3 输入输出边界

Phase 1 不改变现有输入输出模型。

输入：

- `query: str`
- `topic_snapshots: Optional[list[TopicSnapshot]]`
- `identity: Optional[Identity]`

输出：

- `EyeGazeResult`

Phase 1 的关键约束：

- `EyeGazeResult.intent`、`rewritten_query`、`search_keywords`、`worth_saving`、`target_topic`、`new_topic_title`、`new_topic_summary` 的行为保持兼容。
- fallback 行为保持兼容：`GatewayEngine` 或 LLM analyzer 异常时返回 `intent=RAG`、`rewritten_query=raw_query`、`worth_saving=False`、`target_topic="NEW_TOPIC"`、`is_fallback=True`。
- Topic snapshot 文本渲染在 Phase 1 可暂时沿用 `PerceptionContextConverter.snapshots_to_context_text()`，但需要在依赖方向上避免 `system/gateway` 直接依赖 perception engine 的具体实现。迁移时可先复制/抽出轻量 renderer，或在构造 TheEye 时注入 renderer callable。

## 4. 总体架构

### 4.1 目标结构

Phase 1 后的目标结构：

```text
system/
  config/
    gateway.py          # SystemGatewayConfig / RuleInterceptorConfig / LLMAnalyzerConfig
                        # 或从 patchouli.py 迁出的等价配置
  gateway/
    __init__.py
    eye.py              # TheEye 的新归属
    factory.py          # build_system_gateway() / build_gateway_engine()
    contracts.py        # 可选：SystemGatewayRoutes / Gaze callable type
    topic_context.py    # 可选：topic snapshots -> active_topics_menu renderer

engines/gateway/
  engine.py             # 保持纯引擎层
  interceptors.py
  semantic_analyzer.py
  models.py
  interfaces.py

patchouli/
  system.py             # 不再 _init_gateway，不再 self.eye = TheEye(...)
  service.py            # 不再拥有 TheEye concrete；改为通过 route/callable 请求 gaze
  eye.py                # 短期兼容 shim，可选；最终删除
```

推荐拆分：

- `system/gateway/eye.py`：从 `patchouli/eye.py` 迁移 `TheEye`。
- `system/gateway/factory.py`：承接原 `PatchouliSystem._init_gateway()` 的装配逻辑。
- `system/config/gateway.py`：从 `PatchouliConfig.gateway` 拆出 gateway 配置，使 gateway 不再属于记忆域配置。

可接受的第一步兼容：

- 保留 `hivememory.patchouli.eye.TheEye` 为 re-export shim：

```python
from hivememory.system.gateway.eye import TheEye
```

该 shim 仅为测试和外部导入过渡使用，不应包含逻辑。

### 4.2 总体数据流

Phase 1 后的主动 chat 数据流：

```text
User Input
  -> ChatApplicationService
  -> Patchouli prepare public route
  -> PatchouliService.prepare_agent_run()
  -> System Gateway gaze route/callable
  -> TheEye.gaze()
  -> GatewayEngine.process()
  -> EyeGazeResult
  -> Patchouli topic prepare + retrieval
  -> Alice run
  -> Patchouli finalize
```

Phase 1 不改变 `ChatApplicationService` 的 prepare/run/finalize 编排骨架，也不改变 `PatchouliService.prepare_agent_run()` 对 `EyeGazeResult` 的消费逻辑。

Phase 1 的主要变化是 gaze 能力的宿主与注册位置：

```text
Before:
  PatchouliSystem builds TheEye
  Patchouli local bus registers gateway.gaze -> PatchouliService.gaze -> self._eye.gaze

After:
  HiveMemorySystem or SystemGateway factory builds TheEye
  System-level route/callable exposes gateway.gaze
  PatchouliService requests/invokes system gaze
```

### 4.3 依赖方向

Phase 1 的依赖方向以“System 拥有 gateway，Patchouli 消费 gaze result”为准：

```text
HiveMemorySystem.build()
  -> build_system_gateway(config.gateway, config.shared.llm.gateway)
  -> PatchouliSystem(..., gateway_gaze=system_gateway.gaze)

PatchouliService
  -> gateway_gaze(query, topic_snapshots, identity)
  -> EyeGazeResult
```

不推荐让 `system/gateway` 直接请求 Patchouli route 获取 topic snapshots。Topic snapshot 的生产仍属于 Patchouli；TheEye 只接收调用方提供的 snapshots。

不推荐在 Phase 1 中新增大规模全局路由协议。如果需要路由，优先使用最小 `SYSTEM_GATEWAY_GAZE` route；更完整的系统指令路由留到 Phase 2。

## 5. Phase 1: Gateway / TheEye 上移到 System 级

### 5.1 现状

当前实现细节：

1. `TheEye` 位于 `src/hivememory/patchouli/eye.py`。
   - 构造参数：`engine: GatewayEngine`、`bus=None`。
   - 公开方法：`gaze(query, topic_snapshots=None, identity=None) -> EyeGazeResult`。
   - 内部职责：topic snapshots 渲染、调用 `GatewayEngine.process()`、耗时记录、日志、fallback。
   - 文件中已有 TODO：后续考虑上移至 system。

2. `GatewayEngine` 位于 `src/hivememory/engines/gateway/engine.py`。
   - 已经是纯数据操作层。
   - 执行 L1 interceptor 与 L2 semantic analyzer。
   - 不处理 fallback、日志、业务转换。

3. `PatchouliSystem` 当前负责 gateway 装配。
   - `PatchouliSystem.__init__()` 中先构造 `PatchouliRuntime`，再 `_init_gateway()`，再 `self.eye = TheEye(...)`。
   - `_init_gateway()` 使用 `config.shared.llm.gateway` 构造 gateway LLM service。
   - `_init_gateway()` 使用 `config.patchouli.gateway` 构造 interceptor 与 semantic analyzer。

4. `PatchouliService` 当前持有 `eye: TheEye`。
   - `service.gaze()` 是薄包装：调用 `self._eye.gaze(...)`。
   - `prepare_agent_run()` 与 `analyze_and_retrieve()` 并不直接调用 `self._eye.gaze()`，而是请求 `PatchouliLocalRoutes.GATEWAY_GAZE`。

5. `PatchouliRuntime.mount_local_routes()` 当前注册：
   - `PatchouliLocalRoutes.GATEWAY_GAZE -> service.gaze`
   - 这让 Patchouli local bus 成为 TheEye 的入口。

6. 顶层 `ChatApplicationService` 和 `PassiveIngressService` 不直接知道 TheEye。
   - 它们只通过 GlobalSystemBus 调 Patchouli public routes。
   - 因此 Phase 1 迁移理论上可以保持顶层 API 行为不变。

7. 测试现状：
   - `tests/unit/patchouli/test_eye.py` 直接测试 `hivememory.patchouli.eye.TheEye`。
   - E2E 测试中也有直接从 `hivememory.patchouli.eye` import `TheEye` 的路径。
   - 多个 Patchouli service 测试用 mock eye 或 local bus mock `GATEWAY_GAZE`。

### 5.2 目标

Phase 1 完成后，TheEye 应成为 System 级 gateway service，而不是 Patchouli 子系统组件。

目标状态：

1. `TheEye` 的真实实现移动到 `hivememory.system.gateway.eye`。
2. `PatchouliSystem` 不再构造 gateway LLM、interceptor、semantic analyzer、`GatewayEngine` 或 `TheEye`。
3. Gateway 装配逻辑移动到 System 层，例如：
   - `hivememory.system.gateway.factory.build_system_gateway(...)`
   - 或 `HiveMemorySystem.build()` 内部的私有构造函数。
4. `PatchouliService` 不再类型依赖 `hivememory.patchouli.eye.TheEye` concrete。
5. Patchouli 仍可在 prepare/analyze 流程中消费 `EyeGazeResult`，但 gaze 的来源是 System 级 gateway。
6. 现有主动 chat、被动 ingest、topic routing、retrieval 行为保持不变。

目标边界：

```text
TheEye owns:
  - GatewayEngine 调用
  - GatewayResult -> EyeGazeResult 转换
  - fallback
  - processing_time_ms
  - gateway 入口日志

Patchouli owns:
  - topic snapshots 获取
  - topic prepare / discard
  - retrieval_for_gaze
  - interaction submit / finalize
  - memory generation

System owns:
  - TheEye 构造与生命周期归属
  - gateway config 归属
  - 后续 command registry / route target 扩展点
```

### 5.3 模块迁移范围

建议迁移范围：

新增：

- `src/hivememory/system/gateway/__init__.py`
- `src/hivememory/system/gateway/eye.py`
- `src/hivememory/system/gateway/factory.py`
- `src/hivememory/system/gateway/topic_context.py`（可选）
- `src/hivememory/system/config/gateway.py`（推荐）
- `tests/unit/system/gateway/test_eye.py`

迁移：

- `src/hivememory/patchouli/eye.py` 的真实实现迁移到 `src/hivememory/system/gateway/eye.py`。
- `PatchouliSystem._init_gateway()` 的装配逻辑迁移到 `system/gateway/factory.py`。
- `MemoryGatewayConfig`、`RuleInterceptorConfig`、`LLMAnalyzerConfig` 从 `system/config/patchouli.py` 迁移到 `system/config/gateway.py`，或至少在 System config 层提供新的 `gateway` 字段。

调整：

- `HiveMemorySystem.__init__()` 增加 `gateway` 或 `the_eye` 字段。
- `HiveMemorySystem.build()` 在构造 PatchouliSystem 之前构造 System Gateway。
- `PatchouliSystem.__init__()` 接收 `gateway_gaze` callable 或 system gateway service 引用。
- `PatchouliService.__init__()` 接收 `gateway_gaze` callable，而不是 `eye: TheEye` concrete。
- `build_patchouli_route_bindings()` 中 `GATEWAY_GAZE` 可继续注册，但 handler 应来自注入的 system gateway callable，而非 Patchouli-owned eye。
- `hivememory.__getattr__("TheEye")` 改为从 `hivememory.system.gateway.eye` 导出。

保留：

- `src/hivememory/engines/gateway/*` 不迁移。
- `GatewayResult` / `GatewayIntent` / `SemanticAnalysisResult` 行为不改。
- `EyeGazeResult` 暂时仍保留在 `core.protocol.models`。
- `PatchouliLocalRoutes.GATEWAY_GAZE` 可短期保留，作为 Patchouli 内部 workflow 对 gaze 能力的兼容入口。

可选兼容 shim：

- `src/hivememory/patchouli/eye.py` 保留为：

```python
"""Deprecated compatibility import for TheEye."""

from hivememory.system.gateway.eye import TheEye

__all__ = ["TheEye"]
```

该 shim 应标注 deprecated，并在 v0.7 之后考虑删除。

### 5.4 兼容策略

Phase 1 应采用低风险兼容迁移，不一次性删除旧入口。

兼容策略：

1. **导入兼容**
   - 保留 `hivememory.patchouli.eye.TheEye` re-export，避免 E2E 与外部脚本立即失效。
   - 新代码必须使用 `hivememory.system.gateway.TheEye`。

2. **路由兼容**
   - 保留 `PatchouliLocalRoutes.GATEWAY_GAZE`，因为 `PatchouliService.prepare_agent_run()` 与 `analyze_and_retrieve()` 已经通过 local bus 请求它。
   - 但该 route 的 handler 不再绑定到 Patchouli-owned `self._eye`，而是绑定到 System 注入的 gaze callable。

3. **配置兼容**
   - 新增 `config.gateway` 作为 System Gateway 配置位置。
   - 短期允许从旧 `config.patchouli.gateway` 读取默认值，或者让 `PatchouliConfig.gateway` 成为 deprecated alias。
   - 文档与示例配置应优先使用 `gateway.*`。

4. **测试兼容**
   - 新增 `tests/unit/system/gateway/test_eye.py`。
   - 旧 `tests/unit/patchouli/test_eye.py` 可改为 shim import 兼容测试，或直接迁移到 system/gateway。
   - E2E 中直接 import `hivememory.patchouli.eye` 的位置应逐步改为 system path。

5. **行为兼容**
   - 不改 `EyeGazeResult` 字段。
   - 不改 fallback 值。
   - 不改 `prepare_agent_run()` 的输出结构。
   - 不改 chat stream 的 SSE prelude。

### 5.5 风险

主要风险：

1. **启动装配顺序风险**
   - 当前 `PatchouliSystem` 内部构造 TheEye，迁移后 `HiveMemorySystem.build()` 需要先构造 gateway，再注入 Patchouli。
   - 若 Patchouli local route 注册早于 gateway callable 注入，会导致 `gateway.gaze` route 缺失。

2. **配置路径迁移风险**
   - 当前代码读取 `config.patchouli.gateway`。
   - 若直接删除旧字段，会影响 YAML、测试 fixture 与默认配置加载。
   - 应先引入 `config.gateway`，再做兼容读取。

3. **topic snapshot renderer 依赖风险**
   - 当前 TheEye 内部 import `PerceptionContextConverter`。
   - 迁移到 `system/gateway` 后继续 import perception converter 会让 System Gateway 依赖 perception engine。
   - 推荐将 topic snapshot 渲染抽成 `system/gateway/topic_context.py`，或通过构造参数注入 renderer。

4. **测试路径风险**
   - 多个测试和 E2E 直接 import `hivememory.patchouli.eye.TheEye`。
   - 需要 shim 或批量迁移测试路径。

5. **局部总线路由语义风险**
   - `PatchouliLocalRoutes.GATEWAY_GAZE` 名称仍在 Patchouli 内，短期保留有利于兼容，但长期语义不理想。
   - Phase 1 不应为了命名洁癖同步改完整 bus 拓扑，避免扩大范围。

6. **公共导出风险**
   - `hivememory.__getattr__` 当前从 patchouli path 懒加载 `TheEye`。
   - 若忘记同步，会造成新旧路径实例不一致或导入失败。

### 5.6 验收

Phase 1 验收条件：

1. `TheEye` 的真实实现位于 `src/hivememory/system/gateway/eye.py`。

## 14. 风险与开放问题

### 14.1 架构风险

Phase 1 架构风险：

- System Gateway 若继续 import perception converter，会把 perception 细节泄漏到 System 层。
- Patchouli local bus 继续保留 `gateway.gaze` 会形成短期命名不一致。
- 若 `PatchouliSystem` 和 `HiveMemorySystem` 同时能构造 TheEye，可能出现双实例与配置漂移。

规避策略：

- topic snapshot renderer 抽到 System 可接受的位置，或通过 callable 注入。
- Phase 1 保留 `gateway.gaze` 作为兼容 route，但文档标记为过渡状态。
- 最终只允许 System composition root 构造 TheEye。

### 14.2 行为风险

Phase 1 行为风险：

- fallback 行为改变会影响 chat 首轮 topic 创建与 retrieval。
- `identity=None` 默认值改变会影响旧测试与匿名场景。
- topic snapshot 渲染文本改变会影响 LLM routing 稳定性。

规避策略：

- `TheEye.gaze()` 迁移后先保持逐行等价。
- topic snapshot renderer 迁移必须有单元测试锁定输出。
- pre-retrieval 与 golden scenario 作为回归测试。

### 14.3 体验风险

Phase 1 理论上不改变用户可见体验。若迁移后出现体验变化，通常说明热路径行为被误改。

需要重点观察：

- 首轮对话是否仍正确创建 topic。
- 已有话题是否仍能被 TheEye 正确路由。
- chat stream 的前置信息是否仍按原顺序发送。
- passive ingest 的返回字段是否仍保持兼容。

### 14.4 开放问题

Phase 1 开放问题：

1. `PatchouliLocalRoutes.GATEWAY_GAZE` 是否在 v0.6.0 后半段迁移为 System route，还是保留到 v0.7 再清理？
2. `PatchouliConfig.gateway` 是否立即移除，还是保留一个版本作为 deprecated alias？
3. TheEye 是否需要独立 `SystemGateway` 容器类，还是直接作为 `HiveMemorySystem` 的成员即可？
4. `EyeGazeResult` 的注释是否在 Phase 1 一并修正为 System Gateway 输出协议？
