# v0.5.2 Async-Native Adaptation 实施记录

**文档状态**: 已实施  
**适用范围**: `engines/generation/engine.py`、`engines/retrieval/`、`infrastructure/storage/`、`patchouli/services/`  
**前置版本**: v0.5.1 全部 Phase 完成  
**核心目标**: 将 generation 与 retrieval 链路从 `asyncio.to_thread()` 包装模式升级为原生 async，消除对同步 Qdrant 客户端的依赖，并同步补齐生命周期归档与运行时存储健康检查的异步调用。

**完成说明**: v0.5.2 已完成主链路 async-native 改造；本文保留原分阶段方案作为实施记录，当前行为以代码中的 `async def` 接口和调用处的 `await` 为准。

---

## 1. 背景

v0.5.0 完成了 artifact 数据体系与三步生成流水线；在 v0.5.2 改造前，generation 和 retrieval 仍依赖同步 I/O：

- `MemoryGenerationEngine.process()` 是同步方法，由 TaskController 以 `inspect.isawaitable()` 兼容方式调用
- `RetrievalFamiliar.retrieve_async()` 通过线程池包装同步检索
- `QdrantMemoryStore` 全量使用同步 `QdrantClient`

只要底层 Qdrant 客户端是同步的，将引擎方法签名改为 `async def` 仅是外表变化——事件循环仍会在 Qdrant I/O 时阻塞线程。因此 async-native 的前提是**存储层先完成 async 化**。

---

## 2. 核心目标

1. `QdrantMemoryStore` 切换至 `AsyncQdrantClient`，所有 Qdrant I/O 变为原生 async
2. `MemoryGenerationEngine.process()` 改为 `async def process()`
3. `RetrievalFamiliar.retrieve_async()` 去掉 `asyncio.to_thread()` 包裹，直接 `await`
4. TaskController 移除 `inspect.isawaitable()` 兼容代码，直接 `await self.generation_engine.process(request)`

---

## 3. 变更范围

### 3.1 存储层：QdrantMemoryStore → AsyncQdrantClient

这是所有变更的前提。`qdrant-client` 已提供 `AsyncQdrantClient`，API 与同步版本基本一致。

主要变更：
- `__init__` 中将 `QdrantClient(...)` 替换为 `AsyncQdrantClient(...)`
- 所有 `upsert_memory`、`get_memory`、`search`、`update_access_info` 等方法改为 `async def`
- 调用处全部加 `await`

**影响范围**：
- `infrastructure/storage/memory_store.py`（或当前同等文件）
- `MemoryGenerationEngine`（deduplicator 内部的 Qdrant 查询）
- `RetrievalFamiliar`（检索底层）
- `MemoryGenerationTaskController`（`_run_mode_c` 中的 `get_memory` 调用）

### 3.2 GenerationEngine async 化

```python
# 改造前
def process(self, request: GenerationRequest) -> List[MemoryGenerationResult]: ...

# 当前
async def process(self, request: GenerationRequest) -> List[MemoryGenerationResult]: ...
```

内部的 `extractor.extract()`（LLM 调用，已是 async）和 Qdrant 操作（完成 3.1 后均为 async）可以直接 await。

**TaskController 当前行为**：移除 `inspect.isawaitable()` 检查：
```python
# 改造前
process_result = self.generation_engine.process(request)
results = await process_result if inspect.isawaitable(process_result) else process_result

# 当前
results = await self.generation_engine.process(request)
```

### 3.3 RetrievalFamiliar async 化

```python
# 改造前
async def retrieve_async(self, ...) -> RetrievalResponse:
    ...  # 通过线程池包装同步 retrieve

# 当前
async def retrieve_async(self, ...) -> RetrievalResponse:
    return await self.retrieve(...)  # retrieve 本身变为 async
```

### 3.4 bus contract 收敛（原 Phase 4/5 轻量残留）

原 Phase 5 的 bus route 收敛仍有意义，但不再依赖 envelope 模型——只需将旧 string+任意参数 route 统一改为有类型约束的 envelope，可在 storage async 化完成后顺势做。

---

## 4. 依赖链

```
AsyncQdrantClient 接入
  └── QdrantMemoryStore 全量 async
        ├── Deduplicator async（dedup 查询）
        ├── MemoryGenerationEngine.process() async
        │     └── TaskController 移除 isawaitable 兼容
        └── RetrievalFamiliar.retrieve() async
              └── retrieve_async() 去掉 to_thread 包裹
```

各步骤严格依赖前序，不可乱序。

---

## 5. 实施阶段

### Phase 1: AsyncQdrantClient 切换

目标：`QdrantMemoryStore` 全量 async，保持外部接口签名兼容（只加 async/await，不改参数）。

验收：
- 现有集成测试全部通过（需更新 mock 为 async mock）
- `upsert_memory`、`get_memory`、`search` 等均为 async def

### Phase 2: GenerationEngine async 化

目标：`process()` 改为 async，TaskController 移除兼容代码。

验收：
- `MemoryGenerationEngine` 单元测试全部通过（需更新为 async test）
- TaskController `_run_generation` 直接 `await process()`

### Phase 3: RetrievalFamiliar async 化

目标：`retrieve_async()` 去掉 `asyncio.to_thread()`。

验收：
- 检索相关测试全部通过
- 无 `asyncio.to_thread` 残留在检索链路中

---

## 6. 注意事项

**兼容性**：`AsyncQdrantClient` 部分方法（如 batch upsert、scroll）行为与同步版本可能存在细微差异，切换前需逐一核查当前使用的 Qdrant API。

**测试 mock 更新**：存储层 async 化后，所有使用 `MagicMock()` mock storage 的测试需改为 `AsyncMock()`。测试数量不少，建议逐模块迁移。

**v0.5.3 Patchouli 重构衔接**：v0.5.2 完成后，`QdrantMemoryStore` 的 async 接口可直接作为 v0.5.3 `MidTermStore` 的底层实现，无需重写。

---

## 7. 完成定义

1. `QdrantMemoryStore` 全量使用 `AsyncQdrantClient`，无 `asyncio.to_thread()` 残留。
2. `MemoryGenerationEngine.process()` 为 `async def`，内部 LLM 与 Qdrant 调用均 await。
3. `MemoryGenerationTaskController._run_generation` 直接 `await process()`，无 `inspect.isawaitable()` 检查。
4. `RetrievalFamiliar.retrieve_async()` 无 `asyncio.to_thread()` 包裹。
5. 所有受影响的单元测试从 `MagicMock` 更新为 `AsyncMock`，全部通过。
6. 现有 API 与 bus route 行为保持兼容。
