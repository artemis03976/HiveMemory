# v0.6.0 全局指令库系统设计

**文档状态**: Draft  
**适用范围**: `gateway/commands/`、`engines/gateway/interceptors.py`、`system/application/`、`server/routers/`、`frontend/src/`  
**前置版本**: v0.6.0 Gateway 子系统化基础完成或并行推进  
**核心目标**: 建立全局系统指令库，使 `/help`、`/commands`、runtime/status/debug 等系统指令可以在普通 chat 流程前被稳定识别、解析、授权、分发和展示。

---

## 1. 定位

全局指令库是 Gateway 的入口级控制能力，不属于 Patchouli 记忆系统，也不属于 Alice 执行系统。

它解决的问题是：用户输入中存在一类“控制系统行为”的消息，这类消息命中后通常不应进入普通 topic routing、retrieval、Alice generation 或 active memory generation。指令系统需要提供一个稳定、可测试、可扩展的路径，而不是把指令当作普通自然语言交给 LLM router 猜测。

全局指令库与 Gateway Workflow 的关系：

- S0 `EntryInterceptor` 负责调用指令解析能力。
- `CommandRegistry` 定义系统可识别的命令及元数据。
- `CommandParser` 把原始输入解析为结构化 `CommandParseResult`。
- `SystemCommandDispatcher` 根据命令定义执行本地 handler 或转发到 global bus public route。
- 命中 command 后，Gateway 应短路普通 workflow；不加载 active topics，不请求 routed topic context，不触发 Patchouli prepare。

---

## 2. 目标与非目标

### 2.1 目标

1. 建立全局系统指令注册表，支持命令 id、名称、别名、参数 schema、权限、可见性与路由目标。
2. 将系统指令识别接入 Gateway S0，但不把副作用放进 `RuleInterceptor`。
3. 提供稳定的指令解析结果和执行结果模型，供 Gateway、chat stream 和前端消费。
4. 支持本地 handler 与 global route dispatch 两类执行方式。
5. 支持权限拒绝、参数错误、未知命令、未实现路由、需要确认等稳定返回。
6. 系统指令命中后短路普通 chat 流程，避免 retrieval/topic creation/Alice run/active memory generation。

### 2.2 非目标

- 不实现完整任务队列或后台 job 系统。
- 不执行破坏性命令；破坏性命令在 v0.6.0 只能返回需要确认或拒绝。
- 不把 command result 塞进 `rewritten_query`、`reason` 或 assistant token 字符串中传递。
- 不让配置文件定义任意 handler import path，避免配置成为任意执行入口。
- 不在 Phase 2 强行完成 Gateway Workflow 重构；完整 active chat 时序重置由 Gateway 系统文档定义。

## 3. 术语

- **System Command**: 以 `/` 或等价入口触发的系统控制指令，例如 `/help`、`/commands`、`/status`。
- **CommandRegistry**: 系统指令元数据注册表。
- **CommandParser**: 将 raw message 解析为 `CommandParseResult`。
- **CommandDispatcher**: 根据解析结果执行 handler 或 global route。
- **Command Handler**: 本地 Python handler，适合无副作用或轻量只读指令。
- **Route Target**: 指令转发目标，可以是 local handler、global route、future job queue 或未实现占位。
- **Command Short-Circuit**: 指令命中后终止普通 Gateway/chat 流程。

## 4. 模块边界

目标归属：

```text
src/hivememory/gateway/commands/
  __init__.py
  models.py
  registry.py
  parser.py
  dispatcher.py
  builtins.py
  handlers.py

src/hivememory/engines/gateway/
  interceptors.py      # RuleInterceptor 调用 registry/parser，但不执行副作用

src/hivememory/gateway/stages/
  s0_command.py        # EntryInterceptorStage，提交 l1_result/command_parse_result/flow_end_reason
```

依赖规则：

- `commands` 可以依赖 core protocol/model、global route name、权限模型。
- `commands` 不依赖 Patchouli/Alice concrete service。
- `RuleInterceptor` 只做识别与解析，不执行 handler。
- `SystemCommandDispatcher` 可以通过 `GlobalSystemBus` 请求公开 route。
- `ChatApplicationService` 禁止持有 Gateway/Patchouli/Alice 子系统实例，只通过 `GlobalSystemBus` 与协议模型协作。

## 5. 数据模型

### 5.1 CommandDefinition

```python
class CommandDefinition(BaseModel):
    command_id: str
    name: str
    aliases: list[str] = Field(default_factory=list)
    description: str = ""
    category: Literal["general", "runtime", "memory", "debug", "admin"] = "general"
    visible: bool = True
    enabled: bool = True
    requires_confirmation: bool = False
    destructive: bool = False
    required_permissions: list[str] = Field(default_factory=list)
    argument_schema: dict[str, Any] = Field(default_factory=dict)
    route_target: CommandRouteTarget
```

设计决策：

- `command_id` 是稳定内部标识。
- `name` 是主要命令名，例如 `/help`。
- `aliases` 用于兼容短别名，例如 `/h`。
- `visible=False` 的命令不出现在 `/commands` 默认列表中。
- `debug/admin` 命令受配置开关和权限控制。
- `destructive=True` 或 `requires_confirmation=True` 的命令在 v0.6.0 不直接执行副作用。

### 5.2 CommandRouteTarget

```python
class CommandRouteTarget(BaseModel):
    kind: Literal["local_handler", "global_route", "future_job", "not_implemented"]
    handler_id: str | None = None
    global_route: str | None = None
```

设计决策：

- `local_handler` 用于 `/help`、`/commands` 等轻量只读命令。
- `global_route` 用于 runtime/status/config 等跨子系统能力。
- `future_job` 为 v0.6.1 Runtime Job Queue 预留。
- `not_implemented` 必须返回稳定结果，不抛未捕获异常。

### 5.3 CommandParseResult

```python
class CommandParseStatus(str, Enum):
    MATCHED = "matched"
    NOT_COMMAND = "not_command"
    UNKNOWN = "unknown"
    INVALID_ARGS = "invalid_args"
    AMBIGUOUS = "ambiguous"


class CommandParseResult(BaseModel):
    status: CommandParseStatus
    command_id: str | None = None
    name: str | None = None
    raw: str
    args: dict[str, Any] = Field(default_factory=dict)
    error_message: str | None = None
```

解析规则：

- 精确匹配优先于别名匹配。
- 长命令优先于短命令，避免 `/clear-all` 被 `/clear` 提前截断。
- 支持 quoted string、`--key value`、`--flag`。
- 未知命令不进入 LLM 猜测；返回稳定 unknown。

### 5.4 CommandExecutionResult

```python
class CommandExecutionStatus(str, Enum):
    SUCCESS = "success"
    REJECTED = "rejected"
    INVALID_ARGS = "invalid_args"
    NEEDS_CONFIRMATION = "needs_confirmation"
    NOT_IMPLEMENTED = "not_implemented"
    FAILED = "failed"


class CommandExecutionResult(BaseModel):
    command_id: str
    status: CommandExecutionStatus
    message: str
    payload: dict[str, Any] = Field(default_factory=dict)
    error_code: str | None = None
```

执行结果是 chat/SSE/前端展示的稳定协议，不能混入 assistant token。

## 6. 内置命令

v0.6.0 至少提供：

| 命令 | 类型 | 行为 |
| --- | --- | --- |
| `/help` | local handler | 返回命令系统帮助信息 |
| `/commands` | local handler | 返回当前可见、可用命令列表 |
| `/status` 或等价 runtime/status 命令 | global route | 查询系统状态；具体 route 由现有 runtime/readiness 能力决定 |

可选 debug/admin 命令必须满足：

- 默认关闭或默认不可见。
- 需要显式配置启用。
- 权限不足时返回 `REJECTED`。
- 不执行破坏性副作用。

## 7. Gateway S0 接入

S0 `EntryInterceptor` 的职责：

1. 读取 `GatewayState.raw_message`。
2. 调用 `RuleInterceptor` / command parser。
3. 命中 command 时返回 `StageResult`，写入：
   - `l1_result`
   - `command_parse_result`
   - `flow_end_reason="system_command"`
4. 命中 simple chat 时可写入：
   - `l1_result`
   - `intent_type=CHAT`
   - `flow_end_reason="simple_chat"`
5. 未命中时透明放行。

关键约束：

- S0 不拥有 `rewritten_query`、`search_keywords`、`memory_write_signal`、`retrieval_strategy`。
- S0 不触发 topic list、routed topic context、Patchouli prepare 或 retrieval。
- S0 不执行 command handler；真实副作用由 `GatewayService` 在 command 短路后调用 dispatcher。

---

## 8. Dispatcher

执行流程：

```text
GatewayService.process()
  -> S0 EntryInterceptor
  -> if flow_end_reason == "system_command":
       SystemCommandDispatcher.execute(command_parse_result, identity)
       GatewayState.command_execution_result = result
       seal state
       return state
```

分发规则：

- `local_handler`: 从 registry/handler map 查找并执行。
- `global_route`: 通过 `GlobalSystemBus.request(route, ...)` 调用公开 route。
- `future_job`: 返回 `NOT_IMPLEMENTED` 或 future job placeholder。
- `not_implemented`: 返回 `NOT_IMPLEMENTED`。

权限与安全：

- 执行前检查 `required_permissions`。
- `destructive=True` 或 `requires_confirmation=True` 时返回 `NEEDS_CONFIRMATION`，v0.6.0 不执行副作用。
- handler 异常被捕获并转换为 `FAILED`。
- 参数错误返回 `INVALID_ARGS`。

---

## 9. Chat / Stream 行为

命中系统指令后：

```text
ChatApplicationService
  -> GlobalSystemBus.request(GatewayPublicRoutes.PROCESS)
  -> GatewayState.command_execution_result != None
  -> emit command_result event
  -> emit done event
  -> stop
```

不得继续执行：

- Patchouli prepare
- topic creation
- retrieval
- Alice generation
- active memory generation

SSE 事件建议：

```json
{
  "type": "command_result",
  "command_id": "commands",
  "status": "success",
  "message": "..."
}
```

## 10. 前端协作

前端只消费结构化 command result：

- command result 不作为 assistant message token 流的一部分。
- command result 可以展示为系统事件、toast、专用 panel 或 inline system card。
- `/commands` 返回可见命令列表，前端可用于补全或帮助面板。
- debug/admin 命令是否展示由后端结果决定，前端不自行猜测权限。

## 12. 实现计划

### Phase 2.0: Command Core Foundation

- 新增 `CommandDefinition`、`CommandRouteTarget`、`CommandParseResult`、`CommandExecutionResult`。
- 实现 `CommandRegistry`。
- 实现基础 parser。
- 注册 `/help`、`/commands`。

验收：

- command id / alias 冲突报错。
- unknown / invalid args / ambiguous 返回稳定状态。
- listing 不暴露隐藏命令。

### Phase 2.1: Gateway L1 Integration

- `RuleInterceptor` 使用 registry 匹配系统指令。
- 禁用 command registry 时不拦截系统指令。
- L1 命中后不调用 L2 analyzer。
- `GatewayResult` / `EyeGazeResult` 在过渡期可携带 command parse result。

验收：

- `/help` 能被 L1 识别。
- 普通自然语言不被误判为 command。

### Phase 2.2: Dispatcher and Built-in Handlers

- 实现 `SystemCommandDispatcher`。
- 实现 local handler 执行。
- 实现 global route dispatch。
- 实现权限拒绝、需要确认、未实现路由、异常转换。

验收：

- `/commands` 返回可见命令列表。
- 权限不足返回 `REJECTED`。
- destructive/requires_confirmation 不执行副作用。

### Phase 2.3: Chat / Stream Short-Circuit

- chat stream 输出 `command_result` 后正常 `done`。
- 系统指令不触发普通 Alice generation。
- 系统指令不触发 retrieval / topic creation / active memory generation。

### Phase 2.4: Configuration, Observability, Frontend Contract

- 增加 command 配置项。
- 增加 command execution trace/event。
- 定义前端 command result 展示协议。

### Phase 2.5: Cleanup and Compatibility Tightening

- 移除 command 相关临时分支。
- 新代码统一使用 `hivememory.gateway.commands`。
- 旧测试按新结构重写或断开。

## 14. 验收清单

1. `CommandRegistry`、parser、dispatcher 位于 `hivememory.gateway.commands`。
2. 内置命令至少覆盖 `/help`、`/commands` 和一个 runtime/status 类指令。
3. `RuleInterceptor` 不再硬编码系统指令正则，而是从 registry 获取匹配能力。
4. S0 命中 command 时短路普通 Gateway workflow。
5. 指令执行结果使用 `CommandExecutionResult` 或等价稳定协议。
6. `/chat/stream` 可输出 `command_result` 事件并正常 `done`。
7. 权限拒绝、参数错误、未知命令、未实现路由都有稳定返回。
8. 非破坏性命令可执行；破坏性命令不会在 v0.6.0 无确认执行。
9. 系统指令不会隐式触发 Patchouli retrieval、topic prepare、Alice run 或 active memory generation。
10. 前端不需要解析 assistant 文本来识别 command result。
