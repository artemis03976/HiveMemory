# v0.6.0 Passive Conversation Memory Ingress 设计

**文档状态**: Draft  
**适用范围**: `system/application/passive/`、`gateway/`（`GatewayIngressMode`）、`patchouli/`（retrieval/submit）、`server/routers/`  
**前置版本**: v0.6.0 Gateway 核心 workflow（Phase 3A–3F）稳定  
**核心目标**: 将 Passive ingress 定位为外部对话记忆中间件，复用 Gateway 的 topic/query 决策和 Patchouli 的记忆读写能力，但不执行 HiveMemory command、Alice、MTP 或响应生成。

---

## 1. 定位

Passive ingress 的产品边界是"外部对话记忆中间件"，服务类似 Telegram bot、Discord bot 或其他非 HiveMemory 对话链路。它观察外部对话、为外部调用方提供记忆参考，并把完整外部 turn 提交给 Patchouli；它不是第二套 active chat runtime，也不是通用外部数据 ingestion framework。

Passive ingress 与 Gateway 核心系统的关系：

- 复用同一 Gateway workflow、state 和 `GatewayDecision`，不建立 Passive 专用 Gateway state、decision view 或 Engine 组合。
- 通过 `GatewayIngressMode.PASSIVE_MEMORY` 控制入口策略：禁用 HiveMemory command、只返回 `GatewayDecisionOutcome`。
- simple-chat bypass、Topic Routing、User Query Analysis 和 finalize 契约与 `ACTIVE_CHAT` 保持一致。

---

## 2. 能力边界

Passive ingress 负责：

- 接收并规范化外部 `user`、`assistant`、`tool_call` 和 `tool_result` 事件。
- 按来源和外部会话聚合完整 turn。
- user 事件到达时以 `PASSIVE_MEMORY` mode 调用 Gateway，获得 topic、query、memory 和 retrieval 决策。
- 根据 `GatewayDecision` 请求 Patchouli retrieval，并把编译后的 memory context/ref 返回外部调用方。
- turn 完成后构造结构化 `InteractionPayload`，连同该 turn 的 topic decision 提交给 Patchouli。
- 把外部 tool call/result 作为对话事实保存。

Passive ingress 不负责：

- 解释或执行 HiveMemory system command；外部对话拥有自己的 command 体系。
- 调用 Alice、MTP、HiveMemory tool runtime 或生成 assistant response。
- 替外部 bot 控制回复、重试或对话生命周期。
- 执行外部 tool call；输入中的 tool event 只能被记录。
- 解析文档、切分 chunk 或管理 Document Ingestion Job。

---

## 3. Gateway 入口策略

| 能力 | `ACTIVE_CHAT` | `PASSIVE_MEMORY` |
| --- | --- | --- |
| HiveMemory command 识别与执行 | 启用 | 禁用；`/command` 作为普通文本 |
| simple chat 识别与分析旁路 | 启用 | 启用 |
| Candidate Topics Preparation | 启用 | 启用 |
| Topic Routing | 启用 | 启用 |
| Routed Topic Preparation | 启用 | 启用 |
| Standard User Query Analysis | 非 simple chat 时启用 | 非 simple chat 时启用 |
| Gateway outcome | command 或 decision | 只允许 decision |
| 实际 retrieval | Patchouli 执行并交给 Alice | Patchouli 执行并返回外部调用方 |
| Alice/MTP/response generation | 启用 | 禁用 |

`PASSIVE_MEMORY` 复用同一 Gateway workflow、state 和 `GatewayDecision`。mode 只控制 Entry Interception policy 和合法 terminal outcome；simple-chat bypass、topic routing、fallback 和 finalize 契约保持一致。

## 4. 外部事件与会话契约

```python
class PassiveIngressEvent(BaseModel):
    source: str
    external_conversation_id: str
    external_event_id: str
    turn_id: str | None = None
    role: Literal["user", "assistant", "tool_call", "tool_result"]
    content: str
    occurred_at: datetime
    sequence: int | None = None
    is_final: bool = False
    # tool metadata 按现有 TurnEvent 契约继续携带


@dataclass(frozen=True)
class PassiveConversationKey:
    source: str
    external_conversation_id: str
    user_id: str
    agent_id: str
    team_id: str | None = None
```

约束：

- `source + external_conversation_id` 构成外部会话命名空间，不能只按 `user_id + agent_id` 分桶。
- `source + external_event_id` 是幂等键；同一事件重试不得重复追加、重复 retrieval 或重复提交 interaction。
- connector 能提供 `turn_id`、`sequence` 和明确 final signal 时必须直接使用；不能提供时才由下一条 user、idle timeout、显式 flush 和 shutdown drain 兜底。
- `is_final=True` 表示当前事件完成该 turn；它不等价于 assistant role，因为外部 assistant 可能分段输出，也可能在 tool result 后才结束。
- v0.6.0 可以使用有界的进程内 dedup 和 turn buffer，不承诺跨进程 exactly-once；该限制必须在 public API 中明确，后续可替换为持久化 ingress store。

## 5. 读写时序

```text
user event
  -> 若上一 turn 尚未提交，先 seal 并提交上一 turn
  -> Gateway.process(PASSIVE_MEMORY)
  -> GatewayDecision
  -> Patchouli retrieval
  -> 用 decision 初始化当前 turn buffer
  -> 返回 memory context/ref 给外部调用方

assistant / tool_call / tool_result
  -> 追加到当前 turn buffer
  -> 返回 accepted/buffered acknowledgement
  -> 不调用 Gateway，不执行 tool

turn final / next user / idle timeout / explicit flush / shutdown drain
  -> seal InteractionPayload
  -> 放入 pending sealed-turn outbox
  -> Patchouli.submit_interaction(payload, target_topic)
  -> 提交成功后移除 outbox item
```

新 user 到达时必须先提交上一 turn，再分析新 user；不能在新请求的 Gateway/retrieval 完成后才处理旧 turn，否则新请求失败会连带阻塞上一轮记忆提交。

每个 conversation runtime 分离"当前可变 turn accumulator"和"不可变 pending sealed-turn outbox"。上一 turn 提交失败时保留 outbox item，但不能占用或覆盖当前 accumulator；新 user 仍可开始下一 turn。v0.6.0 的 outbox 可以是有界进程内结构，后续持久化时保持同一提交语义。

user event 的公共响应只提供外部调用方实际需要的 memory context/ref 和接收状态，不暴露 `GatewayExecutionState`、runtime event 或内部 fallback。非 user event 只返回 acknowledgement。Passive ingress 不返回 command response 或 assistant response。

---

## 6. 记忆写入与失败语义

- Gateway 的 `memory_write_signal` 只基于 user query，是写入预判而不是丢弃完整外部 turn 的授权。
- 完整 turn 无论预判结果如何都应保存 raw interaction artifact/provenance；`MemoryWriteSignal.SKIP` 可以阻止默认长期记忆生成，但不能删除原始事实。
- Patchouli 在看到完整 assistant/tool 内容后仍拥有最终的记忆生成策略；必要时可以覆盖 user-only 预判，但该判断不反向修改 Gateway decision。
- Gateway 或 retrieval 的可恢复失败不得阻止当前 user 进入 buffer；Passive ingress 使用无 memory context 的降级响应，并继续在 turn 完成后提交原始交互。
- Patchouli submit 失败时必须保留 sealed turn outbox item 供重试，不能在提交前丢弃 payload，也不能阻塞或覆盖下一 turn accumulator。
- 所有降级、重复事件和提交失败只通过 `RuntimeEventSink` 观测，不把 debug/fallback 细节混入外部业务响应。

---

## 7. 与 Document Ingestion 的边界

外源文档不是 conversation turn，不复用 `PassiveIngressEvent`、`MessageTurnBuffer`、`InteractionPayload`、Topic Routing 或 User Query Analysis。未来文档资产化应保持独立路径：

```text
Document Artifact
  -> Document Ingestion Job
  -> Parse / Chunk Artifacts
  -> Candidate Memories
  -> PendingAtom / Reviewable Draft
  -> Patchouli Materialization
```

Passive conversation 与 Document Ingestion 只共享 identity/visibility、artifact/provenance、runtime event、候选记忆生成和 Patchouli materialization 等下层能力。v0.6.0 不为未来文档需求抽象通用 ingress workflow；Document Ingestion 仍属于后续版本和独立设计。

## 9. 可观测性

Passive ingress 不在 buffer/outcome 中积累 trace；重复事件、降级和提交状态同样只以 event sink 为观测来源。Passive event 默认只记录 ID、role、计数和脱敏摘要，不记录外部消息全文、tool args 或完整 memory context。

至少发布以下结构化事件：

| Event | 关键字段 |
| --- | --- |
| `PassiveIngressEventAccepted` | `source`、conversation/event/turn correlation、role |
| `PassiveIngressDuplicateIgnored` | `source`、`external_event_id` |
| `PassiveMemoryContextPrepared` | conversation/turn correlation、总耗时、memory ref 数、是否降级 |
| `PassiveTurnSubmitted` | conversation/turn correlation、topic ID、事件数、触发原因 |
| `PassiveTurnSubmitFailed` | conversation/turn correlation、错误分类、重试状态 |

## 10. 实现计划

### Phase P1: Gateway Ingress Mode 扩展

- 为 Gateway public process 增加必传 `GatewayIngressMode`。
- 实现 `PASSIVE_MEMORY` 下 command 规则禁用与 decision-only invariant。
- 验收：`PASSIVE_MEMORY` 下 `/command` 不调用 registry/dispatcher、不产生 command outcome，并作为普通文本继续 workflow。

### Phase P2: 事件模型与会话隔离

- 扩展 `PassiveIngressEvent` 和会话 key，加入 source、外部 conversation/event/turn correlation、final、sequence 和时间字段。
- 用有界 dedup registry 保证进程内重复事件不重复处理。
- 验收：`source + external_conversation_id` 会话隔离和 `source + external_event_id` 幂等测试。

### Phase P3: 读写时序迁移

- user 事件改为先提交旧 turn，再依次请求 Gateway decision 和 Patchouli retrieval；删除旧 `PATCHOULI_PASSIVE_ANALYZE_AND_RETRIEVE` 聚合入口依赖。
- turn buffer 直接保存稳定 `GatewayDecision` 所需的派生值，不再保存 `EyeGazeResult`。
- assistant/tool event 只构建 `TurnEvent`；不调用 Gateway、Alice、MTP 或 tool runtime。
- final/next-user/idle/manual/shutdown 统一 seal `InteractionPayload` 并放入 pending outbox；只有 Patchouli submit 成功后才移除 outbox item，失败时保留重试且不阻塞下一 turn。
- Passive public response 只返回 memory context/ref 或 acknowledgement，不返回 Gateway internal state、command response 或 assistant response。

### Phase P4: 失败语义与可观测性

- 实现 retrieval/Gateway 可恢复失败的降级响应。
- 实现 Patchouli submit 失败的 outbox 保留与重试。
- 实现 `MemoryWriteSignal.SKIP` 不删除 raw interaction artifact/provenance。
- 接入 passive ingress event 发布。

### Phase P5: 测试

- user 事件先提交旧 turn，再执行 Gateway `PASSIVE_MEMORY` 和 Patchouli retrieval 测试。
- assistant/tool event 只进入 buffer，不调用 Gateway/Alice/MTP/tool runtime 测试。
- explicit final、next user、idle timeout、manual flush 和 shutdown drain 产生同构 `InteractionPayload` 测试。
- retrieval/Gateway 可恢复失败仍接收并累计 turn、返回无 memory context 降级响应测试。
- Patchouli submit 失败保留 sealed outbox item、允许下一 turn 继续，成功后才移除测试。
- `MemoryWriteSignal.SKIP` 不删除 raw interaction artifact/provenance 测试。
- public response 不包含 command、assistant response、Gateway internal state 或 fallback/debug 细节测试。
- Document Ingestion 不复用 Passive event/buffer/InteractionPayload 的依赖边界测试。

## 11. 验收清单

1. `GatewayIngressMode` 是必传固定策略；`PASSIVE_MEMORY` 复用同一 Gateway workflow 和公共 decision。
2. `PASSIVE_MEMORY` 禁用 HiveMemory command 并且只返回 `GatewayDecisionOutcome`，但保留 simple-chat bypass、Topic Routing 和 User Query Analysis 语义。
3. Passive user event 先提交旧 turn，再请求 Gateway decision 与 Patchouli retrieval；非 user event 不调用 Gateway。
4. Passive ingress 不调用 Alice、MTP 或 tool runtime，也不生成 command/assistant response。
5. Passive 会话按 source、外部 conversation 和 identity 隔离；重复 external event 在进程内幂等。
6. explicit final、next user、idle、manual flush 和 shutdown drain 统一生成结构化 `InteractionPayload`。
7. 完整 Passive turn 始终保留 raw artifact/provenance；Gateway memory signal 不作为删除原始事实的依据。
8. Patchouli submit 失败时 sealed-turn outbox item 不丢失、不阻塞下一 turn，提交成功后才移除。
9. Passive ingress 的观测信息只进入 `RuntimeEventSink`，外部响应只包含 memory context/ref 或 acknowledgement。
10. Document Ingestion 不复用 Passive conversation event、buffer、InteractionPayload 或 Gateway workflow，只共享 artifact/provenance 和 Patchouli materialization 等下层能力。
