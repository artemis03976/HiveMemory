# V1 Memory Legacy 数据迁移与 legacy 分支删除

## 1. 背景与问题

v0.6.2 身份收敛（[归档 Plan](../archive/plans/v0.6.2-identity-projection-cleanup.md)）冻结了 V2 身份与策略语义：Memory 的唯一持久化归属是 `meta.workspace_identity`，Workspace 内可见性由 `MemoryAccessPolicy`（`PUBLIC/PRIVATE/TEAM`）表达，来源（`source_agent_id`）只作 provenance、不参与授权。历史 Qdrant 记录仍以 V1 形状存储：payload 中存在平铺 `meta.user_id`，缺少 `workspace_identity` 与 `access_policy`。

当前代码为这些历史记录保留了受控兼容分支（W0/v0.6.2 裁定的临时状态）：

1. `memory_codec.py _legacy_workspace_identity`：读取时从平铺 `meta.user_id` 重建 `WorkspaceIdentity`（映射到该用户的 `main_workspace`）；`user_id` 与投影 owner 冲突或缺失时 fail closed 抛 `MemoryDecodeError`；
2. `filter_adapter.py _ownership_filter`：查询条件在 `meta.owner_user_id + meta.workspace_key` 之外保留对 `meta.user_id` 的 legacy OR 分支，保证旧记录仍可被检索；
3. `InteractionTurnSnapshot` 的旧平铺 actor JSON 读升级分支（缺 `actor_identity` 时从 `user_id/agent_id/team_id` 重建，缺用户归属 fail closed）。

这些分支让历史数据继续可用，但也让"一条记录是否 V2"成为运行时分支判断，且 legacy OR 分支使查询语义长期携带第二套归属字段。V1 全量迁移是删除上述 legacy 解释分支的前置条件。

## 2. 目标与非目标

### 2.1 目标

1. 一次性、可审计地把存储中全部 V1 Memory 记录迁移到 V2 形状（补齐 `workspace_identity`、`access_policy`，移除平铺 `meta.user_id` 权威语义）；
2. 迁移过程 fail closed：无法安全推断归属或策略的记录不落库，进入诊断清单；
3. 输出迁移报告（扫描总数、迁移数、fail-closed 数、逐条原因）；
4. 迁移后经观察窗口验证，删除 legacy codec/filter/快照读升级分支及其测试白名单。

### 2.2 非目标

1. 不迁移 Memory 以外的对象（Artifact 的旧平铺 JSON 升级分支处理范围随本 Plan 一并评估，但 artifact 本身 append-only、不回写）；
2. 不改变 V2 身份/策略语义，不引入新的归属字段；
3. 不实现跨用户 Workspace 授权、认证或多租户（属 [Identity and Execution Safety Governance](../governance/security/identity-and-execution-safety.md) 工作包）；
4. 不在本 Plan 内清理短期 Topic（进程内存态，无持久化 legacy 数据）。

## 3. 当前状态与缺口

| 项 | 现状 | 缺口 |
|:---|:---|:---|
| 新写入 | 全部为 V2（`MetaData.workspace_identity` 必填，`to_qdrant_payload` 只投影 owner/workspace 键） | 无 |
| 历史读取 | codec 兼容分支按 `meta.user_id` 重建归属并 fail closed | 依赖分支长期共存 |
| 历史检索 | `_ownership_filter` legacy OR 分支 | 查询语义携带第二归属字段 |
| InteractionTurnSnapshot | 旧平铺 JSON 读升级，fail closed on 缺归属 | 与 Memory 迁移共享观察窗口 |

## 4. 目标设计

### 4.1 V1 → V2 字段映射

| V1（历史 payload） | V2（目标形状） | 规则 |
|:---|:---|:---|
| `meta.user_id` | `meta.workspace_identity = WorkspaceIdentity(owner_user_id=user_id, workspace_key="main_workspace", workspace_id="main_workspace")` | 唯一合法归属来源；缺失或与既有投影冲突 → fail closed |
| （无） | `meta.access_policy` | 默认 `PUBLIC`（Workspace-local）；已带可见性字段的记录按其值映射，缺失 `visibility` 时 fail closed 进入诊断 |
| `meta.source_agent_id`（如存在） | 保持不变 | provenance 展示，不参与授权 |
| 其余 index/payload/relations 字段 | 原样保留 | 迁移不重写业务内容 |

### 4.2 迁移执行方式

1. 离线脚本（一次性维护工具，不进入请求链路）：按 Workspace 分批 scroll 全量记录，逐条判定 V1/V2（以 `workspace_identity` 是否存在为准）；
2. 每条记录先计算 V2 形状并校验模型，再原位 upsert；单条失败不中断批次，记录进诊断清单（ID、原因、原始 payload 位置）；
3. 脚本输出结构化迁移报告（JSON + 人类可读摘要），作为删除 legacy 分支的验收证据；
4. 幂等：重复执行时 V2 记录跳过，不产生二次写入。

### 4.3 fail-closed 条件

- `meta.user_id` 缺失或为空，且无 `workspace_identity`；
- `meta.user_id` 与 payload 中已投影的 `owner_user_id` 冲突；
- `access_policy` 可见性值不在 `PUBLIC/PRIVATE/TEAM` 枚举内，或 PRIVATE/TEAM 缺少合法 target（含保留 `system` target，V2 模型校验会拒绝）。

### 4.4 观察窗口与 legacy 删除门槛

迁移完成并生成报告后进入观察窗口（建议一个迭代周期）：期间 legacy 分支保留，运行时统计 legacy 读命中数（codec 分支触发次数）。删除 legacy 分支需同时满足：

1. 报告中 V1 存量迁移数为全量（fail-closed 清单已逐条处置或显式豁免归档）；
2. 观察窗口内 legacy codec 分支命中数为 0；
3. 双 Workspace 隔离与管理可见性测试在无 legacy 分支时保持通过；
4. 删除改动本身附带索引重建或全量扫描证据（证明存储中不再存在 V1 形状记录）。

## 5. 测试与验收标准

- 迁移脚本单元测试：V1→V2 映射、幂等重放、fail-closed 清单、报告结构；
- 集成测试：真实 Qdrant（`integration + real_infra`）下迁移前后检索结果一致；
- legacy 分支删除后：全量既有单测/集成通过，删除 `meta.user_id` OR 查询分支不影响双 Workspace 隔离测试；
- 验收出口：
  - [ ] V1 存量迁移完成且报告归档；
  - [ ] 观察窗口结束且 legacy 命中为 0；
  - [ ] legacy 分支与相关白名单删除；
  - [ ] §7 当前文档更新完成。

## 6. 风险与待决问题

1. **PRIVATE/TEAM 历史记录的策略推断**：V1 无 `access_policy`，默认 PUBLIC 会放宽历史可见性。迁移前需确认历史单租户阶段该默认是否可接受；若不可接受，需按 `source_agent_id` 推导 PRIVATE 的备选方案（待决）；
2. **Qdrant scroll 一致性**：迁移期间若有新写入，需按批次幂等设计避免重复或漏扫；
3. **观察窗口的统计口径**：需要为 legacy 分支添加最小命中计数（日志或指标），避免"无从判断是否仍被触发"。
