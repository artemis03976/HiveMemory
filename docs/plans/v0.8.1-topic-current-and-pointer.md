# v0.8.1 拉取当前话题与压缩后只推指针：topic:current 按需确定话题，会话压缩之后只推送句柄

> 状态：Planned（2026-11-26）。v0.8.1 短期记忆的第八份计划。设计依据是[短期记忆 Idea](../ideas/short-term-memory-and-context-compaction.md)第 7 节：话题的归属按需确定、每轮至多一次；拉取是基线，被路由回已有话题时由 agent 拉取；推送只在会话压缩之后、只推送一个指针。

## 1. 背景和问题

上一份计划让 agent 能按句柄读话题，并在 Claude Code 压缩会话之后注入话题的索引。owner 随后把 plugin 模式下前后几次的路由与注入决定统一为两条规则（Idea 第 7 节）：

- **话题的归属按需确定，每轮至多一次**：写入或更新之前、agent 读当前话题之前与轮次结束导入时，用同一个“为在途轮次确定话题”，先到的确定，之后沿用；不单独在轮首路由。
- **拉取是基线，推送只推指针**：每个 harness 都能拉取；推送只在会话压缩之后、harness 支持时做，只推送话题句柄与一句读法，不推送话题或中期记忆的内容。

现在有两处与这两条规则不符：

- 被路由回已有话题时，agent 没有办法读“这一轮所在的话题”：它不知道话题 id，系统也不在轮首推送。
- 压缩之后推送的是索引（进展记录的节选与未整理的轮次），钩子为此同步发一次 MCP 请求。

## 2. 目标与非目标

### 2.1 目标

- READ 接受 `topic:current`：这个会话这一轮所在的话题。读它时按归属规则为这一轮确定话题，再按真实句柄读出索引；不含 `topic:current` 的读取照旧，不确定话题。
- MCP 的 `memory_read` 接受可选的轮次信息；四个连接器像写入一样为含 `topic:current` 的读取补上它。
- Claude Code 压缩会话之后，钩子只输出一句带句柄的指针，不经 MCP 读取，不推送记忆内容。
- hivememory skill 告诉 agent 什么时候读 `topic:current` 与指针的含义。

### 2.2 非目标

- **轮首推送与 `UserPromptSubmit`**：按 Idea 第 7 节不做。
- **controller 模式的 `topic:current`**：Alice 的上下文没有地方发给它句柄，线程提交的读取不带确定话题的回调，`topic:current` 在 MTP 中按未解析交付。
- **`topic:current#n`**：不支持；索引里每一条都带真实句柄，agent 照它读一条的原文。
- **其他 harness 的压缩后推送**：Codex、pi 与 DeepSeek Harness 没有压缩之后的钩子，只能拉取。
- **改动话题的读取与渲染**：沿用上一份计划的 `topic:<id>` 索引与 `#n`。

## 3. 当前状态（2026-11-26 核对）

- **写入的按需确定话题**：MCP 的 `memory_write`、`memory_update` 带可选的 `turn: InFlightTurn`（Claude Code 与 Codex 的连接器在 PreToolUse 中按参数名填写，pi 与 DeepSeek Harness 的工具由 node 连接器在 `needsTurn` 为真时补上）。MCP 入口把 `import_bus_service.place_turn` 包成回调交给 `execute_request`，actor API 在授权与 UPDATE 的基础冷读之后才经 `_dispatch_topic` 调用它：被拒的写入不会路由、建立话题或触发 LRU 退役。同一轮再次请求返回同一个话题，轮末导入时沿用。
- **读取**：`memory_read` 只有 `aliases`；`execute_request` 对检索与读取给出回调时以 `TypeError` 拒绝；`ActorMemoryService.resolve_references` 只按工作 actor 授权，不涉及话题的确定。`topic:current` 现在按不合语法的话题句柄解析为 not_found（`parse_topic_handle` 要求 id 不含 `#` 与空白，`current` 会被当成一个不存在的 id）。
- **钩子的匹配**：Claude Code 与 Codex 的 PreToolUse 只匹配 `memory_write` 与 `memory_update`。连接器回流导入时从记忆工具的参数中去掉 `turn`（Python 与 node 都对全部记忆工具生效）。
- **压缩之后的推送**：`session_start_context` 在登记与派生同步之后，以连接器记下的话题标识经 `core/client.read_memory` 向 `/mcp` POST 一次 `memory_read`，结果作为 `additionalContext`（截到 9,500 字符）输出；`hooks.json` 中 SessionStart 的超时因此是 15 秒。`read_memory` 与 `MemoryReadError` 只有这一个使用方；集成测试中另有一条只发一次 JSON-RPC POST、不先初始化的用例，守护的就是这个调用方式。
- **连接器的语言**：连接器不知道 HiveMemory 的语言设置；skill 的中英文由后端启动时按语言写入。

## 4. 进入条件

阻塞问题已决定（owner，2026-11-26）：话题的归属按需确定、每轮至多一次，不单独在轮首路由；被路由回已有话题时改为由 agent 拉取；会话压缩之后只推送一个指针；plugin 模式下不推送中期记忆。Idea 第 9 节没有阻塞下一份计划的开放问题。依赖均已是事实。

## 5. 目标设计

以下名字与数值是起草时的默认值，计划评审时可以调整。

### 5.1 `topic:current` 句柄

- core 话题模型增加常量 `CURRENT_TOPIC_HANDLE = "topic:current"`；它不是话题 id 句柄，`parse_topic_handle` 不解析它。话题 id 是 `uuid4` 字符串，不会是 `current`。
- 只有不带条目序号的形态；读出的是这一轮所在话题的索引，开头一行照常是真实句柄 `[topic:<id>]`，agent 据此读 `#n`。

### 5.2 读取时按需确定话题（Workspace）

- `ActorMemoryService.resolve_references` 增加可选的 `dispatch_topic`：先按 `memory.read` 授权，再看引用中有没有 `topic:current`；有且给出了回调时，经现有的 `_dispatch_topic(None, dispatch_topic)` 取得这一轮的话题（同一次读取只取一次），把 `topic:current` 换成真实句柄后照常解析。没有 `topic:current` 时不调用回调，不路由。
- 没有回调（线程提交，或 MCP 调用没有带轮次信息）时，`topic:current` 按 not_found 交付，提示需要这一轮的信息。
- 确定话题失败时，整次读取以与写入相同的错误失败（例如话题正忙的 `patchouli.topic.busy`），可以重试。
- `execute_request` 的规则改为：检索不得给出回调；读取可以给出，actor API 只在引用含 `topic:current` 时调用；写入与更新必须给出。请求级提交的调用方仍然只有 MCP 入口。
- 读当前话题可能为这一轮建立新话题、在池满时触发 LRU 退役，与写入时相同；导入时沿用这个话题。

### 5.3 MCP

- `memory_read` 增加 `turn: InFlightTurn | None = None`，说明与写入相同（由插件填写）。给出时 MCP 入口认证后把 `place_turn` 包成回调交给 `execute_request`；没有给出时不带回调。
- `read_description` 与 `aliases_description` 写上 `topic:current`：读这个会话这一轮所在的话题。

### 5.4 连接器

- Claude Code（`hooks.json`）与 Codex（`codex.json`）的 PreToolUse 匹配加上 `memory_read`。`pre_tool_use` 只在 `aliases` 含 `topic:current` 时补上 `turn`，其余读取原样放行（不输出）。
- node 连接器（pi、DeepSeek Harness）：`memory_read` 在 `aliases` 含 `topic:current` 时补上轮次信息，规则同 `needsTurn`。
- 导入回流照旧去掉 `turn`，交互记录中这次读取的作用对象仍是 `topic:current`。

### 5.5 压缩之后只推指针

- `session_start_context` 不再经 MCP 读取：连接器状态里有话题标识时，输出一句指针作为 `additionalContext`，中英文各一句：
  - “HiveMemory：可以读取 topic:<id> 查看这个会话所在的话题进行到哪一步。”
  - “HiveMemory: read topic:<id> to see where this session's topic stands.”
  没有记下话题时不输出。指针不含任何记忆内容。
- 删除只为它存在的 `read_memory`、`MemoryReadError` 与读取超时常量，以及集成测试中只发一次 POST 的那条 MCP 用例（不再有生产使用方）；身份头的共用函数仍供导入客户端使用。
- `hooks.json` 中 SessionStart 的超时恢复为 10 秒。

### 5.6 skill

- `skill-languages/zh` 与 `en` 的 hivememory skill 增加两句：用户回到之前的工作、或不确定一项工作或讨论此前进行到哪一步时，先读 `topic:current`；会话压缩之后看到 HiveMemory 的指针时，读其中的句柄。

## 6. 受影响的系统、契约和数据

| 范围 | 改动 |
|:---|:---|
| core | `CURRENT_TOPIC_HANDLE` |
| Workspace 能力层 | `resolve_references` 的可选回调；`execute_request` 对读取的回调规则 |
| MCP | `memory_read` 的 `turn`；工具说明 |
| 插件 | PreToolUse 匹配与补上轮次信息；node 连接器；压缩之后只推指针；删除 MCP 读取客户端；SessionStart 超时；skill |

不新增 actor 操作、HTTP 路由与请求级提交的调用方；话题日志与各保存格式不变；Import Bus 不变。

## 7. 兼容与迁移

- `memory_read` 多一个可选参数，旧连接器不传它，`topic:current` 按未解析交付，其余读取不受影响。
- 压缩之后注入的内容由索引改为指针，是行为变化：agent 要再读一次句柄才能看到索引。
- 插件更新后才生效：日常实例经桌面客户端重新安装插件（Claude Code 与 Codex 自动重装；pi 与 DeepSeek Harness 重新打开即可）。

## 9. 风险与待决问题

- **拉取不保证发生**：agent 不一定按 skill 去读 `topic:current`，也不一定读指针里的句柄；效果在日常使用里看。
- **读当前话题的等待**：第一次读 `topic:current` 时要等一次话题路由（日常约 3 秒）；这一轮此前已有写入时直接沿用，不再等。
- **读取的副作用**：读当前话题可能建立话题或触发 LRU 退役，与写入相同。
- **指针的语言**：连接器不知道语言设置，默认中英文各一句。
- **待评审的默认值**：`CURRENT_TOPIC_HANDLE` 的名字；确定失败时整次失败（而不是只这一项未解析）；指针的措辞与双语；连接器只在含 `topic:current` 时补轮次信息。
