# v0.7.0 任务进程：结算阶段的中立输入

任务进程方向的第三批实施。第二批（[已归档](../archive/plans/v0.7.0-task-process-prepare-split.md)）让 Patchouli prepare 不再产出 Alice 专属的类型，但结算这一端没有变化：`finalize_agent_run` 仍接收 Alice 的 `AgentRunResult`，并在 Patchouli 内部从中组装交互记录。本批改由进程组装交互记录 `InteractionPayload` 交给 finalize，使 v0.7.0 版本目标第 1 条收口。

设计依据：[任务进程 Idea](../ideas/task-process-table-and-registration-entry.md) 第 1.2 节“结算阶段”（含 2026-09-29 关于进程组装交互记录与 `materialize_tasks` 的决定）与 Q-14（选项 A：进程自行封口并提交交互记录，交互记录采用 `InteractionPayload`）、当前事实文档与代码。

## 1. 背景和问题

`PatchouliService.finalize_agent_run(prepared_run, loop_result, *, used_attachments)`（`patchouli/service.py`）现在先从 Alice 的结果组装交互记录，再提交：

1. 用 `ActionReducer` 与 `TraceReducer` 从 `loop_result.turn_events` 归约 MTP 轨迹；
2. 以 `prepared_run` 中的用户消息与 GatewayDecision、`loop_result` 中的最终回复、轮次事件、物化任务与模型名，以及 `used_attachments` 组装 `InteractionPayload`；
3. 经交互提交队列提交，等待 applied，再派发物化任务、记录检索命中。

问题在第 1、2 步：

- Patchouli 的公开路由接收 Alice 专属的 `AgentRunResult`，与 v0.7.0 版本目标第 1 条冲突；
- 换一个 CPU，就得让 Patchouli 学会读懂它的执行结果；
- 同样是提交交互记录，被动链路由提交方（System 的 turn buffer）自己组装 `InteractionPayload`，主动链路却由接收方组装，两条链路的封口位置不一致。

## 2. 目标与非目标

**目标**：

1. `finalize_agent_run` 接收进程组装好的 `InteractionPayload`，不再接收 `AgentRunResult`；原 `used_attachments` 参数并入 payload。
2. 进程在进入 finalize 之前组装交互记录，材料全部来自进程自身：入口参数 `message`、Gateway 阶段得到的 GatewayDecision、Actor 的执行结果、工作集中实际使用的附件；MTP 轨迹由进程调用 core 中的两个归约器得到。
3. 本批完成后，Patchouli 的公开路由不再产出或接收 `AgentRunContext`、`StreamPrelude`、`AgentRunResult` 与编译好的记忆文本（版本目标第 1 条）。`InteractionPayload.materialize_tasks` 按 owner 决定继续存在，直到写入意图的实时派发实现。
4. 对外行为不变：同一轮对话提交的交互记录与现状逐字段相同；finalize 的时点、continuation、applied gate、物化派发、检索命中、SSE 事件与 `chat.run.*` 事件均不变。

**非目标**：

- CPU 端口、CPU 中立的执行结果类型与非 Alice 的测试 CPU（版本目标第 2 条，下一批）。本批中进程仍从 Alice 的 `AgentRunResult` 读取执行结果，但只在一处读取（4.2）；
- Actor 流式事件格式、SSE `done` 事件字段与非流式结果类型；
- `PreparedAgentRun` 的形状：finalize 不再读取其中的 `user_message` 与 `gateway_decision`；`user_message` 仍由 CPU 分配读取，`gateway_decision` 本批之后不再有读取方，是否删除留待 Topic 按需创建时一并处理；
- Topic 按需创建、Patchouli cleanup 路由的移除、Profile 解析时点；
- 写入意图迁移与 `materialize_tasks` 的移除；
- 命令（不面向 Actor，版本目标第 4 条另行处理）。

## 3. 当前状态（2026-09-29 核对）

### 3.1 结算输入的来源

| `InteractionPayload` 字段 | 现在的来源（finalize 内） | 进程侧已有的同一事实 |
|:---|:---|:---|
| `user_message` | `prepared_run.user_message` | 入口参数 `ProcessRequest.message`（prepare 以它冻结 `user_message`） |
| `rewritten_query`、`worth_saving` | `prepared_run.gateway_decision` | Gateway 阶段的 `gateway_result.decision`（原样传给 prepare） |
| `assistant_final_text`、`turn_events`、`model_used`、`materialize_tasks` | `loop_result` | Actor 阶段的 `loop_result` |
| `mtp_traces` | `TraceReducer.reduce(ActionReducer.reduce(turn_events))` | 两个归约器位于 `core.models.interaction`，进程可直接调用 |
| `used_attachments` | 参数 `used_attachments` | 工作集 `ProcessWorkingSet.used_attachments` |

finalize 在组装之后仍需要 `prepared_run` 的 `identity_scope`、`interaction_id`、`topic_id`、`is_new_topic`、`agent_id`（提交与失败补偿）与 `retrieval_result`（检索命中）。

### 3.2 消费方

- 生产调用方只有任务进程的 finalize 步骤（`workspace/process/task_process.py`）；
- `InteractionPayload` 位于 `core.protocol.models`；`MemoryPerceptionEngine.build_block()` 读取其中的 `turn_events` 与 `mtp_traces`，被动链路的 turn buffer 以 `mtp_traces=[]` 组装；
- 测试：`tests/integration/patchouli/test_active_interaction_submission.py`、`tests/unit/patchouli/test_phase3f_gateway_decision.py`、`tests/unit/patchouli/runtime/test_core.py`、`tests/unit/system/contracts/test_public_routes.py`、`tests/unit/system/test_lifecycle.py`、`tests/unit/workspace/capability/test_agent_profiles.py`、`tests/unit/workspace/capability/test_memory.py`、`tests/unit/workspace/process/` 与 `tests/integration/system/` 中引用 finalize 路由或签名的测试与替身。

## 4. 目标设计

### 4.1 Patchouli：finalize 接收交互记录

```python
finalize_agent_run(
    prepared_run: PreparedAgentRun,
    payload: InteractionPayload,
) -> list[MemoryGenerationTask]
```

- 删除归约与组装；`payload` 原样进入 `InteractionSubmission`，物化任务从 `payload.materialize_tasks` 派发（与现状相同）；
- continuation（按 `interaction_id` 去重、`asyncio.shield`）、applied gate、失败时的空 Topic 补偿、物化派发与检索命中都不变；
- `patchouli/service.py` 不再导入 `AgentRunResult` 与两个归约器。

设计理由随之调整：原契约写的是“Alice 声明本轮发生了什么，Patchouli 归约并形成 Interaction”。本批之后，交互记录由提交方封口，这与被动链路一致；归约规则只有 core 中的一份，由封口方调用，不形成第二套规则；Patchouli 仍负责判断交互如何进入长期知识（提交、感知、生成与 lifecycle），取消与失败的一轮仍不提交（Q-14）。

### 4.2 进程：封口交互记录

- 在 `workspace.process` 中新增一个纯函数（暂名 `seal_interaction`），按 3.1 的来源组装 `InteractionPayload`。它接收显式字段（消息、GatewayDecision、最终回复、轮次事件、模型名、物化任务、实际使用的附件），不接收 `AgentRunResult`，下一批接入 CPU 端口时签名不变；
- 骨架在 `try_enter_finalizing()` 成功之后、调用 finalize 之前封口，只在这一处从 `AgentRunResult` 取出字段；组装失败按进程失败处理，走现有关闭流程（与现状中 finalize 内组装失败的结局相同）；
- 流式与非流式共用同一骨架，无需分别修改。

### 4.3 依赖与分层

进程新增的导入都在 L0（`core.protocol.models`、`core.models.interaction`），不新增跨子系统导入；Patchouli 删除对 `AgentRunResult` 的导入。`InteractionPayload` 的字段说明中关于 `mtp_traces` 来源的描述同步改为“由封口方从结构化轮次事件归约”。

## 5. 受影响的系统、契约和数据

| 范围 | 变化 |
|:---|:---|
| Patchouli 公开路由 | `patchouli.public.finalize_agent_run` 的参数由 `PreparedAgentRun`、`AgentRunResult`、`used_attachments` 改为 `PreparedAgentRun`、`InteractionPayload` |
| Workspace | 任务进程新增交互记录封口步骤 |
| core | `InteractionPayload` 字段说明 |
| 持久数据 | 无变化：提交队列与 apply journal 中的 payload 内容与现状相同 |
| 前端、SSE、RuntimeEvent | 无变化 |

## 6. 兼容与迁移策略

- 路由参数直接修改，不保留别名或转发；所有调用方在同一批内更新；
- 对外行为不变（第 2 节目标 4），由第 8 节的逐字段等价测试守护；
- 回滚：一批一个提交序列，整体回退即可。

## 7. 实施步骤

1. 进程：新增封口函数；骨架在进入 finalize 前封口，并以 `payload` 调用 finalize 路由。
2. Patchouli：`finalize_agent_run` 改为接收 `payload`，删除归约与组装。
3. core：更新 `InteractionPayload` 的字段说明。
4. 更新测试（第 8 节），运行验证。

## 8. 测试和验收标准

测试遵循[测试设计规范](../governance/testing/test-design-standards.md)。

**调整的测试**：第 3.2 节列出的测试随 finalize 签名调整；`tests/unit/system/contracts/test_public_routes.py` 断言 finalize 的参数只有 `prepared_run` 与 `payload`，类型标注中不再出现 `AgentRunResult`。

**新增的行为测试**：

1. 进程封口（`tests/unit/workspace/process/`，Patchouli 与 Alice 以总线路由替身隔离）：完成的进程交给 finalize 的 `InteractionPayload` 逐字段等于预期：
   - `user_message` 为入口消息，`rewritten_query`、`worth_saving` 来自 Gateway 决定；
   - 最终回复、轮次事件、模型名与物化任务来自 Actor 结果；
   - `used_attachments` 等于附件编译实际使用的附件；
   - `mtp_traces` 以一组含 MTP 动作的固定轮次事件断言具体的轨迹内容，不在测试中重复调用归约器计算预期值；
   - 流式与非流式各验证一次。
2. 封口函数的单元测试：给定显式字段组装出的 payload 与预期逐字段相同；没有轮次事件时 `mtp_traces` 为空。
3. Patchouli 一侧（调整 `tests/integration/patchouli/test_active_interaction_submission.py`）：finalize 把收到的 payload 原样提交给交互提交队列，物化任务按 `payload.materialize_tasks` 派发；applied 之前失败时的空 Topic 补偿不变。

取消与失败结局不进入 finalize 由现有测试覆盖，保持通过。

## 9. 风险与待决问题

| 风险 | 应对 |
|:---|:---|
| 进程组装的 payload 与现状不一致，改变感知与记忆生成的输入 | 字段来源与现状一一对应（3.1）；新增测试 1 逐字段守护 |
| 契约中“Patchouli 归约”的设计理由失效 | 收尾时按 4.1 改写子系统公共契约与系统边界中的理由，不只替换签名 |
| 归约器同时被进程与感知引擎调用 | 两者调用 core 中同一份规则；被动链路保持 `mtp_traces=[]` 不变 |

待决问题：无。封口函数的名称与所在模块可在实施评审时调整。
