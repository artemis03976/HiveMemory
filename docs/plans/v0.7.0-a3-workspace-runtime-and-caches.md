# v0.7.0 A3：WorkspaceRuntime 与派生缓存迁移

Profile cache 和 Atom cache 是资源访问的派生加速层，却被 AliceRuntime 创建、清理和命中；canonical mutation 的失效也因此容易只覆盖 Alice 路径。A3 把两个 cache 聚合到一个进程级 `WorkspaceRuntime`，但不把 Patchouli canonical 数据、Topic 状态或业务 API 搬进 WorkspaceRuntime。

调查与既有决定见[WRX-0 清单](./v0.7.0-plan-a-wrx0-boundary-freeze.md)第 1–5/8 节；主要迁移源为 `alice/runtime/profile_cache.py`、`agent_runtime/aliases/cache.py` 和 `alice/runtime/core.py`，AssetStore 保留 `system/runtime/workspace/store.py`。依赖 A1 的已验证 scope/授权规则和 A2 的 Profile/Memory 快照；不依赖 A4 的 Session 或 B 的外部协议。

## 1. 目标和边界

WorkspaceRuntime 组合 access context 所需的基础设施、Profile/Atom snapshot cache、失效、epoch、Asset lease facade 和关闭生命周期。它不保存可变 `current_workspace`，不按 Workspace 创建 Runtime，不导入 Alice、MTP 或 Patchouli 私有 provider，不提供 `get_memory`/`search`/`submit` 等领域方法。

| 状态 | canonical owner | Runtime 责任 |
|:---|:---|:---|
| Memory/Profile | Patchouli | 派生 snapshot、key、revalidation、失效 |
| Topic/working set | Patchouli Perception | 不复制状态；使用 A2/A4 的 application |
| WorkspaceAsset | System AssetStore | scope-aware resolve/acquire/release facade |
| Pending | A5 的资源侧领域 | 不当作 cache、不复制状态机 |
| run/frame/history | Alice | 不进入 WorkspaceRuntime |

生产 SystemAssembler 的改动不是 A3-0 的前置条件；独立组合和真实 application 链可先验证，A6 再完成稳定装配。

## 2. Cache 契约

Profile cache key 至少包含 Workspace、user/Agent/team、profile alias/ref 及必要授权坐标；值包含 source atom UUID、revision/content identity 和 policy projection。Atom cache 按 `(WorkspaceIdentity, normalized_alias/ref)` 分区，值包含 canonical identity、revision、owner 和 provenance。两者都只能保存可重建派生值，不能保存永久授权。

每次命中仍须检查 access、ownership/visibility 和 revision freshness。负缓存必须绑定 scope、epoch 和错误类别；授权失败不能转成跨 Workspace 的 not-found。in-flight fetch 返回后重新检查 epoch，旧结果不能覆盖 canonical mutation 后的新状态。缺少 source revision 时采用同步 revalidation 或 no-cache，不能静默返回旧快照。

### 2.1 继承已关闭决定

WRX-0 第 8 节已冻结：MemorySnapshot 使用 `meta.version` 与 `updated_at` 作 source identity；Profile 配置来自 source atom payload，`ProfileSnapshot.source_revision` 使用同一 `meta.version`，不另设配置 revision；现有 MemoryAtom 版本字段有默认值 1，缓存接入采用同步 revalidation。A3 直接承接这些决定，不重新打开“增加 provider DTO”或拆 revision。未来支持缺失版本的来源时必须显式设计 no-cache/错误，不能借例外改变现有同步重验。

### 2.2 两个 cache 的行为表

| 维度 | 必须满足的行为 |
|:---|:---|
| 内容索引与授权投影 | 内容可共享存储，但每次返回由 Patchouli 重验当前 policy；任何带授权含义的派生视图须绑定完整访问坐标 |
| alias 替换 | 维护 alias→UUID 及反向引用，同一资源多个 alias 的替换/删除不留下可返回的旧值 |
| 并发冷读取 | 可合并同 key 请求；失效代次改变后重新验证，旧 fetch 不能回填或冒充当前成功 |
| 负缓存 | 仅有界、短暂保存允许的 not-found/invisible 结果，绑定 scope/epoch/错误；拒绝授权和存储故障不能污染其他 Actor 的负缓存 |
| 失败 | cache 故障不回滚 canonical 变更；必要时 no-cache/失败关闭，不以旧授权数据伪装成功 |
| close | 停止新读，处理已在途请求的完成/失败，清理仅属于 cache 的派生值；不删除 Pending/Session/canonical |
| 容量与观测 | 可保留全局 LRU，冻结负缓存 TTL/容量；记录 hit/miss/revalidation/invalidation/stale reject/close 拒绝，不承诺 Workspace 独立配额 |

业务调用始终是 application 校验 access → Patchouli 内部 cache 协作/冷读取 → 当前 policy/版本重验 → 返回快照。Workspace cache 只提供存取、索引、epoch 和失效，不接收全局路由或 Patchouli provider 负责冷读取；不形成 application → Workspace service → application 递归。

## 3. 失效、生命周期和装配

Memory create/update/delete/archive/revive、materialization settlement、Profile source/policy 变化和 Asset representation revision 都必须在 canonical 提交边界调用统一 invalidation。RuntimeEvent 可作为观测，但事件投递失败不能成为正确性的唯一保障。单个 run 完成不清理资源 cache；Alice stop 不关闭 WorkspaceRuntime。

关闭顺序是停止接纳、等待 resource read/settlement、drain producers、detach consumers、关闭 cache/Asset/Patchouli。A3 只冻结 runtime contract；A6 负责把它接入完整 System composition。

| canonical 变更源 | 失效覆盖 |
|:---|:---|
| Memory 管理 create/update/delete、archive/revive | Atom 快照、alias 正反索引、引用该 source 的 Profile projection |
| generation/materialization/settlement | canonical revision 可读时同步推进 epoch，并失效对应 Atom/Profile |
| source visibility/policy 或 Profile payload 改变 | 内容未变也要废弃授权/解析投影，返回前使用当前 policy |
| Asset representation 变化/remove | 禁止旧 revision 获得新 lease；已有 lease 按 W1 生命周期处理，不擅自使持有者悬空 |
| 调试/测试/内部管理 mutation | 通过同一 owner 提交和失效协作，不直改私有字典 |

原清单只调查到 Alice settlement 和 MTP UPDATE 两条失效路径；A3 实施必须覆盖所有受支持 canonical mutation，不只移动这两个调用点。同步 invalidation 失败时必须明确读侧如何禁止旧命中，不能仅输出日志继续返回旧值。

## 4. 实施与验收

| 阶段 | 产出 | 验收 |
|:---|:---|:---|
| A3-0 | WorkspaceRuntime、cache/invalidation/Asset 内部接口、close contract | 可脱离 Alice 构造、读取、失效和关闭；没有 per-Workspace Runtime |
| A3-1 | Profile/Atom cache 迁移与 key/snapshot/epoch/negative cache | 两 Workspace 隔离；mutation 后旧 revision 不可命中；旧 fetch 不回填 |
| A3-2 | 所有 canonical mutation 接入和独立组合验证 | management、generation、lifecycle、Asset mutation 都失效；删除 cache 不改变领域结果 |
| A3-3 | Alice 兼容 adapter 和生产装配交接 | 只有一份正式可命中 cache；Alice 不再拥有 clear/close 责任 |

unit 覆盖 key normalization、snapshot、copy-on-read、alias replacement、epoch race、错误和 close。integration 使用真实 application + canonical + cache，覆盖无 Alice、授权变化、cache hit、存储故障、shutdown drain。不得用私有字典、re-export 或转发次数作为完成证据。

## 5. 迁移与收口

旧 cache 属性可以短期委托，但 A3-1 后不允许 Alice 和 Workspace 同时作为成功来源；双写只用于观测对比。若出现授权/一致性回归，回滚旧 adapter 仍使用统一 access 和单一 cache，不把资源状态复制回 Alice。A3 完成后按文档治理更新 Workspace、composition、Alice 和 ADR-0004 的 supersede 关系；跨进程 cache 恢复、Workspace 配额和新 schema 另立计划。

目录按已冻结方向落到 `workspace/runtime.py`、`workspace/cache/{keys,atom,profile}.py` 与基础设施协议；已有 AssetStore 原地保留。无需为组织目录创建空服务类；`workspace/services` 若保留，只能承载失效/lease/snapshot 协作。主要未决项是负缓存窗口、容量、close 的在途行为和失败时禁用旧值的机制，在 A3-0/1 冻结；不把性能调优或固定 TTL 变成跨计划前置。
