# v0.8.0 馆长 agent：结算时先探索本话题的写入与库中相关记忆，再写记忆

> 状态：Planned（2026-11-19）。v0.8.0 的第三个方向“馆长 agent”的计划。设计依据见[写入链路 Idea](../ideas/memory-flow-write-path.md)第 3.1 节。

## 1. 背景和问题

话题结算时，被动生成现在是一次性提取加事后规则：模型看不到本话题已经写入的记忆，也看不到库，只从材料里尽量多地提取草稿；之后逐条以 dense top-1 查重，完全相同的只触碰，相似的新建并提名合并，命中本话题写入的直接丢弃；合并以较新的一条作骨架。复述、误丢与合并改写主动写入，都由这一串规则在补前一层的漏洞（[生成](../patchouli/generation.md)第 3.1、4 节）。

owner 于 2026-11-19 决定：结算时 Patchouli 尽量不与本话题主动写入过的记忆重叠，尽量不与库中相关记忆重叠，在此前提下写记忆；前两步是两个阶段的探索，由馆长 agent 完成，用 agent 的主动探索代替规则拦截与生成；最后仍有重叠就接受，不加复核、去重或兜底的逻辑。工具与循环由 Patchouli 内部自己定义（写入链路 Idea 第 3.1 节）。

## 2. 目标与非目标

### 2.1 目标

1. 结算时运行馆长：一个由 Patchouli 定义的工具循环。它先查看本话题主动写入结算到的记忆，再检索并阅读库中相关的记忆，然后写入新记忆，草稿引用材料中的段。
2. 馆长代替被动提取与其后的规则：结算产出的记忆不再经过查重、触碰、合并提名或丢弃。
3. 馆长的工具只操作 Patchouli 自己拥有的数据，不经过 Workspace 的 actor API，也不使用 MTP。

### 2.2 非目标

- **修订或合并已有记忆**：馆长只新建；不修订本话题的写入，也不修订别的话题留下的记忆（owner 2026-11-19 否掉了结算时对账全库）。
- **读其他话题的原始轨迹**：经旧记忆的段引用回到原文需要一个读取交互快照的组件，现在没有；第一版只读记忆本身，当前话题的材料已经在上下文中。
- **主动写入（Mode B）与修订（Mode C）**：行为不变，查重与合并照旧。
- **同一 Workspace 的结算串行**：两次结算可以同时运行，残余的重叠接受。
- **原生工具调用**：模型服务只有文本接口，第一版用 JSON 动作协议（第 5.2 节）。

## 3. 当前状态（2026-11-19 核对 master）

- **结算链路**：感知冻结话题、构建 `TopicMaterializeTask`，生成接纳之后删除短期话题（`patchouli/services/perception.py`）；协调器以没有焦点的 `GenerationRequest` 提交 SETTLE（`control/memory_generation/coordinator.py`）；控制器执行时把本话题主动写入结算到的记忆并入 `topic_write_memory_ids`，SETTLE 成功后清除（`control/memory_generation/controller.py`）；Familiar 先捕获交互快照，再调用引擎，提交在不可中断的一段里完成（`patchouli/services/memory_generation.py`）。
- **被动生成**：引擎的 Mode A 渲染材料后调用 `extractor.extract`，对每条草稿调用 `_dedup_and_resolve`：dense top-1，命中本话题写入即丢弃，IDENTICAL 触碰，其余新建，SIMILAR 且访问策略相同时提名合并（`engines/generation/engine.py`）。被动提示词与 `ExtractionResult` 只服务 Mode A。
- **模型服务**：Patchouli 共用一个 `LiteLLMService`，唯一入口是文本的 `complete(messages, params)`，没有原生工具调用（`infrastructure/llm/base.py`）；提取器失败最多重试一次，输出无法解析时返回空列表、任务照常完成。
- **可用的读取**：中期库 `search`（dense 或 sparse，单向量、不融合、不重排，返回带分数的记忆）、`get`、`get_by_alias`（`memory_library/stores.py`），都按 `from_actor` 检查可见性；结算以 Workspace 的 system actor 运行，只读得到 PUBLIC 记忆。`RetrievalFamiliar` 的检索会刷新生命力。没有任何代码读回交互快照。
- **并发与超时**：生成 lane 并发 2、超时 300 秒，不按话题或 Workspace 串行；没有步数或 token 预算。
- **配置**：`patchouli.generation` 下有 `extractor.enabled`（前端显示为“自动从对话中提取记忆”）、`deduplicator` 阈值、`transcript`、队列参数与 `active_recent_blocks`。
- **持久化编码**：生成队列信封 1.3，编码整个 `GenerationRequest`。

## 4. 进入条件

阻塞问题已决定（owner，2026-11-19，写入链路 Idea 第 3.1 节）：结算时的三步；由馆长 agent 完成，代替规则拦截与生成；残余的重叠接受；工具与循环由 Patchouli 内部定义，不复用 Alice 的执行循环与 MTP。依赖已成为事实：生成的记忆指向交互轮次（PR #228）。

## 5. 目标设计

### 5.1 位置

馆长放在 `engines/generation/` 之下（与提取器同层）：它可以使用中期库与模型服务的接口，不依赖 Workspace 与 Alice。引擎对 SETTLE 调用馆长，代替 `_process_mode_a`；Familiar 的提交管线不变。

### 5.2 循环与动作协议

- 每一步，馆长把对话历史交给 `complete`，模型输出一个 JSON 动作：`{"tool": "<名称>", "args": {…}}`；Patchouli 执行工具，把结果作为下一条消息交回。
- 动作无法解析或工具不存在时，把错误作为结果交回，计入步数，不中止。
- 结束条件：模型调用 `finish`；步数到达上限（初值 12）；lane 超时。步数用完时照常提交已暂存的记忆，并记一行日志。
- 模型服务失败照旧传播为 `model_provider_failed`；超过上下文窗口传播为 `model_context_window_exceeded`。

### 5.3 工具

| 工具 | 作用 |
|:---|:---|
| `list_topic_writes` | 列出本话题主动写入结算到的记忆：别名、标题、摘要；system actor 读不到的跳过 |
| `search_memories` | 以一句查询检索中期库，`mode` 为 dense 或 sparse，返回别名、标题、摘要、类型与分数（每次最多 5 条） |
| `read_memory` | 按别名读一条记忆的全文 |
| `write_memory` | 暂存一条新记忆：标题、摘要、标签、类型、正文、引用的段 |
| `finish` | 结束 |

- 材料（话题状态与带段标签的各轮）在第一条消息中给出，不需要工具读取。
- 读取与检索都以结算的 system actor 进行，不刷新生命力。
- 暂存的记忆在循环结束后一次性交给 Familiar，按 CREATE 提交：分配别名、写版本记录（带 `cited_segments`）、入库；不查重、不触碰、不提名合并。

### 5.4 提示词

新增馆长的系统提示词（中英文）：说明三步的顺序，即先看本话题写过什么、再查库里相关的，再写；只写既不与本话题的写入、也不与库中相关记忆重叠的内容；草稿引用段作为依据；动作的 JSON 格式与工具说明。被动提示词与 `ExtractionResult` 随 Mode A 删除；`ExtractedMemoryDraft` 仍供主动写入使用。

### 5.5 配置

`patchouli.generation` 下新增 `librarian`：`max_steps`（12）、`search_top_k`（5）。`extractor.enabled` 保留原义：关闭时结算不运行馆长，不产生记忆。`deduplicator` 只服务主动写入。

### 5.6 去掉的部分

- 引擎的 Mode A、`dropped_on_hit` 参数、`extractor.extract`；
- 结算产生的合并提名（MERGE 任务只来自主动写入的提名）；
- 控制器的话题写入记录照旧：它现在是馆长 `list_topic_writes` 的来源。

## 6. 受影响的系统、契约和数据

| 范围 | 变化 |
|:---|:---|
| 生成引擎 | SETTLE 由馆长处理；Mode A 与 `dropped_on_hit` 删除 |
| 馆长（新） | 循环、JSON 动作协议、五个工具、预算 |
| 提取器与提示词 | 删除 `extract` 与被动提示词；新增馆长提示词（中英文） |
| Patchouli 装配 | 引擎拿到馆长的配置 |
| 配置 | 新增 `patchouli.generation.librarian` |
| 公开契约、路由、事件、持久化编码 | 不变（`GenerationRequest` 不变，生成队列信封仍为 1.3） |
| 数据 | 不迁移；新结算的记忆不再与库中记忆合并 |

## 7. 兼容与迁移

- 没有数据迁移。关闭时保存的 SETTLE 下次启动后由馆长执行。
- 旧配置文件中没有 `librarian` 时取默认值。
- 回退需恢复 Mode A 与提示词，已建成的记忆不受影响。

### 8.3 实测

## 9. 风险与待决问题

- **模型不按协议输出动作**：错误作为结果交回、计步；用完步数时提交已暂存的记忆。频繁出现时再考虑原生工具调用（要改模型服务的接口）。
- **成本**：一次结算从一次调用变为若干次，token 随步数增长；步数上限与 `search_top_k` 是第一道约束，实测中记录每次结算的调用次数与 token。
- **私有记忆**：system actor 读不到 PRIVATE 与 TEAM 的记忆，本话题由 UPDATE 修订过的私有记忆不会被列出；这避免私有内容被写进公开记忆，代价是馆长可能与它们重叠。
- **并发结算的重叠**：同一 Workspace 两次结算同时运行时，彼此看不到对方暂存的记忆；按 owner 的决定接受。
- **删除 Mode A 之后**：被动生成没有一次性提取的退路；回退靠代码回滚。
- **候选默认**（不是 owner 决定，可在计划评审时调整）：JSON 动作协议、步数上限 12、`search_top_k` 5、工具的名称与返回字段、馆长的位置在 `engines/generation/`。
