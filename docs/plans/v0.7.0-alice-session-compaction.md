# v0.7.0 Alice 会话压缩

> **文档状态**：Active。阶段一、二已完成实现、验收与代码审查，按阶段停止；阶段三、四尚未开始。本文保留实施中的设计与记录；当前事实文档仍描述上一已完成基线，待阶段四统一晋升。

本计划让 Alice 在任何会话长度下都能组装出不超过模型预算的请求：较早轮次先去掉可以重新取得的工具结果，仍超过阈值时再由接力摘要覆盖；单轮执行的增长由轮内预算守卫拦截；放不下的情况以可区分的失败原因结束。压缩检查点存入会话资源，Session 原文保持不变。

设计依据：

- [短期记忆与上下文压缩 Idea](../ideas/short-term-memory-and-context-compaction.md)：第 2 节 owner 已确认的方向，第 5 节候选机制，第 8 节 AC-1（检查点存入会话资源）与 AC-2（本计划只做自动压缩）的决定（owner，2026-10-16）；
- [Agent Harness 会话压缩技术调研](../ideas/agent-context-compaction-research.md)（2026-10-16 快照）：预算拆分、覆盖边界、检查点接受、取消与有限恢复的外部证据；
- 当前事实：[Workspace 架构](../architecture/workspace.md)第 4.3、5.4、5.5 节，[System 应用服务](../system/application-services.md)第 3、4 节，[子系统契约](../contracts/subsystem-contracts.md)第 4 节，[Agent Runtime](../alice/agent-runtime.md)与 [Alice 编排](../alice/orchestration.md)；
- 已归档：[会话：Alice 改用会话上下文](../archive/plans/v0.7.0-conversation-session.md)（会话资源、全量历史、结果槽与有输出的三种结局，本计划沿用）。

## 1. 背景和问题

- **全量历史没有预算**：进程把会话的全量轮次交给 Alice，`HistoryTranscriptBuilder` 逐轮重放全部事件，包括 MTP 调用全文与 READ、SEARCH、RUN 等工具结果全文。历史增长远快于用户看到的对话，会话一旦越过模型窗口，之后每轮都在第一次生成时失败，本轮没有输出、不写入会话，用户只能新建会话。
- **单轮增长没有上限**：每次 MTP 迭代都把工具结果全文追加到 `working_history`。默认最多 10 次迭代、单次读文件上限 100KB，按 `TokenEstimator` 的英文 4 字符/token 估算，一轮满额读文件约 25 万 token。
- **失败没有原因**：`CPUExecutionResult` 只有状态、回复文本、事件与模型名；进程投影 done 时原因固定为 `agent_run_failed`，`chat.run.failed` 不带原因。超窗与其他失败在用户侧无法区分。
- **没有压缩的落点**：Alice 不保存跨 run 的状态，输入清单与会话资源都没有承载压缩结果的位置。

## 2. 目标与非目标

### 2.1 目标

1. **模型预算**：模型注册表可以登记上下文窗口；Alice 在组装根 frame 之前按本次实际解析出的模型计算输入上限，未登记窗口时使用配置的保守默认值。
2. **工具结果减重**：较早轮次的工具结果在 Alice 的派生视图中替换为可以重新取得的引用或有界摘录，不调用模型。
3. **接力摘要**：减重后仍超过目标大小时，以完整会话轮次为单位，把较早的前缀增量压成有界的接力摘要，近期轮次保留；摘要请求自身满足预算，接受前校验。
4. **会话检查点**：减重边界、摘要与引用清单组成 CPU 中立的检查点，经输入清单与执行结果往返，由会话资源持有（AC-1）。
5. **轮内预算守卫**：agent 循环每次生成之前检查本 frame 的上下文，超出输入上限即结束该 frame，不再发出必然失败的模型调用。
6. **失败原因**：CPU 结果携带中立的失败原因码，进程投影到 done 与 `chat.run.failed`，前端据此提示。
7. **进度与观测**：流式交付压缩进度；前端在会话历史中标记已压缩的位置。

### 2.2 非目标

- `/compact` 与 CPU 端口的压缩操作：留在[命令 Todo](../todo/conversation-compact-command.md)，随命令系统接回实施（AC-2）；本计划只为将来复用保留“强制压缩”参数。
- 轮内压缩、未结束 turn 的分段与检查点：属于[长 Turn Idea](../ideas/long-running-agent-intra-turn-context-folding.md)；本计划对单轮增长只设守卫。
- CALL 子 frame 的历史压缩：子 frame 不接收会话历史；守卫同样适用于子 frame。
- Provider 原生压缩、后台或轮后压缩、单独配置的辅助摘要模型、精确 token 计数。
- 外部 harness 的压缩、Topic page folding 的优化、原始资料保存链与会话持久化。

## 3. 实施前状态（2026-10-16 核对）

- **CPU 输入与历史重放**（`workspace/process/runner.py`、`workspace/contracts/process.py`、`prompts/assembler.py`、`prompts/transcript/history.py`）：CPU 分配时读取会话全部轮次放入 `CPUInputManifest.session_history`；`AgentRunContext` 原样转交；系统提示词依次为 MTP 说明、persona、检索记忆与附件，其后由 `HistoryTranscriptBuilder` 重放各轮事件，再追加本轮用户消息。
- **模型解析**（`agent_runtime/runtime.py`、`system/model_registry.py`）：`AgentRuntime._resolve_model_for_frame` 在 `run_frame` 内按会话请求、Profile、注册表三级合并解析模型，结果写入 `generation_options`；未被 `WorkerAgentService` 取出的键原样传给 LiteLLM。`ModelDefinition` 与 `LLMConfig` 都没有上下文窗口字段。
- **agent 循环**（`agent_runtime/execution/loop.py`）：每次迭代先生成，命中 MTP 时执行并把助手文本与格式化结果追加到 `working_history`，工具结果事件带 `tool_kind`、`target`、`tool_args` 与状态；生成异常收为 FAILED，错误留在 `FrameExecutionResult.error`。`GenerationResult` 已携带 `finish_reason`。
- **执行结果**（`alice/application/agent_run_service.py`、`workspace/contracts/cpu.py`）：`_assemble_execution_result` 只投影状态、文本、事件与模型名，不读取 frame 的错误；流式时 Alice 在 done 中携带结果字段，`AliceCPU` 据此还原 `CPUExecutionResult`。
- **进程收尾**（`workspace/process/runner.py`、`workspace/process/outputs.py`、`workspace/process/events.py`）：拿到 CPU 终态（或停止时结果槽中的结果）后关闭输出流、撤销线程 context；交付方离开或系统关闭时丢弃本轮；有输出时封口、同步追加会话并进入 finalize，三者之间没有 await。done 的结果字段来自 `CPUExecutionResult.model_dump()`（排除 `turn_events`），failed 的原因固定为 `agent_run_failed`。
- **会话资源**（`workspace/sessions/service.py`、`server/routers/sessions.py`）：`ConversationSession` 保存有序 `ConversationTurn`，读取与追加都复制载荷；HTTP 读取接口直接返回该模型，列表返回不含轮次的 `SessionSummary`。
- **别名**（`workspace/resolution/alias.py`）：READ 的目标是 canonical 别名，后续 run 可以经 `AliasResolver` 重新读取。
- **配置**（`config/alice.py`、`configs/config.yaml`）：`alice` 段只有 `koakuma` 与 `runtime`（`max_loop_iterations=10`）；`koakuma.file_read_max_bytes=102400`。

## 4. 目标设计

### 4.1 模型窗口与预算

- `ModelDefinition` 新增可选的上下文窗口（总窗口，tokens）；`LLMConfig` 同步新增该字段，由注册表的 `resolve` 填入，`ModelResolver` 的签名不变。`configs/models.yaml` 为已登记模型补上窗口值（实施时按提供商文档确认）。
- 本次 run 的输入上限 = 上下文窗口 − 解析后的生成上限 `max_tokens` − 安全余量；窗口未登记时取 `alice.compaction` 的默认窗口。会话请求覆盖模型或 `max_tokens` 时按覆盖后的值计算。
- Alice 在组装根 frame 提示词之前解析模型，与 `run_frame` 使用同一解析规则；输入上限随 frame 单独传递，不放进 `generation_options`。
- 估算沿用 `TokenEstimator`，另加每条消息的固定开销；估算误差由安全余量吸收，精确计数不在本计划。
- 三个比例分开设定，都以输入上限为基数：触发阈值（例如 0.75）、压缩后的目标大小（例如 0.5）与近期原文预算（例如 0.25）；最终默认值在阶段三用固定会话样本校准。

### 4.2 失败原因与轮内预算守卫

- `CPUExecutionResult` 新增可选的失败原因码，只在 failed 时有意义，外部 CPU 可以不填。本计划使用以下原因（名称在实施评审时确定，记入错误模型）：

| 原因 | 含义 |
|:---|:---|
| 当前输入过大 | 系统提示词的固定部分（协议、人设、检索记忆、附件）与本轮用户消息已超出输入上限，或加上摘要上限后超出，压缩历史也放不下 |
| 压缩失败 | 历史超出输入上限，压缩失败或摘要未通过校验 |
| 轮内超出预算 | 守卫在一轮之内拦截了下一次生成 |
| 模型报告超窗 | 估算偏低，模型调用仍以上下文超限报错 |

- 进程把原因码投影到 done（failed 的原因字段保持 `agent_run_failed`，另加原因码字段）与 `chat.run.failed` 的 message；只携带稳定的原因码，不携带异常正文。
- **守卫**：`AgentLoopExecutor` 每次生成之前估算 `working_history`，超出本 frame 的输入上限时以带类型的错误返回 FAILED，不调用模型。守卫适用于根 frame 与 CALL 子 frame，各自按自己解析出的模型计算上限；子 frame 被拦截时按现有 CALL 失败语义回到父 frame。根 frame 被拦截时本轮已有输出，照现有规则以 failed 封口、写入会话并提交；下一轮的减重会收缩这一轮的工具结果。
- 模型调用以上下文超限报错时，Alice 把它映射为“模型报告超窗”，不重试。
- Alice 在组装执行结果时按 frame 错误的类型填写原因码，其他错误不填。

### 4.3 会话检查点（AC-1）

- **模型**：检查点与 `ConversationTurn` 同置 `core.protocol.models`（名称在实施评审时确定），字段为：

| 字段 | 内容 |
|:---|:---|
| 产生方与格式版本 | 产生检查点的 CPU（当前为 Alice）与它的格式版本 |
| 减重边界 | 最后一个被减重轮次的 `interaction_id`，可以为空 |
| 摘要覆盖 | 最后一个被摘要覆盖轮次的 `interaction_id`，可以为空 |
| 摘要 | 接力摘要正文，没有摘要时为空 |
| 引用清单 | 程序从被覆盖轮次提取的引用（4.4） |
| 生成时间 | 检查点生成的时间 |

- **持有与往返**：`ConversationSession` 持有至多一份检查点，会话列表不包含它；`CPUInputManifest` 携带当前检查点；`CPUExecutionResult` 新增可选的新检查点，正常终态与停止时写入结果槽的结果都可以带上它。done 不下发检查点。
- **接受**：会话服务新增同步的接受方法。规则：调用方持有该会话的认领；两个游标都指向本会话已有的轮次，减重边界不早于摘要覆盖；与已有检查点相比两个游标都只能前进。不满足时以会话领域错误拒绝，不改变已有检查点。
- **进程写回**：进程拿到 CPU 结果、撤销线程 context 之后，在判断是否丢弃本轮之前接受检查点；接受与封口、追加会话处于同一段不跨越 await 的代码。接受不看 `has_output`：没有输出、或交付方离开而丢弃本轮时同样接受，因为检查点只覆盖已封口的旧轮次；进程异常而拿不到结果时没有检查点。接受被拒绝时进程记录告警、照常收尾本轮。
- **读取**：HTTP 会话读取接口随会话返回检查点；删除会话与关闭清理随会话一并清除它。
- **外部 CPU**：不读取、不产生检查点；产生方或格式版本不符的检查点由 Alice 忽略并重新计算。

### 4.4 Alice 的会话上下文视图

每次 run 在组装根 frame 时按以下顺序处理：

| 步骤 | 内容 |
|:---|:---|
| 1 | 解析模型，取得输入上限（4.1） |
| 2 | 组装固定部分（不含摘要段落的系统提示词与本轮用户消息）；固定部分已超出输入上限时以“当前输入过大”结束，不尝试压缩 |
| 3 | 按会话检查点渲染历史：摘要段落、减重边界之前的轮次以减重形式重放、之后的轮次重放原文；估算完整消息 |
| 4 | 不超过触发阈值：直接使用，不产生新检查点 |
| 5 | 超过触发阈值：先减重，仍高于目标再摘要（见下）；产生新检查点并重新渲染 |
| 6 | 重新渲染后仍超出输入上限：以“压缩失败”结束 |

- **减重**（第一层，不调用模型）：
  - 按 `tool_kind` 改写工具结果事件：READ 替换为目标别名、状态与“可重新 READ”的提示；SEARCH 替换为查询、状态与“可重新检索”的提示；RUN 保留工具名、参数、状态与有界摘录；WRITE/UPDATE 的 ACK、错误原因与 CALL 响应保留原文，过长时有界保留。用户消息、助手回复与工具调用不改。
  - 改写由 `HistoryTranscriptBuilder` 按减重边界执行，Session 原文不变。
  - 减重边界从最旧的未减重轮次向后推进，直到边界之后以原文重放的近期轮次不超过近期原文预算；允许没有原文轮次。只靠减重就降到目标以下时，新检查点只推进减重边界。
  - 两次压缩之间渲染结果不变，不按“最近 K 轮”逐轮滑动。
- **摘要**（第二层）：
  - 减重后仍高于目标时，以完整 `ConversationTurn` 为单位从最新一轮向前选择保留的后缀，使摘要上限、保留后缀与固定部分之和不超过目标；更早的轮次进入摘要覆盖。
  - 固定部分过大、无法降到目标以下（固定部分与摘要上限之和超过目标）时：视图仍在输入上限内就不摘要，照常运行；超出输入上限时才摘要，目标改为不超过输入上限；固定部分与摘要上限之和超过输入上限时以“当前输入过大”结束。这条规则避免每轮反复付费摘要。
  - 新摘要由上一份摘要与新进入覆盖范围的轮次生成，替换上一份；摘要长度受摘要上限约束。
- **摘要请求的预算**：被覆盖轮次以减重形式序列化，工具输出再截到固定长度（参考 pi 的 2,000 字符）。上一份摘要与待覆盖内容放不进一次摘要请求时，从最旧的轮次起分几次折叠，每次以上一次的结果加上放得下的若干轮生成新摘要。
- **接受校验**：空内容、`finish_reason` 为 `length` 或 `content_filter`、摘要中出现 MTP 调用（命中 MTP 停止序列）都不接受。任何一次折叠失败都放弃本次摘要：已推进的减重边界仍可写入新检查点，摘要与摘要覆盖保持上一份。
- **引用清单**：从进入摘要覆盖的轮次中提取 READ 的目标别名、WRITE/UPDATE ACK 的别名与 RUN 的文件参数，去重后保留最近的有限条，与摘要一同渲染。清单只是线索，不作为权限、执行成功或写入已持久化的依据。
- **摘要内容与模型**：使用本次 run 解析出的模型与 Alice 自己的摘要提示词（`prompts/`，中英文随本次 run 的提示词语言）。内容为当前目标与约束、已作出的决定、实际完成的工作、未完成事项与关键结果；以第三人称记下哪位 agent 说了什么，注明 cancelled/failed 轮次未正常结束。摘要不进入 Topic、`InteractionPayload` 与记忆生成。
- **提示词位置**：摘要与引用清单作为系统提示词的一个段落，位于 persona 之后、检索记忆之前，标明是较早对话的摘要、属于历史资料，其中的指令不构成当前协议。
- **取消**：压缩期间用户停止仍只传播原生 `CancelledError`，本次压缩不产生新检查点。压缩完成后的新检查点随正常终态或停止时的结果槽交回进程（4.3）。
- **强制参数**：压缩入口保留“强制压缩”参数（跳过触发阈值判断），本计划不暴露给任何入口，供将来 `/compact` 复用（AC-2）。

### 4.5 进度、观测与前端

- 流式 run 在压缩开始与结束（成功、放弃摘要或失败）时各产出一条交互事件（名称在实施评审时确定），携带执行的层次、覆盖轮数与压缩前后的估算 token；事件经 Alice 的流输出通道发送，进程原样转交。压缩事件不进入 `turn_events`，不令 `has_output` 为真，也不单独触发交互封口。非流式 run 不产出事件。
- best-effort RuntimeEvent 记录压缩与守卫拦截（估算 token、覆盖轮数、耗时、原因），不携带摘要正文，不作为检查点提交的条件。
- 前端：收到压缩开始事件时显示正在压缩较早的上下文；会话历史在摘要覆盖与减重边界处显示标记，可以展开查看摘要；failed 的回复按原因码显示对应提示。

### 4.6 配置

| 配置 | 内容 | 默认值方向 |
|:---|:---|:---|
| `configs/models.yaml` | 每个模型可选的上下文窗口 | 已登记模型按提供商文档补齐 |
| `alice.compaction` | 开关、默认窗口、安全余量、触发比例、目标比例、近期原文预算、RUN 摘录长度、摘要上限、摘要输入中工具输出的截断长度 | 默认窗口取保守值；比例与长度在阶段三按样本校准 |

配置段名称与字段在实施评审时确定，随 `configs/config.yaml` 一同给出；关闭开关时不减重、不摘要，守卫与失败原因照常生效。

## 6. 兼容与迁移策略

- 进程内替换，不涉及持久化数据：会话与检查点都只在进程内；新字段都可选、带默认值。检查点不进入 `InteractionPayload`，`InteractionSubmission` codec 不变。
- **CPU 端口**：输入清单与执行结果只新增可选字段；测试 CPU 不产生检查点，进程照常工作。
- **模型注册表**：未登记窗口的模型使用默认窗口，既有 `models.yaml` 不需要修改即可启动。
- **HTTP 与 SSE**：会话读取新增字段；新增压缩进度事件，前端不认识的事件不影响既有处理；failed 的 done 保留 `agent_run_failed` 并新增原因码字段，仓库内只有前端消费，随阶段四修改。
- **语义变化**：长会话的部分轮次开始时多一次（或几次）摘要调用；较早的工具结果在提示词中只剩引用，agent 需要时重新读取；超窗的轮次不再调用模型，直接以原因码失败。

## 7. 实施阶段

## 8. 测试和验收标准

按[测试设计规范](../governance/testing/test-design-standards.md)分类；每条不变量只在作出判断的归属层写权威测试，上层与 E2E 只保留代表性链路。会话服务、任务进程、Alice 上下文视图与提示词使用真实对象，外部 LLM 使用既有替身。

1. 输入上限按解析后的模型窗口与生成上限计算，会话请求覆盖模型或 `max_tokens` 时随之变化，未登记窗口时取默认值（模型注册表与 Alice 预算的单元测试）。
2. 固定部分已超出输入上限时不调用模型，以“当前输入过大”结束（Alice 运行服务）。
3. 一轮之内 `working_history` 超出输入上限时，下一次生成之前即以“轮内超出预算”结束；根 frame 的这一轮以 failed 封口写入会话；子 frame 被拦截时父 frame 收到 CALL 失败；模型报告超窗时映射为对应原因（agent 循环与 Alice）。
4. CPU 自报失败的原因码出现在 done 与 `chat.run.failed` 中，不含异常正文；没有原因码时行为与现在相同（任务进程输出投影）。
5. 会话服务只接受持有认领的进程提交的检查点；游标必须指向本会话已有轮次、减重边界不早于摘要覆盖、两个游标只能前进；拒绝时已有检查点不变；其他 Workspace 的会话不可写入；删除与关闭后检查点随会话清除（会话服务）。
6. 进程在 completed、cancelled、failed、没有输出与交付方离开丢弃本轮时都接受 CPU 交回的检查点，进程异常时不接受；接受被拒绝时本轮照常收尾；done 不含检查点（任务进程）。
7. 输入清单携带会话当前检查点；HTTP 会话读取返回检查点，会话列表不含它（任务进程与会话 HTTP 各一个代表）。
8. 减重渲染：减重边界之前的 READ、SEARCH、RUN 结果按 4.4 改写，ACK、错误原因与 CALL 响应保留，用户消息、助手回复与工具调用不变；边界之后原文重放；Session 原文不变（`HistoryTranscriptBuilder`）。
9. 历史低于触发阈值时不产生新检查点；超过时减重边界推进到近期原文预算内，只靠减重降到目标以下时不调用模型；两次压缩之间渲染结果逐字相同（Alice 上下文视图）。
10. 减重后仍高于目标时，摘要覆盖以完整轮次为单位前进，保留后缀与摘要、固定部分之和不超过目标；新摘要的输入是上一份摘要与新覆盖的轮次（Alice 上下文视图）。
11. 摘要请求放不下时分次折叠，每次请求都在预算内；工具输出在摘要输入中被截断（Alice 上下文视图）。
12. 空内容、长度截断、内容过滤与出现 MTP 调用的摘要不被接受；此时已推进的减重边界仍写入检查点，摘要保持上一份；视图仍超出输入上限时以“压缩失败”结束；固定部分过大而视图仍在输入上限内时不发起摘要调用（Alice 上下文视图）。
13. 引用清单包含被覆盖轮次中的 READ 目标、ACK 别名与 RUN 的文件参数，有界且去重；摘要与清单位于系统提示词中 persona 之后、检索记忆之前（Alice 与提示词组装）。
14. 压缩期间停止只传播原生 `CancelledError`，不产生新检查点；压缩完成后停止时，结果槽中的结果带新检查点并被进程接受（Alice 运行服务与任务进程各一个代表）。
15. 压缩进度事件只在流式时产出、不进入 `turn_events`、不令 `has_output` 为真；RuntimeEvent 不含摘要正文（Alice 运行服务）。
16. 确定性 HTTP chat E2E：同一会话的多轮对话越过触发阈值，流中出现压缩事件；下一轮的提示词含摘要段落与减重后的旧工具结果；会话读取返回完整原文与检查点；人为放大单轮工具结果时本轮以“轮内超出预算”结束、done 带原因码。
17. 前端 `npm run lint` 与 `npm run build` 通过。

## 11. 实施记录

### 2026-10-16：阶段一（预算、守卫与失败原因）

- 模型窗口字段确定为 `context_window`，由 `ModelDefinition` 经注册表三条解析入口交给 `LLMConfig`；模型管理 HTTP 创建、读取、更新同样支持该字段，显式 `null` 可清除窗口登记。
- `alice.compaction` 先配置 `default_context_window=65536`、`safety_margin=2048`。默认总窗口必须大于项目既有的 32768 生成上限；输出预算挤满窗口时保留非正输入上限，明确拒绝当前输入，不扩大预算。
- `AgentRuntime.resolve_model` 返回 `ResolvedFrameModel`，同时固定实际生成参数、展示名和独立输入上限。根帧在组装历史前解析，CALL 子帧独立解析；同一帧从 CALL 恢复时复用快照，避免注册表变动令预算与请求漂移。预算字段不透传给模型 SDK。
- `estimate_context_tokens` 沿用 `TokenEstimator`，每条消息另计 4 token 固定开销。根帧先检查协议、人设、检索记忆、附件和当前用户消息；循环每次生成前重新检查完整历史，超限不调用模型。
- `CPUExecutionResult.failure_reason` 使用 `CPUFailureReason`：`input_too_large`、`turn_context_budget_exceeded`、`model_context_window_exceeded`。压缩失败码待摘要实现时补充。进程的 failed done 保留 `reason=agent_run_failed`，另投影非空原因码；`chat.run.failed.message` 使用同一码，不带异常正文。
- 模型超窗只按 LiteLLM 的 `ContextWindowExceededError` 类型映射，覆盖非流式请求、流式启动与流式拉取，不按错误文本猜测，也不重试。依据：[LiteLLM 异常映射](https://docs.litellm.ai/docs/exception_mapping)（Context7，2026-10-16）。

- 中立模型确定为 `SessionCompactionCheckpoint`，字段为 `producer`、`format_version`、`reduced_through`、`summarized_through`、`summary`、`references`、`created_at`。会话、输入清单和执行结果使用可选字段 `compaction_checkpoint`。Alice 当前生成 `producer=alice`、`format_version=1` 的纯减重检查点；遇到未知产生方、版本或无法解释的摘要时先重放原文，避免遗漏历史。
- `ConversationSessionService.accept_checkpoint` 同步校验 Workspace 归属、当前认领、两个游标的存在性、减重不早于摘要及各自单调性；拒绝时原检查点不变。非法游标使用 `SessionCheckpointError`（`workspace.session.checkpoint_invalid`），认领和归属错误沿用原领域错误。HTTP 会话读取返回检查点，列表排除检查点。
- 进程在 CPU 流关闭与线程撤销后、判断本轮是否丢弃前同步接受检查点；与正常封口及会话追加之间没有 await。无输出、用户停止、断流、直接关闭和关停兜底均可接收已完成检查点；执行异常不把槽中的候选结果当成完成结果。工作集登记结果槽供关闭路径使用，同一结果只接受一次。接受被拒绝只记录告警，本轮照常收尾。

- `SessionContextView` 按已有边界重放历史，完整消息超过触发比例时才推进减重边界；从最近轮次选择可放入近期原文预算的完整后缀，允许后缀为空，旧边界不回退。两次压缩之间不逐轮滑动边界；内部 `should_compact(force=True)` 可跳过触发阈值，但不能绕过关闭开关。
- `HistoryTranscriptBuilder` 只改写覆盖范围内的工具结果。READ/SEARCH 成功时保留目标或查询、状态及中英文重取提示；RUN 保留工具名、参数、状态与有界正文；ACK、错误与 CALL 响应保留有界原文，长正文保留头尾并标记省略。工具结果通常不带参数，按 `action_id` 关联原调用取得 SEARCH 查询与 RUN 参数；缺少可用重取线索时保留有界原文。用户、助手、工具调用与会话原始载荷不变。
