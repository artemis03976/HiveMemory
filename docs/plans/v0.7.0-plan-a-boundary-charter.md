# v0.7.0 计划 A 边界宪章

本宪章冻结 v0.7.0 计划 A 家族中 Workspace（工作平面）与 Patchouli（记忆库）之间的边界：归属判据、双方角色与独立工作义务、状态归属表、过线契约、证伪条件与回溯证据。

- **效力程序**：owner 采纳本宪章并以完成[第 10 节](#10-生效联动修订清单)联动修订为标志后，本宪章取代 [A2 §1.1 的 2026-09-17/20 裁定](./v0.7.0-a2-workspace-resource-reads-and-caches.md)与 [A4 §4.1 的 2026-09-17 裁定](./v0.7.0-a4-pending-memory-intents.md#41-共同引用读取与-alias-resolver-归属)，成为计划 A 家族边界裁决的唯一理由源。第 10 节联动修订已于 2026-09-23 执行完毕，本宪章生效。
- 本宪章冻结设计归属与契约方向；字段、路由、容量等实现级细节仍由 A2-0/A3-0/A4-0 在宪章框架内冻结（[第 11 节](#11-移交后续冻结的开放点)）。
- 本宪章不修改任何当前事实文档；`AGENTS.md`、`architecture/workspace.md` 与 `patchouli/*` 按文档晋升门禁在实现验收后更新。
- **非目标**：不重议 Memory schema、版本与 lifecycle 语义（A2-P 已交付）；不重议 A1 统一认证、access 契约与行为白名单机制；不重议检索、生成、生命周期算法本身；不承诺 pending registry 或 Session 的跨进程持久化。

- **2026-09-25 修订（能力面入口裁定）**：新增 §5.3——能力面入口为 in-process 的 workspace server API（由现有 `system/application` 改造而成，不新开总线路由），actor 经 HTTP/MTP/外部三类 adapter 归一化调用；能力面作为 client 调用 Patchouli backing API，构成第二层 client-server（§4.4 过线契约）；operation 授权在能力层、backing 调用前执行，Patchouli application 移除 operation 检查、保留资源归属与资源 policy 校验。

## 1. 背景与历史判据的验尸

v0.7.0 期间边界标准多次更替。每次更替的判据及其失效类别如下，记录在此是为了让下一次边界重议必须针对记录在案的失效类别举证，而不是从偏好重新出发：

| 判据 | 出处 | 失效类别 |
|:---|:---|:---|
| "当时只有 Alice 消费" | ADR-0004（v0.6.2 基线） | 偶然事实：消费者集合变化即失效 |
| "谁需要 Workspace key" | v0.7.0 早期调查 | 派生量：寻址需求是归属决定的后果，不是原因 |
| "派生自什么、谁改变其有效性" | A2 §1.1（2026-09-17/20 裁定） | 机制局部最优：以缓存一致性机制裁决所有权，把 actor 工作状态拽入记忆库 |

共同教训有两条。第一，**描述性判据**（"事实是什么"：谁在消费、数据流向谁）随系统描述变化而失效；第二，**机制问题不能裁决所有权问题**——缓存一致性、失效覆盖、当前性是机制需求，应当由契约（事件协作，§4.4）承接，而不是由所有权迁移承接。2026-09-17/20 裁定正是让第二条失误逐级放大：cache 写成"Patchouli 共同读取链内部使用"、pending 判给"Patchouli 资源侧"、resolver 分派判为"Patchouli 领域责任"，三步各自局部自洽，整体却让记忆库背上了 actor 的工作状态。

本宪章即按"判据变更三程序"产出：回溯验证（§8）、证伪条件（§7）、机械测试（§4.5）。

## 2. 归属判据

### 2.1 判据一：管护权（主判据）

状态归谁，由**过线动作**决定：仍在 actor 手中、未被记忆库接收的工作状态归 workspace；库已接收、进入其管护的素材与资产归 Patchouli。过线动作有名字：**材料的过线 = 封口 + 提交**；**写入意图的过线 = 物化**（settlement 回流为注销）。

临时性不作为判据使用——它是"未被接收"的后果，不是原因。Topic 同样临时，但已被库接收，所以归库；pending 同样临时，但从未被接收，所以归 workspace。

### 2.2 判据二：反转（迁移判据）

对 v0.7.0 的存量迁移，按"转变前谁持有"执行：转变前由 actor（Alice/agent runtime）携带的工作状态，翻转为 workspace 持有；转变前已属记忆库的不动；转变前已由 System 持有的共享设施留在 workspace runtime。迁移**不得给 Patchouli 增加任何转变前不属于它的领域内容**，也不得削弱其既有能力。

### 2.3 判据三：用途（未来判据）

新增状态的归属问"它为谁存在"：为 actor 在区域内干活而存在（写意图追踪、热读视图、挂载资产、引用解析）→ workspace；为记忆流水线自身运转而存在（canonical 资产、版本历史、接入素材、生命周期）→ Patchouli；谁都不服务（进程骨架：bus、queue、scheduler、registry、EventBus）→ 共享基础设施。

### 2.4 决断规则：工作产物规则

当两侧都可主张用途时，问它是**谁的即时工作产物**：由 actor 组成、需要同步读回的状态是 actor 的工作产物，归 workspace；仅被异步消费的一方是加工者，不因消费取得所有权。这是 pending 归属的直接依据（§6.2），也是本宪章论证最重的一条规则。

### 2.5 判据的性质声明

本组判据是工程承诺，不是被发现的事实。它的"对"由三件事构成并以此自守：回溯复现全部无争议决定（§8）、可证伪（§7）、边界由机械测试把守（§4.5）。推翻本宪章的正确方式是举出 §7 中被观察证伪的实例，不是提出新的审美偏好。

## 3. 角色定义：分割按角色，不按资源垄断

- **Workspace 与 workspace runtime**：Workspace 是全系统的作用域划分（主子网式的概念边界）；workspace runtime 是其在进程内的持有与运行载体，由 System 组合根装配（延续 WorkspaceAssetStore 的既有归属事实）。本宪章中"workspace 持有"指 workspace runtime 持有。
- **Patchouli 是记忆库**：接收提交、加工生成、存储演化记忆资产的 canonical 知识机构，拥有完整的库内流水线（接入 → 生成 → 存储 → 生命周期 → 检索）。
- **分割按角色执行**：两边都有自己的资源。workspace 资源 = actor 未过线的工作状态（会话记录、写入意图、热读视图、挂载资产）；库资源 = 已接收素材与 canonical 资产（Topic 素材、MemoryAtom、Artifact、版本历史）。"资源平面"一词不再用作双方的分割线。
- **愿景映射**：记忆资产三档中，未提交会话与候选意图的追踪在 workspace 手中；已提交原始素材与可用记忆在库。候选意图的加工在库，追踪在 actor 所在区域的托盘上——托盘跟着干活的人走，不跟着加工车间走。

## 4. 独立工作契约

### 4.1 定义

> **独立工作**：任何一侧在与另一侧的连接断开时，必须仍能启动并完整履行自身名下的职责；由此产生的能力缺口必须以显式错误或显式状态呈现，不得以静默的过期成功替代。

独立工作**不是**：

- 独立部署——系统仍是单进程组合根；
- 独立数据——canonical 记忆资产只存在于库，workspace 不持有第二份；
- 零集成——过线契约照常存在且必须可靠；
- 职责对等——两侧义务不对称，也不互相补位缺省。

独立工作**是**三条可检验性质：

1. **职责完整性**：断开时自身职责清单仍可履行；
2. **降级显式性**：缺口以明确错误或明确状态呈现，绝不伪装成功；
3. **组合无序性**：装配与启动顺序不要求另一侧先在、先健康。

历史病灶对照：旧形态中 Alice 的读路径语义依赖库响应才能完成、Patchouli 的设计（2026-09-17/20 裁定形态）隐式假设库写路径旁边挂着一个需要它维护的缓存——两者分别违反组合无序性与降级显式性。本契约把它们定为设计禁止项。

### 4.2 库模式：Patchouli 的独立工作

义务（workspace 缺席或不可用时必须全部成立）：

1. 库内全流水线可运行：提交接收 → generation 物化 → canonical 存储 → reinforcement/gardening/archive/revive → 检索；
2. canonical 写入的成功不以待任何缓存失效确认为前提；
3. settlement 照常产生并留痕于库侧事实，不等待 workspace registry 确认；
4. canonical 点读、alias 批读、语义检索、Profile 解析路由对任何调用方照常服务；
5. 无订阅者时事件空投（publish 空转）；事件协作的缺席不得改变任何库内业务结果。

持有：canonical MemoryAtom 及其 meta 语义、完整版本历史、四类 Artifact、已接收素材（Topic/短期库）、全部记忆算法、Profile 解析规则（含 builtin）。

禁止：持有 cache、pending registry、alias resolver、会话记录或任何授权结论缓存；假设读侧存在需要库维护的缓存；以订阅者异常为由回滚已成立的 canonical 提交（订阅者异常由总线吞并记日志；D2 保证异常不可能留下过期命中，细则归 A2-0）。

### 4.3 作业模式：Workspace 的独立工作

义务（库不可达时必须全部成立）：

1. 认证交接后的能力面照常接纳 actor；
2. Session 生命周期照常（open/paused/closed、有序交互引用、封口内容保留窗口）；
3. pending 登记照常并返回登记收据；物化提交显式失败且保留可重试收据（登记与物化提交是两个业务阶段——A4 既定；物化提交没有独立队列，排队只发生在库侧 generation task 队列，属库接收之后的库内事实）；
4. L0（registry 本地查表）与 L1（cache）解析及交付边界授权照常执行；
5. WorkspaceAsset facade 照常；
6. 降级显式：L2 冷读返回明确错误，不以过期条目伪装新鲜成功；settlement 暂停期间 pending 保持 in-flight/等待语义；缓存内容只反映最近一次成功同步之前的状态，且不宣称更新。

持有：ConversationSession 与封口交互记录、pending registry（intent 身份、alias、内容、状态、settlement 关联）、Atom cache 与 Profile 解析缓存、alias resolver 与 profile 读取 resolver（二者构成 workspace memory read 能力边界）、逐次行为授权执行点、WorkspaceAssetStore 与 lease facade。

禁止：解释记忆领域语义（内容合并、类型行为、版本推进、检索排序、去重决策）；在库不参与下制造或伪装 canonical 事实；缓存任何 actor 的授权结论；把库的 backing 路由包装为 actor 面向入口绕过能力边界。

### 4.4 过线契约与事件协作

**workspace → Patchouli**（全部为既有路由语义，零新增领域逻辑）：封口交互提交；materialize task 提交；canonical 点读/alias 批读；语义检索；Profile 定义解析。

**Patchouli → workspace**（本宪章唯一新增契约——事件协作，承载于全局系统总线的 `publish`）：两个事件族——

1. **settlement 事件**（复用既有 `pending_atom_settler`/bridge 投递链）：intent 终态回写的加速通道。事件是加速、不是真相：A4 既定约束继续有效——"通知事件仅作观测，不能作为唯一终态真相"、"结算须可从权威任务/领域结果核对"；workspace registry 必须保留 intent_id 锚定的权威对账路径，在 registry 状态可疑或滞后时按 intent 查询 generation 权威结果。
2. **canonical 变更事件**（新增）：库的受控提交在成功后、写入用例返回前发布领域事实（哪个原子以何种方式变更）；订阅者（workspace runtime）据此决定失效哪些条目与索引并推进 epoch。库只声明事实，不计算缓存影响——"失效什么"的解释权归缓存所有者。

两个事件族都是在 `GlobalSystemBus` 上登记的**公共事件族，不是 RuntimeEvent**——AGENTS.md 对 RuntimeEvent 的观测性条款不适用于它们；其事件名、载荷与发布/订阅纪律登记入公共事件契约（`docs/contracts/routes-and-events.md`，A2 联动修订携带）。

发布与订阅以三条硬纪律（D1–D3）保证正确性。实测依据：`AsyncSystemBus.publish` 内联、顺序 await 全部订阅者后才返回，且订阅者异常被吞并仅记日志——因此内联发布在时序上等价同步失效调用，但失败语义必须由纪律补齐：

- **D1 内联发布**：canonical 变更与 settlement 事件必须 `await publish`，禁止 `create_task` 或其他延后投递；一旦 fire-and-forget，"提交后、送达前"的过期命中窗口立即回归。
- **D2 失效优先订阅者**：canonical 变更订阅者的第一步无条件执行受影响条目的 evict 与 epoch 推进（纯内存、不可失败），其后才做任何可能失败的细节工作；handler 内部任何异常都发生在条目已失效之后，失败不可能留下过期命中。总线吞异常的既定行为因此不会退化为 A2 §3 禁止的"仅输出日志继续返回旧值"。
- **D3 仅失效、不携值**：订阅者不回放事件携带的值——mutation 没有全序（lifecycle patch 不推进 `meta.version`），乱序回放会用旧副本覆盖新状态；回填一律交给带 epoch 守护的冷读。lifecycle 类展示性信号可走 advisory 事件 best-effort 刷新或完全不投递，由 A2-0 裁定。

方向约束：库对 cache 的唯一接触是出向事件；workspace 对 canonical 数据的唯一获取是冷读路由。双向都不得出现旁路。写入路径会等待订阅者执行完（内联 publish 的时序耦合），但写入的成功不依赖订阅者结果——以等待换正确性，是本契约的明确取舍。

### 4.5 断开测试

独立工作契约的机械形式。以下测试是 §7 证伪条件第 2 条的落地载体，也是宪章边界的常驻守卫：

- **Test A（库模式测试，integration）**：不注册任何 workspace 订阅者，独立组装 Patchouli，跑通提交 → 生成 → 存储 → 生命周期 → 检索全链路；断言 canonical 提交成功、事件空投不影响提交结果、settlement 留痕、读路由可用。
- **Test B（作业模式测试，integration）**：注入库路由不可达，断言 session 创建、交互封口登记、pending 登记、L1 命中读取、资产获取全部成功；L2 冷读与物化提交显式失败且登记收据保留（凭 intent identity 可重试）；全过程中不出现静默过期成功。
- **Test C（纯 actor 测试，随 A6 验收）**：Alice 在不含自有 resolver/cache/pending registry 的装配下完成一次 run，读路径全部走 workspace 能力边界。
- **Test D（订阅者纪律测试，unit/integration）**：对 canonical 变更订阅者构造"evict 之后失败"的注入场景，断言条目与 epoch 已失效、后续读取不命中过期值（D2），且发布方调用正常返回、canonical 提交不受影响；另断言 canonical 变更发布为内联 await，不存在延后投递路径（D1）。

测试纪律：Test B 不得通过 mock 库内部状态通过，只允许不可达注入；"正常工作"的语义是降级存活，不是全功能。

## 5. 状态归属冻结表

| 状态/能力 | 持有者 | 过线动作 | 判据依据 |
|:---|:---|:---|:---|
| canonical MemoryAtom、meta.version、完整版本历史 | Patchouli | —（库内） | 已接收资产 |

### 5.1 workspace 读取能力的双向边界

取代协调入口"Workspace service 不能复制 `get_memory`/`search`/`submit_interaction`"的笼统禁令。该禁令要保护的对象（不出现第二个记忆库）继续有效，改用双向精确边界表达：

| resolver 可以 | resolver 禁止 |
|:---|:---|
| 引用归一化；L0/L1/L2 定位；pending 中立结果的引用级跟随（含 settlement 指向的 canonical ref） | 检索排序、dense/sparse 算法、去重决策 |
| 按原子自身 policy 做逐次授权判定（纯谓词，与库共享同一份 core 实现；policy 字段的当前性由失效事件协作与 D1–D3 保证） | 任何内容语义解释、编译、记忆类型行为 |
| epoch 守护的回填、single-flight 合并、负缓存规则执行 | 任何写路径；缓存授权结论 |
| 完整原子 copy-on-read 交付 | 持有 canonical 状态或绕过失效事件自造当前性 |

配套约束：授权谓词从 `engines/retrieval/policy.py` 上收 core（resolver 不得 import Patchouli engines 包，落点由 A2-0 冻结）；`patchouli.public.memory.*` 为 backing 契约——直连仍安全（库侧校验独立成立），但无缓存且不是 actor 面向入口；管理读取直连库管理路由，不过 resolver。

### 5.2 管辖权命名更正

短期记忆库的语义是"库已接收素材的接入暂存（intake buffer）"，不是 actor 可见的记忆分层。会话的真相源是 Session（workspace）；素材管护的真相源才是 Topic（库）。代码与配置命名是否随之调整由 A3-0 决定，文档语义自本宪章起按此管辖权表述。

### 5.3 能力面入口与 actor adapter（2026-09-25 裁定）

workspace 能力面的入口形状裁定为 **in-process 的 workspace server API，不新开总线路由**：actor 是 client，经三类 adapter（HTTP/System API、MTP/Alice、MCP 与外部 B transport）归一化后调用能力面；能力面为实现真实功能，作为 client 调用 Patchouli 的 backing API——形成第二层 client-server，即 §4.4 的过线契约。总线只承载 workspace→Patchouli 的 backing 调用与失效事件。

能力层由现有 `system/application` 改造而成，不新建中间层：拥有平面状态（resolver、双 cache、边界授权、lease）或组合多个领域步骤的方法构成能力实现；向单个 backing 领域操作的无状态委托允许保持薄转发——合法条件是转发前已在能力边界完成 operation 授权、且转发目标是一个完整领域操作而非裸机制（如 `patch_payload`）。物理落位：A2-1 将 `system/application` 迁为 `workspace/capability`（迁移期 re-export shim，A6 删除）；`readiness` 等纯基础设施观测留在 system 组合根。

**actor adapter 五条判据**：只做协议翻译；只做认证交接（A1 网关、access context 取得/复用）；一次操作恰好调用一个能力方法；错误映射为 wire 格式；决定触发时机。出现任一即属能力层代码：需要 resolver/cache/lease/registry；组合多个领域步骤；解释资源 policy；持有平面状态。

**operation 授权落点（§10 第 8 项的落实方式）**：逐次 operation 检查在能力层、backing 调用前执行；Patchouli application 移除 operation/行为白名单检查（职责整体迁出，不双重检查），保留资源归属与资源 policy 校验作为存储边界纵深防御；A1 的行为白名单机制与网关认证不变，仅检查点迁移。

## 6. 硬案例裁定

### 6.1 cache

归 workspace runtime；唯一读者是 resolver；库的唯一接触是出向失效事件。依据：(a) 反转判据——转变前由 Alice 持有；(b) 用途判据——为 actor 读加速存在，可丢弃派生；(c) 结构收益——库的读路径回到 storage-shaped，否证"Patchouli 成为依赖缓存的读取器"。A2 §2 的行为契约（资源 key、完整原子 copy-on-read、不缓存授权结论、epoch、负缓存规则、close、容量与观测）全部原样迁移，仅"消费者"从 Patchouli 链改为 resolver；语义检索仍执行检索并可协作预热，缓存不替代搜索。

### 6.2 pending（最重论证）

pending registry 归 workspace runtime。四层论证：

1. **判据面**：pending 是未被接收的要约——可撤销（CANCELLED 是既有状态）、无任何入库承诺、从未进入库的管护，所以它在 actor 手里，托盘在 workspace。
2. **决断规则面**：intent 是 actor 的即时工作产物——由 actor 组成、需要同步读回；generation 是异步任务消费者，不因消费取得所有权。**本条明确推翻 A4 §4.1 的 2026-09-17 反方向裁定，是全宪章需要最重论证的一处。**
3. **不增不减面**：generation 消费 materialize task 是既有交接，不变；settlement 报告通道从"经 bridge/event 写回 Alice runtime"改为总线事件协作（registry 订阅 + 权威对账），属出边通道的形态变化，不是领域扩张。
4. **结构收益**：resolver 的 L0 变为本地查表（registry 与 resolver 同在 workspace runtime）；A4 的三项动机——外部 actor 可读回意图、意图活得过单次 run、单一权威状态机——全部保留且满足更好，权威状态机即 workspace registry。

执行拆分：Alice 现 `PendingAtomRuntime` 中的 run/frame/action 关联是执行状态，留 actor；intent/alias/内容/状态/settlement 关联是资源工作状态，进 registry。旧实现按 A4 对迁移源的既定定性处理——是迁移起点，不是共享实现的合法依赖。

### 6.3 Session 与 Topic

本宪章确认 A3（2026-09-18 冻结）的切分即为宪章归属：ConversationSession 是 workspace 归属的会话资源（System 会话服务持有本地记录），是会话连续性的真相源；Topic 是库对已提交素材的管护，由封口提交路由产生，Patchouli 不持有第二份完整历史。后果与确认：

1. 提交可靠性是过线契约——active finalize 的"Interaction applied 硬成功边界"与被动链 InteractionSubmissionQueue 即该契约的现状形态，宪章只指认不重建；
2. 结算触发（idle/LRU/shutdown）是库管理自身接入积压的库内事务，不改为会话生命周期驱动；关闭 Session 不级联 Topic/Memory（A3 既定）；
3. Session 持封口 payload、Topic 持路由 blocks 的双份内容是既定接受成本，不新增第三份；
4. 管辖权更正见 §5.2。

本案例同时是判据的回溯证据：判据与 2026-09-18 独立冻结的 A3 结论一致（§8）。

## 7. 证伪条件

观察到以下任一实例，本宪章即告失效，必须再裁定；不得以偏好或美学理由重开：

1. 某 workspace 持有状态的正确性必须同步依赖库内部事实，且无法经过线契约表达；
2. 断开测试无法写成不依赖 mock 库内部的可执行测试；
3. 出现一类 actor，其接入必须理解库内部结构而非仅消费能力面；
4. 工作产物决断规则在真实新状态上无法给出单侧裁决，且两侧用途论证等强；
5. 事件协作无法在无订阅者的库组合中以空投成立，或 D1 内联发布纪律无法在写入路径中维持；
6. 订阅者无法按 D2 失效优先纪律实现，即存在 handler 失败留下过期命中的路径；
7. 独立工作义务清单中任一条与 A2-P 已验收语义冲突。
