# v0.7.0 A5：能力面 API 收敛与库职责退出

## 0. 重新定性（2026-09-25）

按[计划 A 边界宪章](./v0.7.0-plan-a-boundary-charter.md) §5.3 与 2026-09-25 顺序重排，本计划**不再是能力层的搭建者**：能力层骨架由 [A2](./v0.7.0-a2-workspace-resource-reads-and-caches.md) 交付（`system/application → workspace/capability` 迁移、operation 守卫、读取能力方法），session/交互/topic 切片由 [A3](./v0.7.0-a3-conversation-session-and-topic-projection.md) 交付，pending registry 与 intent 切片由 [A4](./v0.7.0-a4-pending-memory-intents.md) 交付。A5 是**收敛者与核对者**，交付四件事：

1. **两层目录收敛**：能力面 API 目录（`workspace/capability` 暴露的业务操作）与 backing 路由目录（`patchouli.public.*`）逐项核对，每个能力方法恰一 backing 路由或纯平面状态，无孤儿、无旁路；
2. **差额补齐**：检索跨操作语义、usage/citation/feedback 报告与管理操作剩余差额；
3. **operation 检查全量退役核对**：A2/A3/A4 各自迁移其路径后，核对所有 backing 路由的 operation 检查均已迁出、能力层单点生效；
4. **旧 PatchouliService 职责退出**：逐项职责映射到已验证入口，退出清单交 A6 执行删除。

## 1. 两层目录

- **能力面目录**（actor 面向，经 operation 守卫）：memory read/retrieve/管理、Profile 读取、session 管理/读取、`interaction.submit`、`memory_intent.submit`、topic 资料/准备/管理、memory task 观察、usage/citation/feedback、Asset facade。
- **backing 路由目录**（L2，库侧归属与 policy 校验独立成立）：`patchouli.public.memory.*`、`get_agent_profile`、`patchouli.public.topic.*`、`patchouli.public.interaction.submit`、`patchouli.public.memory_intent.submit`、`patchouli.public.memory_task.*`、管理 API。

API 是能力面提供的稳定业务操作、输入、授权、结果、失败和生命周期语义；总线路由是 backing 实现在 `GlobalSystemBus` 上的地址；能力层方法按宪章 §5.3 组装平面状态（resolver/cache/守卫）并委托 backing；adapter 只转换协议、取得 access、决定触发时机和呈现结果。

三方（System/Alice/外部 adapter）差异只在 principal 来源、触发时机、输入输出协议上。管理员、Alice 与外部 Actor 对同一业务操作必须经同一能力面方法；adapter 可以承担各自的协议编排，但不能形成第二个领域实现，也不能绕过能力层直连 backing 路由。

## 2. 三方共通操作目录

| 共通操作 | System adapter | Alice adapter | 外部 adapter | 能力面语义（backing 委托） |
|:---|:---|:---|:---|:---|
| memory search | Passive context 或管理应用查询 | prepare、MTP SEARCH | 自动 context、search 工具 | 同条件同 policy 的可见检索；直连 L2 backing，结果可预热 cache |
| resource read/resolve | 应用引用读取 | MTP READ、CALL context_refs | read 工具 | resolver 多级解析与交付边界授权（A2）；L0 registry 分支（A4） |
| profile read | 管理和应用读取 | Root/CALL | 可选读取 Profile 定义 | profile 读取 resolver（解析结果缓存 + 交付授权）；L1 miss 调库按别名读取，源原子定位与解析在库内部；不等于应用执行配置 |
| Topic 资料 | 摄入关联和读取 | prepare 读取 | Session/交互关联的 Topic 资料 | 库持有 Topic 路由和快照；能力层薄委托 |
| Pending 登记 | 应用主动写入 | MTP WRITE/UPDATE | write/update 工具 | registry 可读意图（A4），不等同 Memory |
| memory intent submit | 应用策略提交 | settlement adapter | 工具立即或延迟提交 | 接纳 `PendingAtomMaterializeTask`，读取全部可用 Topic 资料并生成/修订 |
| interaction submit | Passive seal/flush | run 结束后的事件整理与封口 | 外部完成回调/封口 | 去重、领域投影并应用交互到 Topic/证据；不隐式物化 intent |
| result/usage observe | 展示与反馈 | 引用、使用与结算 | 结果查询和反馈 | 分开表达接收、应用、物化、canonical 与实际使用 |

共同操作不表示相同权限或相同触发信号；统一的是领域语义和业务链路。

## 3. operation 检查全量退役核对

按宪章 §10 第 8 项与 [A2 §5.2](./v0.7.0-a2-workspace-resource-reads-and-caches.md#52-operation-授权迁移)：读取路径的 Patchouli 侧 operation 检查由 A2 退役，session/topic/intent 路径由 A3/A4 随切片迁移。本计划核对：所有 backing 路由的 operation/行为白名单检查均已迁出（`access_consumption` 共享检查退役）；能力层守卫对每个能力方法单点生效；库侧资源归属与资源 policy 校验完整保留（存储边界纵深防御）；管理路径仍走独立管理 operation 与 owner-management 规则。发现遗漏路径即登记修复，不借核对新建第二套检查。

## 4. PatchouliService 的收缩与退出

| 旧职责 | 目标承担方 |
|:---|:---|
| prepare 中的 Profile、Topic、检索 | 调用侧 prepare adapter 组合能力面方法；Patchouli 保留领域解析、Topic 准备和检索 |
| `AgentRunContext`、stream prelude、运行参数 | Alice/Chat 执行侧 |
| 附件选择、编译、lease | 调用侧协调 Asset facade 与 AttachmentCompiler |
| finalize 的运行事件整理、交互封口和提交时机 | Alice/System adapter；形成 InteractionPayload，分别调用 interaction 与 memory_intent 能力方法 |
| TurnEvent → AgentAction/TurnRecord 领域投影、交互应用、Topic 路由、生成、settlement | Patchouli application/领域服务的唯一实现；投影规则按 A3，不由各 adapter 重复归约 |
| citation、feedback、Topic 条件清理 | Patchouli 领域 API；能力层薄委托，adapter 只报告事实和请求操作 |

旧方法可以在迁移期委托新入口，但不再直接提交内部 queue、controller 或 generation local route。取消、continuation、lease release 和 shutdown drain 必须由调用侧 coordinator 和能力层分别承接；不能因为拆分而丢失这些保障。调用侧负责尚未交接的运行工作，能力层接纳后负责领域工作；后置主动物化失败不能把已应用交互改判失败。

## 5. 兼容与输入来源

- canonical 完整 MemoryAtom/列表、AgentProfile、copy-on-read 与缓存内部 source UUID/version 以 [A2](./v0.7.0-a2-workspace-resource-reads-and-caches.md)为准；不保留 MemorySnapshot/ProfileSnapshot 作为目标 API。
- `RetrievalResponse` 仅用于 adapter 协议包装或本地运行上下文过渡；backing 路由不返回该 envelope，也不按调用方选择返回类型。现有 route 名不要求随 search/read 的业务命名新增同义 API。
- InteractionPayload/TurnEvent、交互接纳与应用结果、Topic prepare/handle/路由关联/cleanup 及资料绑定以 [A3](./v0.7.0-a3-conversation-session-and-topic-projection.md)为准，不要求独立 assignment 实体。
- `PendingAtomMaterializeTask`、Pending 内容/状态及完整引用读取以 [A4](./v0.7.0-a4-pending-memory-intents.md)为准。
- 调用方提交使用报告是 provenance 声明；返回过 ref 不等于实际使用过。附件使用只承接已有编译确认的 ref 快照，不能回查当前 UI 选择替代。
- HTTP/MTP/SSE 兼容由 adapter 维护，内部签名变更记录 access、DTO、错误及删除窗口。旧 Alice 专属 prepare/finalize/cleanup 不在"全部路由永久保留"范围内。

本计划从 A2–A4 已交付接口核对完整操作目录，不冻结它们的输入模型或共同状态机。发现领域行为缺陷，在所属实现修复并更新其唯一设计记录；这属于消费阶段发现的缺陷，不预设前置计划必须等待 A5 才能完成。

## 6. 实施、测试和完成条件

| 阶段 | 产出 | 验收 |
|:---|:---|:---|
| A5-0 | 基于 A1–A4 已交付切片的两层目录、缺口与旧职责交接表 | 每项模型/生命周期均有前置领域依据；能力方法 ↔ backing 路由无孤儿无旁路；没有这里先冻结才能完成的 A2–A4 接口 |
| A5-1 | 检索、usage/citation/feedback 与管理操作的剩余差额 | 自动 context 与主动 SEARCH 使用同一领域语义；返回、实际使用、引用、评价分开；普通 Actor 不借管理 bypass |
| A5-2 | 全操作能力方法、access、输入、结果与错误的组合核对 | 两条提交独立；三方中立样例到达相同能力入口；无重复 DTO、状态机或共同 resolver |
| A5-3 | Patchouli 侧 operation 检查全量退役核对 + 旧 PatchouliService 职责/调用方/退出窗口清单 | 所有 backing 路由 operation 检查已迁出且能力层单点生效；每项领域职责有已验证入口；清单交 A6 验收实际迁移与删除 |

integration 使用真实 GlobalSystemBus、能力层、PatchouliBridge、application、queue 和 domain collaborator；fake 只能替换外部模型/网络。复用 A2–A4 的读取、Topic、Pending 行为证据，这里补检索/使用报告差额、跨操作授权、输入结果映射和三方相同能力入口的组合验证，不重复实现整套领域测试。A5 的中立 adapter 样例不替代 A6 的生产消费者验收。

完成条件是两层目录与实际能力方法/backing 路由一致、剩余业务差额有真实实现和证据、operation 检查退役核对通过、旧职责都有接收方；不等待 A6 删除旧入口或 B 发布外部协议。事实文档仍按版本稳定收尾门禁更新，未收尾设计留在计划中。

A5-0 只关闭本计划新增差额，例如普通 Actor usage/feedback 的签名和 operation；不重新决定 Topic handle、InteractionPayload 或 Pending 输入。回滚仅保留委托同一领域实现的受信 adapter，不恢复旧 queue/generation 旁路；任何兼容入口写明调用方与删除时点。
