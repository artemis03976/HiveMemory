# v0.7.0 提示词编译前移至任务进程

> **文档状态**：Planned（2026-10-17）。尚未实施；目标结构与字段名不能作为当前事实使用。

任务进程在分配 CPU 时已经编译记忆与附件，理由是让不同执行者共用同一份编译结果（[System 应用服务](../system/application-services.md)第 3.1 节）。但这件事只做了一半：文本由进程编译，最终的提示词却由 Alice 在 CPU 内从原料重新组装，HiveMemory 自己的内容（人格、环境通知、记忆、附件）与 Alice 的工具教学、会话压缩混在同一个组装器里。外部 harness 接入后，HiveMemory 无法干预它的上下文管理与压缩，HiveMemory 想注入的内容只能在 CPU 边界之前定稿。

本计划把提示词按归属拆成两半：HiveMemory 的部分由任务进程编译完成，以 CPU 中立的文本交给任何 CPU；工具教学、历史渲染、会话压缩与 CALL 子帧提示词是 CPU 内部的 harness 职责，Alice 只把进程交来的文本当作不透明的固定输入放置。对 Alice 而言，最终提示词与现在保持一致。

设计依据：

- 当前事实：[Agent Runtime](../alice/agent-runtime.md)第 3 节（提示词的分层顺序与“不能拼成一段再反向解析”的理由）与第 3.1 节（会话上下文视图）、[Alice](../alice/README.md)第 3 节（人格与权限分离）、[子系统契约](../contracts/subsystem-contracts.md)第 4 节（CPU 端口与输入清单）、[System 应用服务](../system/application-services.md)第 3.1 节（CPU 分配与编译放在进程一侧的理由）；
- 代码：2026-10-17 分支 `refactor/v0.7.0-cleaning` 提交 `b4f72840`；
- 已归档：[Alice 与 agent_runtime 结构重构](../archive/plans/v0.7.0-alice-agent-runtime-restructure.md)，其非目标中“Alice 专属提示词组装与 `AgentRunContext` 移出共享层，需要时另行立项”由本计划承接；
- 背景 Idea：[外部 Actor](../ideas/external-actor-registration-and-runtime-access.md)第 1.1 节（controller 模式下 harness 自管 loop、工具、上下文压缩与子 agent，经 MCP 访问能力层）与第 3.4 节（不要求外部 Actor 采用 Alice 的 prompt history 或 MTP 语法）与[执行单元](../ideas/execution-unit-thread-and-environment.md)前提 9（persona 对外部 harness 只能作为首轮内容尽力应用）。

## 1. 背景和问题

1. **组装器依赖 Alice 配置**：`AgentPromptAssembler(koakuma_config)`（`prompts/assembler.py`）同时负责人格、存储离线通知、记忆、附件与 MTP 教学；MTP 教学的开关来自 `alice.koakuma`。HiveMemory 的那部分内容因此无法离开 Alice 产出，任务进程只能交出原料。
2. **压缩反向依赖组装器**：会话摘要经 `SystemPromptBuilder.with_session_summary` 插在人格段与记忆段之间。`SessionContextView._fixed`（`alice/context/view.py`）为了在不同摘要下估算固定部分，每次都调用 `build_main_agent_messages` 重新渲染整份系统提示词，所以 `RootContextBuilder` 与运行服务都持有组装器。
3. **CPU 中立的清单仍面向 Alice**：`CPUInputManifest` 携带 `memory_context`、`attachment_context`、`storage_available` 与整份 `AgentProfile`，最终怎样拼成提示词由 CPU 决定。换成外部 CPU 驱动，就必须在驱动里复刻同一套拼装，或者各自拼出不同的结果，进程侧编译的初衷落空。
4. **`AgentRunContext` 只是清单的重复**：它由运行服务从清单逐字段转换而来（`alice/run/service.py`），只为喂给组装器，并作为公共模型留在 `core.protocol`。
5. **CALL 子帧提示词与根帧共用组装器**：`build_sub_agent_messages` 的 docstring 仍写“父 frame 继承的动词集合”，并在策略已去掉 CALL 之后再去掉一次（收敛清单第 1.2 条）；`with_topic_state` 与 i18n `topic_state_header` 没有生产调用方（第 1.3 条）。

## 2. 目标与非目标

### 2.1 目标

1. HiveMemory 的提示词内容在任务进程中编译完成，编译不依赖任何 CPU 的配置；输入清单交付成品文本与解析好的提示词语言。
2. Alice 只在 CPU 内负责 harness 职责：MTP 工具教学、历史渲染、会话视图与压缩、CALL 子帧提示词；不再渲染人格、记忆、附件或环境通知。
3. 会话压缩把进程交来的部分当作不透明的固定块计量，不再依赖组装器；摘要是 Alice 自己的段落。
4. 对相同输入，Alice 的根帧消息与现状一致（第 4.4 节列出的唯一差异除外）；检查点格式、交互事件与 RuntimeEvent 不变。
5. 删除 `AgentRunContext` 与 `AgentPromptAssembler`，提示词的组装入口与所有者一一对应。

### 2.2 非目标

- 实现外部 CPU 驱动或确定其协议映射：第 4.5 节只说明清单如何被外部驱动使用，驱动随 controller 模式另行实施。
- 修改 MTP 教学的内容与裁剪规则、历史重放格式、会话压缩算法与检查点格式。
- 把历史渲染或会话压缩移出 CPU：二者属于 harness，外部 harness 自管。
- 让进程按 CPU 的模型窗口裁剪记忆或附件：进程不知道 CPU 选用的模型，固定部分超窗仍由 CPU 以 `input_too_large` 拒绝，与现状相同。
- 重写提示词与 i18n 文案（收敛清单第 3.8 条的内联文案仍按清单处理），第 4.4 节的存储离线通知除外。
- 把只被 Alice 使用的提示词模块（MTP 教学、摘要渲染、历史重放）迁出 `prompts`：Alice 的 `context` 与 `orchestration` 都要使用它们而彼此不能导入，留在共享的 L2 层是合规的落点。

## 3. 当前状态（2026-10-17 核对）

- **CPU 分配**（`workspace/process/allocation.py`）：读取操作快照、租借并编译附件、编译记忆，然后组装清单。清单字段见[子系统契约](../contracts/subsystem-contracts.md)第 4 节：`user_message`、`agent_profile`、`allowed_operations`、`memories`、`memory_context`、`attachment_context`、`storage_available`、`topic_id`、`session_history`、`compaction_checkpoint` 与 `labels`、`process_id`。`memories` 另被进程用于投影 `memory_refs` 事件。
- **Alice 根帧**：运行服务把清单转换为 `AgentRunContext`，`RootContextBuilder` 解析模型后构造 `SessionContextView`；视图以组装器渲染固定部分（系统提示词 + 用户消息），在两者之间插入历史，压缩时带着摘要重新渲染固定部分。
- **提示词顺序**（[Agent Runtime](../alice/agent-runtime.md)第 3 节）：MTP 教学与存储离线通知 → 人格 → 会话摘要与引用线索 → 记忆 → 附件 → 历史 → 用户消息。存储离线通知只在开启 MTP 教学时加入，语言取 Profile 的语言设置。
- **CALL 子帧**：`CallCoordinator` 以被调用方的操作快照翻译动词并去掉 CALL，再调用 `build_sub_agent_messages` 组装 MTP 教学、被调用方人格、共享上下文与任务。
- **提示词模块的使用者**：`prompts/mtp.py`、`prompts/session_compaction.py`、`prompts/transcript/history.py` 只被 Alice 使用；`prompts/gateway.py` 只被 Gateway 使用；`prompts/transcript/generation.py` 只被 Patchouli 使用。

## 4. 目标设计

### 4.1 职责划分

| 部分 | 归属 | 理由 |
|:---|:---|:---|
| 人格段（Profile 的 persona） | 任务进程 | HiveMemory 的 agent 设定，任何 CPU 都应拿到同一份 |
| 环境通知（记忆存储离线） | 任务进程 | 反映 HiveMemory 的运行状态，与 CPU 的工具机制无关 |
| 记忆与附件段 | 任务进程 | 已由进程编译，放置顺序也由进程定稿 |
| 提示词语言 | 任务进程 | 进程渲染与 CPU 渲染必须使用同一语言 |
| 用户消息 | 任务进程（原样） | 已在清单中 |
| MTP 工具教学 | CPU（Alice） | 工具机制属于 harness；外部 harness 经 MCP 描述工具，不使用 MTP 语法 |
| 历史渲染、会话视图与压缩、摘要段 | CPU（Alice） | harness 自管上下文；摘要替代历史前缀，是压缩产物 |
| CALL 子帧提示词 | CPU（Alice） | CALL 是 Alice 的内部能力，外部 harness 的子 agent 不识别为执行线程 |

任务进程的产物是不透明文本：CPU 只决定放在哪里，不解析、不改写，保持“不能拼成一段后再由 Runtime 反向解析”的现有约束。

### 4.2 输入清单的变化

清单增加三项，删除只剩原料用途的三项：

| 变化 | 字段（候选名） | 内容 |
|:---|:---|:---|
| 新增 | `language` | 按 Profile 语言解析出的提示词语言 |
| 新增 | `instructions` | 环境通知与人格段，相对稳定的 agent 级内容；没有内容时为空字符串 |
| 新增 | `turn_context` | 记忆段与附件段，按现有顺序拼接的本轮材料；没有内容时为空字符串 |
| 删除 | `memory_context`、`attachment_context`、`storage_available` | 已并入上面两段 |

`user_message`、`memories`、`agent_profile`（此后只用于模型参数与展示）、`allowed_operations`、`session_history`、`compaction_checkpoint`、`labels`、`topic_id` 保持不变。字段名以及三项是否收拢为一个嵌套模型在实施评审时确定，记入第 11 节。

分成两段而不是一整段，是为了让 CPU 能按自身能力放置：Alice 把两段都放进系统提示词并在中间插入摘要，从而保持现有顺序；不支持系统提示词的外部协议可以把 `instructions` 放在建会话或首轮，把 `turn_context` 随每轮附带（第 4.5 节）。

### 4.3 任务进程的编译

- `prompts` 中新增中立的输入编译：由 Profile、存储可用性、已编译的记忆与附件文本与语言，产出 `instructions` 与 `turn_context`。它只依赖 core、i18n 与提示词片段，不接收任何 CPU 的配置。人格段与环境通知的渲染函数供 CALL 子帧复用。
- `CPUAllocator` 在附件与记忆编译之后调用它，再组装清单。语言解析沿用现有规则（Profile 语言优先，否则取进程默认语言）。
- 编译放在进程侧的理由（共用同一份结果）由事实文档继续维护，本计划只把它从“编译文本”扩展到“编译提示词内容”。

### 4.4 Alice 的根帧布局

- 根帧消息：系统消息 = MTP 教学 + `instructions` + 摘要段（有摘要时）+ `turn_context`；其后是历史视图；最后是用户消息。各段为空时省略，顺序与现状一致。
- MTP 教学仍由 `prompts/mtp.py` 按动词集合与 `alice.koakuma` 生成，语言取清单的 `language`；摘要段仍由 `prompts/session_compaction.py` 渲染。
- `SessionContextView` 接收两段不透明文本、用户消息与语言，不再接收组装器；带摘要估算固定部分时只替换摘要段。固定部分超出输入上限仍以 `input_too_large` 结束，摘要预留的估算方式不变。
- `RootContextBuilder`、运行服务与 `AliceSystem` 不再持有组装器；运行服务直接消费清单，动词翻译仍在 `orchestration/verbs.py`；删除 `AgentRunContext`。
- 唯一的可见差异（候选设计）：存储离线通知改为只要存储不可用就加入，不再以开启 MTP 教学为条件；文案去掉“本地系统工具仍可使用”这类只对 Alice 成立的句子。中英文模板同步修改。

### 4.5 外部 CPU 驱动如何使用清单（说明，不在本计划实施）

controller 模式的驱动拿到同一份清单后：`instructions` 按协议能力放进系统提示词、建会话参数或首轮内容；`turn_context` 与 `user_message` 随每轮发送；`allowed_operations` 翻译为该 harness 的工具描述（例如 MCP 工具列表，不含 CALL）；`session_history` 与检查点是否使用由驱动决定，harness 自管历史与压缩。这些映射由驱动所在的计划确定；清单是进程内对象端口，若届时需要调整字段，不涉及持久化兼容。

### 4.6 CALL 子帧提示词

`CallCoordinator` 直接组装子帧消息：MTP 教学（被调用方的动词集合；CALL 只在构造策略时去掉一次）、被调用方人格段（复用第 4.3 节的中立渲染函数）、共享上下文与任务；语言取被调用方 Profile 的语言，与现状相同。删除 `AgentPromptAssembler`、`SystemPromptBuilder.with_topic_state` 与 i18n `topic_state_header`。

### 4.7 承接的收敛条目

[v0.7.0 代码收敛清单](../todo/v0.7.0-code-convergence.md)中以下条目由本计划处理：第 1.2 条；第 1.3 条中“话题状态提示词”一项；第 3.6 条中 `AgentPromptAssembler` 的部分；第 4.2 条中 `workspace/process/allocation.py` 的两处“拆分前”、`CPUInputManifest` docstring 与 `AgentRunContext` 注释。清单其余内容不变。

## 5. 受影响的系统、契约和数据

- **workspace**：`CPUInputManifest` 字段变化；CPU 分配增加提示词编译步骤，不新增依赖方向（workspace → prompts 属于 L3 → L2）。
- **prompts**：新增中立输入编译；删除组装器与无调用方的话题状态片段；`SystemPromptBuilder` 的职责随之收窄或拆分，实施时确定。
- **Alice**：根帧布局、上下文视图、运行服务、CALL 编排与 `AliceSystem` 的构造参数。
- **core**：删除 `core.protocol.models.AgentRunContext`。
- **i18n**：存储离线通知的中英文模板。
- **不变**：CPU 端口与执行结果、检查点结构与 `format_version`、交互事件与 SSE、RuntimeEvent、持久化数据、配置键。

## 6. 兼容与迁移

- 输入清单是进程内对象端口且尚未发布，字段一次性切换，不保留旧字段或别名；测试 CPU 与清单构造 helper 同批更新。
- 迁移以提示词等价为准：实施时对代表性输入（有无人格、记忆、附件、摘要、存储离线）比较迁移前后的根帧与子帧消息，除第 4.4 节的通知差异外逐字一致，比较结果记入第 11 节；这是迁移检查，不保留为永久测试。
- 原提示词测试按新的归属改写：中立编译的断言迁入进程侧与 `prompts` 测试，布局断言留在 Alice；不留“旧组装器已删除”式的墓碑测试。

## 7. 实施阶段

每个阶段结束时后端全量测试与静态检查通过，可单独审查与合并。

**阶段一：进程侧编译与根帧布局**

1. `prompts` 中立输入编译与人格段、环境通知的渲染函数；存储离线通知模板改为中立文案；
2. CPU 分配产出 `language`、`instructions`、`turn_context`，清单切换字段；
3. Alice 根帧按第 4.4 节布局，上下文视图、`RootContextBuilder`、运行服务与 `AliceSystem` 不再接收组装器；删除 `AgentRunContext`；
4. 根帧提示词的等价比较。

验收：第 8 节第 1–4、6、7 项。

**阶段二：CALL 子帧与收尾**

1. CALL 编排直接组装子帧提示词，删除 `AgentPromptAssembler`、`with_topic_state` 与 `topic_state_header`；
2. 子帧提示词的等价比较；
3. 晋升事实文档（第 10 节），同步收敛清单、Plans 导航与 ROADMAP，归档本计划。

验收：第 8 节全部。

## 8. 测试和验收标准

按[测试设计规范](../governance/testing/test-design-standards.md)分类：每条不变量只在作出判断的归属层写权威测试，上层与 E2E 只保留代表性链路；验收测试写入归属层的现有文件。

1. **中立编译**：人格段、环境通知、记忆与附件按固定顺序与解析出的语言渲染，空段省略，存储不可用时附带通知（`tests/unit/prompts/`，改写现有 `test_system_prompt.py`、`test_attachment_section_order.py`、`test_message_assembler.py`）。
2. **CPU 分配**：清单携带编译结果与语言，编译不读取任何 CPU 配置（`tests/unit/workspace/process/test_cpu_allocation.py`）。
3. **根帧布局**：MTP 教学、`instructions`、摘要段、`turn_context`、历史与用户消息的顺序；Alice 不再渲染人格、记忆、附件或通知（`tests/unit/alice/context/test_view.py` 与运行服务测试）。
4. **压缩**：固定部分作为不透明块计量，超限以 `input_too_large` 结束；摘要只替换自己的段落；检查点格式不变（现有视图、摘要与运行服务的压缩测试）。
5. **CALL 子帧**：被调用方人格、动词集合（不含 CALL）、共享上下文与任务（`tests/unit/alice/orchestration/call/test_coordinator.py`、`tests/unit/prompts/test_mtp_permissions.py`）。
6. **依赖方向**：中立编译模块与 CPU 分配不导入 `config.alice` 或 Alice（扩展 `tests/unit/architecture/` 中既有的分层或边界守卫）。
7. **链路不变**：HTTP chat、CALL、会话压缩的现有集成与 E2E 测试通过，断言只随清单字段调整。
