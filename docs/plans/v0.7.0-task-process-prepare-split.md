# v0.7.0 任务进程：prepare 拆分与 CPU 输入清单

任务进程方向的第二批实施。第一批（[已归档](../archive/plans/v0.7.0-task-process-table.md)）把进程表与四阶段编排迁入 `workspace.process`，但 Patchouli 与 Alice 之间的交接没有变化：Patchouli prepare 仍然解析 Profile、取得附件租借、编译记忆与附件，并组装 Alice 专用的 `AgentRunContext`。本批把这些工作从 Patchouli 移到进程，由进程组装一份与 CPU 无关的输入清单交给 Alice。

设计依据：[任务进程 Idea](../ideas/task-process-table-and-registration-entry.md) 第 1.2 节（含 2026-09-29 关于编译、附件与 Profile 的决定）、[总 Idea](../ideas/workspace-network-task-process-architecture.md) 第 10 节 D-9、当前事实文档与代码。

## 1. 背景和问题

`PatchouliService.prepare_agent_run`（`patchouli/service.py`）现在依次做七件事：

1. 经本地路由解析 Agent Profile；
2. 解析或新建 Topic，读取候选话题与话题上下文；
3. 按 GatewayDecision 检索记忆；
4. 用 `MemoryCompiler` 把检索结果编译为 `RETRIEVAL_CONTEXT` 文本；
5. 按用户选择逐项取得附件租借并核对版本摘要；
6. 用 `AttachmentCompiler` 编译附件，得出实际用到的附件；
7. 组装 `AgentRunContext`、`StreamPrelude` 与 `PreparedAgentRun`。

其中 1、4、5、6、7 都在为 Alice 这一次执行服务，不属于记忆库（[ADR-0006](../architecture/decisions/0006-memory-library-custody-criteria-and-independence-contract.md)：挂载资产、为 Actor 干活的状态不归记忆库）。结果是：

- Patchouli 的公开路由产出 Alice 专属的 `AgentRunContext` 与编译好的记忆文本；
- 附件租借由 Patchouli 持有，释放逻辑分散在 prepare 的异常分支、finalize 的 continuation 与 cleanup 三处；
- 换一个 CPU，就得让 Patchouli 学会为它组装另一种上下文。

## 2. 目标与非目标

**目标**：

1. Patchouli prepare 只做 Topic 与检索：返回话题信息与未编译的检索结果，不再解析 Profile、不碰附件、不编译、不组装 `AgentRunContext` 与 `StreamPrelude`；
2. 进程在分配 CPU 时解析 Profile（经 Patchouli 公开路由）、取得附件租借并编译附件、编译记忆，组装输入清单；
3. 输入清单模型位于新建的 `workspace.contracts`，Alice 的执行路由接收它，在内部转换为提示词组装使用的 `AgentRunContext`；
4. 附件租借由进程持有，进程结束时无论哪条路径统一释放；实际用到的附件由进程交给 finalize；
5. SSE 的 `topic_info` 与 `memory_refs` 由进程从 prepare 结果推导；
6. 对外可观察行为不变：SSE 事件序列与内容、错误类型与文案、取消语义、finalize 的交互内容。

**非目标**（留给后续批次）：

- finalize 输入的中立化：finalize 仍接收 `AgentRunResult`；
- 写入意图迁移、`materialize_tasks`；
- Topic 按需创建、`topic_info` 的异步化、ConversationSession（Topic 的准备与话题上下文暂由 Patchouli 处理）；
- CPU 端口、非 Alice 的 CPU、由 CPU 声明编译参数；
- Profile 改经能力层（需要 A1 返工的访问上下文与 Profile 缓存失效机制）；
- Alice 的读取实现迁移到 workspace、engines 对 `agent_runtime.aliases` 的已知例外；
- `PreparedAgentRun` 改名、`ProcessPhase` 新增分配阶段。

## 3. 当前状态（2026-09-29 核对）

### 3.1 交接对象

| 对象 | 位置 | 内容 |
|:---|:---|:---|
| `AgentRunContext` | `core/protocol/models.py` | `identity_scope`、`interaction_id`、`topic_id`、`user_message`、`topic_context`、`retrieval_result`、`memory_context`（编译好的文本）、`agent_profile`、`storage_available`、`attachment_compile_result` |
| `StreamPrelude` | `patchouli/models.py` | `topic_id`、`is_new_topic`、`pool_topics`、`memory_refs` |
| `PreparedAgentRun` | `patchouli/models.py` | `agent_run_context`、`gateway_decision`、`stream_prelude`、`generation_options`、`attachment_leases`；`identity_scope`、`interaction_id`、`topic_id`、`user_message`、`agent_profile` 等为派生属性 |

### 3.2 消费方

- **进程**（`workspace/process/service.py`）：把 `prepared.agent_run_context` 传给 `ALICE_RUN_AGENT(_STREAM)`；用 `stream_prelude` 发 `topic_info` 与 `memory_refs`；finalize、cleanup 传回整个 `PreparedAgentRun`。
- **Alice**（`alice/application/agent_run_service.py`）：用 `retrieval_result.memories` 登记预检索 alias；把整个 `AgentRunContext` 交给 `AgentPromptAssembler`；用 `identity_scope`、`topic_id`、`agent_profile` 建根 frame 与运行事件。Alice 不使用 `interaction_id`。
- **提示词组装**（`prompts/assembler.py`，L2）：使用 `agent_profile`、`storage_available`、`memory_context`、`attachment_compile_result.attachment_context`、`topic_context`、`identity_scope`、`user_message`。L2 不能导入 L3 的 `workspace.contracts`。
- **finalize**：用 `agent_run_context` 的 `user_message` 与 `attachment_compile_result.used_attachments` 组装 `InteractionPayload`；用 `retrieval_result.memories` 记录检索命中；continuation 在交互 applied 后释放附件租借；失败时按 `is_new_topic` 清理空话题。
- **cleanup**：释放附件租借，并在满足条件时清理预创建的空话题。

### 3.3 可复用的现有能力

- **Profile**：公开路由 `PATCHOULI_GET_AGENT_PROFILE`（`AgentProfileManagementService.get_agent_profile`）与 prepare 使用的本地路由 `GET_AGENT_PROFILE` 是同一条解析规则；公开路由在缺少访问上下文时按迁移期兼容分支受信处理，与 prepare 现状相同。返回 `ResolvedAgentProfile`，取 `.profile`。
- **附件**：`WorkspaceAssetReaderPort`（`core/ports/workspace_assets.py`）由进程级 `InMemoryWorkspaceAssetStore` 实现，组合根现在把它注入 Patchouli；`acquire_ready_representation` 与 `release_representation_lease` 都是同步方法，释放是幂等的。
- **编译器**：`MemoryCompiler` 与 `AttachmentCompiler` 位于 `engines`（L2），workspace 可以直接使用；配置段分别是 `memory_compiler` 与 `attachment_compiler`，现由 Patchouli 接收。
- **Artifact promotion** 在生成时按 `binding.asset_ref` 自行取得内容（`patchouli/services/memory_generation.py`），不依赖本轮的租借。

## 4. 目标设计

### 4.1 Patchouli：prepare 只做 Topic 与检索

`PreparedAgentRun` 保留为 Patchouli prepare 的结果，以及 finalize 与 cleanup 的输入句柄，但只含 Patchouli 自己的内容（名称本批不改）。进程需要读取它的字段，而 L3 子系统之间只能导入对方的 contracts，因此实施评审时把它从 `patchouli/models.py` 移入 `patchouli/contracts/prepare.py`，进程一侧据此标注类型：

| 字段 | 说明 |
|:---|:---|
| `identity_scope`、`interaction_id`、`user_message`、`gateway_decision` | 由 prepare 入参冻结 |
| `topic_id`、`is_new_topic`、`topic_context`、`pool_topics` | Topic 准备结果；`topic_context` 与 `pool_topics` 在 ConversationSession 一批之前暂时保留 |
| `retrieval_result` | 未编译的检索结果（`RetrievalResponse`） |
| `storage_available` | 记忆存储健康状态 |

删除 `agent_run_context`、`stream_prelude`、`attachment_leases`、`generation_options` 与 `agent_profile`；`StreamPrelude` 类删除。

公开路由签名的变化：

| 路由 | 变化 |
|:---|:---|
| `PATCHOULI_PREPARE_AGENT_RUN` | 删除参数 `generation_options` 与 `selected_attachments`；不再解析 Profile、不再编译；异常分支只清理预创建的空话题 |
| `PATCHOULI_FINALIZE_AGENT_RUN` | 新增参数 `used_attachments: tuple[WorkspaceAssetRef, ...] = ()`，写入 `InteractionPayload.used_attachments`；continuation 不再释放租借 |
| `PATCHOULI_CLEANUP_PREPARED_AGENT_RUN` | 只做条件话题清理，不再释放租借 |

`PatchouliService` 不再持有 `asset_reader`、`AttachmentCompiler`、`MemoryCompiler` 与 `memory_compiler_config`；`PatchouliSystem` 不再接收 `attachment_compiler_config`。Patchouli runtime 注入的 `workspace_asset_reader`（供 Artifact promotion 使用）保持不变。

### 4.2 workspace.contracts：CPU 输入清单

新建 `src/hivememory/workspace/contracts/`，只依赖 L0（`core`）。本批定义一个模型（名称可在实施评审时调整）：

```text
CPUInputManifest（frozen）
  process_id
  identity_scope
  user_message
  agent_profile            # CPU 分配时解析
  memories                 # 未编译的检索结果（MemoryAtom 列表）
  memory_context           # 进程编译的 RETRIEVAL_CONTEXT 文本
  attachment_context       # 进程编译的附件文本
  storage_available
  topic_id                 # 暂时保留，ConversationSession 一批后重审
  topic_context            # 暂时保留，同上
```

`generation_options` 仍作为 Alice 路由的独立参数，本批不并入清单。

### 4.3 进程：CPU 分配与编译

`TaskProcessService` 在进入 Alice 之前执行 CPU 分配。分配期间仍处于 `PREPARE` 阶段（不新增阶段取值）：

1. **Profile**：经 `PATCHOULI_GET_AGENT_PROFILE` 以 `identity.agent_id` 与冻结的 `identity_scope` 解析，取 `.profile`。实施评审时（2026-09-29，owner 决定）改为在 Gateway 之后、prepare 之前解析，作为中间态：prepare 会按路由决定预先新建 Topic，话题池已满时还会先按 LRU 结算一个已有话题，若 Profile 在 prepare 之后才失败，失败的请求会留下这些不可逆的副作用。Topic 的新建与驱逐改到 interaction 提交之后以后，Profile 可以回到 prepare 之后；
   以下 2–5 在 prepare 之后执行；
2. **附件**：逐项 `acquire_ready_representation` 并核对 `representation_id`、`revision`、`content_hash`，不一致时释放该租借并抛出 `AssetOperationConflictError`（从 Patchouli 原样迁移）；租借登记进进程工作集；
3. **编译**：`AttachmentCompiler.compile(leases)` 得到附件文本与实际用到的附件；`MemoryCompiler.compile(memories, RETRIEVAL_CONTEXT, retrieval_strategy_config)` 得到记忆文本，检索为空时为空字符串（与现状相同）；
4. **清单**：组装 `CPUInputManifest`；
5. **前导事件**：分配成功后，流式路径依次发出 `topic_info`（`topic_id`、`is_new`、`pool_topics`）与 `memory_refs`（原 `_memory_ref_from_atom` 投影迁入进程）。分配失败时不发出，与现状“prepare 失败时不发出”一致。

进程工作集（`workspace/process/working_set.py`，新增）持有本进程的 `PreparedAgentRun`、输入清单与附件租借，并提供幂等的资源释放方法：逐项释放租借，Store 关闭等 `WorkspaceDomainError` 只记录警告。编排服务在 `finally` 中调用它，覆盖完成、取消、失败、断流与分配失败各条路径；finalize 收到的 `used_attachments` 来自附件编译结果。

Profile 缺失时在 prepare 之前失败，不触发 prepare 与 cleanup。其余分配失败（附件不可用或版本不一致、编译失败）沿现有异常路径处理：`finally` 先同步释放已取得的租借，再请求 Patchouli cleanup 以清理 prepare 预创建的空话题；释放不依赖 cleanup 等 `await` 完成（实施评审时补充：owner task 在这些 `await` 期间被取消时，释放与进程记录的关闭仍须执行）。

### 4.4 取消

按 Q-15，取消只在进入 Alice 之前检查一次。现有“prepare 返回后立即检查”的位置移到 CPU 分配完成之后、进入 Alice 之前：prepare 与分配期间收到的停止请求都在此生效，此前的分配工作照常完成，取得的租借在 `finally` 中释放。Gateway 与 Alice 阶段的可中断行为、finalize 拒绝取消都不变。

### 4.5 Alice：接收输入清单

- `ALICE_RUN_AGENT` / `ALICE_RUN_AGENT_STREAM` 的参数 `agent_run_context` 改为 `input_manifest: CPUInputManifest`；`AgentRunService.run_agent` / `run_agent_stream` 同步修改。
- Alice 在内部把清单转换为 `AgentRunContext`（`interaction_id` 取 `process_id`，`retrieval_result` 由 `memories` 构造），用于预检索 alias 登记、提示词组装、根 frame 与运行事件，其余逻辑不变。
- `AgentRunContext` 留在 `core/protocol`，因为 L2 的提示词组装需要它；它不再出现在任何 Patchouli 路由上。`attachment_compile_result` 字段改为 `attachment_context: str`，提示词组装随之修改（附件 section 的位置不变）。

### 4.6 依赖与装配

- 组合根把 `workspace_asset_store`（作为 `WorkspaceAssetReaderPort`）、`memory_compiler` 与 `attachment_compiler` 配置段注入 `TaskProcessService`，不再把后两者与 asset reader 交给 `PatchouliService`。
- `workspace.process` 新增对 `engines.memory_compiler`、`engines.attachment_compiler`、`core.ports` 的依赖，符合分层规则（L3 → L2/L0）。
- Alice 导入 `workspace.contracts`，符合“L3 子系统之间只导入对方 contracts”的规则。
- `tests/unit/workspace/test_import_boundaries.py` 新增规则：`workspace.contracts` 只导入 `hivememory.core`，不导入 workspace 的其他模块。

## 6. 兼容与迁移策略

- 路由参数与模型字段直接修改，不保留别名或转发；所有调用方在同一批内更新。
- 对外行为保持不变（第 2 节目标 6），由现有测试断言与第 8 节新增测试守护。
- 附件租借的释放时点：正常完成时，现有实现在交互 applied 后由 finalize continuation 释放；本批改为在进程 `finally` 中释放，而 finalize 现在仍等到 applied 才返回，所以正常路径时点相同。唯一的差异是 finalize 期间客户端断开：进程被取消，租借随即释放，而交互仍由 Patchouli continuation 继续应用。这符合 Q-1 已决定的“租借随进程关闭释放”，Artifact promotion 自行取得内容，不受影响。
- 回滚：一批一个提交序列，整体回退即可。

## 8. 测试和验收标准

测试遵循[测试设计规范](../governance/testing/test-design-standards.md)。

**迁移与调整的测试**：

- `tests/unit/patchouli/test_prepare_attachments.py` 的场景迁到 `tests/unit/workspace/process/`，由进程承担：按用户顺序取得租借；版本摘要不一致时抛出 `AssetOperationConflictError` 并释放已取得的租借；未知 ref 与已移除的资产被拒绝且不泄漏租借；Store 关闭时释放租借只记录警告。原有的“finalize 失败的 continuation 仍释放租借”“未经 finalize 的 cleanup 释放租借”两个场景，改为验证进程结束时释放（新增测试 3）；
- `tests/unit/patchouli/test_phase3f_gateway_decision.py`、`tests/integration/patchouli/test_active_interaction_submission.py`、`tests/unit/patchouli/runtime/test_core.py`：按精简后的 `PreparedAgentRun` 与 finalize 签名调整；
- `tests/unit/alice/application/test_agent_run_service.py`、`tests/integration/alice/application/`：改为传入输入清单；
- `tests/unit/prompts/test_attachment_section_order.py`、`test_message_assembler.py`：随 `attachment_context` 调整，断言不变；
- `tests/unit/workspace/process/` 现有测试中的 prepare 替身、`tests/unit/workspace/capability/test_agent_profiles.py` 与 `test_memory.py` 中构造 `PreparedAgentRun` 的辅助函数、`tests/integration/system/test_workspace_asset_chat_selection.py`、`tests/unit/system/contracts/test_public_routes.py`、`tests/unit/system/test_lifecycle.py`：随签名调整。

**新增的行为测试**（`tests/unit/workspace/process/`，Patchouli 与 Alice 以总线路由替身隔离）：

1. CPU 分配经 `PATCHOULI_GET_AGENT_PROFILE` 解析 Profile，清单中的 `agent_profile` 即其结果；Profile 解析失败时进程以错误结束，不发出 `topic_info`，并请求 cleanup；
2. 清单中的 `memory_context` 是进程对 prepare 返回的检索结果编译得到的文本，`memories` 为原始原子；检索为空时 `memory_context` 为空字符串；
3. 附件租借在每条结束路径上都被释放：完成、Alice 前取消、Alice 失败、分配失败；以真实的 `InMemoryWorkspaceAssetStore` 观察租借状态，不断言私有字段；
4. finalize 收到的 `used_attachments` 等于附件编译结果中实际用到的附件；被预算跳过的附件不在其中；
5. prepare 或分配期间收到的停止请求在进入 Alice 前生效：Alice 与 finalize 均未调用，cleanup 被调用，租借已释放。

**Patchouli 侧**：prepare 返回的 `PreparedAgentRun` 不含 Profile、租借与编译文本；公开路由签名中不再出现 `AgentRunContext`、`StreamPrelude`（`tests/unit/system/contracts/test_public_routes.py` 增加断言）。
