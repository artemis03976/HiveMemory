# v0.7.0 A2：Workspace 资源读取、Runtime 与派生缓存

Profile cache 和 Atom cache 当前作为 Alice 客户端缓存，由 AliceRuntime 创建和清理，resolver 在命中时独立返回结果。失效缺口的直接原因是协作围绕消费路径建立，没有覆盖全部 canonical mutation；只移动实例并不能解决这一问题。v0.7.0 将它们转为 Patchouli 共同读取链内部使用的资源缓存，A2 同时交付完整 MemoryAtom 的 canonical 读取与 Profile 定义读取契约，并把缓存基础设施聚合到一个进程级 `WorkspaceRuntime`；后续消费者迁移负责退出 Alice 的独立命中路径。Patchouli canonical 数据、Topic 状态和业务 API 不迁入 WorkspaceRuntime。

调查与既有决定见[WRX-0 清单](./v0.7.0-plan-a-wrx0-boundary-freeze.md)第 1–5/8 节；主要迁移源为 `alice/runtime/profile_cache.py`、`agent_runtime/aliases/cache.py` 和 `alice/runtime/core.py`，AssetStore 保留 `system/runtime/workspace/store.py`。前置成果是 A1 的已验证 scope/授权规则，以及 [A2-P 记忆内容版本与 Lifecycle 状态重构](./v0.7.0-a2-pre-memory-version-and-lifecycle.md)交付的完整原子、历史记录与受控 mutation。A2 消费这些稳定数据/写入契约，在本计划内冻结并实现 canonical/Profile 读取路由和缓存协作，不借用后续 API 收敛计划的约定。Session、共享 Pending、外部 wire 和生产消费者切换不属于本计划的验收前置。

本计划承接原 A2 已开展的读取契约工作与原 A3 的缓存计划，因此标记 Active；该状态不表示新增缓存迁移已经实施或通过验收。

2026-09-20 缓存语义修订：两个 cache 按 Workspace 与资源引用共享，不按 Actor 分区；Atom cache 保存完整 `MemoryAtom`，供 `MemoryCompiler` 编译。公共 application 沿用 A1 的 access 有效性与 operation 检查，缓存命中后由 Patchouli 执行资源可见性授权，不重复 Workspace authentication，也不逐次回源读取 policy/revision。当前性由受控写入的同步更新/失效与 epoch 保证。本修订替代本计划及 WRX-0 中相反的旧约定，详细规则集中在第 2 节；其他已识别的接口、迁移和生命周期待决项仍由 A2-0 冻结。

2026-09-20 mutation 补充修订：A2-P 为本计划新增的硬前置。`meta.version` 只表示内容修订，动态状态归 `meta.lifecycle`；lifecycle 维护不得重写原子内容或向量，不生成内容版本。完整历史和 schema 迁移先由 A2-P 完成，A2 只接入其同步变更协作；不再保留裁剪 MemorySnapshot，也不把所有 metadata 更新统一处理为 Atom/Profile 全量失效。A2 的 Active 保留既有工作状态，不表示此前缺失的前置工作已完成。

## 1. 目标和边界

WorkspaceRuntime 组合 access context 所需的基础设施、Profile/Atom 资源缓存、失效、epoch、Asset lease facade 和关闭生命周期。它不保存可变 `current_workspace`，不按 Workspace 创建 Runtime，不导入 Alice、MTP 或 Patchouli 私有 provider，不提供 `get_memory`/`search`/`submit` 等领域方法。

| 状态 | canonical owner | Runtime 责任 |
|:---|:---|:---|
| Memory/Profile | Patchouli | 保存完整原子及可重建的 Profile 解析结果、key、epoch、失效；资源授权由 Patchouli 执行，当前性由领域写入与缓存协作保证 |
| Topic/working set | Patchouli Perception | 不复制状态；由其领域 application 管理 |
| WorkspaceAsset | System AssetStore | scope-aware resolve/acquire/release facade |
| Pending | Patchouli 资源侧领域 | 不当作 cache、不复制状态机；本计划只交付 canonical 读取 |
| run/frame/history | Alice | 不进入 WorkspaceRuntime |

生产 SystemAssembler 的改动不是 A2-0 的前置条件；独立组合和真实 application 链可先验证，A6 再完成稳定装配。

### 1.1 ADR-0004 冲突裁定与适用范围

2026-09-17 裁定：**v0.7.0 采用资源侧共同读取与通用缓存，两个 cache 不再属于 Alice；统一引用解析同样退出 Alice。** 这是本版本已选定的实施方向，不再把“保留 Alice 所有权或迁入 WorkspaceRuntime”列为待决。ADR-0004 继续记录 v0.6.2 已落地的客户端缓存基线；它的所有权结论不作为本版本目标设计的否决依据。

冲突来自两轮设计采用不同判据：早期按“需要 Workspace key”推导所有权，ADR-0004 又按“当时只有 Alice 消费”确定执行侧归属。前者只能说明寻址方式，后者只能解释当时的调用关系。稳定判据应是派生结果依赖什么、谁改变其有效性、删除它是否丢失权威状态，以及更换 Actor 后哪些语义必须保留。通用资源缓存依赖资源版本和访问策略，失效源覆盖管理、生成与生命周期路径，因此与资源读取共同维护；run/frame 和实际执行配置仍属于 Actor。

| ADR-0004 原决定 | v0.7.0 处理 | 原因与承担方 |
|:---|:---|:---|
| 第 1 条：两个 cache 归 Alice，WorkspaceRuntime 解体 | 替换这一具体归属；采用单一 WorkspaceRuntime 聚合 | 缓存从 Alice 客户端加速转为资源读取内部加速，不能只换构造位置 |
| 第 1 条及 Consequences：Pending 与 cache 同属执行路径状态 | 不沿用这一分类 | 权威 Pending 意图与 Alice 执行关联应分开；Pending 不可作为可淘汰缓存处理 |
| 第 2 条：System 只拥有跨子系统事实源 | 保留 AssetStore 所有权，收窄“只拥有”的概括 | System 可装配派生基础设施；实例持有不转移 Patchouli 的领域责任 |
| 第 3 条：按派生源 Workspace/授权坐标键控 | 保留 Workspace 分区，替换 Profile 的 Actor 授权坐标 key | 两个 cache 均按 Workspace 与资源引用共享；Actor 仅参与逐次资源授权，不进入 key |
| 第 4 条：分区不替代授权 | 保留并补足当前性 | Patchouli 对命中原子执行当前 Actor 的资源可见性判断；policy 与内容的当前性由受控写入同步失效保证，不逐次回源重验 |
| 第 5 条：生命周期随所有者，Alice stop 清 cache | 保留原则，替换 Alice 清理责任 | A2/A6 按资源服务生命周期 drain/close；停止 Alice 不关闭其他 Actor 使用的缓存 |
| 第 6 条：拒绝无 scope 访问，保留观测 | 保留行为要求 | 内部 cache 校验与公共访问错误分别遵循其契约，不要求外部协议暴露 Python TypeError |

“Workspace-owned 资源”“领域责任”“运行时持有/装配”分别表达数据归属、业务权威和实例生命周期。Workspace 资源体系包含 Patchouli、System 资源服务与共享基础设施，不要求全部对象进入 WorkspaceRuntime。此聚合用于明确组合和关闭边界，不需要增加业务转发方法证明其价值；也不能反过来导入 Alice 内部加速器或 Patchouli 私有 provider。通用 bus/queue 等保持进程级骨架，资源缓存按来源分区，无需再声明“共享基础设施分区特例”。

### 1.2 解析、缓存和执行的交接

| 责任 | 实施位置 | 明确边界 |
|:---|:---|:---|
| canonical 引用定位、资源可见性、完整原子读取 | Patchouli，本计划 | 对外只有一条 canonical 领域读取链；不放入 WorkspaceRuntime |
| Profile 定义查找、类型/内容解析、builtin 规则 | Patchouli，本计划 | 返回定义快照，不组装完整 system prompt |
| cache 存取、索引、epoch、容量、失效、close | WorkspaceRuntime，本计划 | 不决定 Pending 状态、不执行 Profile 解析、不持有授权许可 |
| Pending 意图与结算解析 | Patchouli 的后续领域扩展 | 复用这里的 canonical 读取；不成为本计划完成条件 |
| run-local 引用、Profile 应用、prompt/模型/工具配置 | Actor adapter/runtime | 不直接查询通用缓存；运行输入快照不成为后续资源读取的成功来源 |

### 1.3 canonical 读取、快照与公开路由

本计划直接复用并完善 `patchouli.public.memory.read/retrieve_by_aliases`、管理 Memory 读取与 `get_agent_profile_snapshot` 等已有 application 路由，完成 access 传播、方法的 operation 绑定、中立输入输出和真实总线验证。公共方法由 Patchouli application 按领域提供；不等待后续统一 API 目录再发布，也不新增 Workspace 读取 service 或 provider。access 来自 A1 统一认证网关，有效期间可复用，各读取方法分别检查行为许可；管理读同时满足管理 operation 和资源 owner 的管理 policy，普通资源读不得取得 owner bypass。

输入是 A1 access 与 canonical alias/UUID/ref，不要求 `MTPExecutionContext`、Alice run 或 RuntimeScope。alias 和 UUID 均在可信 scope 指定的 Workspace 内定位，缓存写入前校验原子归属与分区一致；命中后只按当前 Actor 执行资源可见性授权，不再次调用 Workspace 准入。canonical Memory 读取返回完整 `MemoryAtom` 的独立副本，保留编译所需的 index、meta、payload、artifacts 和 history 等字段，不暴露缓存内部共享可变引用。冷读和缓存命中必须具有相同的领域结果和错误语义。未知、不可见、scope 冲突和 unavailable 的对外结果由本计划按 A1 冻结，不回退到其他 Workspace 或过期成功值。

`ProfileSnapshot` 继续表达定义读取的 builtin/source atom UUID/revision，裸 Profile 仅在兼容窗口内作为投影；该 API 结果不替代缓存中的完整源原子，也不是资源授权凭证。裁剪型 `MemorySnapshot` 及相关导出由 A2-P 删除，本计划不保留“其他用途待评估”的选项，不能为接入缓存先把完整原子裁剪后再重建。完整原子与历史结构由 A2-P 维护，缓存使用的版本依据见第 2.1 节。READ、RUN、UPDATE 和 Profile 类型读取可以复用已提交资源事实，但读取成功不授予执行、修订或身份切换权限。

这里只冻结 canonical 完整原子与 Profile 定义读取的基础契约，不提前定义 Pending 的状态联合结果。后续扩展须保持 canonical 行为并承担新增结果类型的兼容；在本计划支持范围内，无法识别或不支持的引用明确拒绝，不猜测为同名 canonical。批量读取的逐项结果、已有方法的签名兼容和删除窗口在 A2-0 记录。

### 1.4 Profile 定义读取与执行配置应用

当前 Patchouli `services/retrieval.py::get_agent_profile_snapshot()` 已承担 builtin/alias/type/内容解析，Alice `runtime/profile_resolver.py` 主要重复 builtin 判断并做缓存/总线/错误适配，完整 system prompt 则在 `prompts/assembler.py::AgentPromptAssembler` 组装。目标沿这条职责分界收敛，不把“Profile resolver 是否移走”处理为整个类的机械搬迁。

| 责任 | 唯一承担方 | 输出/限制 |
|:---|:---|:---|
| Profile 资源查找、类型检查、定义解析、builtin 规则 | Patchouli Profile API | ProfileSnapshot 与 source identity/revision；Root/CALL/外部读取一致 |
| 定义缓存和失效 | A2 基础设施，由 Patchouli 内部使用 | 源 MemoryAtom 与可选解析结果按 Workspace 共享并关联失效；不缓存 Actor 授权结论、完整 prompt、运行上下文、模型客户端或工具实例 |
| 选择 Profile、绑定实际模型/工具、应用执行限制 | 对应 Actor runtime/adapter | 本次运行的实际配置；读取 Profile 不等于获得其描述的权限 |
| persona、MTP、记忆、附件、Topic 等 prompt 拼装 | Alice AgentPromptAssembler 或外部执行器自己的实现 | 接收能力与拼装策略由执行器决定，不成为 Patchouli 读取职责 |

`AgentProfile` 当前含 `model_name`、`allowed_mtp_verbs`、`allowed_sys_tools` 等运行环境相关字段。v0.7.0 保留资源定义及已有 Alice 解释，不承诺每个外部 harness 都能执行这些配置，也不为此引入通用 harness 配置框架。外部读取定义是一项可选操作；外部接入的最低要求是共同记忆 API，不要求加载 Profile 或接收动态 system prompt。

例如同一 `researcher` 定义，Alice 可应用 persona/模型/工具限制并组装 prompt；支持指令配置的外部 harness 可由 adapter 映射其支持的字段；无法修改 system prompt 的 harness 仍可搜索、读取、写入和自动提交交互。若请求“应用 Profile”，adapter 必须区分已应用、部分支持和拒绝，不把读取成功或普通工具返回文本等同于 system prompt 已生效；无法落实的强制执行限制必须拒绝相应应用请求，不能静默忽略。权限由实际服务/执行边界落实，Profile 不能自行扩大 Workspace 中的行为或资源权限。

Profile 定义更新后，后续资源读取必须使用当前授权和版本；已经启动的 run 可以固定启动时取得的配置快照和来源版本。资源 cache 失效不隐式热更新本轮配置，固定快照也不免除后续资源操作的当前授权。v0.7.0 不新增运行中 Profile 热加载协议。此处交付定义读取及执行侧应遵守的限制；真实 Actor 配置应用和外部协议映射是后续消费者工作，不作为本计划完成条件。

## 2. Cache 契约

缓存用于把高频资源的 alias/UUID 定位从存储查询转为平均 O(1) 的内存查表。当前冷读来自向量数据库；未来若实现长期记忆本地存储读取，可在同一领域边界扩展，但不是本计划已实现能力。语义 SEARCH 仍执行检索，检索结果可由 Patchouli 内部协作预热 Atom cache，后续 READ/RUN 等按引用访问复用完整原子；缓存不替代语义搜索。完整对象复制和编译的成本仍随内容大小变化，O(1) 仅指缓存索引查找。

两个 cache 的资源 key 均基于 `(WorkspaceIdentity, normalized_alias/ref)` 或 `(WorkspaceIdentity, UUID)`，不包含 Actor 的 user/agent/team/session 投影；WorkspaceIdentity 自身的 owner 坐标仍保留。同一 Workspace 的多个 Actor 复用同一资源条目，每次返回时分别授权。UUID 可作为内部索引，但所有读取必须带 Workspace 坐标，不提供跨分区的成功旁路。

Atom cache 保存完整 `MemoryAtom`，其 ownership、access_policy、source revision 与 provenance 使用原子内已有字段，不另建精简快照或第二套来源记录。写入和对外返回均隔离可变对象引用，调用方不能借修改返回值改变缓存或后续授权结果。此处的 copy-on-read 指完整原子副本，不是字段裁剪；它可直接交给现有 `MemoryCompiler`。

Profile 的正式资源同样是 `MemoryType.AGENT_PROFILE` 的完整原子。Profile cache 不按读取者复制条目，也不能仅保存曾经通过授权的裸 `AgentProfile` 并直接返回。若保留解析缓存，它只是源原子的共享解析结果；源原子由 Atom cache 持有即可，不要求两个 cache 各存一份独立原子。使用解析结果前必须取得有效源原子并检查其可见性，源条目失效或缺失时不能靠解析结果独立返回成功。builtin Profile 继续由 Patchouli 的显式规则处理，不伪造 source atom。

### 2.1 版本依据与历史决定修订

版本与数据结构消费 [A2-P 第 3–5 节](./v0.7.0-a2-pre-memory-version-and-lifecycle.md#3-数据模型与不变量)：`meta.version` 是内容修订序号，`meta.updated_at` 是内容最后修订时间，动态状态在 `meta.lifecycle`；它们不是整个对象的变化标记或乐观锁。`ProfileSnapshot.source_revision` 仍取 source atom 的内容版本，不拆配置 revision，不新增 provider DTO。同版本原子可以具有不同的 lifecycle 或 policy，不能按版本相等跳过状态/授权依据更新。历史中的 lifecycle 只是捕获时状态，不能覆盖当前缓存状态；本计划不引入历史版本 cache。

2026-09-20 明确替代 WRX-0 第 8 节第 7 项的“缓存命中同步回源 revalidation”，并撤回第 1 项将裁剪型 MemorySnapshot 作为缓存主体的推导。正常命中不通过数据库查询证明当前性，也不查询历史 Artifact 比较版本。

当前性由所有受支持的 canonical 写入路径同步更新/失效缓存来保证，包括 policy、alias、metadata、内容、删除和归档等变化，即使 `meta.version` 未增加也必须处理。epoch 是运行时失效代次，不是新的持久化业务 revision。无法确认缓存有效性时禁用受影响命中，转入受控冷读或明确失败；不能把每次回源作为正常命中流程，也不能用 TTL 代替写入一致性。保证范围是经过受控提交路径的写入，不包含绕过系统直接修改底层存储；引入其他写入者时须先接入相同一致性约定。

缓存维护按变更实际影响执行：lifecycle 更新同步刷新完整 Atom 中的状态，保持内容版本、alias 和未变化的 Profile 解析结果；policy 更新替换源原子的授权依据；内容修订更新/失效受影响的内容与解析结果。缓存接收资源所有者已协调的提交结果，不能用调用方旧副本合并回最新状态。不能可靠更新时使 Atom 失效，此时 Profile 解析结果也不能脱离有效源原子独立返回。所有可见变更都参与防止旧回填的 epoch 协作，但 epoch 推进不等于必须淘汰所有派生值。

### 2.2 两个 cache 的行为表

| 维度 | 必须满足的行为 |
|:---|:---|
| 共享内容与资源授权 | 两个 cache 按 Workspace 与资源寻址；Patchouli 用有效源原子的 policy 对当前 Actor 授权，不缓存授权结论，不重复 Workspace authentication |
| 完整对象与编译 | 缓存完整 MemoryAtom，返回独立完整副本；调用方修改不污染缓存，MemoryCompiler 可直接编译 |
| lifecycle 状态变化 | 同版本同步刷新完整 Atom 的 lifecycle，不重写内容、不重新计算 embedding、不无故淘汰 Profile 解析；现时 vitality 计算仍归领域维护，不由 cache 自行启动 |
| alias 替换 | 维护 alias→UUID 及反向引用，同一资源多个 alias 的替换/删除不留下可返回的旧值 |
| 并发冷读取 | 可合并同资源 key 请求，但不合并各 Actor 的授权结论；读取前记录 epoch，返回后代次已变则拒绝旧值回填与成功返回，重新取得有效值或明确失败 |
| 负缓存 | 不缓存 Actor 不可见/无权限结果；它们不能污染 Workspace 共享条目。只有能确认 Workspace 内资源确实不存在时，才可按资源 key/epoch 有界短暂保存；底层把缺失与不可见合并为 None 时不得据此写共享负缓存。首版是否启用仍在 A2-0 冻结 |
| 失败 | cache 故障不回滚 canonical 变更；必要时 no-cache/失败关闭，不以旧授权数据伪装成功。有效命中不探测存储可用性；存储故障影响实际需要冷读的请求，不为保持错误一致而强制命中回源 |
| close | 停止新读，处理已在途请求的完成/失败，清理仅属于 cache 的派生值；不删除 Pending/Session/canonical |
| 容量与观测 | 可保留全局 LRU，冻结容量及启用负缓存时的 TTL；记录 hit/miss/cold read/invalidation/stale reject/资源授权拒绝/close 拒绝，不承诺 Workspace 独立配额 |

### 2.3 读取与授权顺序

```text
公共 application 检查 access 有效性与该方法的 operation
  -> 从可信 scope 取得 Workspace 分区及当前 Actor
  -> Patchouli 内部按 Workspace + alias/UUID 查 cache
       命中有效条目：不回源查询 policy/revision
       未命中/已失效：读取 canonical、验证资源归属、核对 epoch 后回填
  -> Patchouli 按原子的 MemoryAccessPolicy 检查当前 Actor 可见性
  -> 返回完整 MemoryAtom 的独立副本，供 MemoryCompiler 等消费者使用
```

冷读路径可沿用存储 adapter 的资源授权；任何共享冷读结果在交付每个调用者前都须满足其各自 policy。管理读取继续采用 A1 已冻结的独立 operation 与 owner-management 规则，不因共享条目给普通 Actor 授权。Profile 定义 API 复用内部原子读取与授权协作，不递归请求公共 Memory API，也不要求持有 `profile.read` 的调用方额外取得 `resource.read`。

Workspace authentication 已由 A1 网关完成；application 的逐次 access/operation 检查照常保留，cache 不持有 CallerPrincipal，不调用认证网关。原子 ownership 在冷读及缓存写入时验证，后续分区寻址保持该不变量；这属于资源归属约束，不是对 Actor 再次执行 Workspace 准入。cache 只提供存取、索引、epoch 和失效，不接收全局路由或 Patchouli provider 负责冷读取，不形成 application → Workspace service → application 递归。

## 3. 失效、生命周期和装配

Memory 的四类 mutation 复用 [A2-P 第 6 节](./v0.7.0-a2-pre-memory-version-and-lifecycle.md#6-交付给-a2-的变更协作契约)的受控提交与同步协作点；A2 接入 cache 更新/失效和 epoch，不复制内容提交、lifecycle 更新或历史写入逻辑。Memory create/update/delete/archive/revive、当前 generation/materialization 提交、Profile source/policy 变化均须覆盖，Asset representation revision 继续遵循自身 lease 契约。RuntimeEvent 可作为观测，但事件投递失败不能成为正确性的唯一保障。单个 run 完成不清理资源 cache；Alice stop 不关闭 WorkspaceRuntime。

关闭顺序是停止接纳、等待 resource read/settlement、drain producers、detach consumers、关闭 cache/Asset/Patchouli。A2 完成 Runtime 局部生命周期的实现与独立验证；A6 负责把它接入完整 System composition。

| canonical 变更源 | 同步更新或失效覆盖 |
|:---|:---|
| Memory 管理 create/update/delete、archive/revive | 完整 Atom 条目、alias 正反索引、引用该 source 的 Profile 解析结果 |
| generation/materialization/settlement | A2-P 的内容与完整历史提交成立后同步推进 epoch，更新/失效对应 Atom 与受影响的 Profile；不以 settlement 通知替代 canonical 提交协作 |
| source visibility/policy 改变 | 同步替换完整源原子的 policy，后续读取据新 policy 授权；定义未变化无需重解析，源原子无效时解析结果不能独立返回 |
| Profile payload 等内容改变 | 使用新内容版本，更新/失效完整源原子及受影响的解析结果 |
| feedback/citation/访问统计/活力刷新等 lifecycle 更新 | 经 A2-P 局部提交同步更新完整 Atom 的 lifecycle；不增内容版本、不影响 alias，解析输入未变则保留 Profile 结果；不能安全更新时失效源原子 |
| Asset representation 变化/remove | 禁止旧 revision 获得新 lease；已有 lease 按 W1 生命周期处理，不擅自使持有者悬空 |
| 调试/测试/内部管理 mutation | 通过同一 owner 提交和失效协作，不直改私有字典 |

原清单只调查到 Alice settlement 和 MTP UPDATE 两条失效路径；A2 消费 A2-P 已核对的当前写入者清单，覆盖所有受支持的 canonical mutation，不只移动这两个调用点。后续新增或迁移的 mutation 必须复用已交付的受控提交与缓存协作契约，其接入测试由引入该路径的计划承担，不反向阻塞 A2。同步更新/失效失败时必须明确读侧如何禁止旧命中，不能仅输出日志继续返回旧值。

正式写入成功返回前，实际受影响的缓存值/索引必须已经更新或失效，并推进相关 epoch；新开始的读取不能再命中提交前的内容、policy 或已更新的 lifecycle 字段。未变化的 alias 和 Profile 定义不因状态更新而重建。在途旧冷读即使晚到，也不能越过代次检查重新回填。内容/历史提交的失败语义由 A2-P 冻结；canonical 已提交而缓存协作失败时，不能继续把旧缓存当作有效值，也不能假称 canonical 已回滚。缓存禁用范围与恢复条件、提交中取消及并发交错的读侧处理在 A2-0 冻结，并消费 A2-P 的提交结果。内存事件只用于观测，不承担这项正确性保证。

## 4. 实施与验收

| 阶段 | 产出 | 验收 |
|:---|:---|:---|
| A2-0 | 核对 A2-P 完成交付；按第 1–2 节冻结 canonical/Profile 签名、operation、兼容及 cache 更新/失效、Asset、close 契约 | 消费已稳定的完整原子/schema 与 mutation，不重定版本或 lifecycle；细化缓存读写时序与失败处理，不等待后续 Pending 或 API 目录 |
| A2-1 | canonical/Profile 公共路由、定义解析与 Profile/Atom cache 迁移 | 无 Alice/MTP 可读取并编译完整原子；builtin/type/source 一致；两 Workspace 隔离；同 Workspace 不同 Actor 共享条目但分别授权；有效命中不触达存储 |
| A2-2 | 当前受控 mutation 的缓存协作接入和独立组合验证 | 内容/策略/可读性变化正确更新或失效；lifecycle 同版本刷新、Profile 未变则保留；Asset lease 遵循原契约；旧 fetch 不回填；删除 cache 不改变领域结果 |
| A2-3 | 完整原子/Profile 定义读取与失效交付记录、旧 cache 委托与消费者退出清单 | 本计划真实公共读取可用，只有一份正式可命中 cache；旧消费者删除及最终生产装配另由 A6 验收 |

unit 覆盖资源 key normalization、完整原子 copy-on-read、alias replacement、epoch race、错误和 close。integration 使用真实 application + A2-P 受控提交 + canonical + cache，并由真实 MemoryCompiler 验证冷读与命中原子的编译结果一致；同时验证调用方修改副本不影响后续内容和授权、同 Workspace 两个 Actor 共享一次加载但获得各自可见性结果、拒绝结果不污染其他 Actor、有效命中不回源读取，以及 lifecycle/policy 未推进内容 version 时仍能更新读取结果。生命周期更新后 alias 与 Profile 定义仍可复用，在途旧原子不得覆盖最新状态；内容更新不得回退同期累计的 lifecycle。完整历史与 schema 的持久化证据复用 A2-P，不在这里重新实现。覆盖无 Alice、两 Workspace 隔离、cache hit、存储故障、更新/失效失败和 shutdown drain；管理员修改 Profile 后下一次共同读取不得返回旧定义。不得用私有字典、re-export 或转发次数作为完成证据。本计划以 canonical/Profile 路由、完整原子与定义读取、当前 mutation 的缓存协作和 Runtime 独立生命周期证据完成验收；Pending 分派及后来新增的 mutation 接入由引入方验证，不作为本计划的遗留待验收项。

## 5. 迁移与收口

旧 cache 属性可以短期委托，但 A2-1 后不允许 Alice 和 Workspace 同时作为成功来源；兼容直接访问仅属于尚未切换的旧链路，不算共同读取验收通过，A6 必须删除。双写只用于观测对比。若出现授权/一致性回归，回滚旧 adapter 仍使用统一 access 和单一 cache，不把资源状态复制回 Alice。Memory/schema 与历史迁移由 A2-P 完成；A2 的缓存回滚不能回退已经迁移的数据格式或重新引入 lifecycle 整原子 upsert。跨进程 cache 恢复与 Workspace 配额另立计划。

本计划第 1.1 节是 v0.7.0 替代裁定的唯一理由源；旧 WRX-0 调查和 v0.6.2 归档不追改为新结论。ADR-0004 当前保留 accepted 基线状态和适用范围链接，不把未完成实现写成已生效事实。本计划完成不等于所有旧 Alice 路径已经退出；以下是交付给版本收口的事项，不是本计划完成门禁：A6 验证共同读取、Pending 解析、所有消费者切换及资源生命周期，并进入稳定收尾后，依据最终实现建立后继 ADR，明确继承第 3 条的 Workspace 分区及第 4/6 条原则、替换第 3 条的 Profile Actor key 和第 1/2/5 条的相关范围，再将 ADR-0004 标为 superseded 并双向链接；不预占 ADR 编号。此时同步 Workspace、composition、Alice 与公共契约事实文档。

目录按已冻结方向落到 `workspace/runtime.py`、`workspace/cache/{keys,atom,profile}.py` 与基础设施协议；已有 AssetStore 原地保留。无需为组织目录创建空服务类；`workspace/services` 若保留，只能承载失效/lease/cache 协作。主要未决项是 canonical/Profile 具体签名与兼容、负缓存是否启用及窗口、容量、close 的在途行为和失败时禁用旧值的机制，在 A2-0/1 冻结；不得重新把 Actor 放入资源 key、用裁剪投影替代完整原子，或把逐次回源作为正常命中实现，也不把性能调优或固定 TTL 变成跨计划前置。
