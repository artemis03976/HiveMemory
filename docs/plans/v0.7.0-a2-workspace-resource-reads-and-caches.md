# v0.7.0 A2：Workspace 资源读取、Runtime 与派生缓存

Profile cache 和 Atom cache 当前作为 Alice 客户端缓存，由 AliceRuntime 创建和清理，resolver 在命中时独立返回结果。失效缺口的直接原因是协作围绕消费路径建立，没有覆盖全部 canonical mutation；只移动实例并不能解决这一问题。v0.7.0 将它们转为 Patchouli 共同读取链内部使用的资源缓存，A2 同时交付 Patchouli 的 canonical/Profile 公共读取及快照契约，并把缓存基础设施聚合到一个进程级 `WorkspaceRuntime`；后续消费者迁移负责退出 Alice 的独立命中路径。Patchouli canonical 数据、Topic 状态和业务 API 不迁入 WorkspaceRuntime。

调查与既有决定见[WRX-0 清单](./v0.7.0-plan-a-wrx0-boundary-freeze.md)第 1–5/8 节；主要迁移源为 `alice/runtime/profile_cache.py`、`agent_runtime/aliases/cache.py` 和 `alice/runtime/core.py`，AssetStore 保留 `system/runtime/workspace/store.py`。唯一计划前置是 A1 的已验证 scope/授权规则。Profile/Memory 快照、读取路由和缓存协作在本计划内一起冻结并实现，不借用后续 API 收敛计划的约定。Session、共享 Pending、外部 wire 和生产消费者切换不属于本计划的验收前置。

本计划承接原 A2 已开展的读取契约工作与原 A3 的缓存计划，因此标记 Active；该状态不表示新增缓存迁移已经实施或通过验收。

## 1. 目标和边界

WorkspaceRuntime 组合 access context 所需的基础设施、Profile/Atom snapshot cache、失效、epoch、Asset lease facade 和关闭生命周期。它不保存可变 `current_workspace`，不按 Workspace 创建 Runtime，不导入 Alice、MTP 或 Patchouli 私有 provider，不提供 `get_memory`/`search`/`submit` 等领域方法。

| 状态 | canonical owner | Runtime 责任 |
|:---|:---|:---|
| Memory/Profile | Patchouli | 保存派生 snapshot、key、epoch、失效；当前授权/新鲜度的判定由 Patchouli 执行 |
| Topic/working set | Patchouli Perception | 不复制状态；由其领域 application 管理 |
| WorkspaceAsset | System AssetStore | scope-aware resolve/acquire/release facade |
| Pending | Patchouli 资源侧领域 | 不当作 cache、不复制状态机；本计划只交付 canonical 读取 |
| run/frame/history | Alice | 不进入 WorkspaceRuntime |

生产 SystemAssembler 的改动不是 A2-0 的前置条件；独立组合和真实 application 链可先验证，A6 再完成稳定装配。

### 1.1 ADR-0004 冲突裁定与适用范围

2026-09-17 裁定：**v0.7.0 采用资源侧共同读取与通用缓存，两个 cache 不再属于 Alice；统一引用解析同样退出 Alice。** 这是本版本已选定的实施方向，不再把“保留 Alice 所有权或迁入 WorkspaceRuntime”列为待决。ADR-0004 继续记录 v0.6.2 已落地的客户端缓存基线；它的所有权结论不作为本版本目标设计的否决依据。

冲突来自两轮设计采用不同判据：早期按“需要 Workspace key”推导所有权，ADR-0004 又按“当时只有 Alice 消费”确定执行侧归属。前者只能说明寻址方式，后者只能解释当时的调用关系。稳定判据应是派生结果依赖什么、谁改变其有效性、删除它是否丢失权威状态，以及更换 Actor 后哪些语义必须保留。通用资源缓存依赖资源版本和访问策略，失效源覆盖管理、生成与生命周期路径，因此与资源读取共同维护；run/frame 和实际执行配置仍属于 Actor。

| ADR-0004 原决定 | v0.7.0 处理 | 原因与承担方 |
|:---|:---|:---|
| 第 1 条：两个 cache 归 Alice，WorkspaceRuntime 解体 | 替换这一具体归属；采用单一 WorkspaceRuntime 聚合 | 缓存从 Alice 客户端加速转为资源读取内部加速，不能只换构造位置 |
| 第 1 条及 Consequences：Pending 与 cache 同属执行路径状态 | 不沿用这一分类 | 权威 Pending 意图与 Alice 执行关联应分开；Pending 不可作为可淘汰缓存处理 |
| 第 2 条：System 只拥有跨子系统事实源 | 保留 AssetStore 所有权，收窄“只拥有”的概括 | System 可装配派生基础设施；实例持有不转移 Patchouli 的领域责任 |
| 第 3 条：按派生源 Workspace/授权坐标键控 | 保留 | 单进程实例与条目逻辑分区可以并存，session 不作为资源缓存身份 |
| 第 4 条：分区不替代授权 | 保留并补足当前性 | 相同坐标或检查缓存内旧 policy 不证明当前授权；Patchouli 负责当前 policy/revision 重验 |
| 第 5 条：生命周期随所有者，Alice stop 清 cache | 保留原则，替换 Alice 清理责任 | A2/A6 按资源服务生命周期 drain/close；停止 Alice 不关闭其他 Actor 使用的缓存 |
| 第 6 条：拒绝无 scope 访问，保留观测 | 保留行为要求 | 内部 cache 校验与公共访问错误分别遵循其契约，不要求外部协议暴露 Python TypeError |

“Workspace-owned 资源”“领域责任”“运行时持有/装配”分别表达数据归属、业务权威和实例生命周期。Workspace 资源体系包含 Patchouli、System 资源服务与共享基础设施，不要求全部对象进入 WorkspaceRuntime。此聚合用于明确组合和关闭边界，不需要增加业务转发方法证明其价值；也不能反过来导入 Alice 内部加速器或 Patchouli 私有 provider。通用 bus/queue 等保持进程级骨架，资源缓存按来源分区，无需再声明“共享基础设施分区特例”。

### 1.2 解析、缓存和执行的交接

| 责任 | 实施位置 | 明确边界 |
|:---|:---|:---|
| canonical 引用定位、当前 policy/revision、内容快照 | Patchouli，本计划 | 对外只有一条 canonical 领域读取链；不放入 WorkspaceRuntime |
| Profile 定义查找、类型/内容解析、builtin 规则 | Patchouli，本计划 | 返回定义快照，不组装完整 system prompt |
| cache 存取、索引、epoch、容量、失效、close | WorkspaceRuntime，本计划 | 不决定 Pending 状态、不执行 Profile 解析、不持有授权许可 |
| Pending 意图与结算解析 | Patchouli 的后续领域扩展 | 复用这里的 canonical 读取；不成为本计划完成条件 |
| run-local 引用、Profile 应用、prompt/模型/工具配置 | Actor adapter/runtime | 不直接查询通用缓存；运行输入快照不成为后续资源读取的成功来源 |

### 1.3 canonical 读取、快照与公开路由

本计划直接复用并完善 `patchouli.public.memory.read/retrieve_by_aliases`、管理 Memory 读取与 `get_agent_profile_snapshot` 等已有 application 路由，完成 access 传播、operation 绑定、中立输入输出和真实总线验证。公共方法由 Patchouli application 按领域提供；不等待后续统一 API 目录再发布，也不新增 Workspace 读取 service 或 provider。管理读继续使用管理 grant/policy，普通资源读不得取得 owner bypass。

输入是 A1 access 与 canonical alias/UUID/ref，不要求 `MTPExecutionContext`、Alice run 或 RuntimeScope。alias 按 Workspace 定位，UUID 可用于索引加速但返回前仍检查 ownership/visibility。返回不可变或 copy-on-read 的内容、canonical identity、source revision 与允许披露的来源；冷读和缓存命中必须具有相同的领域结果和错误语义。未知、不可见、scope 冲突和 unavailable 的投影由本计划按 A1 冻结，不回退到其他 Workspace 或过期成功值。

ProfileSnapshot 明确 builtin/source atom UUID/revision，裸 Profile 仅在兼容窗口内作为投影。MemorySnapshot 的版本依据见第 2.1 节。READ、RUN、UPDATE 和 Profile 类型读取可以复用已提交资源事实，但读取成功不授予执行、修订或身份切换权限。

这里只冻结 canonical/Profile 的基础签名与快照，不提前定义 Pending 的状态联合结果。后续扩展须保持 canonical 行为并承担新增结果类型的兼容；在本计划支持范围内，无法识别或不支持的引用明确拒绝，不猜测为同名 canonical。批量读取的逐项结果、已有方法的签名兼容和删除窗口在 A2-0 记录。

### 1.4 Profile 定义读取与执行配置应用

当前 Patchouli `services/retrieval.py::get_agent_profile_snapshot()` 已承担 builtin/alias/type/内容解析，Alice `runtime/profile_resolver.py` 主要重复 builtin 判断并做缓存/总线/错误适配，完整 system prompt 则在 `prompts/assembler.py::AgentPromptAssembler` 组装。目标沿这条职责分界收敛，不把“Profile resolver 是否移走”处理为整个类的机械搬迁。

| 责任 | 唯一承担方 | 输出/限制 |
|:---|:---|:---|
| Profile 资源查找、类型检查、定义解析、builtin 规则 | Patchouli Profile API | ProfileSnapshot 与 source identity/revision；Root/CALL/外部读取一致 |
| 定义缓存和失效 | A2 基础设施，由 Patchouli 内部使用 | 不缓存完整 prompt、运行上下文、模型客户端或工具实例 |
| 选择 Profile、绑定实际模型/工具、应用执行限制 | 对应 Actor runtime/adapter | 本次运行的实际配置；读取 Profile 不等于获得其描述的权限 |
| persona、MTP、记忆、附件、Topic 等 prompt 拼装 | Alice AgentPromptAssembler 或外部执行器自己的实现 | 接收能力与拼装策略由执行器决定，不成为 Patchouli 读取职责 |

`AgentProfile` 当前含 `model_name`、`allowed_mtp_verbs`、`allowed_sys_tools` 等运行环境相关字段。v0.7.0 保留资源定义及已有 Alice 解释，不承诺每个外部 harness 都能执行这些配置，也不为此引入通用 harness 配置框架。外部读取定义是一项可选操作；外部接入的最低要求是共同记忆 API，不要求加载 Profile 或接收动态 system prompt。

例如同一 `researcher` 定义，Alice 可应用 persona/模型/工具限制并组装 prompt；支持指令配置的外部 harness 可由 adapter 映射其支持的字段；无法修改 system prompt 的 harness 仍可搜索、读取、写入和自动提交交互。若请求“应用 Profile”，adapter 必须区分已应用、部分支持和拒绝，不把读取成功或普通工具返回文本等同于 system prompt 已生效；无法落实的强制执行限制必须拒绝相应应用请求，不能静默忽略。权限由实际服务/执行边界落实，Profile 不能自行扩大 Workspace grant。

Profile 定义更新后，后续资源读取必须使用当前授权和版本；已经启动的 run 可以固定启动时取得的配置快照和来源版本。资源 cache 失效不隐式热更新本轮配置，固定快照也不免除后续资源操作的当前授权。v0.7.0 不新增运行中 Profile 热加载协议。此处交付定义读取及执行侧应遵守的限制；真实 Actor 配置应用和外部协议映射是后续消费者工作，不作为本计划完成条件。

## 2. Cache 契约

Profile cache key 至少包含 Workspace、user/Agent/team、profile alias/ref 及必要授权坐标；值包含 source atom UUID、revision/content identity 和 policy projection。Atom cache 按 `(WorkspaceIdentity, normalized_alias/ref)` 分区，值包含 canonical identity、revision、owner 和 provenance。两者都只能保存可重建派生值，不能保存永久授权。

每次命中仍须检查 access、ownership/visibility 和 revision freshness。负缓存必须绑定 scope、epoch 和错误类别；授权失败不能转成跨 Workspace 的 not-found。in-flight fetch 返回后重新检查 epoch，旧结果不能覆盖 canonical mutation 后的新状态。缺少 source revision 时采用同步 revalidation 或 no-cache，不能静默返回旧快照。

### 2.1 继承已关闭决定

WRX-0 第 8 节已冻结：MemorySnapshot 使用 `meta.version` 与 `updated_at` 作 source identity；Profile 配置来自 source atom payload，`ProfileSnapshot.source_revision` 使用同一 `meta.version`，不另设配置 revision；现有 MemoryAtom 版本字段有默认值 1，缓存接入采用同步 revalidation。A2 直接承接这些决定，不重新打开“增加 provider DTO”或拆 revision。未来支持缺失版本的来源时必须显式设计 no-cache/错误，不能借例外改变现有同步重验。

### 2.2 两个 cache 的行为表

| 维度 | 必须满足的行为 |
|:---|:---|
| 内容索引与授权投影 | 内容可共享存储，但每次返回由 Patchouli 重验当前 policy；任何带授权含义的派生视图须绑定完整访问坐标 |
| alias 替换 | 维护 alias→UUID 及反向引用，同一资源多个 alias 的替换/删除不留下可返回的旧值 |
| 并发冷读取 | 可合并同 key 请求；失效代次改变后重新验证，旧 fetch 不能回填或冒充当前成功 |
| 负缓存 | 仅有界、短暂保存允许的 not-found/invisible 结果，绑定 scope/epoch/错误；拒绝授权和存储故障不能污染其他 Actor 的负缓存 |
| 失败 | cache 故障不回滚 canonical 变更；必要时 no-cache/失败关闭，不以旧授权数据伪装成功 |
| close | 停止新读，处理已在途请求的完成/失败，清理仅属于 cache 的派生值；不删除 Pending/Session/canonical |
| 容量与观测 | 可保留全局 LRU，冻结负缓存 TTL/容量；记录 hit/miss/revalidation/invalidation/stale reject/close 拒绝，不承诺 Workspace 独立配额 |

业务调用始终是 application 校验 access → Patchouli 内部 cache 协作/冷读取 → 当前 policy/版本重验 → 返回快照。Workspace cache 只提供存取、索引、epoch 和失效，不接收全局路由或 Patchouli provider 负责冷读取；不形成 application → Workspace service → application 递归。

## 3. 失效、生命周期和装配

Memory create/update/delete/archive/revive、materialization settlement、Profile source/policy 变化和 Asset representation revision 都必须在 canonical 提交边界调用统一 invalidation。RuntimeEvent 可作为观测，但事件投递失败不能成为正确性的唯一保障。单个 run 完成不清理资源 cache；Alice stop 不关闭 WorkspaceRuntime。

关闭顺序是停止接纳、等待 resource read/settlement、drain producers、detach consumers、关闭 cache/Asset/Patchouli。A2 完成 Runtime 局部生命周期的实现与独立验证；A6 负责把它接入完整 System composition。

| canonical 变更源 | 失效覆盖 |
|:---|:---|
| Memory 管理 create/update/delete、archive/revive | Atom 快照、alias 正反索引、引用该 source 的 Profile projection |
| generation/materialization/settlement | canonical revision 可读时同步推进 epoch，并失效对应 Atom/Profile |
| source visibility/policy 或 Profile payload 改变 | 内容未变也要废弃授权/解析投影，返回前使用当前 policy |
| Asset representation 变化/remove | 禁止旧 revision 获得新 lease；已有 lease 按 W1 生命周期处理，不擅自使持有者悬空 |
| 调试/测试/内部管理 mutation | 通过同一 owner 提交和失效协作，不直改私有字典 |

原清单只调查到 Alice settlement 和 MTP UPDATE 两条失效路径；A2 实施必须覆盖当前受支持的所有 canonical mutation，不只移动这两个调用点。后续新增或迁移的 mutation 必须复用已交付的 invalidation 契约，其接入测试由引入该路径的计划承担，不反向阻塞 A2。同步 invalidation 失败时必须明确读侧如何禁止旧命中，不能仅输出日志继续返回旧值。

## 4. 实施与验收

| 阶段 | 产出 | 验收 |
|:---|:---|:---|
| A2-0 | 按第 1 节冻结 canonical/Profile 签名、operation、快照、兼容及 cache/invalidation/Asset/close 契约 | 读取契约和基础设施均在本计划内闭合；不等待后续 Pending 或 API 目录 |
| A2-1 | canonical/Profile 公共路由、定义解析与 Profile/Atom cache 迁移 | 无 Alice/MTP 可取得中立快照；builtin/type/source 一致；两 Workspace 隔离；命中与冷读授权相同 |
| A2-2 | 当前支持的 canonical mutation 接入和独立组合验证 | management、generation、lifecycle、Asset mutation 都失效；旧 fetch 不回填；删除 cache 不改变领域结果 |
| A2-3 | 读取/快照/失效交付记录、旧 cache 委托与消费者退出清单 | 本计划真实公共读取可用，只有一份正式可命中 cache；旧消费者删除及最终生产装配另由 A6 验收 |

unit 覆盖 key normalization、snapshot、copy-on-read、alias replacement、epoch race、错误和 close。integration 使用真实 application + canonical + cache，覆盖无 Alice、授权变化、cache hit、存储故障、shutdown drain；同一读取在开启/关闭 cache 时领域结果和授权一致，管理员修改 Profile 后下一次共同读取不得返回旧定义。不得用私有字典、re-export 或转发次数作为完成证据。本计划以 canonical/Profile 路由、快照、当前 mutation 和独立生命周期证据完成验收；Pending 分派及后来新增的 mutation 接入由引入方验证，不作为本计划的遗留待验收项。

## 5. 迁移与收口

旧 cache 属性可以短期委托，但 A2-1 后不允许 Alice 和 Workspace 同时作为成功来源；兼容直接访问仅属于尚未切换的旧链路，不算共同读取验收通过，A6 必须删除。双写只用于观测对比。若出现授权/一致性回归，回滚旧 adapter 仍使用统一 access 和单一 cache，不把资源状态复制回 Alice。跨进程 cache 恢复、Workspace 配额和新 schema 另立计划。

本计划第 1.1 节是 v0.7.0 替代裁定的唯一理由源；旧 WRX-0 调查和 v0.6.2 归档不追改为新结论。ADR-0004 当前保留 accepted 基线状态和适用范围链接，不把未完成实现写成已生效事实。本计划完成不等于所有旧 Alice 路径已经退出；以下是交付给版本收口的事项，不是本计划完成门禁：A6 验证共同读取、Pending 解析、所有消费者切换及资源生命周期，并进入稳定收尾后，依据最终实现建立后继 ADR，明确继承第 3/4/6 条原则、替换第 1/2/5 条的相关范围，再将 ADR-0004 标为 superseded 并双向链接；不预占 ADR 编号。此时同步 Workspace、composition、Alice 与公共契约事实文档。

目录按已冻结方向落到 `workspace/runtime.py`、`workspace/cache/{keys,atom,profile}.py` 与基础设施协议；已有 AssetStore 原地保留。无需为组织目录创建空服务类；`workspace/services` 若保留，只能承载失效/lease/snapshot 协作。主要未决项是 canonical/Profile 签名与兼容、负缓存窗口、容量、close 的在途行为和失败时禁用旧值的机制，在 A2-0/1 冻结；不把性能调优或固定 TTL 变成跨计划前置。
