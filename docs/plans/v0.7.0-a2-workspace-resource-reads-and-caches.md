# v0.7.0 A2：Workspace 读取能力面与派生缓存

## 0. 地位与效力

本计划从属[计划 A 边界宪章](./v0.7.0-plan-a-boundary-charter.md)（计划 A 家族边界裁决的唯一理由源）。2026-09-25 整份重写，取代此前 2026-09-17/20 的分段修订与 2026-09-23 补丁（历史见版本库）；本文本即 A2-0 冻结基线，标注"A2-0 待冻结"的条目是仅存开放点。

本计划交付：workspace memory read 能力（alias resolver 与 profile 读取 resolver）、双资源 cache、失效事件订阅者、能力层 operation 授权迁移的实施，以及 canonical/Profile 读取的 L2 backing 契约语义。交付完成后，无 Alice 的独立组合即可完成完整原子读取与编译，命中不回源，逐次授权在交付边界，写入经事件协作保持当前性。

调查与既有决定见[WRX-0 清单](./v0.7.0-plan-a-wrx0-boundary-freeze.md)第 1–5/8 节；迁移源为 `alice/runtime/profile_cache.py`、`agent_runtime/aliases/cache.py`、`agent_runtime/aliases/resolver.py`、`alice/runtime/core.py` 与 `system/application/`；AssetStore 原地保留于 `system/runtime/workspace/store.py`。前置成果是 A1 的 scope/授权规则与 [A2-P](../archive/plans/v0.7.0-a2-pre-memory-version-and-lifecycle.md) 交付的完整原子、历史记录与受控 mutation。Session、共享 Pending registry、外部 wire 和生产消费者切换不属于本计划的验收前置。

## 1. 组件与归属

### 1.1 交付归属表（宪章 §5 的 A2 子集）

| 组件 | 归属 | 本计划交付 |
|:---|:---|:---|
| alias resolver（workspace memory read 能力） | workspace runtime | L1/L2 解析、原地逐次授权、epoch 守护回填、L0 端口预留 |
| profile 读取 resolver | workspace runtime | 解析结果缓存（key = `(Workspace, agent_alias)`）、命中逐次授权、事件失效；L1 miss 经 `get_agent_profile` |

### 1.2 能力层入口与 A1 返工

按宪章 §5.3：能力面是 in-process 的 workspace server API，由现有 `system/application` 改造而来，不新开总线；actor 经 HTTP/MTP/外部 adapter 归一化调用，能力面作为 client 调用 Patchouli backing API（第二层 client-server，§4.4 过线契约）。本计划的具体改造：

- `memory_service` 的 read/retrieve_by_aliases/retrieve 改造为能力方法：operation 授权（backing 调用前）→ resolver 多级解析 → 交付；管理方法保持薄委托库管理路由（owner-management 规则不变，不过 resolver）。
- `topic_service`/`memory_task_service` 维持薄委托；`agent_service`/`chat_service`（复合工作流能力）与 `passive_ingress_service`（摄入能力）归能力层，其记忆读取一律走本层读取能力，不得绕行。
- **operation 授权迁移**（宪章 §10 第 8 项落实）：A1 行为白名单机制与网关认证不变；检查点从 Patchouli application（现 `access_consumption` 共享检查）整体迁至能力层、backing 调用前执行；Patchouli application 保留资源归属与资源 policy 校验（存储边界纵深防御），operation 检查退役、不双重检查。切换**按路径拆分**：本计划迁移并退役**读取路径**（memory read/retrieve/Profile）的 Patchouli 侧 operation 检查；session/topic/intent 等路径的检查随 A3/A4 能力切片分别迁移，**全量退役核对归 A5**。检查不是成功路径，过渡期并存不违反单一成功来源。
- **骨架接口稳定承诺**：能力层骨架（目录迁移、operation 守卫、adapter 判据）按宪章 §5.3 实现；A3/A4 的能力切片（session/交互/topic 资料、intent 登记/读取）接入同一骨架，本计划向其承诺入口与守卫接口稳定，不预留会随切片变化的钩子。
- 物理落位：A2-1 将 `system/application` 迁为 `workspace/capability`（迁移期 re-export shim，A6 删除）；`readiness_service` 留在 system 组合根。

### 1.3 与 A4 的接口

resolver 预留 `PendingResolutionPort`（命名 A2-0 冻结）：`lookup(reference, access) -> 中立 Pending 解析结果 | None`，缺省不接入（等价 L0 miss）；A4 交付 registry 后接入，L0 分支的交付前授权使用 Pending policy 谓词（A4-0 冻结）。canonical 分支的引用跟随语义按 [A4 §4.1](./v0.7.0-a4-pending-memory-intents.md#41-共同引用读取与-alias-resolver-归属)；settlement 事件与 registry 权威对账全部归 A4，本计划不实现。

### 1.4 非目标

Pending registry 实现与 settlement 对账（A4）；Session/Topic 生命周期（A3）；生产 assembler 装配与真实消费者切换（A6）；跨进程 cache 恢复与 Workspace 配额；语义检索算法及其缓存化；Profile 热加载协议。

## 2. 读取契约

### 2.1 固定返回类型与 backing 路由

公共返回契约（2026-09-20 修订，继续有效）：单项读取返回完整原子，alias 批量读取和语义检索直接返回原子列表，Profile 定义读取返回已有 `AgentProfile`。为减少无关迁移，保留现有 `retrieve_by_aliases` / `retrieve` 路由名。这些路由自本计划起是 **L2 backing 契约**，不是 actor 面向入口；actor 面向入口是能力层方法（宪章 §5.3）。

| 正式方法形状（均为异步） | 公共总线路由 | 返回与 operation |
|:---|:---|:---|
| `read(memory_id: UUID, *, access: WorkspaceAccessContext)` | `patchouli.public.memory.read` | `MemoryAtom \| None`；`resource.read` |
| `retrieve_by_aliases(aliases: list[str], *, access: WorkspaceAccessContext)` | `patchouli.public.memory.retrieve_by_aliases` | `list[MemoryAtom]`；`resource.read` |
| `retrieve(request: RetrievalRequest, *, access: WorkspaceAccessContext)` | `patchouli.public.memory.retrieve` | `list[MemoryAtom]`；`resource.search` |
| `get_agent_profile(agent_alias: str \| None, *, access: WorkspaceAccessContext)` | `patchouli.public.get_agent_profile` | `AgentProfile`；`profile.read` |

表中 operation 自本计划起由能力层在 backing 调用前检查（§1.2）；管理 get/list 同样使用完整原子/列表，绑定独立管理 operation。`RetrievalRequest` 沿用已有检索参数；其中保留的 identity_scope 必须与 access 的可信 scope 一致，不能据请求体重新选择 Workspace。UUID 字符串归一化及旧参数过渡在 A2-0 记录。

输入是 A1 access 与 canonical alias/UUID/ref，不要求 `MTPExecutionContext`、Alice run 或 RuntimeScope。成功但无可见结果时列表为空；点读未知/不可见资源按 A1 防泄露规则返回 None，alias 批量读取只包含实际可读的完整原子，不能用列表下标表达逐项状态。alias 归一化/去重与顺序沿用已有语义，检索保持领域排序；请求级授权失败、scope 冲突和存储不可用按明确错误处理，不能伪装为空列表。

### 2.2 能力面读取流程与错误语义

```text
adapter 完成两阶段认证交接，能力层检查该方法的 operation
  -> 从可信 access 取得 Workspace 分区及当前 Actor
  -> alias resolver 多级解析，任一级交付前原地执行授权：
       L0 registry 本地查表（A4 接入后启用）
       L1 AtomCache 命中：不回源查询 policy/revision，按原子自身 policy 逐次授权
       L1 未命中/已失效：L2 冷读 Patchouli backing 路由（库侧资源归属与 policy 校验独立成立）、
            核对 epoch 后回填
  -> 返回完整 MemoryAtom 的独立副本，供 MemoryCompiler 等消费者使用
```

任何一级交付都绑定同一边界校验；命中不回源的前提是 policy 字段的当前性由失效事件协作（D1–D3）保证。冷读路径的库侧资源授权独立成立，构成纵深防御。Workspace authentication 已由 A1 网关完成，能力层不调用认证网关；原子 ownership 在冷读及缓存写入时验证，后续分区寻址保持该不变量——这属于资源归属约束，不是对 Actor 再次执行 Workspace 准入。resolver 的 L2 经公共 backing 路由冷读（宪章 §4.4 既定过线契约），不形成递归。

### 2.3 Profile 读取

`MemoryAtom` 是 `AGENT_PROFILE` 类型的 canonical 资源；`AgentProfile` 是 Patchouli 从正文与 `payload.agent_config` 解析出的运行配置——解析纯能力在库，workspace 不做 atom→profile 转换。**alias（agent_id）是 AgentProfile 的 actor 面向身份**（2026-09-25 C2 裁定），profile cache 按 `(Workspace, agent_alias)` 作 key。正式流程：profile 读取 resolver 查 L1 解析结果缓存 → 命中：按缓存项随存的授权依据对当前 Actor 逐次授权，交付独立副本 → 未命中：调用 Patchouli `get_agent_profile(agent_alias)`（库内部完成源原子定位、类型检查与解析）→ 以响应附带的缓存内部元数据（source UUID、`meta.version`、解析时的 policy 依据——不扩大公共结果）建立缓存项 → 交付。

三条硬规则：① 同一 Workspace 内 alias 唯一性修复（[todo](../todo/memory-alias-uniqueness.md)）先于或伴随 A2-1 交付，否则 alias key 不唯一；② canonical 变更事件的 alias 集必须包含**被释放的旧 alias**（重绑定/删除/两个 Agent 交换 alias 的场景依赖它失效条目）；③ 缓存项随存解析时的 policy 依据供命中逐次授权，policy 更新必触发失效，不缓存任何 Actor 的授权结论。类型不符、配置损坏、alias 缺失/不可见均按既有错误规则失败，不降级为默认配置。未指定 alias 或显式选择 `default` / `omni_doll` 时，按 builtin 规则返回内置 AgentProfile 独立副本（无源原子；是否进缓存由 A2-0 定）。Profile 定义更新后，后续读取使用当前授权；已经启动的 run 可以固定启动时取得的副本，不引入热加载协议。选择 Profile、绑定实际模型/工具、应用执行限制归 Actor runtime/adapter；读取 Profile 不等于获得其描述的权限。AgentProfile 模型自身的已知限制（无身份字段、MTP 中心字段、外部 actor 语义未定义）见 [todo](../todo/agent-profile-model-evolution.md)，其演进不改变本节缓存契约——缓存对解析结果不透明。

### 2.4 旧返回值的迁移边界

| 当前依赖 | 本计划改动与消费者交接 |
|:---|:---|
| RetrievalFamiliar/application 的 alias 与语义检索返回 `RetrievalResponse` | 正式读取链改为 `list[MemoryAtom]`，local/public route 与类型标注同步；引擎内部排序/诊断结果可保留，不直接成为公共返回值 |
| `AgentRunContext.retrieval_result`、旧 prepare、Passive context、MTP SEARCH/READ 与相关测试 | 迁移期由调用侧 adapter 用列表构造旧协议 envelope 或本地上下文；A2 交付兼容映射及必要桥接，A6 完成生产消费者切换/清理，B 映射外部 wire |
| `ProfileSnapshot` 和 snapshot 路由消费者 | 改为读取 `AgentProfile`；不建立另一个 Profile 包装 DTO，也不伪造 builtin 源原子 |

`memories_count` 若旧协议需要，由 adapter 对列表计数；`latency_ms` 明确为 adapter 测量的调用耗时或独立观测指标。兼容层不重新实现检索、授权或缓存，不保留同一公共方法按调用方返回 `RetrievalResponse | list[MemoryAtom]` 的分支。A2 完成时正式路由只能返回表中类型。裁剪型 `MemorySnapshot` 已由 A2-P 删除；本计划删除 `ProfileSnapshot`、`get_agent_profile_snapshot` 及其 `GET_AGENT_PROFILE_SNAPSHOT` 全局/局部路由、bridge/binding 和导出，保留 `GET_AGENT_PROFILE -> AgentProfile` 为正式 API。

## 3. Cache 契约

缓存用于把高频资源的 alias/UUID 定位从存储查询转为平均 O(1) 的内存查表。当前冷读来自向量数据库；未来若实现长期记忆本地存储读取，可在同一领域边界扩展，但不是本计划已实现能力。语义 SEARCH 仍执行检索，检索结果可由能力面协作预热 Atom cache，后续 READ/RUN 等按引用访问复用完整原子；缓存不替代语义搜索。完整对象复制和编译的成本仍随内容大小变化，O(1) 仅指缓存索引查找。

两个 cache 的资源 key 均基于 `(WorkspaceIdentity, normalized_alias/ref)` 或 `(WorkspaceIdentity, UUID)`，不包含 Actor 的 user/agent/team/session 投影；WorkspaceIdentity 自身的 owner 坐标仍保留。同一 Workspace 的多个 Actor 复用同一资源条目，每次返回时分别授权。UUID 可作为内部索引，但所有读取必须带 Workspace 坐标，不提供跨分区的成功旁路。

Atom cache 保存完整 `MemoryAtom`，其 ownership、access_policy、source revision 与 provenance 使用原子内已有字段，不另建精简快照或第二套来源记录。写入和对外返回均隔离可变对象引用，调用方不能借修改返回值改变缓存或后续授权结果。此处的 copy-on-read 指完整原子副本，不是字段裁剪；它可直接交给现有 `MemoryCompiler`。

Profile 的正式资源同样是 `AGENT_PROFILE` 类型的完整原子。profile cache 保存的是 Patchouli 解析后的共享结果，key 为 `(Workspace, agent_alias)`——alias 经唯一性修复后是 actor 面向的唯一身份（见 [todo](../todo/memory-alias-uniqueness.md)）；不按读取者复制条目，也不能仅保存曾经通过授权的裸 `AgentProfile` 并直接返回。缓存项随存解析时的 policy 依据；使用解析结果前必须按该依据对当前 Actor 逐次授权，源原子 policy 更新必触发失效，失效或缺失时不能靠解析结果独立返回成功。builtin Profile 由 Patchouli 的显式规则处理，不伪造 source atom。

### 3.1 版本依据与历史决定修订

版本与数据结构消费 [A2-P 第 3–5 节](../archive/plans/v0.7.0-a2-pre-memory-version-and-lifecycle.md)：`meta.version` 是内容修订序号，`meta.updated_at` 是内容最后修订时间，动态状态在 `meta.lifecycle`；它们不是整个对象的变化标记或乐观锁。Profile cache 以 `(Workspace, agent_alias)` 作 key，条目内保存响应元数据中的 source UUID、`meta.version` 与 policy 依据，用于失效对账与命中授权；不拆配置 revision，也不在公共 AgentProfile 外新增 source revision DTO。同版本原子可以具有不同的 lifecycle 或 policy，不能按版本相等跳过状态/授权依据更新。历史中的 lifecycle 只是捕获时状态，不能覆盖当前缓存状态；本计划不引入历史版本 cache。

正常命中不通过数据库查询证明当前性，也不查询历史 Artifact 比较版本。当前性由所有受支持的 canonical 写入路径经失效事件协作（D1–D3）保证，包括 policy、alias、metadata、内容、删除和归档等变化，即使 `meta.version` 未增加也必须处理。epoch 是运行时失效代次，不是新的持久化业务 revision。无法确认缓存有效性时禁用受影响命中，转入受控冷读或明确失败；不能把每次回源作为正常命中流程，也不能用 TTL 代替写入一致性。保证范围是经过受控提交路径的写入，不包含绕过系统直接修改底层存储；引入其他写入者时须先接入相同一致性约定。

缓存维护按变更实际影响执行：lifecycle 更新经失效事件协作反映到读取结果（advisory 刷新或失效回填由 A2-0 裁定）；policy 更新替换源原子的授权依据；内容修订更新/失效受影响的内容与解析结果。缓存接收资源所有者已协调的提交事实，不能用调用方旧副本合并回最新状态。不能可靠处理时使 Atom 失效，此时 Profile 解析结果也不能脱离有效源原子独立返回。所有可见变更都参与防止旧回填的 epoch 协作，但 epoch 推进不等于必须淘汰所有派生值。

### 3.2 行为表

| 维度 | 必须满足的行为 |
|:---|:---|
| 共享内容与资源授权 | 两个 cache 按 Workspace 与资源寻址；读取交付边界（resolver）用有效源原子的 policy 对当前 Actor 逐次授权，不缓存授权结论，不重复 Workspace authentication |
| 完整对象与编译 | 缓存完整 MemoryAtom，返回独立完整副本；调用方修改不污染缓存，MemoryCompiler 可直接编译 |
| lifecycle 状态变化 | 经失效事件协作反映到读取结果——advisory 刷新或失效回填由 A2-0 裁定；不重写内容、不重新计算 embedding、不无故淘汰 Profile 解析；现时 vitality 计算仍归领域维护，不由 cache 自行启动 |
| alias 替换 | 维护 alias→UUID 及反向引用，同一资源多个 alias 的替换/删除不留下可返回的旧值 |
| 并发冷读取 | 可合并同资源 key 请求（single-flight），但不合并各 Actor 的授权结论；读取前记录 epoch，返回后代次已变则拒绝旧值回填与成功返回，重新取得有效值或明确失败 |
| 负缓存 | 不缓存 Actor 不可见/无权限结果；它们不能污染 Workspace 共享条目。只有能确认 Workspace 内资源确实不存在时，才可按资源 key/epoch 有界短暂保存；底层把缺失与不可见合并为 None 时不得据此写共享负缓存。首版不启用，启用与否 A2-0 最终冻结 |
| 失败 | cache 故障不回滚 canonical 变更；必要时 no-cache/失败关闭，不以旧授权数据伪装成功。有效命中不探测存储可用性；存储故障影响实际需要冷读的请求，不为保持错误一致而强制命中回源 |
| close | 停止新读，处理已在途请求的完成/失败，清理仅属于 cache 的派生值；不删除 Pending/Session/canonical |
| 容量与观测 | 可保留全局 LRU，冻结容量及启用负缓存时的 TTL；记录 hit/miss/cold read/invalidation/stale reject/资源授权拒绝/close 拒绝，不承诺 Workspace 独立配额 |

alias 重名是现存域缺陷（[todo](../todo/memory-alias-uniqueness.md)），破坏本契约的资源 key 唯一性前提；修复归属与衔接时机由 A2-0 裁定，先于或伴随 A2-1 的 alias 索引交付。

### 3.3 读取与授权顺序

见 [§2.2](#22-能力面读取流程与错误语义)流程图。补充约束：原子 ownership 在冷读及缓存写入时验证，后续分区寻址保持该不变量；cache 只提供存取、索引、epoch 和失效，不接收全局路由，冷读取由 Patchouli backing provider 负责；不存在 application → Workspace service → application 递归。

## 4. 事件协作

### 4.1 canonical 变更事件

发布点：库的受控提交成功后、写入用例返回前，内联 `await publish`（D1）。载荷为领域事实草案：`workspace ref + memory_id + 受影响 alias 集（必须包含被释放的旧 alias——alias 重绑定/删除/交换场景依赖它失效 alias-keyed 条目）+ 变更类别（create/update/policy/delete/archive/revive/lifecycle）`；字段级定义、事件名与错误语义在 A2-0 冻结，A2-1 交付时登记入 `docs/contracts/routes-and-events.md`（非 RuntimeEvent 的公共事件族）。载荷不携带资源值（D3），订阅者不回放值——回填一律交给带 epoch 守护的冷读；lifecycle 类展示性信号可走 advisory 事件 best-effort 刷新或完全不投递，由 A2-0 裁定。

### 4.2 订阅者纪律

订阅者由 WorkspaceRuntime 实现并注册：第一步无条件执行受影响条目的 evict 与 epoch 推进（纯内存、不可失败），其后处理 alias 正反索引与关联 Profile 解析结果的失效；handler 内部任何后续失败都发生在条目已失效之后，失败不可能留下过期命中（D2）。总线吞并订阅者异常并仅记日志的既定行为因此不会退化为"仅输出日志继续返回旧值"。

### 4.3 失效覆盖矩阵

| canonical 变更源 | 同步更新或失效覆盖 |
|:---|:---|
| Memory 管理 create/update/delete、archive/revive | 完整 Atom 条目、alias 正反索引、引用该 source 的 Profile 解析结果 |
| generation/materialization/settlement | A2-P 的内容与完整历史提交成立后，经失效事件更新/失效对应 Atom 与受影响 Profile；不以 settlement 结果替代 canonical 提交 |
| source visibility/policy 改变 | 同步替换完整源原子的 policy，后续读取据新 policy 授权；定义未变化无需重解析，源原子无效时解析结果不能独立返回 |
| Profile payload 等内容改变 | 使用新内容版本，更新/失效完整源原子及受影响的解析结果 |
| feedback/citation/访问统计/活力刷新等 lifecycle 更新 | 经 A2-P 局部提交发布失效事件反映到读取结果（advisory 刷新或失效回填由 A2-0 裁定）；不增内容版本、不影响 alias，解析输入未变则保留 Profile 结果 |
| Asset representation 变化/remove | 禁止旧 revision 获得新 lease；已有 lease 按 W1 生命周期处理，不擅自使持有者悬空 |
| 调试/测试/内部管理 mutation | 通过同一 owner 提交和失效协作，不直改私有字典 |

后续新增或迁移的 mutation 必须复用受控提交结果，并由引入该路径的计划定义缓存协作，其接入测试由引入方承担，不反向阻塞 A2。

### 4.4 时序保证

正式写入成功返回前，订阅者已在内联发布中完成受影响缓存值/索引的失效与 epoch 推进（D1）；新开始的读取不能再命中提交前的内容、policy 或已更新的 lifecycle 字段。未变化的 alias 和 Profile 定义不因状态更新而重建。在途旧冷读即使晚到，也不能越过代次检查重新回填。内容/历史提交的失败语义由 A2-P 冻结；canonical 已提交而事件处理异常时，D2 保证条目已失效，读侧不得继续把旧缓存当作有效值，也不能假称 canonical 已回滚。缓存禁用范围与恢复条件、提交中取消及并发交错的读侧处理在 A2-0 冻结。

## 5. 授权

### 5.1 交付边界逐次授权

授权谓词 `memory_is_readable` 上收 core（A2-1 交付；签名 A2-0 冻结，形如 `(atom, *, workspace_identity, actor_identity) -> bool`），resolver 与库存储边界共用同一实现，杜绝解释分叉。授权输入是原子自身 `MemoryAccessPolicy` + 可信 access context；结论不缓存，逐次评估。

### 5.2 operation 授权迁移

operation 登记（`resource.read`/`resource.search`/`profile.read`/`management.*`）沿用 A1 行为白名单机制；检查点迁至能力层、backing 调用前执行。Patchouli application 的 operation/共享检查（现 `access_consumption`）对**读取路径**随 A2-3 退役；session/topic/intent 路径的检查随 A3/A4 切片迁移，**全量退役核对归 A5**。库侧始终保留资源归属与资源 policy 校验。管理读取继续采用独立 operation 与 owner-management 规则，直连库管理路由、不过 resolver，不因共享条目给普通 Actor 授权。

## 7. 迁移与收口

旧 cache 属性可以短期委托，但 A2-1 后不允许 Alice 和 Workspace 同时作为成功来源；兼容直接访问仅属于尚未切换的旧链路，不算共同读取验收通过，A6 必须删除。双写只用于观测对比。若出现授权/一致性回归，回滚旧 adapter 仍使用统一 access 和单一 cache，不把资源状态复制回 Alice。Memory/schema 与历史迁移由 A2-P 完成；A2 的缓存回滚不能回退已经迁移的数据格式或重新引入 lifecycle 整原子 upsert。跨进程 cache 恢复与 Workspace 配额另立计划。

ADR-0004 保留 accepted 基线状态；边界归属的唯一理由源是[边界宪章](./v0.7.0-plan-a-boundary-charter.md)。A6 验证共同读取、Pending 解析、所有消费者切换及资源生命周期后，依据最终实现建立后继 ADR 并将 ADR-0004 标为 superseded，同步 Workspace、composition、Alice 与公共契约事实文档。

目录落位：`workspace/runtime.py`、`workspace/resolution/{alias,profile}.py`、`workspace/cache/{keys,atom,profile}.py`、`workspace/capability/`（自 `system/application` 迁入，含薄委托方法）；AssetStore 原地保留。无需为组织目录创建空服务类；`workspace/services` 若保留，只能承载失效/lease/cache 协作。主要未决项已在 A2-0 列全；第 2.1 节返回类型已定，不再重新选择包装模型。不得重新把 Actor 放入资源 key、用裁剪投影替代完整原子、把逐次回源作为正常命中实现，也不把性能调优或固定 TTL 变成跨计划前置。
