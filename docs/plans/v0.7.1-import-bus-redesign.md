# v0.7.1 Import Bus 重设计：以 Claude Code 对话回流为第一条真实路径

> **文档状态**：In Progress（2026-10-21 起实施，阶段一至三已完成，见第 11 节），v0.7.1 的首份计划（[Plans 导航](../plans/README.md#v071)）。本文是实施依据，不描述当前行为；当前事实仍以[被动对话摄入](../system/passive-ingress.md)等文档为准，完成后按第 10 节晋升。

v0.7.1 的版本目标是 plugin 模式的真实外部 harness 接入，首个接入的 harness 为 Claude Code，目的是让外部 harness 在用户真实的日常使用中使用 Patchouli 记忆，以此检验记忆系统的闭环（[ROADMAP](../ROADMAP.md) 第 4.3、4.4 节）。plugin 模式由对话回流与记忆访问两部分组成，本计划完成对话回流：把现有 Passive Ingress 按 Import Bus 的新前提重做，并提供 Claude Code 的连接器，使记忆在真实使用路径中积累。记忆访问（MCP 工具）是候选的下一步，不在本计划内。

本计划把现有的逐事件接收改为一次接收一轮已结束交互的完整记录：经统一认证网关认证，经 Gateway 只做话题落位与价值信号，不检索、不返回记忆上下文；载荷与任务进程封口的交互记录相同，经 Patchouli 的公开路由提交。Claude Code 一侧以插件形式挂载 hooks，由连接器读取会话记录、按游标提交，被中断或发送失败的轮次在下次被唤醒时补发。记忆生成的转写同时扩展为纳入思考与外部工具的三元组，使导入的过程事实能够进入记忆提取。

设计依据：

- **owner 决定（背景 Idea）**：[Import Bus Idea](../ideas/import-bus.md) 前提 1–5，第 4 节 Q-11（仍经 Gateway 路由）、Q-12（沿用 `worth_saving`）、Q-13（只接收实时或刚结束的交互）、Q-15（内容与任务进程封口相同）、D-8a（经统一认证网关）的决定及 Q-15 之后关于生成视图的决定（2026-10-21），第 5 节连接器分层与游标的分析；[任务进程 Idea](../ideas/task-process-table-and-registration-entry.md#plugin-模式与进程模型的交界)中 `interaction_id` 的推导与先查重后路由；[身份与访问体系 Idea](../ideas/identity-and-access-model.md#4-已登记的暂缓与例外)第 4 节的 root 声明范围；[外部 Actor Idea](../ideas/external-actor-registration-and-runtime-access.md#v071-的步骤与各步的阻塞问题)第 4 节第一步的范围与验收方向。
- **当前事实**：[被动对话摄入](../system/passive-ingress.md)，[身份与授权](../workspace/identity-and-authorization.md)，[认证与访问登记](../workspace/authentication.md)，[任务进程](../workspace/task-process.md)第 8 节（封口），[子系统公共契约](../contracts/subsystem-contracts.md)，[路由与事件](../contracts/routes-and-events.md)，[错误模型](../contracts/error-model.md)，[Gateway 分析](../gateway/analysis.md)，[Patchouli 感知](../patchouli/perception.md)、[生成](../patchouli/generation.md)第 2 节（生成视图）与 [Artifact](../patchouli/artifacts.md)第 6 节（双视图）。
- **代码**：2026-10-21 在 commit `f658128a` 上的核对，见第 3 节。
- **已冻结的 Research**：[接口调研快照](../research/harness-interface-survey-snapshot.md) B1（Claude Code 会话的存储位置）。

## 1. 背景和问题

1. **现有链路与 Import Bus 的前提不符**：Import Bus 只向网络输入，不读取记忆，也不返回记忆上下文（Import Bus Idea 前提 1）。现有 `/api/v1/ingest` 在 user 事件到达时经 Gateway 分析并检索记忆，把编译后的记忆上下文返回调用方；它按事件逐次接收，跨请求累积一轮，靠下一条 user、`is_final`、空闲超时、手动 flush 或关闭来封口。前提 5 决定首份计划只接收一轮结束后的完整记录，这些累积与封口机制随之失去用途。
2. **认证前组装身份的例外**：`/ingest` 不经统一认证网关，由 `resolve_request_identity_scope` 在认证前组装 `IdentityScope`，是访问模型登记过的例外；它也不拒绝保留的 `system` 作为 `agent_id`。D-8a 决定经统一认证网关。
3. **载荷与主动链路不一致**：被动载荷不经归约器（`mtp_traces` 恒为空），不设 `outcome` 与 `model_used`；主动链路由 `seal_interaction` 封口。Q-15 决定两者相同。
4. **新话题丢失标题与摘要**：Gateway 判定新建话题时给出标题与摘要，被动链路只提交 `NEW_TOPIC`，感知以默认标题“新建话题”和空摘要建立话题；后续路由依赖候选话题的标题与摘要，持续导入会让落位质量下降。主动链路经 prepare 用 Gateway 的标题建话题，没有这一问题。
5. **Gateway 没有会话上下文**：主动链路把最近若干轮（`gateway.session_turn_limit`，默认 3）交给 Gateway，被动链路不传；“继续”“改一下”一类依赖上文的消息因此难以落位，重复输入的跳过规则也不会触发。
6. **直接持有提交队列**：被动服务直接持有 Patchouli 的 `InteractionSubmissionQueue`，而 Patchouli 提供了公开路由 `patchouli.public.interaction.submit`，并注明被动与外部来源应经此提交；该路由至今没有生产调用方。队列容量满或已停止时抛出的错误没有映射，HTTP 返回 500，调用方无法区分可重试的拥塞。
7. **没有真实来源**：`/ingest` 在仓库中没有调用方，前端与 E2E 都不使用；没有任何 harness 接入，记忆无法在真实使用中积累。
8. **生成视图只有用户问题、最终回复与 MTP 轨迹**：感知以 `TurnEvent → AgentAction → TraceItem → TurnRecord` 保存一轮内容，`AgentAction` 即思考、工具调用与工具结果的三元组，随交互 Artifact 持久化；但记忆生成的转写只渲染 SEARCH、READ、RUN 轨迹的一行摘要，思考、工具参数与工具结果都不交给提取记忆的模型（[生成](../patchouli/generation.md)第 2 节称之为丢弃执行噪音）。Alice 不产生思考事件，这一缺口此前没有暴露；外部工具不是 MTP 动词，不产生轨迹，导入的轮次在生成时只剩用户消息与最终回复，编码过程中的报错、修复经过与推理都不会进入记忆。owner 于 2026-10-21 决定扩展生成视图并并入本计划。

## 2. 目标与非目标

### 2.1 目标

1. Import Bus 以一次请求接收 harness 一轮已结束交互的完整记录；删除逐事件接收、跨请求累积、空闲封口与手动 flush。
2. Import Bus 不检索记忆、不返回记忆上下文；Gateway 以 `PASSIVE_MEMORY` 模式只产出话题落位与价值信号，并得到与主动链路相同形态的最近轮次。
3. 导入的载荷与任务进程封口的交互记录相同：两条链路共用同一个封口函数。
4. 导入请求经统一认证网关认证，以 (user, 具体 Agent) 声明；Import Bus 不声明 `system`；认证前组装 `IdentityScope` 的例外消除。
5. `interaction_id` 由服务端按认证结果与连接器提供的外部标识推导；查重先于路由；同一外部会话内的轮次按到达顺序处理。
6. Import Bus 经 Patchouli 公开路由查重与提交，不再持有提交队列；新话题保留 Gateway 给出的标题与摘要。
7. 记忆生成的转写纳入思考与外部工具的三元组：两条链路都渲染思考；非 MTP 工具按思考、工具名、参数摘要与截断后的结果渲染，报错优先保留；MTP 动作维持现有的一行摘要；新增的渲染内容计入轮次的 token 统计。
8. Claude Code 连接器以插件形式提供：轮次结束后提交完整记录；被中断、发送失败的轮次由游标补发；HiveMemory 不可用时不阻塞 Claude Code。
9. 真实使用验收：日常使用 Claude Code 一段时间后，记忆库中出现来自这些会话、来源可查的记忆。

### 2.2 非目标

- **流式监听**：推迟，与 controller 模式下 Patchouli 的流式接收一并设计（前提 5）。
- **记忆访问与写入意图**：Claude Code 经 MCP 工具检索、读取或提交写入意图，是候选的下一步。
- **历史导入**：连接器不回填接入之前已经存在的会话内容（Q-13），历史导入见 [ROADMAP](../ROADMAP.md) 第 4.5 节。
- **第二个 harness**：连接器的公共骨架与 Claude Code 读取器分开组织，但本计划只交付 Claude Code。
- **改名 Gateway 的 `PASSIVE_MEMORY` 模式**：Gateway 契约不变。
- **导入轮次进入会话资源**：plugin 模式的会话归外部 harness 所有，导入的轮次不写入 ConversationSession。
- **敏感信息过滤**：Q-15 决定连接器不做筛选；生成一侧只在提示词中要求不把凭据写入记忆，风险见第 9 节。
- **其他视图**：Page Folding 的接力摘要、MTP 动作的渲染与交互 Artifact 的内容不变；生成视图之外的消费方不读取新增的渲染。
- **跨重启的恰好一次**：查重依赖进程内记录，与现有被动摄入的承诺相同。
- **前端变化**、Claude Code 子代理的内部轨迹、会话编辑与回退产生的分叉、插件市场发布。

### 3.2 主动链路的封口与提交

- `workspace/process/sealing.py` 的 `seal_interaction` 以入口消息、Gateway 决定、CPU 结果与实际使用的附件组装 `InteractionPayload`：缺少 `assistant_message` 时按最终正文补齐，`mtp_traces` 由 core 的 `ActionReducer` 与 `TraceReducer` 归约，带 `outcome` 与 `model_used`。它要求非空的 Gateway 决定，唯一调用方是 `TaskProcessRunner`。
- `TraceReducer` 只为 MTP 动词（READ、SEARCH、RUN、CALL、WRITE、UPDATE）产生轨迹，其他 `tool_kind` 或没有 `tool_kind` 的工具调用不产生轨迹，但仍保留在 `turn_events` 与归约出的行动中。
- 感知拒绝空的 `turn_events`；记忆生成的转写（`prompts/transcript/generation.py` 的 `GenerationTranscriptBuilder`，被动结算与主动写入的材料共用）只使用用户消息、结局、最终正文与 SEARCH/READ/RUN 轨迹，思考与工具结果的内容不进入生成，只随交互 Artifact 持久化。块的 `total_tokens` 只计入用户问题、最终回复与轨迹的查询和目标（`engines/perception/memory_perception_engine.py`），折叠阈值据此判断。由交互结算生成的记忆是 PUBLIC，以保留的 `system` 为来源，参与的 Agent 记入贡献者（[Patchouli](../patchouli/README.md) 第 3 节、[生成](../patchouli/generation.md)）。
- 提交队列以 `interaction_id` 为工作项标识与幂等键，同一标识携带不同的编码载荷时报错；`is_accepted` 查询侧索引与运行时存储，终态记录在保留窗口外会被裁剪。公开提交路由按 `topic:{requested_topic_id}` 生成排序键，`correlation` 为空，不等待应用。

### 3.3 认证与授权

- `ActorAuthenticationGateway.authenticate` 先做 principal 认证，再做 Workspace 准入，签发密封的访问 context；关闭后以 `authentication_gateway_closed` 拒绝（HTTP 503），准入失败为 403。
- 现有 HTTP 路由中，管理路由以 (user, `system`) 取得请求级 context，chat 以具体 Agent 注册任务进程；没有路由以 (user, 具体 Agent) 取得请求级 context。`resolve_request_identity_claims(require_agent=True)` 与 `authenticate_request_access` 组合即可做到。
- 从访问 context 取得 `IdentityScope` 只能经授权点：`authorize_operation` 检查六项 actor 操作，`authorize_stage` 只在任务进程中调用，`authorize_root` 要求 `system`；这些调用位置由架构测试锁定。Import Bus 需要一个新的授权方法。
- 访问登记允许空的 `allowed_operations`，表示可以准入但不能执行 actor 操作；精确记录优先于用户级记录。准入不要求 Agent Profile。现有用户级记录让 `default` 用户的所有具体 Agent 拥有全部六项操作。

### 3.4 Claude Code 会话记录（本地核对）

在本机 Claude Code（VS Code 扩展）的会话记录上只统计了字段与类型，没有读取对话内容：

- 对话条目为 `user`、`assistant`、`system` 三类，另有大量内部条目（请求记录、标题、模式、文件快照等）。条目带 `uuid`、`parentUuid`、`sessionId`、`timestamp`、`isSidechain`、`isMeta`。
- 用户发出的提问带 `turnOrigin: human` 与 `promptId`；工具结果以 `user` 条目中的 `tool_result` 块出现；助手条目的内容块为 `text`、`thinking`、`tool_use`。
- 压缩产生 `system` 的 `compact_boundary` 与标为 `isCompactSummary` 的 `user` 条目；API 错误产生 `system` 的 `api_error`。
- 这份记录中没有找到被中断轮次的标记，中断的表示方式需要实测。

## 4. 目标设计

### 4.1 链路总览

```text
Claude Code hooks（Stop / StopFailure / SessionStart / SessionEnd）
  -> 连接器：读取游标之后已经结束的轮次，整理为完整记录
  -> POST /api/v1/import/turns
server：声明 (user, 具体 Agent) -> 统一认证网关（server principal + http adapter，请求级 context）
Import Bus 服务（system）：
  导入授权 -> 本次请求内有效的 IdentityScope
  按外部会话串行
  推导 interaction_id -> 经 Patchouli 查询是否已接纳 -> 已接纳：duplicate
  没有输出 -> skipped
  Gateway PASSIVE_MEMORY（附最近轮次）-> 话题落位与价值信号
  共用封口函数 -> InteractionPayload
  Patchouli 公开提交路由（附新话题的标题与摘要）-> accepted
请求结束：context 失效
```

### 4.2 接收契约

新入口 `POST /api/v1/import/turns`，请求模型拒绝未知字段：

| 字段 | 说明 |
|:---|:---|
| `source` | 来源标识，小写字母、数字与连字符，例如 `claude-code` |
| `external_conversation_id` | harness 的会话标识 |
| `external_turn_id` | 该轮在 harness 中的标识，同一轮重发时不变 |
| `agent_id` | 连接器所代表的具体 Agent；缺失或为 `system` 返回 400 |
| `outcome` | `completed`、`cancelled` 或 `failed`，与 `InteractionOutcome` 相同 |
| `user_message` | 该轮的用户消息 |
| `events` | 用户消息之后的轮次事件，按 `sequence` 严格递增：`assistant_message`、`thought`、`tool_call`、`tool_result`；字段为 `kind`、`sequence`、`content`，工具事件另带 `action_id`、`tool_name`、`tool_args`、`status` |
| `assistant_final_text` | 该轮最终的自然语言回复，可为空 |
| `model_used` | 实际使用的模型名，可为空 |
| `recent_turns` | 该轮之前最近的若干轮（用户消息与回复正文），只供 Gateway 落位，不进入载荷 |

- 事件不携带 `role`、`tool_kind`、`target` 与 `render_as`：`role` 由服务端按 `kind` 填写（与现有被动链路相同，工具结果为 `system`）；`tool_kind` 只表示 MTP 动词，外部工具不设置，因此不会产生 MTP 轨迹，也不会被误当作记忆操作。
- `user_message` 由服务端写成序号为 0 的 `user_message` 事件，保证感知收到的 `turn_events` 非空。
- 没有输出（既无用户消息之外的事件，也无最终正文）的轮次与任务进程一样不封口，返回 `skipped`。
- 请求体超过 `import_bus.max_request_bytes` 时返回 413。

响应为 200，`status` 取 `accepted`、`duplicate` 或 `skipped`，并带推导出的 `interaction_id`。错误按是否可重试区分，连接器据此决定游标（第 4.11 节）：

| 情况 | 状态码 | 可重试 |
|:---|:---:|:---:|
| 请求校验失败、Agent 缺失或为 `system`、请求体过大 | 400 / 413 / 422 | 否 |
| 准入失败 | 403 | 否 |
| 认证网关已关闭（服务关闭中） | 503 | 是 |
| Gateway 可恢复的失败（超时、依赖暂不可用） | 503 | 是 |
| 提交队列容量已满或已停止 | 503 | 是 |
| 其他错误 | 500 | 有限次重试（第 4.11 节） |

Gateway 可恢复的失败改为返回可重试错误，而不是像现有被动链路那样不带话题继续提交：导入没有用户在等待，稍后重发可以得到正常的落位与价值信号；Gateway 长时间不可用时 HiveMemory 也无法生成记忆，积压在连接器一侧按顺序保留。

### 4.3 认证与导入授权

- server 用 `resolve_request_identity_claims(require_agent=True)` 解析 (user, 具体 Agent) 与请求进入的 Workspace，以自身 principal 与 `http` adapter 经网关取得请求级 context，请求结束时失效，与管理路由的做法相同。不为连接器另行登记 principal：请求头中的用户身份不做证明，沿用本地单用户部署的信任假设（Import Bus Idea D-8a 的候选设计）。
- workspace 的授权点新增**导入授权**：校验 context 有效、已准入且目标等于驻留 Workspace，不检查 actor 操作白名单，返回本次请求的 `IdentityScope` 与认证通过的 principal 标识。理由：导入提交的是已经发生的交互，与任务进程结算阶段提交交互记录同类，后者同样只经阶段授权、不检查白名单；Import Bus 不调用任何 actor 操作。导入授权只允许 Import Bus 服务调用，由架构测试锁定调用位置。
- `IdentityScope` 只在这一次请求的调用链内经公共路由到达 Gateway 与 Patchouli，不写入记录、事件或后台任务。提交的归属取目标 Workspace，发起者取认证通过的 (user, Agent)，与现有被动链路相同。

### 4.4 `interaction_id`、查重与顺序

- `interaction_id` 为 `import_` 加上对（principal、user、Agent、`source`、`external_conversation_id`、`external_turn_id`）规范化序列取 SHA-256 的前 32 位十六进制。本计划的认证方式下 principal 恒为 server，因此同时纳入认证通过的 actor，使代表不同用户或 Agent 的连接器不会撞号；前缀把它与 `process_id` 及其他来源的标识分开。
- Import Bus 服务按（user、Agent、`source`、`external_conversation_id`）持串行门，门内依次完成查重、Gateway 与提交接纳；同一外部会话的并发请求（例如两个 hook 同时补发）因此按到达顺序处理，后到的请求查重时看到已接纳。
- 查重经 Patchouli 新增的公开查询（第 4.7 节）。已接纳的轮次直接返回 `duplicate`，不再调用 Gateway：Gateway 的结果写入载荷，重发时若重新路由，载荷可能不同而被队列判为冲突。
- 已知限制（任务进程 Idea 的决定）：查重依赖进程内记录，队列终态记录与应用日志都有保留上限；接纳之后、确认送达之前服务重启，或超出保留窗口后重发，会形成重复的交互。

### 4.5 Gateway 的落位与价值信号

- 以 `PASSIVE_MEMORY` 模式调用 `gateway.public.process`，消息为该轮的用户消息，`session_turns` 取请求中 `recent_turns` 的最后 `gateway.session_turn_limit` 轮，转换为 `GatewaySessionTurn`；超时沿用 Gateway 的默认请求时限。
- 使用决定中的 `target_topic_id`、`new_topic_title`、`new_topic_summary`、`rewritten_query` 与 `worth_saving`（Q-12）；忽略检索计划，不调用检索。
- Gateway 返回命令结果视为契约错误；可恢复错误按第 4.2 节返回 503，其他错误原样传播。

### 4.6 载荷封口（共用）

`seal_interaction` 迁入 core，作为两条链路共用的封口函数，与它依赖的归约器放在一起；任务进程改为调用 core 的版本。迁移后的函数接受可缺省的 Gateway 决定（缺省时 `rewritten_query` 与 `worth_saving` 为空），行为对任务进程不变。Import Bus 以 `user_message`、`assistant_final_text`、补上用户消息事件后的 `turn_events`、`outcome`、`model_used` 与 Gateway 决定调用它，`used_attachments` 为空。

### 4.7 Patchouli 的提交与查重

- **公开提交路由**：`patchouli.public.interaction.submit` 增加可选的 `new_topic_title` 与 `new_topic_summary`；`InteractionSubmission` 增加同名字段，只在 `requested_topic_id` 为 `NEW_TOPIC` 时允许非空，编解码版本加一。感知建立新话题时使用它们，缺省时保持现有的默认标题。主动链路经 prepare 建话题，不受影响。
- **公开查询路由**：新增 `patchouli.public.interaction.accepted(identity_scope, interaction_id) -> bool`，回答该交互是否已被提交队列接纳；按调用方 scope 校验归属，同名提交属于另一个 Workspace 时报冲突。
- **来源标签**：`InteractionOrigin` 的 `passive_memory` 改为 `import_bus`，它只是标签，没有下游消费者。
- **排序**：沿用公开路由按话题生成排序键；导入与主动链路落到同一话题时由同一个排序键保证先后，同一外部会话内的先后由 Import Bus 的串行门保证接纳顺序。
- Import Bus 服务不再持有队列；组合根不再把队列注入 System 的服务。

### 4.8 删除与配置

- 删除第 3.1 节标为删除的全部部分，以及只为它们存在的测试（契约有意变更，不保留墓碑测试）。
- 新增 `config/import_bus.py` 的 `ImportBusConfig`，挂在 `HiveMemoryConfig.import_bus`，首版只有 `max_request_bytes`（默认 8 MiB）；删除 `passive_ingress` 段与 `observer_idle_flush_*` 三项。配置模型拒绝未知字段，旧配置文件中残留这些键会在加载时报错，迁移说明见第 6 节。
- server 的错误映射：提交队列容量已满与已停止映射为 503 的稳定原因码，不再落入 500。

### 4.9 关闭与观测

- 关闭顺序沿用现有位置：认证网关先关闭，新的导入请求以 503 拒绝；Import Bus 在原被动摄入的位置等待在途请求结束（串行门中的会话），不再排空队列；提交队列由 Patchouli 停止时排空。`SYSTEM_STOPPED` 的数据改为报告 Import Bus 等待的结果。
- Import Bus 没有维护任务，不再向调度器注册。
- 运行时事件：`import.turn.accepted`（落位的话题、是否新建、价值信号）、`import.turn.duplicate`、`import.turn.skipped`、`import.turn.deferred`（可重试失败，原因为 `gateway_unavailable` 或 `queue_unavailable`）。事件只携带来源、外部会话与轮次标识、`interaction_id` 与事件数量，不携带正文与工具参数，沿用现有的脱敏规则。

### 4.10 生成视图：思考与外部工具的三元组

owner 于 2026-10-21 决定（Import Bus Idea Q-15 之后的决定）：记忆生成的转写纳入思考与外部工具的三元组。改动只在 Patchouli 的生成视图与 token 统计，`TurnRecord`、`AgentAction` 与交互 Artifact 的内容不变。

- **思考**：两条链路都按出现顺序渲染。附属于某个动作的思考随该动作渲染，未附属于动作的思考（例如第一次工具调用之前的推理）从 `turn_events` 单独成行。Alice 目前不产生思考事件，它的转写不变。
- **非 MTP 工具的动作**：按思考、工具名、参数摘要与结果渲染；结果按单条上限截断，出错的结果标明状态并优先保留。
- **MTP 动作**：维持现有的一行摘要（SEARCH、READ、RUN，CALL、WRITE、UPDATE 仍不渲染），不渲染结果。READ、SEARCH 的结果是从记忆库读回的内容，渲染进生成会把已有记忆重复提取。
- **单轮上限**：一轮的动作渲染有总上限。超出时依次保留思考、出错的动作、最近的动作，其余动作只保留工具名与参数摘要的一行。
- **上限的配置**：`patchouli.generation.transcript` 新增思考、参数摘要、单条结果与单轮动作的字符上限（候选默认依次为 1000、300、800 与 8000，阶段四按真实样本调整）。
- **token 统计**：块的 `total_tokens` 计入新增渲染的长度，统计与生成转写使用同一套截断规则，折叠阈值因此反映生成实际看到的材料。
- **提示词**：提取记忆的提示词说明动作段的含义：工具结果是外部观察，可以作为事实依据；思考是 Agent 的推理，不能当作用户陈述或已验证的事实；不要把密钥、令牌等凭据写入记忆。

### 4.11 Claude Code 连接器

**位置与组成**：插件根目录 `integrations/claude-code/`，含 `.claude-plugin/plugin.json`、`hooks/hooks.json` 与 `connector/`。连接器只用 Python 标准库，不依赖 HiveMemory 包，可由 Claude Code 所在环境的 `python3` 直接运行。`connector/` 按 Import Bus Idea 第 5 节分层：公共骨架（状态、游标、提交与重试分类）与 Claude Code 读取器（会话记录的解析与轮次切分）分为不同模块，接入第二个 harness 时再把骨架抽出共用。

**hooks**：均以不阻塞 Claude Code 的方式运行。

| hook | 行为 |
|:---|:---|
| `Stop` | 把会话记录中最后一轮记为 `completed`，再同步这份会话记录 |
| `StopFailure` | 把最后一轮记为 `failed`，再同步 |
| `SessionStart` | 登记这份会话记录（首次见到的规则见下），并补发其他会话记录中尚未提交的已结束轮次 |
| `SessionEnd` | 结束这份会话记录中仍未结束的最后一轮（没有结束记录的记为 `cancelled`），再同步 |

**轮次的切分与映射**（读取器，按所装版本核对）：

- 只读取 `user`、`assistant` 与 `system` 条目，跳过其他类型、`isSidechain`、`isMeta` 与 `isCompactSummary` 的条目，以及压缩边界；不认识的条目跳过，不报错。
- 一轮从一条由人发出的用户消息开始，到下一条这样的消息之前为止；`external_turn_id` 取开启该轮的那条用户消息的标识。
- 助手内容块 `text` → `assistant_message`，`thinking` → `thought`（只能转交 Claude Code 写入本地记录的思考；本地核对中多数 thinking 块只有签名、没有正文，阶段三核对能否经设置取得完整思考），`tool_use` → `tool_call`（`action_id` 为工具调用标识，`tool_args` 为输入）；用户条目中的 `tool_result` → `tool_result`（`action_id` 为对应的工具调用标识，出错时 `status` 为 `error`）。`assistant_final_text` 取最后一次工具结果之后的助手正文，`model_used` 取最后一条助手条目的模型。
- `recent_turns` 取该轮之前最近三轮的用户消息与最终正文。

**结局**：由 `Stop` 结束的轮次为 `completed`，由 `StopFailure` 结束的为 `failed`；被下一条用户消息或会话结束关闭、没有结束记录的为 `cancelled`。结束记录先写入状态再提交，发送失败后的重发仍使用原结局。

**游标与状态**：状态文件位于插件数据目录，按会话记录保存游标（最后一个已提交轮次的标识与其后的文件位置）与结束记录，读写持文件锁、以替换方式原子写入。

- 一轮在其后出现下一条用户消息、刚收到结束记录或会话已结束时才算结束；会话记录末尾仍在进行的轮次不提交。没有 `SessionEnd` 的崩溃会话，在后续扫描中末尾超过 30 分钟没有新条目时按 `cancelled` 结束。
- 按顺序提交，确认后游标才前进。遇到可重试错误（网络错误、503）立即停止这份会话记录，保留游标等待下次唤醒；不可重试错误（4xx）把该轮的标识、状态码与原因（不含正文）写入数据目录中的拒绝记录，游标前进；同一轮连续三次得到 500 也按不可重试处理，避免一轮阻塞整份会话。
- 首次见到的会话记录：首个条目晚于连接器首次运行时间的从头读取；更早的（接入前已经存在、后来被恢复的会话）游标放在当前末尾，不回填。
- 文件位置失效（会话记录被重写或缩短）时从头扫描到已提交的最后一轮之后继续；找不到该轮时停止处理这份记录并写入拒绝记录，不重发整个会话。

**配置**：环境变量 `HIVEMEMORY_URL`（默认 `http://localhost:8000`）、`HIVEMEMORY_USER_ID`（缺省时不发送用户头，由服务端取默认用户）、`HIVEMEMORY_AGENT_ID`（默认 `claude_code`）。连接器的日志与拒绝记录只写标识与状态，不写正文。

**安装**：以本地目录加载插件，步骤写入 [安装与启动](../help/setup.md)；不发布到插件市场。

### 4.12 访问登记

`configs/workspace_actors.yaml` 为 `default` 用户在 `main_workspace` 登记 `claude_code` 的精确记录，`allowed_operations` 为空：精确记录优先于用户级记录，这个 Agent 只能准入，不继承用户级的六项操作。不为它建立 Agent Profile。由交互结算生成的记忆是 PUBLIC，Alice 的会话可以召回。

## 8. 测试和验收标准

按[测试设计规范](../governance/testing/test-design-standards.md)分类；每条不变量只在作出判断的归属层写权威测试，上层与 E2E 只保留代表性链路，验收测试写入归属层的现有文件或新模块对应的测试文件，不以计划命名。

1. **共用封口**：同样的输入经 core 封口函数得到的载荷与迁移前的任务进程封口一致；缺少助手消息时补齐；非 MTP 工具调用不产生轨迹；Gateway 决定缺省时价值信号与改写查询为空（core 的归属层测试，原封口测试随函数迁移）。
2. **导入授权**：已准入且目标一致时返回 scope 与 principal；context 失效、目标不一致时拒绝；空白名单的 Agent 可以通过；只有 Import Bus 服务调用它（workspace 授权测试与架构测试）。
3. **Patchouli 契约**：新话题的标题与摘要随提交到达感知并用于建立话题，非 `NEW_TOPIC` 时携带它们被拒绝；接纳查询区分已接纳与未接纳，归属不同时报冲突；编解码拒绝旧版本键集（Patchouli control 与 services 的归属层测试）。
4. **Import Bus 编排**：已接纳的轮次返回 `duplicate` 且不调用 Gateway；没有输出的轮次返回 `skipped`；Gateway 可恢复失败为可重试错误、契约错误与程序错误原样传播、取消原样传播；最近轮次按上限截断；同一外部会话串行、不同会话并发；`interaction_id` 对同一输入稳定、对不同 actor 或来源不同；事件不携带正文（System 归属层测试）。
5. **HTTP 入口**：未知字段、非递增序号、`user_message` 类事件、携带 `tool_kind` 的事件与过大的请求体被拒绝；缺失 Agent 或 `system` 返回 400；未登记的 Agent 返回 403；认证网关关闭与队列拥塞返回 503（server 路由测试；错误信封由现有的 OpenAPI 测试覆盖）。
6. **真实队列与感知**：导入的一轮经真实队列应用一次，重发不重复应用；新话题带 Gateway 的标题（集成测试，改写现有被动提交的集成测试）。
7. **关闭**：认证网关关闭后新请求被拒，在途请求完成后服务才报告关闭；不再注册维护任务（System 生命周期测试）。
8. **代表性链路**：经 HTTP 导入一轮完整记录，最终在 Patchouli 中形成该轮的交互（离线 E2E 一例，存储与模型按现有 E2E 的方式替换）。
9. **生成转写**：思考按出现顺序渲染，附属于动作的随动作、其余单独成行；非 MTP 动作渲染思考、工具名、参数摘要与截断的结果，出错的结果标明状态；超出单轮上限时依次保留思考、出错的动作与最近的动作，其余降为一行；MTP 动作的渲染与现状相同；只有用户消息与最终回复的轮次与现状相同（prompts 转写的归属层测试）。
10. **token 统计**：块的 `total_tokens` 计入新增渲染，且与生成转写在同一截断规则下一致；折叠阈值按新统计触发（感知引擎的归属层测试）。
11. **连接器骨架**：确认后游标才前进；可重试错误保留游标并停止处理该会话记录；4xx 与连续三次 500 写入拒绝记录并前进；结束记录先于提交写入；首次见到的旧会话不回填；文件位置失效时从已提交的最后一轮之后继续；并发运行时状态文件不损坏（连接器的单元测试，使用合成的会话记录，不使用真实对话）。
12. **Claude Code 读取器**：合成会话记录覆盖普通轮次、工具调用与结果、思考、子代理条目、压缩摘要、元条目、未知条目与中断；切分、映射、结局与最近轮次符合第 4.11 节（同上）。
13. **真实使用（阶段四，人工）**：在 Claude Code 中安装插件并日常使用一段时间：记忆库出现来自这些会话的记忆，可从记忆回查到交互 Artifact 与来源会话；中断的轮次以 `cancelled` 进入；HiveMemory 停止期间 Claude Code 正常工作，重新启动后积压的轮次按顺序补发且不重复；Alice 的新会话能召回这些记忆。

| 风险或问题 | 处理 |
|:---|:---|
| Claude Code 的会话记录格式不是公开接口，升级后可能变化 | 解析只在读取器中，跳过不认识的条目；阶段三记录所核对的版本；格式变化导致无法切分时写入拒绝记录，不静默丢弃 |

| Claude Code 本地记录的思考可能只有显示用的摘要 | 连接器只能转交本地记录的内容；阶段三核对设置，结论记入第 11 节 |

### 阶段一：服务端的 Import Bus（2026-10-21，commit `f995ea7f`）

按第 7 节阶段一的五步实施，第 8 节第 1–8 项的测试写入各自归属层：core 封口、workspace 授权与架构测试、Patchouli control/application/感知、System 编排器、server 路由与错误映射、真实队列与感知的集成测试，以及离线 E2E 一例。

### 阶段三：Claude Code 连接器（2026-10-21）

**核对的版本与接口**：本机 Claude Code CLI 2.1.278、VS Code 扩展 2.1.304。hooks 与插件按官方文档（经 Context7 查询，2026-10-21）核对：

- 全部 hook 的输入带 `session_id`、`transcript_path`、`cwd`、`hook_event_name`；`Stop` 在用户中断时不触发；API 错误结束一轮时触发 `StopFailure` 而不是 `Stop`，输入另带 `error`；`SessionStart` 的 `source` 为 `startup`、`resume`、`clear`、`compact`；`SessionEnd` 的 `reason` 为 `clear`、`resume`、`logout`、`prompt_input_exit`、`bypass_permissions_disabled`、`other`。
- `SessionEnd` 的 hook 默认只有 1.5 秒，插件 hook 设置的 `timeout` 不会提高这一时限；命令 hook 支持 `async: true`。
- 插件的持久数据目录为 `${CLAUDE_PLUGIN_DATA}`（`~/.claude/plugins/data/{插件标识}/`，插件更新后保留）；`--plugin-dir` 只对一次会话生效，长期使用以本地 marketplace 安装。

**不阻塞的方式**：四个 hook 同步运行，但只做本地工作（登记、写结束记录），网络提交交给脱离 Claude Code 的后台进程（独立会话，不继承标准输入输出）；本机冒烟测试中 hook 耗时约 0.05 秒。`Stop` 必须同步运行：它在下一条消息写入之前结束，“最后一轮”才确定是刚结束的那一轮；`SessionEnd` 也因 1.5 秒时限只写结束标记。

**会话记录的结构核对**：读取本机会话记录目录被 Claude Code 的自动模式拦截（判为会话记录篡改），改由 owner 运行连接器附带的 `integrations/claude-code/scripts/transcript_stats.py`（只统计字段名、类型、计数与 Claude Code 写入的固定标记和枚举，不输出正文）。2026-10-21 在 41 份主会话记录与 17 份子代理记录（版本 2.1.280–2.1.304）上的结果：

- 由人发出的消息：带 `turnOrigin` 的用户条目 1304 条，其中 `human` 1284 条、`task_notification` 19 条、`peer` 1 条；全部用户条目都带 `promptId`。没有 `turnOrigin` 的 23390 条用户条目中，23078 条是工具结果，其余是元条目（139）、压缩摘要（56）、中断标记（12）与工具注入的内容（带 `sourceToolUseID`/`turnCompanion`，66）。读取器因此只认 `turnOrigin` 为 `human` 的消息开启新轮，不再把没有该字段的文本条目当作提问。
- 被中断的轮次：12 条 `[Request interrupted by user]` 文本的用户条目，都没有 `turnOrigin`；另有 1 条助手条目带 `isAbortedMidStream`。读取器以前者结束一轮。
- 子代理：独立写在会话目录的 `subagents/` 下，条目带 `isSidechain` 与 `agentId`；读取器只读主会话记录，并跳过 `isSidechain` 条目。
- 同一 API 消息：助手内容块总数等于助手条目数（49948），每个条目只含一个块并带 `apiBlockIndex`，是增量写入；读取器按消息标识与块位置去重。
- 思考：18413 个思考块中只有 2219 个有正文。官方文档：较新的模型默认不返回思考正文（`display` 为 `omitted`），`showThinkingSummaries: true` 只在交互式 CLI 中恢复思考摘要，对 VS Code 扩展无效，且返回的始终是摘要而不是完整推理。连接器只能转交本地记录中有正文的思考。
- 其他：`system` 条目为 `compact_boundary`（56）、`api_error`（42）与 `local_command`（3）；工具结果的 `is_error` 有 `true`、`false` 与缺失三种，内容多为字符串，少数为块列表；另有大量内部条目（`attachment`、`api-request`、`last-prompt` 等），读取器都跳过。

**实施中与第 4.11 节描述不同或第 4.11 节未写明的取舍**：

- 插件名 `hivememory-connector`；`integrations/.claude-plugin/marketplace.json` 声明本地 marketplace `hivememory-local`，只供本机安装，不发布。启动脚本 `hivememory_hook.py` 把插件根目录放进导入路径后交给 `connector` 包。
- 状态目录依次取 `HIVEMEMORY_CONNECTOR_STATE_DIR`、`CLAUDE_PLUGIN_DATA`，都没有时用 `~/.hivememory/claude-code-connector`；状态按会话记录分文件，读改写持状态锁，同一会话记录的同步另持同步锁，提交期间不阻塞 hook。
- 4xx 中只有 413 与 422（这一轮内容本身的问题）写入拒绝记录并前进；其余 4xx（身份声明不合法、未获准入、地址或版本不对）是连接器配置的问题，前进会让后续轮次全部丢失，因此与可重试错误一样保留游标、停止处理，修正配置后补发。
- Claude Code 写入的 `[Request interrupted by user...]` 标记立即结束一轮（结局 `cancelled`），不必等下一轮或会话结束。
- 游标的有效性除了落在行首，还核对最后确认的一轮仍从记录的位置开始：重写后的文件恰好在原位置换行时，只检查行首会让游标悄悄落到别的内容上。
- 会话记录被删除（例如过期清理）时移除它的状态，不写拒绝记录、不再补发。
- 条目缺少 `sessionId` 时，外部会话标识取会话记录的文件名。
- 结局以状态中实际保存的为准提交：同步与 hook 可能同时为同一轮写结局，先写入的生效。

**安装步骤（草稿，收尾时写入[安装与启动](../help/setup.md)）**：在 Claude Code 中执行 `/plugin marketplace add <仓库>/integrations`，再 `/plugin install hivememory-connector@hivememory-local`；按需在环境中设置 `HIVEMEMORY_URL`、`HIVEMEMORY_USER_ID`、`HIVEMEMORY_AGENT_ID`；`configs/workspace_actors.yaml` 已为 `claude_code` 登记准入。

**阶段三代码审查记录的、未在本阶段改动的事项**：

- 30 分钟无新条目即按中断结束的规则，会把等待权限确认超过 30 分钟、恰逢其他会话启动补发的一轮按中断提交，之后写入的内容不再导入。
- 超过请求体上限的一轮以 413 拒绝后整轮跳过（第 9 节已登记），阶段四观察比例。
- Windows 上的文件锁改为持续重试取得；连接器只在 Linux（WSL）上验证过。
