# v0.7.0 A6：Actor 适配、执行边界与集成收口

A1–A5 分别交付访问边界、资源读取与缓存、交互/Topic、Pending 与统一 API 收敛，但只有 A6 会把现有消费者真正切换过去。A6 不再创造新的业务 API；它负责 Root/CALL/Profile、MTP SEARCH/READ/WRITE/UPDATE、管理入口、Passive context/submit、Alice finalize 和 System composition 的适配与退出旧旁路。

## 1. 依赖与非目标

A6 依赖 A1–A5 各自稳定的签名和行为证据。它可以按读取、交互、Pending、执行 capability 和装配分批推进，不要求未稳定的完整系统提前进入生产 assembler。具体外部协议由 B 负责；真实厂商 connector、MTP RUN 可靠性、强沙箱、配额和通用恢复留给 v0.7.1。

现状迁移证据是[WRX-0](./v0.7.0-plan-a-wrx0-boundary-freeze.md)的读取 R1–R7、兼容矩阵及 prepare/finalize 差额。主要代码入口包括 `alice/runtime/profile_resolver.py`、`alice/services/`、`agent_runtime/aliases/resolver.py`、`agent_runtime/mtp/`、`patchouli/service.py`、`system/application/`、`system/services/passive/` 和 `system/assembler.py`。只按证据安排剩余改动，不把已有 WRX-0/1 的函数和测试重新实现一次。

2026-09-23 边界宪章修订：按[计划 A 边界宪章](./v0.7.0-plan-a-boundary-charter.md)，alias resolver 与 profile 读取 resolver 迁入 workspace runtime（不是 Patchouli），缓存归 workspace runtime、库只在受控提交后发布失效事件（D1–D3）；pending 资源状态归 workspace registry。下文旧表述已随动。

## 2. 消费者迁移

Topic prepare/handle 的有效性、接纳后责任转移、条件清理及资料交接统一消费 [A3 第 4 节](./v0.7.0-a3-conversation-session-and-topic-projection.md#4-topic-路由指令与交接)。A6 验证真实调用方按该契约交接并正确释放附件 lease，不新增 handle 生命周期；需要将某次交互纳入主动生成时须查询其 applied 和实际 Topic 关联，不能仅凭 prepare 或路由结果认定内容已应用。

| 适配区域 | 迁移动作 | 完成条件 |
|:---|:---|:---|
| Root/CALL/Profile | 经 A1 access 经 workspace 能力面取得 AgentProfile（L2 为 A2 Profile API）；Alice 应用执行配置并拼装 prompt | 根与 CALL 使用同一资源授权/解析规则；不依赖 ProfileSnapshot；builtin 也无本地解析旁路；caller/callee scope 分开 |
| SEARCH/READ | MTP resource adapter 走 workspace 能力面，消费 A2 完整原子/列表与 A4 固定状态结果；在调用侧编译/包装 | 不直查 Pending/cache 或自行跟随 settlement；MTP 输出/SSE 兼容，不要求领域层返回 RetrievalResponse |
| Passive | 记忆 context 通过 resource.search 取得原子列表并编译；seal 后用 A3 InteractionPayload 调 interaction.submit | 两项操作可复用 A1 网关签发的有效认证上下文，但分别检查行为许可；接纳前不清空 buffer；重复完成沿用 interaction_id，不重复应用 |
| Alice finalize | 运行侧保留 TurnEvent 并封装 InteractionPayload，分别调用 interaction 与 memory_intent | 不直接调用内部 queue/controller；缺少保存工具也自动提交完整交互 |
| Attachment | 通过 Asset application 取得 READY lease，交给 AttachmentCompiler | lease、revision、release 和 scope 语义保持 |
| 结果观察 | 通过带 scope 的 application 投影观察 interaction/Pending/task | task ID 不成为越权凭证；canonical 另行授权 |

## 3. Alice 与 AgentRuntime 的最终边界

Alice 保留 run/frame/loop、模型调用、取消/超时、working history、执行结果、run/frame 与 Pending 引用的关联，以及 adapter 的提交时机。它移出 Profile/Atom cache、Pending 权威状态、Patchouli 私有 store/local route 和“停止 Alice 即清资源”的生命周期假设。

`agent_runtime/runtime.py` 聚焦执行信号和输出。原 `aliases/resolver.py` 的领域解析迁入 workspace resolver（宪章 §5/§6.2）；如保留兼容入口，仅将 run-local 引用转换后调用 workspace 能力面、适配公开结果与 MTP 格式，不保留 Pending 判定、cache 命中、冷读或 settlement 跟随算法。`finalize_run` 产生 settlement/harvest action，由 adapter 调用共同路由，不再拥有全部 materialization policy。A3 的 Session 历史、Topic working set 和 Alice prompt history 彼此分开；外部 Session 不被 Alice 的压缩策略改写。

Alice 的 prepare 可以利用 Topic 视图选择临时上下文，但运行输入、StreamPrelude、PreparedAgentRun、模型配置与 working history 都归调用侧。已有 TurnEvent 及其 action 关联直接保留在 A3 的 InteractionPayload 中，不能为了形式统一先丢掉结构再从文本猜测，也不另提交 execution_projection 正文。TurnEvent→AgentAction/TurnRecord 的领域投影规则只维护在 Patchouli，不在 Alice、Passive 和 B 分别实现。

调用侧保留尚未交接的工作及必要 shield/continuation；领域接纳后责任转交 Patchouli，客户端断连不能撤销已承诺的处理。为纳入本轮资料，Alice 可等待交互 applied 再提交 intent，但二者仍是独立操作；一个失败不能改写另一个已成立的结果。frame 级收束、run 级提交、Pending 结算和 cache 失效分别验收，避免单帧 finalize 过早清理整个 run。

### 3.1 Profile 应用与 resolver 退出

按 [A2 第 2.3 节](./v0.7.0-a2-workspace-resource-reads-and-caches.md#23-profile-读取时序)，Alice `AgentProfileResolver` 的缓存、builtin 和资源有效性判断退出，由 workspace profile 读取 resolver 承接（源原子定位、解析结果缓存、交付授权——宪章 §5）；解析纯能力（按原子解析入口：`from_atom` + builtin 规则，agent_id 由解析填入）由 Patchouli Profile API 提供，必要总线调用/MTP 错误转换并入既有 adapter。Root 与 CALL 经 workspace 能力面取得定义，`CallContextProvider` 的 context_refs 使用共同引用读取。调用方可按既有编排决定缺失 context_ref 的展示/跳过策略，但不重新解释资源权限和 Pending 终态。

`AgentPromptAssembler` 及运行配置应用仍属 Alice 执行侧：组合 persona、MTP 指令、记忆、附件、Topic/共享上下文，绑定实际模型和工具限制。已启动 run 固定实际取得的 AgentProfile 副本，不要求公共结果额外提供 source/version。完整资源及 provenance 通过相应 Memory API 取得；来源记录必须有真实依据，不能把另一次读取所得的版本自动配给本次配置，builtin 也不伪造源原子。修改资源后下一次共同读取取得新定义，不借缓存失效暗中重写运行配置。后续资源操作仍按当前权限执行，Profile 读取不授予 CALL 身份、RUN 或 UPDATE 权限。

外部 Actor 不要求实现上述 Alice 拼装流程。B 暴露 Profile 定义读取即可，具体 harness 能否加载或部分应用由其 adapter 明示；不能修改 system prompt 的参考客户端仍须完成共同记忆链路。A6 不新增跨 harness 配置框架或 Profile 热加载机制。

## 4. MTP capability seam

按 protocol/resource/execution/tool 四类依赖拆分：protocol 保存语法、结果、错误和 SSE；resource 取得 access 调 workspace 能力面（L2 为 A2–A5 backing 路由）或 System Asset API；execution 维护 Alice frame/run；tool provider 显式绑定环境和 Workspace。第二 Workspace 不能静默复用第一个 `workspace_path`，缺少环境绑定要明确失败。A6 只验收 capability 可分别替换、拒绝越界和保留现有 envelope，不实现 v0.7.1 的强沙箱。

## 5. 装配、关闭和迁移

稳定后由 System composition 创建总线、A1 统一 Actor Authentication 网关、Patchouli application、WorkspaceRuntime、AssetStore 和 adapters；composition 只装配，不作请求时 service locator，网关本身承担运行期两项认证。三类 adapter 使用同一认证入口，公共 application 只消费中立 context 和共享行为检查，不依赖 System 网关实现。关闭顺序固定为：停止网关接受新认证 → 停止新执行 → 等待 resource reads/settlement → drain producers → detach consumers → close 网关/runtime/store；关闭网关后旧 context 失效，已接纳工作按原 drain 契约收尾。先卸载 Alice bridge 会丢最后 settlement，必须有可重复测试。

旧 cache、旧 Pending、旧 prepare/finalize/cleanup 入口只可在明确期限内委托到新实现；一次操作不得同时进入新旧成功路径。回滚不得重放已接纳副作用、删除 Session/Pending 或开放裸 scope。

### 5.1 兼容和删除清单

| 旧入口/契约 | 过渡与退出要求 |
|:---|:---|
| `AliceRuntime.atom_cache/profile_cache`、clear_derived_caches | 仅迁移窗口允许委托单一 cache；A6 删除直接命中/预热/失效、属性和 stop 清理，缓存归 workspace runtime，库在受控提交后发布失效事件（宪章 §4.4 D1–D3） |
| 旧 cache 模块导入 | 允许有期限 re-export 供源码迁移；测试改为新行为入口，A6-4 删除旧 import，不用 re-export 测试作为验收 |
| ProfileResolver/CallContextProvider | 资源定义统一走 Profile API，删除本地 builtin/cache 判断；保留执行配置和 prompt 组装，兼容薄转发可并入现有 adapter |
| `ProfileSnapshot` / `GET_AGENT_PROFILE_SNAPSHOT` 依赖 | 消费 A2 的 AgentProfile 正式结果，删除旧导入/调用与包装断言；不得恢复已删除路由或伪造 builtin/source DTO |
| `RetrievalResponse` / `AgentRunContext.retrieval_result` | 消费 A2 原子列表；旧 MTP/Passive 协议或本地上下文确需 envelope 时由 adapter 构造，数量和耗时来源明确；移除对 Patchouli 返回该类型的依赖，核对相关测试与类型标注 |
| RuntimeAliasResolver L0/L1/L2 | Pending/canonical 统一交 workspace 读取能力面解析；删除本地分派/命中/冷读/跟随，run-local 仅保留关联和协议转换 |
| Patchouli prepare/finalize/cleanup 公共入口 | 每项职责对照 A5；删去直接 queue/generation/local route 的第二成功路径，必要兼容仅委托并记录调用方/删除时点 |
| 旧裸 IdentityScope 业务路由 | System service/AliceBridge 透传完整 access；内部领域层才派生 scope，迁移结束不得留下无 grant 公共成功路径 |
| MTP method/result、SSE/error | 名称与成功/失败 envelope 默认兼容；内部签名可以变化，差异单独列清楚 |
| WorkspaceAsset、Topic binding、Artifact provenance | READY/lease/revision/release 不变；实际使用 refs 快照在交互 applied 后绑定，重试不替换 |

组合测试先直接构造真实总线/bridge/application/runtime，未稳定前无需调用生产 HiveMemorySystem.build。最终生产接入仍是 A6-4 的完成条件，不能用“没有提前装配”豁免最终集成。B 的新 transport 有自己的装配验收，但共用这里的资源就绪与关闭顺序。

## 6. 实施、测试与收口

| 阶段 | 产出 | 验收 |
|:---|:---|:---|
| A6-0 | Root/CALL/Profile、SEARCH/READ、Asset 和 Passive context 迁移 | 真实总线/application 协作，权限、来源、错误和 lease 不回退 |
| A6-1 | A3 InteractionPayload 生成与 interaction/result adapter | 自动交接不依赖模型保存工具；Session 不被 RelayController 压缩 |
| A6-2 | A4 Pending/workset/settlement 与共同引用读取接入 | 无 Pending 克隆或 Alice 领域 resolver；交互与主动意图独立；取消/断连/drain 正确 |
| A6-3 | MTP capability 注入和环境绑定 | resource/execution/tool 可替换；第二 Workspace 不串文件根 |
| A6-4 | 生产装配、旧旁路退出、事实文档和 ADR 收口 | 无 Alice 资源闭环、Alice 参考闭环、shutdown 和兼容矩阵全部通过 |

integration/e2e 使用真实 GlobalSystemBus、PatchouliBridge、application、WorkspaceRuntime、AssetStore、Pending 和 queue；外部模型/网络可用确定性替身。覆盖两个 Workspace 并发、完整/partial 交互、无关联事件保留、无保存工具交互、空 Topic 主动写入、cache invalidation、结果越权、shutdown drain 和 MTP error/SSE 兼容。转发次数、类名和 fake handler 不构成完成证据。

| 验证组 | 组合证据 | 必须识别的反例 |
|:---|:---|:---|
| headless resource | 无 Alice/MTP 的两 Workspace Profile/Memory/READY Asset 读取、变更再读 | 隐式创建 AliceRuntime、管理 bypass 污染 Agent、失效后返回旧值 |
| interaction | 真实 queue/application 接收 A3 样例、查询 apply/assignment | 没有模型保存工具就漏交互、只解析 schema 但未路由、重复封口生成两个 blocks |
| headless Pending | 登记→物化前 READ→提交→结算→原引用解析 | 空 Topic 跳过、只看最近五条、事件丢失改变终态、canonical 读取缺重验 |
| common reference read | 同授权条件下，System/Alice/外部 adapter 读取 Pending、终态、redirect、canonical，覆盖 cache hit/miss | adapter 自行判 Pending、跟随 alias、缓存旧 policy；协议不同造成领域结果不同 |
| Profile definition/application | Root/CALL 读取相同定义后应用配置；无 prompt 注入能力的客户端仅读定义仍可使用记忆 API | 读取成功冒充配置已应用；Profile 失效暗改已启动 run；以 profile.read 扩大执行权限 |
| Alice execution | 并发 run/frame、CALL 身份、取消/超时/continuation、主动提交一次 | 两 run 串 history/pending、frame finalize 过早驱逐、断连中断已承诺交接 |
| lifecycle | 停收、仍在途的读取/交互/intent、producer drain、consumer detach、close | 提前卸载 bridge 丢最后 settlement、停 Alice 清全局资源 |
| static/compatibility | 跨包 import、旧 public route、cache/Pending 单一来源、HTTP/MTP/SSE | Workspace 导入私有 provider、同进程旁路、application/cache 递归 |

各子计划已经通过的局部测试不在 A6 重复写一份；这里补跨组件回归。遵循仓库测试规范与实际 CI 配置，原计划快速集/覆盖率和 e2e 门槛在实施时核对，不能为便于迁移降低既有质量门槛。最少同时保留真实无 Alice 资源证据和 settlement 证据，B 的 HTTP 客户端不能替代它们。

A6 完成后按文档治理更新事实文档并分别归档已完成子计划；计划 B 仍需独立完成外部协议与参考客户端出口，A6 不把 B 未完成写成 A 的失败，也不把 A 的完成写成整个 v0.7.0 已发布。
