# v0.7.0 Alice 与 agent_runtime 结构重构

> **文档状态**：Planned（2026-10-17）。v0.7.0 收尾工作，在 `refactor/v0.7.0-cleaning` 分支实施，不改变已发布版本。

v0.7.0 把写入意图、读取缓存、Profile 解析、chat 编排与进程控制都从 Alice 中移走之后，Alice 的职责收窄为“一次 CPU 执行内的多 Agent 调度与对外接口”，`agent_runtime` 仍是“把一帧运行到终态或 trap”的执行内核。本计划不改变这一分工，而是让两个包的目录结构重新与职责对应：alice 内部按依赖方向分层并消除子包间的环；`agent_runtime` 收回内核装配、建立唯一的公开接口；删除只有 Alice 自己调用的总线路由与 `done` 往返转换。

设计依据：

- 当前事实：[Alice](../alice/README.md)第 1、2、6 节（两层分工、`agent_runtime` 不是子系统、启停与公开能力）、[Agent Runtime](../alice/agent-runtime.md)第 1、4–7 节、[多 Agent 编排](../alice/orchestration.md)第 1 节、[MTP Runtime](../alice/mtp-runtime.md)第 1、2 节、[子系统契约](../contracts/subsystem-contracts.md)中 CPU 端口与 Alice 执行入口的说明、[System 配置](../system/configuration.md)中的 Alice 会话预算；
- 代码：`src/hivememory/alice/`、`src/hivememory/agent_runtime/` 与守卫 `tests/unit/architecture/test_alice_boundaries.py`、`test_access_boundaries.py`、`test_package_layers.py`（2026-10-17，master `239b1a7c`）；
- 已归档：[会话压缩](../archive/plans/v0.7.0-alice-session-compaction.md)（`alice.compaction` 配置段与上下文视图在本版本引入、未发布）、[总线路由类型化](../archive/plans/v0.7.0-typed-bus-routes.md)（Alice 路由拆为两条类型化路由）、[CPU 端口与测试 CPU](../archive/plans/v0.7.0-task-process-cpu-port.md)（任务进程只经对象端口调用 CPU）。

## 1. 背景和问题

两层之间的边界是健康的：`agent_runtime` 不导入 alice，alice 中只有 `RunExecutor` 推进 frame，两条都有架构测试；`src/` 中只有组合根从外部导入 `AliceSystem`。问题都在包内：

1. **alice 的三个子包互相依赖成环**。`application` 导入 `orchestration` 与 `runtime`；`orchestration` 导入 `application.operation_policy` 与 `runtime.runtime_events`；`runtime` 导入 `application`（bridge）与 `orchestration`（streaming 实现编排层的输出端口并使用 `RunSession`）。“application / orchestration / runtime”的命名看似分层，实际没有方向。
2. **`alice/runtime/` 承载四件互不相关的事**：内核装配（`AliceRuntime`，52 行，只构造 Koakuma 与 `AgentRuntime`）、总线挂载（`bridge.py`）、交互事件投影与流式队列（`streaming.py`）、观测事件（`runtime_events.py`）。`AliceRuntime`、`AgentRuntime`、`KoakumaRuntime` 三个名字并存。
3. **`orchestration/` 混入了单次 run 的上下文准备**：`context_view.py`、`relay_summary.py`、`summary_references.py` 约 470 行负责会话视图与压缩，与 CALL 调度无关。
4. **对外接口分散**：CPU 端口实现在 `application/cpu.py`，总线路由在 `contracts/` 与 `runtime/bridge.py`，交互事件形态在 `runtime/streaming.py`。两条总线路由在生产中只被同包的 `AliceCPU` 调用，参数中传递的是不可序列化的提交函数与结果槽；流式路径中 Alice 先把 `CPUExecutionResult` 拍成 `done` 字典，`AliceCPU` 再还原并从结果槽补回检查点。
5. **`AgentRunService`（541 行）承担整条骨架**：清单到上下文的转换、模型解析、会话压缩与进度事件、根帧创建、执行器、流式与非流式两条分支、结果组装、终态事件与结果槽回填，`if stream:` 出现七次。
6. **`agent_runtime` 没有公开接口**：alice 直接导入 `models`、`context_budget`、`policy`、`output`、`products`、`runtime`、`execution.worker`、`model_resolution` 八个内部模块。`models.py` 混合 frame 状态、停机信号、LLM 生成 DTO 与 MTP 执行上下文；内核装配一半在 `AgentRuntime.__init__`（循环与 Worker），一半在 alice 的 `AliceRuntime`（Koakuma）；输入预算依赖 `config.alice.CompactionConfig` 的两个字段；`WorkerAgentService` 实为 LLM 客户端，在 frame 外被 alice 的摘要器直接使用，litellm 的 15 个异常类型泄漏到编排层；Koakuma 一个类 853 行，协议分派、六个动词与用户工具沙箱混在一起，syscalls 挂在 `mtp/` 之下。
7. **两处落位与使用者不符**：`RuntimeScope`（`core/models/pending.py`）只被 alice 与 `agent_runtime` 使用；`MTPExecutionResult`（`core/protocol/models.py`）只被 `agent_runtime.mtp` 使用。

## 2. 目标与非目标

### 2.1 目标

1. **alice 按依赖方向分层**：`interface → run → {context, orchestration} → events`，各层只依赖下层与 `agent_runtime` 的公开接口，由架构测试固定。
2. **`agent_runtime` 收回内核装配并建立唯一公开接口**：alice 只经 `hivememory.agent_runtime` 包根导入，内部按 frame、模型、循环、MTP、工具划分。
3. **Alice 的对外接口只有 CPU 端口**：删除只被自身调用的总线路由与 bridge；流式输出以 `CPUExecutionResult` 作为最后一项，不再经 `done` 字典往返。
4. **运行骨架与输出形态解耦**：运行服务只面向输出端口，流式与非流式的差异收敛到接口层；上下文准备与结果组装从运行服务中拆出。
5. **行为与外部契约不变**：CPU 端口、输入清单与执行结果、交互事件名与字段、`agent.run.*` 与 `agent.context.*` RuntimeEvent、MTP 文本协议、取消与结果槽语义均保持现状。

### 2.2 非目标

- 把 Alice 专属的提示词组装（`prompts/assembler.py` 等）与 `AgentRunContext` 移出共享层；它们留在 `prompts` 与 `core.protocol`，需要时另行立项。
- 移除非流式交付路径（[收敛清单](../todo/v0.7.0-code-convergence.md)第 2.7 条已决定保留给 v0.7.1）。
- Koakuma 的行为调整：MTP READ 的输出顺序（收敛清单第 3.7 条）、RUN 目标的可执行性检查（[Todo](../todo/run-target-executability-check.md)）、内联中英文文案（第 3.8 条）。
- 工具执行的超时、隔离与 provider 化：`tools/` 只提供 v0.7.1 执行基座的落点，不在本计划改变执行语义。
- `agent_runtime` 与 alice 合并为一个顶层包：独立的顶层包让“内核不导入 alice”保持一眼可查。
- workspace 一侧的改动：任务进程、`workspace.contracts` 与 `outputs` 的投影不变。

## 3. 当前状态（2026-10-17 核对）

- **组合**：`AliceSystem.__init__` 构造 `AliceRuntime`（内部构造 `KoakumaRuntime`、`KoakumaMTPExecutor`、`AgentRuntime`）、`FrameFactory`、`AgentPromptAssembler`、`CallContextProvider`、`CallCoordinator`、`AgentRunService`（另构造 `RelaySummarizer(WorkerAgentService())`、`AgentRunStreamAdapter`、`AgentRunEventEmitter`）、`AliceBridge` 与 `AliceCPU`；`global_bus` 可为 `None`，此时没有 CPU 端口。
- **执行入口**：`AliceCPU.execute` 返回 `CPURunHandle`，经全局总线按 `stream` 选择 `alice.public.run_agent(_stream)`；bridge 以 `stream=False/True` 调用 `AgentRunService.run_agent`。Alice 停止时卸载路由，此后 CPU 调用在首次拉取时失败，进程按失败收口。
- **运行骨架**：`AgentRunService._run_agent` 在流式时创建 `AgentRunStream`（有界队列、runner task、`stream_sequence`），压缩进度以 `context_compaction` 事件直接产出，终态以 `done` 字典产出（排除检查点）；非流式直接 await `RunExecutor.run` 并产出结果；`finally` 中按三条路径回填结果槽。
- **执行内核**：`AgentRuntime.run_frame` 解析模型（`resolve_model` 与 `_input_token_limit` 在门面内，读取 `CompactionConfig.default_context_window/safety_margin`）后调用 `AgentLoopExecutor.execute_frame`；`FrameExecutionPolicy` 默认允许全部动词，Koakuma 在策略为空时放行；编排层用 `getattr` 读取 `max_iterations` 再写回策略。
- **配置**：`alice.compaction` 含 `default_context_window` 与 `safety_margin`；该配置段随本版本会话压缩引入，已发布的 `v0.6.2` 配置中不存在。
- **测试**：59 个测试文件导入这两个包；`test_alice_boundaries.py` 以文件名 `run_executor.py` 断言唯一的 `run_frame` 调用方，`test_access_boundaries.py` 以 `alice/application/cpu.py` 与 `alice/system.py` 作为允许接触线程凭据的文件。

## 4. 目标设计

### 4.1 职责划分

- **`agent_runtime` 回答“一帧怎么跑”**：模型解析与输入预算、LLM 调用、单帧循环、MTP 解析与分派、工具执行、帧级输出端口，以及 CALL trap 之后把响应写回挂起帧（`apply_call_response`）、收割成功帧的 ACK alias（`finalize_frame`）这两个帧级机制。它与 Agent 数量无关，不知道主帧、子帧或下一步调度谁。
- **alice 回答“有哪些帧、帧的输入是什么、帧之间如何衔接、结果如何交出”**：根帧输入（会话视图、压缩、摘要、引用线索）、CALL 调度与响应映射、operation 到 MTP 动词的翻译（“RUN 始终可用”是 Alice 的策略）、结果组装、观测事件，以及 CPU 端口的实现。
- 会话压缩留在 alice：检查点格式与会话语义是 Alice 作为 CPU 的策略；只有输入预算这一机制下沉到内核。

### 4.2 目标目录

```text
agent_runtime/
  __init__.py          # 唯一公开接口（4.3）
  runtime.py           # AgentRuntime 门面与内核装配工厂
  frame.py             # ExecutionFrame、ExecutionProgress、FrameExecutionResult/Status、CallSuspension、
                       #   FrameProducts、FrameExecutionPolicy、RuntimeScope
  loop.py              # AgentLoopExecutor
  output.py            # FrameOutputSink 与三类帧输出
  model/
    resolution.py      # ModelResolver 端口、ResolvedFrameModel、模型解析与输入预算
    budget.py          # 上下文估算与预算错误类型
    client.py          # LLM 客户端（原 WorkerAgentService）、GenerationResult、StreamChunk、提供商错误翻译
  mtp/
    runtime.py         # Koakuma：解析、动词检查、分派、格式化；MTP 执行端口
    context.py         # MTPExecutionContext、MTPExecutionResult
    verbs/             # 每个动词一个 handler；CALL 只产生 trap
  tools/               # 原 mtp/syscalls 与用户工具沙箱

alice/
  __init__.py          # 只导出 AliceSystem
  system.py            # 装配与生命周期
  interface/
    cpu.py             # AliceCPU：CPU 端口、线程提交函数绑定、启停闸门、流式与非流式的选择
    stream.py          # 有界队列、runner task、帧输出与 CALL 边界到交互事件的投影
  run/
    service.py         # 运行用例：清单→上下文、驱动根帧与执行器、终态事件
    result.py          # 执行结果组装与失败原因映射
  context/
    view.py            # SessionContextView、CompactionResult、CompactionFailedError
    builder.py         # 根帧输入：模型预算下的视图、压缩与进度报告
    summarizer.py      # RelaySummarizer
    references.py      # 摘要引用线索
  orchestration/
    executor.py        # RunExecutor（唯一推进 frame 的组件）
    session.py         # RunSession
    frames.py          # FrameFactory、FrameSpec
    output.py          # AgentRunOutput 端口与 CALL 边界输出
    verbs.py           # operation 快照到 MTP 动词的翻译
    call/

      context.py       # CallContextProvider、CallContext
      record.py        # CallRecord

```

文件名与类名是实施时的候选，实施评审确定后记入第 11 节；层次与依赖方向是本计划的约束。

### 4.3 `agent_runtime` 的公开接口

包根导出 alice 与组合根所需的全部符号，内部模块不再被 alice 直接导入：门面与装配工厂、frame 模型与停机信号、执行策略、帧输出端口与三类输出、`ResolvedFrameModel` 与 `ModelResolver`、LLM 客户端及其结果与错误类型、上下文估算与预算错误类型。测试可以继续导入内部模块验证内核自身。

- **内核装配收回内核**：装配工厂接收 `AgentRuntimeConfig`、`KoakumaConfig`、`MemoryCompilerConfig` 与可选的 `ModelResolver`，构造 Koakuma、MTP 执行端口、循环与 LLM 客户端并返回 `AgentRuntime`；删除 `AliceRuntime`。`AliceSystem.health()` 的输出结构保持不变，内核健康由门面提供。
- **输入预算的配置下沉**：`default_context_window` 与 `safety_margin` 从 `alice.compaction` 移到 `alice.runtime`，内核不再读取压缩配置。两个键随本版本引入、未发布，不提供兼容别名，随仓库发布的 `configs/config.yaml` 同步修改。
- **MTP 执行端口**：改为 `KoakumaRuntime` 直接满足的协议，删除只做委托的 `KoakumaMTPExecutor`。
- **必填的执行参数**：`ExecutionFrame` 与 `MTPExecutionContext` 的提交函数、执行策略改为必填，`FrameExecutionPolicy` 不再提供“全部动词”的默认值；Koakuma 公开方法的执行上下文改为必填；删除 `_handle_call` 中与统一检查重复的 CALL 判断。编排层构造策略时不再传 `max_iterations`，由门面统一回落到 `AgentRuntimeConfig`，门面只保留一个迭代上限属性。
- **提供商错误翻译**：LLM 客户端在调用边界把提供商错误翻译为一个中立错误类型（与上下文超窗错误并列），摘要器只捕获该类型；程序错误与取消照常传播。
- **两个类型移入内核**：`RuntimeScope` 移入 `frame.py`，`MTPExecutionResult` 移入 `mtp/context.py`；`ExecutionLabels` 与 `core.mtp` 的协议模型留在 core（workspace 契约、prompts 与 MemoryCompiler 使用）。

### 4.4 alice 的层次

| 层 | 可以依赖 | 不得依赖 |
|:---|:---|:---|
| `system.py` | alice 全部层、`agent_runtime` 包根 | — |
| `interface` | `run`、`orchestration.output`、`events`、`agent_runtime` 包根、`workspace.contracts` | — |
| `run` | `context`、`orchestration`、`events`、`agent_runtime` 包根 | `interface` |
| `context`、`orchestration` | `events`、`agent_runtime` 包根 | 彼此、`run`、`interface` |
| `events` | — | alice 其他层 |

线程凭据（`WorkspaceAccessContext`、`OperationEntry`）只在 `interface/cpu.py` 与 `system.py` 出现，frame、CALL 与 MTP 只持有提交函数，与现有守卫一致。

### 4.5 对外接口与运行骨架

- **删除总线路由**：删除 `alice/contracts/`、bridge 与 `AliceRoutes`，`AliceCPU` 直接调用运行服务。CPU 端口（`workspace.contracts.CPUPort`）是 Alice 唯一的对外契约，任务进程仍只持有端口对象。若将来出现经总线调用 Alice 的外部消费者，再按其需要重新声明路由。
- **启停闸门**：`AliceSystem.start/stop` 切换 CPU 端口的可用状态。未启动或已停止时，`execute` 返回的输出流在首次拉取时以结构化的不可用错误失败，进程的结局与现在路由未挂载时相同（按失败收口）；具体错误类型实施时确定。`AliceSystem` 的 `global_bus` 参数随路由一起删除。
- **运行服务只面向输出端口**：运行服务接收输入清单、提交函数、生成参数、结果槽与 `AgentRunOutput`，返回 `CPUExecutionResult`；压缩进度经输出端口发出（端口增加对应方法，或拆出运行级输出端口，实施时确定），非流式使用空实现。运行服务中不再有流式分支。
- **流式在接口层完成**：`interface/cpu.py` 在流式时用 `interface/stream.py` 创建有界队列与 runner task，逐项产出交互事件，最后产出 `CPUExecutionResult`（`CPUOutput` 本来就是交互事件与执行结果的并集）；非流式直接 await 运行服务。删除 Alice 的 `done` 字典与 `AliceCPU` 中的还原逻辑；检查点随结果对象交回，取消路径仍经结果槽。队列容量、背压、断流时取消并 join runner 的语义不变。
- **运行服务瘦身**：根帧输入（模型预算下的会话视图、压缩与进度报告）移入 `context/builder.py`；执行结果组装与失败原因映射移入 `run/result.py`；结果槽回填集中为一个收尾步骤。`StreamExitReason` 改为与流式无关的名字并删除未使用的成员；`RunSession.process_id` 改为必填；`RunSession.register_frame` 改为私有。

### 4.6 收敛清单中由本计划承接的条目

[v0.7.0 代码收敛清单](../todo/v0.7.0-code-convergence.md)中以下条目改由本计划处理，清单中已注明：第 2.3 条中 alice 与 `agent_runtime` 的部分（`AliceSystem` 的总线、frame 与 MTP 上下文的提交函数、Koakuma 的执行上下文、`RunSession.process_id`）、第 2.4、2.5、2.6 条、第 2.14 条中 `StreamExitReason` 与 `register_frame` 两行、第 2.15 条中 `operation_policy` 的落位、第 3.2、3.10 条。移动文件时，被移动文件中属于收敛清单第 1.1、1.8、4.2 条的注释一并按清单改写。

## 5. 受影响的系统、契约和数据

- **Alice 与 `agent_runtime`**：全部模块的位置；alice 包根只导出 `AliceSystem`。
- **组合根**：`system/assembler.py` 只需更新 `AliceSystem` 的构造参数（删除 `global_bus`）。

## 6. 兼容与迁移策略

- 阶段一、二只移动与重命名，不改变行为；文件移动使用 `git mv` 保留历史。
- 删除的符号与路径不保留别名或转发模块：两个包在 `src/` 中只有组合根一个外部导入方，随同修改。
- 配置键的移动不提供兼容别名（第 4.3 条）；`alice` 配置段对未知键的处理保持现状。
- 测试随源码移动到对应目录；契约有意变更的测试（Alice 路由的注册与卸载、经路由的调用）在同一改动中改写为 CPU 端口与启停闸门的测试，不留“路由已删除”式的墓碑测试。
- 收敛清单中其余涉及这两个包的条目以文件与符号为准，行号在本计划完成后失效。

## 8. 测试和验收标准

按[测试设计规范](../governance/testing/test-design-standards.md)分类；每条不变量只在作出判断的归属层写权威测试，上层与 E2E 只保留代表性链路。结构移动不新增行为测试，现有行为测试只改导入路径即为合格。

1. **行为不变**：Agent loop、CALL、会话压缩、流式输出、CPU 端口、任务进程与 HTTP chat E2E 的现有测试在每个阶段都通过；阶段一、二中这些测试的断言不变，只改导入路径。
2. **alice 层次**：AST 守卫按 4.4 检查 alice 子包之间的导入方向，`context` 与 `orchestration` 互不导入，子包之间无环（`tests/unit/architecture/test_alice_boundaries.py`）。
3. **既有守卫延续**：`agent_runtime` 不导入 alice；只有编排执行器调用 `run_frame`；线程凭据只在 `interface/cpu.py` 与 `system.py` 出现（同上，以及 `test_access_boundaries.py`）。
4. **公开接口**：alice 与组合根只从 `hivememory.agent_runtime` 包根导入（`test_alice_boundaries.py`）；包根导出集合覆盖这些使用方。
5. **必填参数与策略**：缺少执行策略或提交函数无法构造 frame 与 MTP 执行上下文；策略之外的动词在执行前被拒绝（`agent_runtime` 的 frame 与 Koakuma 单元测试，扩展现有 `test_policy.py`、`test_permissions.py`）。
6. **配置**：`alice.runtime` 的两个预算字段生效，输入上限按其计算（`tests/unit/system/test_config_agent_runtime.py` 与 `agent_runtime` 门面测试）。
7. **提供商错误**：LLM 客户端把提供商错误翻译为中立类型；摘要器对该类型放弃本次摘要、对程序错误与取消照常传播（LLM 客户端与摘要器单元测试）。
8. **工具与动词拆分**：syscall 与用户工具沙箱的现有测试随目录移动后通过；各动词 handler 的错误映射与现状一致（现有 Koakuma 测试）。
9. **CPU 端口**：流式时交互事件逐项转交、最后一项是带检查点的 `CPUExecutionResult`，不再出现 Alice 的 `done`；非流式只产出执行结果；输出流被关闭时 runner 被取消并 join；取消时结果槽仍交回部分输出与检查点（`tests/unit/alice/` 下 CPU 端口与流式测试，改写现有 `test_alice_cpu.py`、`test_streaming.py`）。
10. **启停闸门**：未启动与停止后的 CPU 端口在首次拉取时以结构化错误失败，任务进程按失败收口（CPU 端口单元测试，任务进程一侧保留一个代表）。
11. **契约测试改写**：删除 Alice 路由注册与卸载、经路由调用的测试，`tests/unit/system/contracts/test_public_routes.py` 与 `scripts/typecheck_bus_routes.py` 不再包含 Alice 路由。
