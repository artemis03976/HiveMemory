# 用户身份上下文与裸 user_id 兼容投影收敛

## 1. 计划定位

`v0.6.2` W0 Workspace MVP（已归档）建立了三模型身份坐标系：`ActorIdentity` 回答谁在执行，`WorkspaceIdentity` 回答资源归属于哪个用户与 Workspace，`IdentityScope` 冻结一次操作的不可变硬边界（当前事实见 [Workspace 架构](../architecture/workspace.md)）。W0 归档[实施计划](../archive/plans/v0.6.2-workspace-mvp.md)同时写明了收敛规则：新领域对象不得同时保留含糊的 `user_id`、独立 `owner_user_id` 与 `workspace_identity.owner_user_id`；历史 `meta.user_id` 只由 legacy decoder/filter 解释；兼容投影只允许存在于 storage adapter/filter builder。

当前代码中权威模型已在存储索引与资源键边界生效，但 server 与前端尚未同步 W0 的用户导向身份选择，裸 `user_id` 兼容投影仍在三类位置普遍残留：

1. **服务入口层**：应用服务以 `user_id: str`（常附带 `agent_id` 默认值）作为公共 API 签名，内部各自调用 `resolve_default_identity_scope`，形成"router 传字符串、service 再解析"的双重解析；各服务对缺失 agent 的默认值互不一致（`"ui"`、`"omni_doll"`、`DEFAULT_AGENT_ID`、空缺）。
2. **用户导向层**：前端仍只发送 `user_id` / `agent_id` 的旧组合，尚未显式传递 `workspace_id`；不同路由分别使用 body、query、header 或后端默认值，导致用户选择的身份上下文不能稳定冻结。
3. **领域模型层**：个别快照字段、共享命名键与读侧属性仍以平铺 `user_id` 字符串或兼容 property 表达 actor / owner 语义。

本计划在不触碰 W0 已裁定保留的存储兼容投影的前提下，把上述用户导向入口、服务入口与领域模型收敛到权威身份模型。它不是引入第二种后端身份 scope，而是让前端先冻结用户选择，再由 server 边界一次性构造唯一的 `IdentityScope`。它是 `v0.6.2` 内 W1 Chat Attachments 之前的契约清理切片：W1 必须复用稳定的 Workspace 公共契约，不应在裸 `user_id` 入口上继续叠加附件能力。

当前仍保留 W0 的 same-owner 边界：`actor_identity.user_id` 必须等于 `workspace_identity.owner_user_id`。本计划保留 actor 与 Workspace 两个独立身份轴，即使在当前阶段它们由同一用户选择构造。未来允许跨用户 Workspace 访问属于独立的授权/Grant 设计，不在本计划内。

用户导向层只冻结一次选择，不替代后端的执行事实。其传输形状为一个基础 Workspace 选择加一个可选的 Agent 选择：

```text
IdentitySelection
  user_id
  workspace_id
  agent_id?       # 仅 Agent action 提供
  session_id?     # Chat/被动会话需要时提供

server 边界
  -> 校验 user_id 与 workspace owner 的 same-owner 约束
  -> Agent action 要求具体 agent_id
  -> 非 Agent action 注入 SYSTEM_AGENT_ID = "system"
  -> 冻结为唯一 IdentityScope
```

`system` 的准确语义是“**没有具体 Agent 作为操作来源主体**”。它是 actor/provenance 的保留值，不是超级 Agent、不是前端可选 Agent，也不是 `MemoryAccessPolicy` 的授权目标。V2 Memory 的 `source_agent_id/source_team_id` 只记录来源；V2 可见性由 Workspace ownership 与 `MemoryAccessPolicy` 决定。

## 2. 当前基线与缺口

对 `src/hivememory` 全量调查（2026-09-05）发现约 39 处裸 `user_id: str` 字段/参数声明（`owner_user_id` 与 `ActorIdentity` 自身字段除外），routers 层约 56 处 `user_id` 引用。前端当前固定使用 `user_id=default`，Chat 传递 `agent_id`，Topic 通过 query 传递 `user_id`，其他管理请求依赖 server 默认入口，尚无 `workspace_id` 选择状态。按 W0 判定规则分为五类：

| 类别 | 代表位置 | 判定 |
|:---|:---|:---|
| A. 存储层 legacy 兼容投影 | `engines/retrieval/memory_codec.py` `_legacy_workspace_identity`；`engines/retrieval/filter_adapter.py` `_ownership_filter` legacy OR 分支；`core/models/memory.py` `to_qdrant_payload` 平铺索引 | W0 明确允许；保留至"Workspace 历史数据转换"未排期事项执行，本计划不动 |
| B. 读侧兼容属性 | `core/models/topic.py` `TopicData.user_id`；`core/models/interaction.py` `StreamMessage.user_id`；`engines/perception/models.py` `TopicMaterializeTask.user_id`；`core/protocol/models.py` / `agent_runtime/models.py` / `patchouli/models.py` 的 `.identity` property | 内部已权威，仅剩投影出口；收口或标注 |
| C. 领域模型残留裸字段 | `core/models/artifact.py` `InteractionTurnSnapshot.user_id/agent_id/team_id`（投影点 `engines/artifacts/interaction.py` `_snapshot`）；`system/services/passive/models.py` `PassiveConversationKey` 平铺三元组；`server/models/` 请求/响应 DTO | 本计划核心收敛对象 |
| D. 服务入口裸参数 | `chat_service`（`chat` / `chat_stream` / `cancel_generation`，后者 `user_id: str = "default"`）；`memory_service`（6 个方法 + 私有 `_default_identity_scope`，硬编码 `agent_id="ui"`）；`topic_service`（`list_active_topics` / `settle_topic` / `evict_topic`，无 scoped 变体）；`agent_service`（2 个方法，无 scoped 变体，硬编码 `agent_id="ui"`）；`passive_ingress_service`（3 个方法，无 scoped 变体）；`server/deps.py get_user_id` + 各 router | 本计划最大迁移面 |
| E. 用户导向身份上下文未同步 | 前端 `chatApi.ts` 只发送 `user_id/agent_id`；`topicApi.ts` 使用 `user_id` query；Memory/Agent 管理请求不携带 Workspace 选择；Stop 只发送 `generation_id` | 需要统一输入模型和 generation scope 复用规则 |

其中 `chat_service` 与 `memory_service` 已存在成对的 `*_scoped` 权威入口，证明该模式已验证可行；其余三个服务只有裸入口。

## 3. 目标与非目标

### 3.1 目标

1. **服务入口统一 `IdentityScope`**：全部 System 应用服务公共方法只接受 `identity_scope: IdentityScope`（或已有 scoped 变体则删除裸包装）；选择的 Workspace 解析只发生在最外层，消除双重解析。后端不引入第二种身份 scope。
2. **用户导向身份选择显式化**：前端维护并传递 `user_id + workspace_id` 基础选择；只有 Chat、Agent run 等确实由具体 Agent 执行的操作才附加 `agent_id`。server 按入口语义将选择一次性冻结为完整 `IdentityScope`。
3. **非 Agent action 使用保留系统 actor**：当操作没有具体 Agent 作为来源主体时，server 构造 `agent_id="system"`。它只表示 provenance 上“没有具体 Agent 作为操作来源主体”，不代表超级 Agent，不得被前端选择，也不得写入 `MemoryAccessPolicy.target_agent_id`。
4. **管理可观测性与 Agent 可见性分离**：Memory 管理页面在 Workspace ownership hard boundary 通过后，可以访问该 Workspace 的全部 Memory；Agent 检索和运行上下文继续执行 `MemoryAccessPolicy`。管理读取不能依赖 `system` 获得隐式权限。
5. **领域模型裸字段值对象化**：`InteractionTurnSnapshot` 的平铺 actor 三元组改为单一 `actor_identity: ActorIdentity` 字段。
6. **读侧兼容属性收口**：删除无消费者的 `user_id` 兼容 property；确需保留的派生 property 统一标注只读派生语义。`ActorIdentity.buffer_key` 若全仓库无消费者则一并删除。
7. **隐藏默认身份显式化**：删除 `cancel_generation` 的 `user_id: str = "default"` 默认参数与服务内硬编码 agent 默认值；身份选择缺失或冲突在入口层显式失败或按本计划规定的兼容策略处理。
8. **收敛规则进入当前文档**：把“actor 语义用 `ActorIdentity`、owner 语义用 `WorkspaceIdentity`、跨边界传递用 `IdentityScope`、非 Agent 来源使用保留 `system` actor、管理可见性不等于 Agent 可见性”的判定规则写入 Workspace、System、Contracts 与 Frontend 当前文档。

### 3.2 非目标

1. **V1 Memory 批量迁移的实现**：本计划冻结 V2 身份和策略语义，并输出迁移设计与验收要求；实际脚本、观察窗口和 legacy 分支删除属于紧随其后的独立迁移切片。
2. **跨用户 Workspace 授权**：当前仍强制 `actor_identity.user_id == workspace_identity.owner_user_id`，不实现 Grant、Mount 或跨用户访问。
3. **对外响应归属字段改名**：请求 DTO 继续兼容 `user_id`，响应 DTO 的 `user_id` 字段暂保留（见已确认决策 D1）；新增 `workspace_id` 的请求上下文属于契约同步，不再宣称“完全无 HTTP 契约变化”。
4. **`ActorIdentity` 字段结构重做**：不在本计划中引入第二种 scope，也不把 `agent_id` 改为可选；`system` 是非 Agent 来源的保留 actor（见已确认决策 D2）。
5. **认证、多租户安全沙箱与外部身份对齐**：归属 [Identity and Execution Safety Governance](../governance/security/identity-and-execution-safety.md) 工作包。
6. **Workspace 创建与授权产品化**（创建、切换、Mount、Grant）：W0 已明确非目标。
7. **W1 Profile resolver/cache 的 Workspace 资产化**：当前 resolver 维度暂不加入 `workspace_id`；W1 附件与 Workspace 资产化工作另行处理（见已确认决策 D6）。

## 5. 实施批次

### B1 用户导向上下文与服务入口统一（核心批次）

1. 定义前端/HTTP 层的用户导向选择上下文：基础选择为 `user_id + workspace_id`，Agent action 可附加 `agent_id` 与 `session_id`；不引入第二种后端 scope 类型。
2. `server/deps.py` 或等价入口解析器一次性构造 `IdentityScope`：当前校验 `user_id == workspace.owner_user_id`，`workspace_id` 仅允许已声明的 `main_workspace` 公共入口；Chat 的 body、普通资源请求的统一上下文以及现有 Topic query/header 兼容入口必须收敛到同一解析规则；body、query、header 同时出现且不一致时显式拒绝，不静默选择其中一个。
3. `topic_service`、`agent_service`、`passive_ingress_service` 各方法改为唯一 `identity_scope: IdentityScope` 入口，删除内部 `resolve_default_identity_scope` 调用；无具体 Agent 的入口由 server 构造 `agent_id="system"`。
4. `chat_service` 删除 `chat` / `chat_stream` / `cancel_generation` 裸包装（含 `user_id: str = "default"` 默认参数），保留并复用 `*_scoped`；Chat 必须要求具体 Agent，不能静默回退到 `system`。
5. `memory_service` 删除 6 个裸方法与 `_default_identity_scope` 私有 helper；管理用例接收完整 scope，但按 owner-management 语义访问 Workspace 全部 Memory，不把 `system` 当作可见性绕过。
6. `/chat/stop` 通过 generation registry 使用创建时冻结的原始 scope；不能只凭前端当前选择重新构造可能不同的 scope。
7. `tests/helpers/`、server router 测试和前端服务同步迁移到统一选择/解析约定。

验收：`src/hivememory/system/application/` 公共服务方法签名中不再出现 `user_id: str`；`server/routers/` 不再向服务传裸 `user_id`；所有身份-bearing HTTP 入口明确处理 `workspace_id`；非 Agent action 使用 `system`，Chat 不使用 `system`；body/query/header 冲突有显式失败测试。

### B2 领域模型收敛

1. `InteractionTurnSnapshot` 改为 `actor_identity: ActorIdentity`，更新投影点 `engines/artifacts/interaction.py:_snapshot` 与全部构造/断言点；
2. artifact 反序列化增加旧平铺 JSON 读兼容（见 §6）；
3. `PassiveConversationKey` 保留平铺并补充来源注释。

验收：`core/models/` 与 `engines/` 中不再存在裸 `user_id` 领域字段（`memory.py` 的存储投影与 `passive` 命名键除外，均需注释说明）。

### B3 读侧兼容属性收口

1. 逐一确认 `TopicData.user_id`、`StreamMessage.user_id`、`TopicMaterializeTask.user_id` 等实际兼容 property 的消费者；无消费者则删除，有消费者则迁移后删除；
2. 三个 `.identity` 派生 property 统一 docstring 标注。
3. `ActorIdentity.buffer_key` 全仓库无消费者时删除，不将其继续作为公共契约。

### B4 零散项与文档

1. 清理 `engines/generation/extractor.py`、`interfaces.py` 过时的 metadata 示例；
2. 增加 `SYSTEM_AGENT_ID = "system"` 常量及其语义注释；禁止 `system` 作为 `MemoryAccessPolicy.target_agent_id`；
3. Memory 管理 DTO 与前端表单对 `PUBLIC / PRIVATE / TEAM` 的 target 字段执行组合校验；`target_agent_id` 与 `target_team_id` 均禁止使用 `system`；管理读取与 Agent retrieval 的可见性路径分别测试；
4. `DEFAULT_USER_ID` 使用边界收敛并加注释；
5. 执行 §8 的当前文档更新，并建立 V1 Memory 迁移的后续 Plan 输入。

批次顺序：B1 与 B2 相互独立可并行；B3 依赖 B1/B2 落定后的消费者盘点；B4 收尾。建议整体先于 W1 Chat Attachments 合并，避免 W1 在裸入口和隐式 Workspace 默认值上叠加。V1 迁移脚本不在本批次实现，但必须在本计划收尾时形成独立 Plan、字段映射、失败策略和删除 legacy 分支的前置条件。

## 6. 兼容与迁移策略

1. **裸入口直接删除，不保留 deprecated 包装**。理由：调用方全部在仓库内（routers 与 tests），可与本计划同批迁移；与 Identity 旧别名一次性移除的先例一致；保留双入口会延长"两套真相源"并存时间。HTTP 路由路径和现有响应事件保持稳定，但请求上下文新增/统一 `workspace_id`，属于显式契约同步，不再宣称完全无 HTTP 变化。
2. **`InteractionTurnSnapshot` 持久化读兼容**：该快照经 `model_dump(mode="json")` 持久化于 artifact 存储并支持回读。反序列化在 `actor_identity` 缺失时从旧平铺 `user_id/agent_id/team_id` 字段重建 `ActorIdentity`；旧数据缺少具体 Agent 时使用 `SYSTEM_AGENT_ID`，表示没有具体 Agent 作为操作来源主体，不得回落到 `omni_doll` 等真实 Agent。缺少用户归属等无法安全推断的字段时 fail closed 或进入迁移诊断；只做读取升级，不批量回写已存储 artifact。
3. **用户导向请求上下文同步**：请求继续兼容 `user_id`，新增/统一 `workspace_id`；Agent action 继续携带具体 `agent_id`，agentless action 不要求前端选择 Agent，由 server 使用 `SYSTEM_AGENT_ID = "system"`。同一请求的 body/query/header 不得表达冲突的选择；冲突显式失败。响应中的 `user_id` 暂保留为 owner 展示投影。
4. **管理读取不执行 Agent 可见性过滤**：Memory 管理入口通过 `IdentityScope.workspace_identity` 执行 ownership hard boundary 后，允许读取该 Workspace 全部 Memory；Agent retrieval 仍执行 `MemoryAccessPolicy`。`system` 不作为权限绕过条件。
5. **共享 infra 不解释 scope**：`PassiveConversationKey` 等命名键维持平铺，不因本计划改为携带 scope 对象。
6. **V1 迁移先设计后实现**：本计划不批量回写历史 Memory，不删除 legacy codec/filter；收尾必须创建后续迁移 Plan，明确 V1→V2 映射、fail-closed 条件、报告、观察窗口和 legacy 删除门槛。

## 9. 风险与已确认决策

### 9.1 风险

1. **router 改造面广**（约 56 处引用）：属机械改动，遗漏风险以签名/模型守卫测试兜底；
2. **artifact 旧 JSON 兼容**：读兼容分支若与 `model_dump` 新格式冲突会破坏既有 artifact 回读，需双格式测试先行；
3. **管理可见性路径混用**：若 Memory 管理入口继续复用 Agent retrieval 的 `memory_is_readable()`，会错误隐藏 PRIVATE/TEAM Memory；必须以 owner boundary 与管理用例语义覆盖测试；
4. **V1/V2 语义冲突**：legacy 记录可能继续从旧 `source_agent_id` 恢复访问策略；迁移完成前不得把 V2“来源不参与授权”表述套用于旧数据；
5. **与 W1 的合并冲突**：本计划改动 chat router、请求上下文和服务签名，若与 W1 附件入口并行开发会产生冲突，建议本计划先行合并。Profile resolver/cache 的 Workspace 资产化留给 W1。

### 9.2 已确认决策与实施约束

| 编号 | 问题 | 当前默认 |
|:---|:---|:---|
| D1 | 响应 DTO `user_id` 是否改名为 `owner_user_id` | 不改名；保留为 owner 展示兼容字段，代码与前端注释其来源；前端不得将其反推为 actor 选择 |
| D2 | 非 Agent action 如何表达 actor | 保留唯一 `IdentityScope`；server 使用 `SYSTEM_AGENT_ID = "system"`，其精确定义为“没有具体 Agent 作为操作来源主体”；不得作为 policy target 或前端可选 Agent |
| D3 | 三个 `user_id` 兼容 property 是删除还是保留为展示字段 | 按实际消费者盘点；无消费者则删除，有消费者的迁移到权威字段后删除；`ActorIdentity.buffer_key` 无消费者时一并删除 |
| D4 | Memory 管理是否执行 Agent 可见性策略 | 不执行 Agent `MemoryAccessPolicy` 过滤；在 Workspace ownership hard boundary 通过后，管理入口可访问该 Workspace 全部 Memory；`system` 不承担权限绕过语义 |
| D5 | V1 Memory 迁移何时实施 | 不在本计划内批量迁移；本计划收尾必须建立后续迁移 Plan，V1 全量迁移是后续删除 legacy 解释分支的前置条件 |
| D6 | Profile resolver/cache 是否立即加入 workspace 维度 | 不在本计划内；W1 附件与 Workspace 资产化时统一改造 |
