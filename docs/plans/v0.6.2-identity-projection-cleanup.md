# 裸 user_id 兼容投影收敛

## 1. 计划定位

`v0.6.2` W0 Workspace MVP（已归档）建立了三模型身份坐标系：`ActorIdentity` 回答谁在执行，`WorkspaceIdentity` 回答资源归属于哪个用户与 Workspace，`IdentityScope` 冻结一次操作的不可变硬边界（当前事实见 [Workspace 架构](../architecture/workspace.md)）。W0 归档[实施计划](../archive/plans/v0.6.2-workspace-mvp.md)同时写明了收敛规则：新领域对象不得同时保留含糊的 `user_id`、独立 `owner_user_id` 与 `workspace_identity.owner_user_id`；历史 `meta.user_id` 只由 legacy decoder/filter 解释；兼容投影只允许存在于 storage adapter/filter builder。

当前代码中权威模型已在存储索引与资源键边界生效，但裸 `user_id` 兼容投影仍在两类位置普遍残留：

1. **服务入口层**：应用服务以 `user_id: str`（常附带 `agent_id` 默认值）作为公共 API 签名，内部各自调用 `resolve_default_identity_scope`，形成"router 传字符串、service 再解析"的双重解析；各服务对缺失 agent 的默认值互不一致（`"ui"`、`"omni_doll"`、`DEFAULT_AGENT_ID`、空缺）。
2. **领域模型层**：个别快照字段、共享命名键与读侧属性仍以平铺 `user_id` 字符串或兼容 property 表达 actor / owner 语义。

本计划在不触碰 W0 已裁定保留的存储兼容投影的前提下，把上述入口与模型收敛到权威身份模型。它是 `v0.6.2` 内 W1 Chat Attachments 之前的契约清理切片：W1 必须复用稳定的 Workspace 公共契约，不应在裸 `user_id` 入口上继续叠加附件能力。

## 2. 当前基线与缺口

对 `src/hivememory` 全量调查（2026-09-05）发现约 39 处裸 `user_id: str` 字段/参数声明（`owner_user_id` 与 `ActorIdentity` 自身字段除外），routers 层约 56 处 `user_id` 引用。按 W0 判定规则分为四类：

| 类别 | 代表位置 | 判定 |
|:---|:---|:---|
| A. 存储层 legacy 兼容投影 | `engines/retrieval/memory_codec.py` `_legacy_workspace_identity`；`engines/retrieval/filter_adapter.py` `_ownership_filter` legacy OR 分支；`core/models/memory.py` `to_qdrant_payload` 平铺索引 | W0 明确允许；保留至"Workspace 历史数据转换"未排期事项执行，本计划不动 |
| B. 读侧兼容属性 | `core/models/topic.py` `TopicSnapshot.user_id`；`core/models/interaction.py` `StreamMessage.user_id`；`engines/perception/models.py` `user_id`；`core/protocol/models.py` / `agent_runtime/models.py` / `patchouli/models.py` 的 `.identity` property | 内部已权威，仅剩投影出口；收口或标注 |
| C. 领域模型残留裸字段 | `core/models/artifact.py` `InteractionTurnSnapshot.user_id/agent_id/team_id`（投影点 `engines/artifacts/interaction.py` `_snapshot`）；`system/services/passive/models.py` `PassiveConversationKey` 平铺三元组；`server/models/` 请求/响应 DTO | 本计划核心收敛对象 |
| D. 服务入口裸参数 | `chat_service`（`chat` / `chat_stream` / `cancel_generation`，后者 `user_id: str = "default"`）；`memory_service`（6 个方法 + 私有 `_default_identity_scope`，硬编码 `agent_id="ui"`）；`topic_service`（`list_active_topics` / `settle_topic` / `evict_topic`，无 scoped 变体）；`agent_service`（2 个方法，无 scoped 变体，硬编码 `agent_id="ui"`）；`passive_ingress_service`（3 个方法，无 scoped 变体）；`server/deps.py get_user_id` + 各 router | 本计划最大迁移面 |

其中 `chat_service` 与 `memory_service` 已存在成对的 `*_scoped` 权威入口，证明该模式已验证可行；其余三个服务只有裸入口。

## 3. 目标与非目标

### 3.1 目标

1. **服务入口统一 `IdentityScope`**：全部 System 应用服务公共方法只接受 `identity_scope: IdentityScope`（或已有 scoped 变体则删除裸包装）；默认 Workspace 解析只发生在最外层（`server/deps.py` 与被动/内部入口），消除双重解析。
2. **领域模型裸字段值对象化**：`InteractionTurnSnapshot` 的平铺 actor 三元组改为单一 `actor_identity: ActorIdentity` 字段。
3. **读侧兼容属性收口**：删除无消费者的 `user_id` 兼容 property；确需保留的派生 property 统一标注只读派生语义。
4. **隐藏默认身份显式化**：删除 `cancel_generation` 的 `user_id: str = "default"` 默认参数与服务内硬编码 agent 默认值；身份缺失在入口层显式失败或显式回退。
5. **收敛规则进入当前文档**：把"actor 语义用 `ActorIdentity`、owner 语义用 `WorkspaceIdentity`、跨边界传递用 `IdentityScope`"的判定规则写入 Workspace 架构文档。

### 3.2 非目标

1. **历史 Qdrant 数据批量迁移与 legacy codec/filter 分支删除**：归属 [ROADMAP 未排期事项](../ROADMAP.md)的"Workspace 历史数据转换"，需独立脚本、观察窗口与回滚方案；本计划保留全部 A 类兼容投影。
2. **对外 HTTP 契约字段变更**：请求 DTO 保留 `user_id` 传输字段，响应 DTO 的 `user_id` 字段保留（见待决问题 D1）。
3. **`ActorIdentity` 字段默认值必填化**：波及全部构造点与测试夹具，另行评估（见待决问题 D2）。
4. **认证、多租户安全沙箱与外部身份对齐**：归属 [Identity and Execution Safety Governance](../governance/security/identity-and-execution-safety.md) 工作包。
5. **Workspace 产品化入口**（创建、切换、Mount、Grant）：W0 已明确非目标。

| 现状 | 语义 | 替代方案 | 备注 |
|:---|:---|:---|:---|

| `InteractionTurnSnapshot.user_id/agent_id/team_id` | 该轮执行者（actor） | `actor_identity: ActorIdentity` 单字段 | 持久化读兼容见 §6 |
| `PassiveConversationKey.user_id/agent_id/team_id` | 共享 infra 命名键（从 scope 平铺） | 保留平铺字段，注释标明来源为 `identity_scope.actor_identity` | 共享 infra 不解释 scope，符合 W0 约束 |
| `TopicSnapshot.user_id`、`StreamMessage.user_id`、perception `user_id` property | owner/actor 展示兼容 | 确认消费者后删除；展示需求改读 `workspace_identity.owner_user_id` / `identity.user_id` | 见待决问题 D3 |
| `RetrievalRequest.identity`、`ExecutionFrame.identity`、`MTPExecutionContext.identity`、`GenerationRequest.identity` property | actor 只读派生 | 保留 property，docstring 统一标注"只读派生，新代码走 `identity_scope`" | runtime 内消费面大，保留降低风险 |
| `server/models/` 请求 DTO `user_id` | HTTP 传输字段 | 保留；router 通过 `get_identity_scope` 一次性解析后传 scope | 对外契约不变 |
| `MemoryResponse.user_id`、`patchouli/service.py` 对外 payload `user_id` | 对外展示兼容（来源已是 `owner_user_id`） | 保留字段名，代码注释标明语义来源 | 见待决问题 D1 |

| extractor / generation interfaces docstring 中 `metadata={"user_id": ...}` 示例 | 过时文档（调用点已不传） | 清理文档 | 无行为变更 |

## 5. 实施批次

### B1 服务入口层统一（核心批次）

1. `topic_service`、`agent_service`、`passive_ingress_service` 各方法新增/改为唯一 `identity_scope: IdentityScope` 入口，删除内部 `resolve_default_identity_scope` 调用；
2. `chat_service` 删除 `chat` / `chat_stream` / `cancel_generation` 裸包装（含 `user_id: str = "default"` 默认参数），保留并复用 `*_scoped`；
3. `memory_service` 删除 6 个裸方法与 `_default_identity_scope` 私有 helper；
4. `server/deps.py` 新增 `get_identity_scope`（`X-User-Id` / `X-Agent-Id` header → `resolve_default_identity_scope` 一次性解析），各 router 改传 scope，删除逐方法传参；
5. `tests/helpers/` 与相关测试同步迁移到 scoped 入口。

验收：`src/hivememory/system/application/` 公共服务方法签名中不再出现 `user_id: str`；`server/routers/` 不再向服务传裸 `user_id`。

### B2 领域模型收敛

1. `InteractionTurnSnapshot` 改为 `actor_identity: ActorIdentity`，更新投影点 `engines/artifacts/interaction.py:_snapshot` 与全部构造/断言点；
2. artifact 反序列化增加旧平铺 JSON 读兼容（见 §6）；
3. `PassiveConversationKey` 保留平铺并补充来源注释。

验收：`core/models/` 与 `engines/` 中不再存在裸 `user_id` 领域字段（`memory.py` 的存储投影与 `passive` 命名键除外，均需注释说明）。

### B3 读侧兼容属性收口

1. 逐一确认 `TopicSnapshot.user_id`、`StreamMessage.user_id`、perception `user_id` property 的消费者；无消费者则删除，有消费者则迁移后删除；
2. 三个 `.identity` 派生 property 统一 docstring 标注。

### B4 零散项与文档

1. 清理 `engines/generation/extractor.py`、`interfaces.py` 过时的 metadata 示例；
2. `DEFAULT_USER_ID` 使用边界收敛并加注释；
3. 执行 §8 的当前文档更新。

批次顺序：B1 与 B2 相互独立可并行；B3 依赖 B1/B2 落定后的消费者盘点；B4 收尾。建议整体先于 W1 Chat Attachments 合并，避免 W1 在裸入口上叠加。

## 6. 兼容与迁移策略

1. **裸入口直接删除，不保留 deprecated 包装**。理由：调用方全部在仓库内（routers 与 tests），可与本计划同批迁移；与 Identity 旧别名一次性移除的先例一致；保留双入口会延长"两套真相源"并存时间。对外 HTTP 路由路径与请求/响应字段不受影响，破坏面限于内部 Python API。
2. **`InteractionTurnSnapshot` 持久化读兼容**：该快照经 `model_dump(mode="json")` 持久化于 artifact 存储并支持回读。反序列化在 `actor_identity` 缺失时从旧平铺 `user_id/agent_id/team_id` 字段重建 `ActorIdentity`（缺失值落到模型默认）；只做读取升级，不批量回写已存储 artifact。
3. **HTTP 契约不变**：请求 DTO `user_id` 字段与 `X-User-Id` header 保留；`get_identity_scope` 是新增解析点而非替换对外字段。是否引入 `X-Agent-Id` header 由 router 现有传参现状决定（chat 已有 agent 字段，memories/topics 路径当前无 agent 维度，继续走服务内既定默认的显式化替代）。
4. **共享 infra 不解释 scope**：`PassiveConversationKey` 等命名键维持平铺，不因本计划改为携带 scope 对象。

### 9.1 风险

1. **router 改造面广**（约 56 处引用）：属机械改动，遗漏风险以签名/模型守卫测试兜底；
