# v0.7.0 A2-P：记忆时间语义与可控取时

本计划只为 [A2-P 记忆内容版本与 Lifecycle 状态重构](./v0.7.0-a2-pre-memory-version-and-lifecycle.md)提供时间边界。它解决记忆原子、版本 Artifact、Lifecycle 计算和 MemoryCompiler 在本次重构中必须统一的问题，不把全项目时间治理作为 A2-P 的前置条件。

时间实现继续放在 `hivememory.utils`。`core` 只声明业务字段、校验和值对象，不保存全局时钟或时间服务。A2-P 需要的可控取时采用现有服务的局部 `Callable[[], datetime]` 注入；本计划不新增全局 `Clock` 协议、`SystemClock` 对象或组合根改造。

## 1. 目标与非目标

本计划完成后，A2-P 应能够：

1. 以 timezone-aware UTC datetime 保存 Memory 和版本 Artifact 的业务时点。
2. 区分 `created_at`、`updated_at`、`last_accessed_at` 与 `decay_anchor_at` 的职责，避免用一个时间字段替代其他字段。
3. 在内容提交、Lifecycle 更新和版本 Artifact 捕获中使用同一次显式取时，并让测试通过局部 callable 控制时间。
4. 让 TimeFormatter 只消费已解释的 UTC 时间，不再猜测 naive datetime 的时区。
5. 为旧 Memory 和旧 Artifact 提供明确的读取/迁移失败边界，不用当前时间伪造历史事实。

本计划不包括：

- Queue、Scheduler、Passive buffer、Workspace lease、限流、HTTP middleware 或其他进程内耗时的全面迁移；
- `time.monotonic()` 的全项目统一、全局可控时钟、contextvar 时钟覆盖或新的领域 Clock 模型；
- 用户时区、日历调度、展示层全面本地化；
- Memory schema、MemoryVersionArtifact schema、Lifecycle 数值规则或 mutation API 的重新定义；这些由 A2-P 维护，本计划只规定它们使用时间的方式；
- 为每一种时间操作新增 DTO、service 或公共 facade。

当前缺口集中在 A2-P 直接触及的路径：`MetaData` 和多个 Artifact 模型仍以 `datetime.now` 作为默认值，生成与 Lifecycle 路径仍直接读取系统时间，`VitalityCalculator` 仍以 `updated_at` 计算衰减，TimeFormatter 仍会为 naive 值猜测时区，Artifact adapter 在缺少时间时会用当前时间补值。这些事实分别可在 front matter 的代码入口中核对；本计划只要求修正会影响 A2-P 结果的调用点。

## 2. A2-P 的时间不变量

### 2.1 持久化时间统一为 UTC

进入 canonical Memory、MemoryVersionArtifact、MemoryCreationArtifact 或 A2-P 管理的 Artifact 引用的 datetime 必须满足：

- `tzinfo` 存在且 `utcoffset()` 有效；
- 写入前规范化为 UTC；
- 序列化使用带 `Z` 或显式 offset 的 ISO 8601；
- 新格式拒绝 naive datetime；旧格式只能在显式迁移入口处理。

UTC 是存储规范，不代表展示时区。展示层可以在读取 UTC 值后转换时区，但不能把展示后的值写回业务字段。

### 2.2 四个 Memory 时间字段各负其责

| 字段 | A2-P 语义 | 允许更新的操作 |
| --- | --- | --- |
| `meta.created_at` | 记忆原子首次创建时间 | 仅创建时设置，迁移保留可验证的原值 |
| `meta.updated_at` | 内容事实最后一次提交时间 | 创建和实际内容修订；HIT、普通访问、反馈、策略变化、Lifecycle 评分和迁移不更新 |
| `meta.lifecycle.last_accessed_at` | 最近一次成功访问/引用事件时间 | 按 A2-P 已定义的访问事件更新；不得因无关状态 patch 改写或倒退 |
| `meta.lifecycle.decay_anchor_at` | 遗忘衰减的计算基准 | 创建时等于创建时间；CITATION 和内容修订按 A2-P 规则推进；HIT、普通反馈和评分刷新不推进 |

`last_accessed_at` 记录“最近发生过访问”，`decay_anchor_at` 记录“衰减曲线从何时重新起算”。两者都使用 UTC，但值不同、更新触发不同，也不能通过相互复制来实现职责兼容。A2-P 的 lifecycle patch 必须按字段白名单提交，不能把整个 `meta` 或整个 `lifecycle` 作为替换值。

### 2.3 一个业务操作只取一次 now

进入内容提交、Lifecycle 状态 mutation 或版本 Artifact 捕获边界时取得一个 UTC `now`，随后将它传给所有需要同一时点的字段和 Artifact。长任务开始时间不作为提交时间；提交边界重新取时并合并最新 Lifecycle，避免旧候选覆盖新状态。

时间字段不得用于计算运行耗时。A2-P 只关心业务时点；检索或生成耗时仍可沿用现有相对计时实现，后续由独立计划治理。

## 3. 最小工具与调用约定

新增 `src/hivememory/utils/time.py`，只提供两个生产入口：

```python
from datetime import UTC, datetime


def utc_now() -> datetime:
    """返回 timezone-aware UTC 当前时间。"""


def require_utc(value: datetime) -> datetime:
    """校验并返回规范化为 UTC 的 datetime；naive 值抛出 ValueError。"""
```

实现要求：

- `utc_now()` 使用 `datetime.now(UTC)`；模块不保存可变当前时间；
- `require_utc()` 检查 `tzinfo` 和 `utcoffset()`，通过 `astimezone(UTC)` 返回 canonical 值；
- 不在 `utils` 定义 Pydantic 模型、Memory 类型或 Lifecycle 方法；
- Core 模型可以导入这两个纯函数作为 `default_factory` 和校验工具，依赖方向为 `core -> utils`；
- 需要可控时间的服务使用已有构造函数增加一个局部参数：

  ```python
  now: Callable[[], datetime] = utc_now
  ```

  测试传入 fake callable；生产默认值使用 `utc_now`。不新增公共测试时钟模型。

同一操作内应写成 `current = require_utc(self._now())` 后复用。不要让模型默认值承担 Lifecycle 规则，也不要在业务方法中多次直接读取系统时间。

## 4. TimeFormatter 的边界

`src/hivememory/utils/time_formatter.py` 仍然是展示工具，不是时间来源。A2-P 只需做以下收紧：

- `format(dt, reference=None)` 的 `dt` 和显式 `reference` 必须是 aware datetime，并在入口通过 `require_utc` 规范化；
- `reference` 省略时使用 `utc_now()`；需要确定性结果的 MemoryCompiler 和测试显式传入同一 `reference`；
- 删除通过 `replace(tzinfo=...)` 将 naive 值猜成某个时区的兼容逻辑；
- 相对时间使用 `delta.total_seconds()`，正确处理未来时间和负差值；
- 未来时间和不满一小时的时间差沿用现有 `recently` 文案，不得因为 `timedelta.seconds` 的折叠而显示成“数小时前”；
- formatter 只格式化调用方给出的字段，不自行在 `updated_at`、`last_accessed_at`、`decay_anchor_at` 中选择。

旧数据的时区解释属于 codec/迁移入口。TimeFormatter 遇到无法解释的旧值应失败，而不是补当前时间或本地时区。

## 5. A2-P 需要调整的实现边界

以下是本计划的实施清单；具体字段结构、版本号和 mutation 白名单以 A2-P 为准。

| 位置 | 调整 | 约束 |
| --- | --- | --- |
| `core/models/memory.py` | Memory schema `2.1` 的业务时间使用 `utc_now` 默认值并拒绝 naive；Lifecycle 模型中的时间字段复用 `require_utc` | 不在此处实现衰减、访问或版本分配规则 |
| `core/models/artifact.py` | `BaseArtifact`、MemoryCreationArtifact、MemoryVersionArtifact、事件时间使用 UTC-aware 默认值和校验 | Artifact schema 版本与 Memory schema 独立；不得用当前时间补旧记录的缺失时间 |
| `engines/artifacts/memory.py` | 版本 Artifact 构建方法接收一次 `now` 或 `Callable`，`changed_at` 与本次提交使用同一时点 | 版本捕获时点由内容提交边界决定，不能由 builder 再次隐式取时 |
| `engines/generation/engine.py`、`patchouli/services/memory_generation.py` | 内容 create/update 在提交边界取得 UTC now；`updated_at` 与 `decay_anchor_at` 按 A2-P 规则更新；删除 `history_summary` 写入 | 正文中的 `## 更新 (YYYY-MM-DD)` 是内容生成规则，需使用同一提交日期；不能把它当作展示层时间 |
| `engines/lifecycle/reinforcement.py`、`engines/lifecycle/vitality.py` | 将 now 作为显式输入；衰减计算读取 `decay_anchor_at`；访问事件只更新授权字段 | HIT 不推进 decay anchor；CITATION 按 A2-P 推进；不得直接 `datetime.now()` |
| `patchouli/memory_library/adapters/mid_term.py` | 生命周期和访问更新走 A2-P 的受限 patch，并在提交边界使用 UTC now | 不能加载旧原子后整颗 upsert 覆盖新时间或新内容 |
| `patchouli/memory_library/adapters/artifact.py`、旧迁移入口 | 读取带 offset 的值并规范化 UTC；naive/缺失值进入显式迁移报告或拒绝 | 禁止 `created_at = datetime.now()` 伪造历史时间 |
| `engines/memory_compiler/handlers/prompt.py` | 调用 TimeFormatter 时传入明确的 UTC reference | 不在 compiler 内部选择 lifecycle 时间字段 |

检索器中与 A2-P 衰减评分直接相关的“当前时刻”可以采用同一个局部 `now`，但检索 latency 的 `time.time()` 不属于本计划。A2-P 完成后，项目仍可能存在其他模块的裸时间调用；它们不能被描述为本计划的失败。

## 6. 旧数据与兼容策略

时间处理与 A2-P 的 schema 迁移一起交付，不能靠新模型默认值静默吞掉旧字段：

1. 带 offset 的旧 ISO 值解析后规范化为 UTC。
2. naive 旧值只有在迁移命令显式提供来源时区时才转换；没有可证明来源时区的记录进入失败/人工处理报告。
3. 缺失 `created_at`、`changed_at` 或其他历史事实时，不用迁移执行时的当前时间补值；记录保持不可恢复并由 Artifact 完整性标记表达。
4. 迁移建立 `decay_anchor_at` 时遵循 A2-P 的规则：优先使用可验证的历史衰减基准；只有 A2-P 明确允许时才从旧 `updated_at` 初始化，并在报告中记录这是兼容推断。
5. 迁移不改变 Memory 内容版本、不生成伪造的 MemoryVersionArtifact、不重算向量；可重复执行且冲突输入拒绝。

A2-P 的 schema 迁移负责旧字段布局、`MemoryProvenance`、`history_summary` 和 `agent_config`；本计划只补充其中时间字段的解析、校验和报告要求。

## 7. 实施切片与验收

### A2-P-T0：冻结时间字段

在 A2-P 的 MVL-0 清单中增加每个时间字段的 owner、当前表示、目标类型、更新触发、旧数据来源和是否可跨重启。至少覆盖 Memory MetaData、Lifecycle、MemoryVersionArtifact、MemoryCreationArtifact、ArtifactRef 以及检索衰减输入。明确 `last_accessed_at` 与 `decay_anchor_at` 的差异后，才能开始模型迁移。

### A2-P-T1：工具与模型

实现 `utils.time.utc_now`、`require_utc`；替换 A2-P 相关模型默认值；为新格式添加 aware/UTC 校验；收紧 TimeFormatter。此阶段不改 Queue、Scheduler 或其他子系统的时间实现。

### A2-P-T2：提交与 Lifecycle

在现有内容提交边界和受限 lifecycle patch 中传递局部 `now`；版本 Artifact 使用提交时点；VitalityCalculator 接收显式 now 并以 `decay_anchor_at` 计算；补齐 generation、Artifact adapter 和 MemoryCompiler 的调用方。所有新写入必须产生可解释的 UTC 值。

### A2-P-T3：迁移、测试与交付

将旧时间解析接入 A2-P 的迁移预检/报告；验证新旧格式、历史完整性、时间字段职责和可控取时；在 A2-P 验收清单中记录未迁移的全项目时间调用，不把它们扩大为 A2-P 阻塞项。

完成门槛：

- A2-P 管理的所有新持久化时间均为 UTC-aware，naive 输入被拒绝；
- 一次内容提交的 Memory 与 MemoryVersionArtifact 使用同一提交时点，历史记录不可被后续状态更新改写；
- HIT、CITATION、内容修订、反馈和评分刷新分别遵守四个时间字段的不变量；
- `decay_anchor_at` 是衰减计算唯一时间基准，`last_accessed_at` 不被误作衰减基准；
- TimeFormatter 对 UTC aware 输入给出确定结果，无法解释的旧值失败而不是猜测；
- fake `now` 可以在不 patch 全局 datetime、没有固定 sleep 的情况下验证上述行为；
- 迁移对缺失/naive/冲突时间有可诊断结果，且不会伪造当前时间或生成重复版本。

## 8. 测试范围

测试应验证行为和持久化结果：

- `utc_now`、`require_utc`、TimeFormatter 的 aware/UTC、未来时间和负差值边界；
- Memory schema `2.1` 与 MemoryVersionArtifact schema 的独立时间字段往返；
- 内容提交中 `created_at` 保持不变、`updated_at` 与 `decay_anchor_at` 按规则变化，Artifact 与原子时间一致；
- HIT 不推进 `decay_anchor_at`，CITATION 推进 `last_accessed_at` 和 `decay_anchor_at`，Lifecycle patch 不改变内容时间；
- 使用 fake `now` 的衰减计算、版本捕获和 MemoryCompiler 输出；
- 旧 aware 值转换、旧 naive 值无来源时区拒绝、缺失时间不被当前时间补齐、迁移重跑不增版本。

按仓库测试规范运行受影响的 unit/integration 测试、静态检查和 `git diff --check`。不要求在本计划中运行或修复与 A2-P 无关的全项目时间调用；这些工作另立计划后再治理。

## 9. 交接与后续边界

交付 A2-P 时，应向 A2 提供：Memory/Artifact 的 UTC 时间字段样例、四个字段的更新规则、局部 `now` 的调用约定、旧时间迁移报告格式，以及明确的“当前时间由哪个提交边界决定”。A2 可以据此实现缓存 epoch 和冷读协作，但不重新解释时间字段，也不把缓存时间写回 Memory。

本计划完成后，若项目仍需统一 monotonic、异步 timeout、Workspace lease、队列和前端展示时区，应建立独立的时间治理计划；不得把那些未实施的内容写成 A2-P 已完成能力。

主要风险是把旧的 naive 值错误解释成 UTC、在版本 Artifact 与 canonical Memory 之间重复取时，或让 lifecycle 更新重新走整原子写入。迁移入口必须要求可验证的来源时区，提交边界必须把同一个 `now` 传给所有相关对象，状态维护必须继续使用 A2-P 的受限 patch。

实现、迁移、测试和审查完成后，由 A2-P 按其收口清单更新 `docs/architecture/data-model.md`、`docs/patchouli/memory-library.md`、`docs/patchouli/lifecycle.md`、`docs/patchouli/artifacts.md` 与相关契约；本计划随后归档。完成前，本文仍是时间边界的唯一计划真相源，不向当前事实文档晋升未落地设计。
