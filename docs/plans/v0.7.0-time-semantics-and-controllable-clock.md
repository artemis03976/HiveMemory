# v0.7.0：全项目时间语义与可控时钟统一

本计划把时区、时间类型、相对时间计算和测试时钟作为一个跨子系统治理切片，独立于具体业务功能实施。时间相关的实现统一放在 hivememory.utils；core 继续只承载业务模型、协议和值对象，不新增 Clock 领域模型，也不保存全局时钟状态。

本文是 Planned 设计，不表示项目已经完成 UTC 迁移或所有运行路径已经可控。当前实现仍同时存在 naive datetime、UTC-aware datetime、Unix 浮点时间、time.time() 和局部 monotonic 注入。A2-P 只消费本计划确定的时间工具和字段语义；Memory schema、MemoryVersionArtifact schema 以及生命周期字段的业务职责仍由 A2-P 负责。

## 1. 背景与当前证据

当前时间问题同时影响持久化数据、生命周期计算、超时控制、缓存驻留和测试可重复性。它们不是同一种问题，不能通过全局替换 datetime.now() 解决。

| 当前模式 | 证据入口 | 风险 |
|:---|:---|:---|
| Memory、Artifact、Interaction、Pending、Protocol 等模型使用 datetime.now() 作为默认值 | [core/models/memory.py](../../src/hivememory/core/models/memory.py)、[core/models/artifact.py](../../src/hivememory/core/models/artifact.py)、[core/models/interaction.py](../../src/hivememory/core/models/interaction.py)、[core/models/pending.py](../../src/hivememory/core/models/pending.py)、[core/protocol/models.py](../../src/hivememory/core/protocol/models.py) | 持久化时间可能没有时区，跨环境解释不一致；模型默认值无法由行为测试控制 |
| 部分路径使用 datetime.now(UTC) | [system/contracts/runtime_events.py](../../src/hivememory/system/contracts/runtime_events.py)、[infrastructure/work_queue/in_memory_store.py](../../src/hivememory/infrastructure/work_queue/in_memory_store.py)、[patchouli/services/memory_generation.py](../../src/hivememory/patchouli/services/memory_generation.py) | 时区正确但仍绕过可控时钟，测试需要直接 patch 模块或依赖真实时间 |
| 检索、Server、MTP、Patchouli runtime 使用 time.time() 计算耗时 | [engines/retrieval](../../src/hivememory/engines/retrieval/)、[server/app.py](../../src/hivememory/server/app.py)、[agent_runtime/mtp/runtime.py](../../src/hivememory/agent_runtime/mtp/runtime.py)、[patchouli/runtime/core.py](../../src/hivememory/patchouli/runtime/core.py) | 系统时钟回拨会产生负耗时或错误延迟 |
| Topic working set、Workspace access、附件预算已经注入可替换的 monotonic 函数 | [patchouli/services/topic_working_set.py](../../src/hivememory/patchouli/services/topic_working_set.py)、[workspace/access.py](../../src/hivememory/workspace/access.py)、[system/services/attachments/limits.py](../../src/hivememory/system/services/attachments/limits.py) | 局部做法不一致，组合根无法用同一个测试时间推进整个运行链路 |
| sys_clock 使用 datetime.now().astimezone() | [agent_runtime/mtp/syscalls/clock.py](../../src/hivememory/agent_runtime/mtp/syscalls/clock.py) | 本地时区展示与业务时间来源耦合，且无法控制 |
| StreamMessage、LogicalBlock、TopicData、被动 buffer 使用 Unix 浮点值 | [core/models/interaction.py](../../src/hivememory/core/models/interaction.py)、[core/models/topic.py](../../src/hivememory/core/models/topic.py)、[system/services/passive/turn_buffer.py](../../src/hivememory/system/services/passive/turn_buffer.py) | 事件时间、持久化快照时间和进程内 idle 时间混用，重启和迁移语义不清楚 |

## 2. 目标与非目标

本计划交付：

1. 在 hivememory.utils.time 建立唯一的时间工具与最小 Clock 协议，工具模块不依赖 core 或任何业务子系统。
2. 明确 UTC 业务时间、monotonic 运行时间、展示时间和外部输入时间的边界。
3. 让所有持久化业务时间使用 timezone-aware UTC；让超时、TTL、idle、LRU、限流和耗时使用 monotonic。
4. 在 System 组合根统一创建并注入运行时 Clock；让需要时间推进的服务可以在测试中确定性运行。
5. 迁移模型默认值、服务写入、codec、运行时计时、测试 fixture 和旧数据入口，并设置禁止新增违规调用的检查。

本计划不交付：

- Memory 字段重新分组、Memory schema 版本选择、decay_anchor_at 业务规则或 MemoryVersionArtifact 格式；这些由 A2-P 负责。
- 时区感知的日历调度、用户偏好时区或重复事件规则。若未来需要此能力，应显式保存业务时区和日历语义，不复用本计划的本地展示逻辑。
- 全局可变时钟、contextvar 时钟覆盖、通用时间服务、事件溯源平台或新的领域时间模型。
- 将所有现有浮点时间机械替换成 datetime；每个字段必须先按语义分类。

## 3. 责任边界

| 边界 | 时间相关职责 | 明确不负责 |
|:---|:---|:---|
| hivememory.utils.time | UTC 获取与校验、Clock 协议、SystemClock、必要的标准库转换函数 | Memory、Topic、Lifecycle 等业务含义；Pydantic 领域模型；全局可变状态 |
| Core/Contracts | 声明业务字段的时间类型和不变量，调用 utils 提供默认值或校验 | 实现时钟、决定超时策略、保存共享 clock 实例 |
| System 组合根 | 创建进程级 SystemClock 并将其传入需要相对时间或业务时间的服务 | 重新解释下游业务字段；在路由中自行计算时间 |
| 子系统服务 | 使用注入的 clock 做生命周期、队列、缓存、调度和提交时点判断 | 直接调用 datetime.now()、time.time() 或依赖其他子系统的私有时钟 |
| 存储/协议 adapter | 在边界序列化 UTC，兼容已冻结的旧格式并报告迁移假设 | 用当前时间填补旧数据缺失的业务事实 |
| 测试支持 | 提供 FrozenClock/TestClock，通过显式推进验证时间行为 | 修改生产全局时钟或用固定 sleep 等待状态 |

Core 可以导入 hivememory.utils.time 的纯标准库工具以构造或校验业务字段；依赖方向必须保持为 core -> utils，utils 不得反向导入 core、Patchouli、System 或配置对象。

## 4. 统一时间语义

### 4.1 业务时间：timezone-aware UTC

所有表示一个现实世界时点、会进入 Memory/Artifact/Interaction/Protocol/Queue/Workspace 持久化或对外结果的 datetime 必须满足：

- tzinfo 存在且 utcoffset() 有效；
- 写入前规范化为 UTC；
- JSON/codec 默认输出带 Z 或显式 offset 的 ISO 8601；内部 canonical 值为 UTC；
- 新模型拒绝 naive datetime；旧数据只在显式迁移入口转换；
- 需要保证不倒退的状态（例如访问时间、衰减基准、队列完成时间）在提交时遵循各自业务的不倒退规则，不能用 wall clock 差值代替该规则。

这类字段共享同一个 Clock.now() 来源。last_accessed_at 和 decay_anchor_at 都使用 UTC，但继续保持各自的业务职责：前者记录最近访问事件，后者作为衰减计算基准。

### 4.2 运行时间：monotonic

以下值只表示进程运行期间的相对时间，统一使用 Clock.monotonic()：

- 请求、检索、生成、工具执行和解析耗时；
- deadline、超时、重试等待和 scheduler interval；
- Topic working set 的 LRU/lease、Workspace access TTL、附件预算；
- passive buffer idle、rate limiter、内存内 cache 的过期判断。

monotonic 值不能写入持久化模型、事件 payload、日志中需要跨进程比较的字段或外部协议。若 idle 状态需要跨重启恢复，必须保存 UTC 业务时间，并在恢复后以当前 UTC 重新计算。

### 4.3 展示时间与外部输入

MTP sys_clock、日志人类化输出和 UI 展示可以使用 clock.now().astimezone() 或指定展示时区。展示转换不改变领域对象中的 UTC 值。

外部带 offset 的时间先解析为 aware datetime，再规范化为 UTC。没有时区的外部时间必须由 adapter 提供已知来源时区；通用工具不得默认把它解释成本地时区或 UTC。

### 4.4 TimeFormatter：UTC 时间的展示消费者

TimeFormatter 继续放在 src/hivememory/utils/time_formatter.py；它属于展示工具，不是时间来源，也不负责定义业务时间字段。src/hivememory/i18n/time_formatter.py 继续只提供多语言文案。两者都不保存当前时间、默认时区或可变 Clock。

TimeFormatter 的输入契约调整为：

- dt 和 reference（若传入）必须是 timezone-aware datetime，并在格式化入口通过 require_utc 规范化；
- reference 继续保持可选以兼容现有调用；未显式提供时，只由 time_formatter 通过 utc_now() 取得当前 UTC；
- 需要确定性结果的服务、MemoryCompiler 和测试应显式传入同一 reference，例如使用注入 Clock.now() 的结果；TimeFormatter 不需要 monotonic，也不应自行创建或持有测试时钟；
- naive datetime 不再由 formatter 通过 replace(tzinfo=...) 猜测时区。兼容旧数据由上游 codec/adapter 在进入展示层前完成，并保留迁移假设；
- 相对时间计算使用 delta.total_seconds()，明确处理未来时间，不能依赖 timedelta.seconds 对负时间差的折叠行为；
- formatter 只按调用方提供的字段显示相对时间。它不在 updated_at、last_accessed_at 和 decay_anchor_at 之间自行选择，也不把 stale warning 当作 lifecycle 状态。

因此，TimeFormatter 与统一 Clock 的关系是“消费 UTC now/reference”，而不是“实现 Clock”。业务服务需要同一操作中的一致时间时，先从 Clock.now() 取得 reference，再把它传给所有 formatter 调用；单纯的展示入口可以继续使用 formatter 的默认 utc_now()。

### 4.5 当前字段的目标分类

| 当前字段或状态 | 目标类型 | 处理方式 |
|:---|:---|:---|
| Memory.meta.created_at、updated_at、last_accessed_at、decay_anchor_at | UTC datetime | 由 A2-P 的模型与 codec 使用 utils 的 UTC 校验；不由本计划改变业务更新规则 |
| Artifact 的 created_at、captured_at、changed_at、事件 at | UTC datetime | 默认值改用 utc_now，读取拒绝无法解释的 naive 值 |
| ProtocolMessage.timestamp、PassiveIngressEvent.occurred_at、RuntimeEvent/Queue 时间 | UTC datetime | 入口规范化；重试、完成和事件排序不使用 wall clock 差值 |
| StreamMessage.timestamp、LogicalBlock.created_at、交互快照创建时间 | UTC datetime 或明确的 adapter 兼容表示 | 新 canonical 格式使用 UTC；旧 numeric epoch 只在已知为 Unix 秒时转换 |
| TopicData.last_update、perception 投影中的 last_update | UTC datetime | 这是可恢复的业务快照时间；is_idle 通过注入时钟计算，不再直接读取系统时间 |
| TopicWorkingSet resident/lease 时间、access context TTL、附件预算 | monotonic float | 保留相对时间语义；不得序列化或从持久化数据恢复 |
| passive buffer _last_activity、rate limiter、scheduler 和各类耗时起止点 | monotonic float | 由 Clock 注入；测试通过 advance() 推进 |

字段最终分类必须在 T0 清单中逐项确认；表中兼容表示不能成为新代码继续写入旧格式的理由。

## 5. hivememory.utils.time 最小接口

工具模块只依赖 Python 标准库，目标接口如下；实现时可按现有项目风格调整命名，但不得增加同义的第二套入口：

    # src/hivememory/utils/time.py
    from datetime import UTC, datetime
    from typing import Protocol
    import time

    class Clock(Protocol):
        def now(self) -> datetime:
            """返回 timezone-aware UTC 时间。"""

        def monotonic(self) -> float:
            """返回不能回拨的进程时间。"""

    class SystemClock:
        def now(self) -> datetime:
            return datetime.now(UTC)

        def monotonic(self) -> float:
            return time.monotonic()

    def utc_now() -> datetime:
        return datetime.now(UTC)

    def require_utc(value: datetime) -> datetime:
        if value.tzinfo is None or value.utcoffset() is None:
            raise ValueError("datetime must be timezone-aware")
        return value.astimezone(UTC)

实现约束：

- SystemClock 是无状态默认实现；不得在 utils 中保存可变的“当前测试时钟”。
- utc_now() 供 Pydantic default_factory 和无服务上下文的纯构造使用；有业务时间决策的服务必须使用注入的 Clock。
- 不在 utils 中定义 Pydantic 专用模型、Memory 专用类型或生命周期方法。模型可以在自己的模块中复用 require_utc，避免 Core 反向依赖业务实现。
- 仅使用 monotonic 的低层 helper 可以继续接收 Callable[[], float] 以减少无关接口变更，但调用方必须传入同一个 Clock 的 monotonic 方法；同时需要 wall time 的服务使用完整 Clock。
- 任何对外 deadline 若以 UTC datetime 传入，服务入口先转换成剩余秒数和 monotonic deadline，内部只比较 monotonic 值。

测试专用的 FrozenClock/TestClock 放在 tests/support 或测试 fixture 中，不作为生产公共 API。它至少提供 now()、monotonic() 和 advance(seconds)；需要验证 wall clock 跳变时可单独调整业务时间，但不能改变 monotonic 时间。

## 6. 注入与调用规则

System 组合根创建一个 SystemClock，沿现有 application service、runtime、scheduler、Patchouli service 和适配器构造链传递。子系统之间只传递 Clock 协议或已经确定的 UTC 值，不持有其他子系统的具体时钟实现。

模型默认值只能解决“创建对象时需要一个当前时间”的问题。以下操作必须由调用方把同一时点显式传入或从注入的 Clock 取得：

- lifecycle 状态更新、decay_anchor_at 推进和访问事件记录；
- Artifact/Interaction/Queue 提交时点；
- retry/deadline/idle/TTL 判定；
- 同一操作中需要保持一致的多个时间字段。

同一个业务操作内应取得一次 now 后复用，避免 created_at、事件时间和日志时间因多次调用产生不必要的微小差异。对于需要不倒退的字段，提交边界以最新持久化值和当前候选值共同决定结果；不能把开始长任务时读取的旧时间整颗写回。

禁止：

- 在业务代码中直接调用 datetime.now()、datetime.utcnow()、datetime.now(UTC) 或 time.time()；唯一例外是 utils.time、明确的旧数据迁移工具和仅展示的 adapter，并须有注释或 allowlist。
- 通过 monkeypatch 全局 datetime 作为生产服务的测试替代；
- 用 UTC wall clock 计算耗时，用 monotonic 值作为业务时间，或把两种值存入同一个字段；
- 在通用 require_utc 中默认为 naive 值附加本地/UTC 时区。

## 7. 迁移阶段与代码落点

### T0：时间语义清单与边界冻结

建立逐字段清单，记录字段 owner、持久化范围、当前表示、目标时间域、旧数据来源、是否允许跨重启和所有写入者。重点核对 Memory、Artifact、Interaction、Topic、Passive、Queue、Workspace、RuntimeEvent、MTP、缓存、scheduler 和 rate limiter。

T0 必须关闭以下问题后才能进入模型迁移：

- 每个 Unix 浮点字段究竟是 Unix epoch、事件顺序辅助值还是 monotonic 运行状态；
- 旧 naive datetime 的实际来源时区。无法证明时必须进入迁移报告和人工处理范围；
- 哪些 last_update/idle 字段需要跨进程恢复，哪些应在启动时重置；
- 对外 JSON/协议是否保留 numeric epoch 兼容读取，以及兼容截止版本。

### T1：utils 工具与组合根

新增 src/hivememory/utils/time.py、单元测试和 System 组合根注入点。将已有的 Callable[[], float] 时钟注入样板统一到同一个默认来源，先不改变业务公式。同步收紧 utils/time_formatter.py 的输入契约：它消费 UTC datetime/reference，不再替 naive 值猜测时区。

完成门槛：新工具只依赖标准库；SystemClock.now() 必须返回 UTC-aware 值；SystemClock.monotonic() 不受 wall clock 跳变影响；服务可以在测试中接收 fake clock。

### T2：持久化模型与 codec

迁移 Core/Contracts、Memory、Artifact、Interaction、Pending、Passive event、Queue 和 Workspace 相关的业务时间字段。所有新写入使用 UTC，codec 在边界完成规范化，模型拒绝 naive 值。

Memory schema 的版本选择、迁移脚本和 MemoryVersionArtifact schema 不在本阶段重新定义；A2-P 负责把本计划的 UTC 校验接入其 2.1 Memory 格式，并在自己的迁移报告中记录旧时间语义。

### T3：运行时相对时间

将检索、Server、MTP、Patchouli runtime、生命周期执行统计、scheduler、rate limiter、Topic working set、Workspace access、附件预算和 passive buffer 的耗时/TTL/idle 判定改为 monotonic。需要持久化的 last_update 等字段先转换为 UTC，再由 Clock 计算 idle。

每个长操作在入口取得 monotonic deadline；内部重试和取消只比较该 deadline，不根据 wall clock 重新计算剩余时间。

### T4：测试与 fixture

将受影响测试中的 datetime.now()、time.time() 和固定 sleep 替换为显式 UTC 样本或 TestClock.advance()。TimeFormatter 测试统一使用带 UTC 的固定 dt/reference，覆盖 naive 输入拒绝、带 offset 输入规范化、显式 reference 的确定性输出和未来时间边界。其他测试覆盖：

- naive 输入被拒绝，带 offset 的输入被规范化为 UTC；
- wall clock 回拨不影响 timeout、TTL、LRU 和耗时；
- now() 与 monotonic() 可以分别推进；
- 同一提交中的时间字段使用同一时点；
- access、lifecycle、Topic idle、passive seal、queue retry 和 scheduler 在不等待真实时间的情况下到达终态；
- 取消、失败和重试不会把较新的时间状态覆盖成旧值。

### T5：旧数据与兼容入口

提供只读预检、显式时区参数、可重跑转换、校验报告和备份/回滚说明。迁移规则如下：

- 带 offset 的旧 ISO 时间规范化为 UTC；
- 已确认是 Unix epoch 秒的 numeric 值转换为 UTC datetime；
- 旧 naive 值必须使用迁移参数提供来源时区，不能由新模型默认值吞掉；
- 无法区分 wall clock 与 monotonic 的数值字段不得猜测，按字段 owner 的规则重建或清空进程状态，并报告损失范围；
- 迁移不改变 Memory 内容版本，不制造虚假的访问、衰减或交互事件；
- 新 codec 只写 canonical UTC，旧格式兼容读取有明确截止条件，不能长期双写。

### T6：门禁与文档收口

增加静态检查脚本或等价 Ruff/CI 检查，扫描生产源码中的裸 datetime.now*、datetime.utcnow 和用于耗时的 time.time()。迁移工具、utils.time 和展示 adapter 使用窄 allowlist；测试代码允许显式构造样本，但不得用真实时间验证时间推进。

实现、测试、迁移和审查完成后，按本计划 front matter 的 updates 列表更新当前事实文档；在此之前，时间治理设计只在本计划中生效，不提前写入当前架构文档。

## 8. 与 A2-P 的协作边界

A2-P 使用本计划的 utc_now/require_utc/Clock 约束实现 created_at、updated_at、last_accessed_at 和 decay_anchor_at。它负责决定这些字段何时变化、由哪个 lifecycle 操作写入以及 Memory schema 如何迁移；本计划只保证时间来源和类型稳定。

A2-P 的内容提交、lifecycle patch、Artifact 历史捕获和并发提交必须使用同一注入时钟取得提交时点。生命周期算法可以继续保持纯计算，但不得在算法内部读取系统时间。A2-P 不需要等待 T3 的所有运行时迁移才能冻结字段语义，但不得新增裸时间调用或继续写入无法解释的 naive 值。

## 9. 测试与验收标准

计划完成必须同时满足：

1. hivememory.utils.time 是唯一生产时间实现入口，且不反向依赖 Core 或业务子系统。
2. 所有 canonical 持久化业务时间为 UTC-aware；新模型对 naive 输入 fail closed。
3. 所有生产耗时、timeout、TTL、idle、LRU、scheduler 和 rate-limit 判定使用 monotonic 或其注入函数。
4. System 组合根能够构造真实 Clock 和测试 Clock；受影响的行为测试无需固定 sleep 或全局 datetime patch。
5. TimeFormatter 只负责展示，接受 UTC-aware dt/reference；不通过 replace(tzinfo=...) 修补 naive 值，也不自行选择 lifecycle 字段。
6. MTP 展示时间可以显示本地时区，但持久化、比较和协议 canonical 值仍为 UTC。
7. 旧数据迁移有明确来源时区、numeric epoch 规则、无法恢复范围和可重跑报告；不存在静默猜测。
8. A2-P 的 Memory schema/Artifact schema 版本仍由 A2-P 各自管理，时间统一没有制造第三条版本轴。
9. 静态门禁阻止新增裸 datetime.now*、datetime.utcnow 和以 time.time() 计算耗时；allowlist 有具体文件和理由。
10. 运行受影响的 unit/integration 测试、ruff check、black --check、mypy、git diff --check，并记录外部依赖未运行范围。

## 10. 风险与完成后文档

主要风险是把持久化事件时间误判为进程内 idle 时间，或在无法确认旧数据来源时静默附加 UTC。T0 的字段清单、迁移预检和报告必须先于批量转换；任何无法解释的旧时间都应保持可见的迁移缺口。

实现完成后，更新 Memory 数据模型、Lifecycle、Artifact、Runtime/Event、协议和测试治理的当前文档，并把本计划移入 docs/archive/plans/。A2-P 在同一收口阶段补充其对本计划的依赖和最终字段类型；未完成的时间迁移设计继续留在本计划，不晋升为当前事实。
