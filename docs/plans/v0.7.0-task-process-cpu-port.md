# v0.7.0 任务进程：CPU 端口与测试 CPU

任务进程方向的第四批实施。前三批让 Patchouli 的公开路由不再产出或接收 Alice 专属的类型（版本目标第 1 条），但任务进程自己仍按名字调用 Alice：Actor 执行阶段写死了 Alice 的两条路由，并把 Alice 的 `done` 事件解析成 `AgentRunResult`。本批由 workspace 定义 CPU 端口，Alice 实现它，进程只经端口调用 CPU，并用一个非 Alice 的测试 CPU 跑通整个任务进程，使版本目标第 2 条收口。

设计依据：
- [任务进程 Idea](../ideas/task-process-table-and-registration-entry.md) 第 1.2 节“CPU 分配与输入清单”：2026-09-30 关于对象端口的决定，以及 2026-10-01 关于端口输出与 Alice 统一入口的决定；
- [外部 Actor Idea](../ideas/external-actor-registration-and-runtime-access.md#12-harness-登记的两个侧面owner2026-09-30) 1.2：harness 登记派生接入与执行两个侧面；
- [总 Idea](../ideas/workspace-network-task-process-architecture.md) 第 10 节 D-9：端口由 workspace 定义、Alice 实现，workspace 不导入 Alice；
- 当前事实文档与代码。

## 1. 背景和问题

`TaskProcess.run()`（`workspace/process/task_process.py`）的 Actor 执行阶段现在：

- 流式时调用 `GlobalRoutes.ALICE_RUN_AGENT_STREAM`，逐条拉取事件，遇到 `event == "done"` 时用其中的数据构造 `AgentRunResult`；
- 非流式时调用 `GlobalRoutes.ALICE_RUN_AGENT`，直接得到 `AgentRunResult`；
- 阶段产出 `RunCompleted` / `RunFailed` / `RunCancelled` 与非流式结果 `NonStreamingAgentOutcome` 都携带 `AgentRunResult`。

问题：

- 换一个 CPU 就要改进程代码，与版本目标第 2 条冲突；
- Alice 一侧同样有两个入口（`AgentRunService.run_agent` / `run_agent_stream`）与两条路由，两条路径重复了一套执行骨架，与第三批之前任务进程的情况相同；
- `AgentRunResult.mtp_iterations` 与 `total_iterations` 是 Alice 的统计，经 SSE `done` 事件发给前端，但前端只声明了类型、没有读取。

## 2. 目标与非目标

**目标**：

1. `workspace.contracts` 定义 CPU 端口（对象协议）与 CPU 中立的执行结果。任务进程只经组合根注入的端口调用 CPU，`workspace.process` 中不再出现 Alice 的路由名或 `AgentRunResult`。
2. 执行结果包含终态、最终回复、轮次事件、模型名，以及过渡期保留的物化任务；不含 `mtp_iterations` 与 `total_iterations`。去掉这两个字段后，它与 `AgentRunResult` 的字段一致，因此取代 `AgentRunResult` 与 `AgentRunStatus`，不让两个 DTO 表达同一概念并存。
3. 端口是一个以参数控制是否流式的统一入口，返回一个异步迭代器：流式时先产出交互事件，再产出唯一的终态结果；非流式时只产出终态结果。交互事件原样透传，进程不解释。
4. Alice：
   - `AgentRunService` 的两个入口合并为一个，与 `run_process` 一样以 `stream` 参数控制是否流式，内部只有一套执行骨架；
   - 两条执行路由合并为一条；
   - Alice 提供端口的实现，由组合根注入任务进程。
5. 移除 `mtp_iterations` 与 `total_iterations`，范围是：
   - 执行结果；
   - SSE `done` 事件（含命令短路的 `done`）；
   - `server/models/chat.py` 的 `ChatDoneEvent`；
   - 前端 `ChatDoneEvent` 类型。

   `agent.run.*` RuntimeEvent 中的同名统计属于 Alice 的观测，改由 Alice 从 frame 进度取得，事件载荷不变。
6. 一个非 Alice 的测试 CPU 能跑完整个任务进程，覆盖：
   - 流式与非流式；
   - 完成、CPU 自报取消与失败；
   - Actor 阶段的停止请求。

   测试中总线上不注册任何 Alice 路由，进程与入口代码不为此做任何改动（版本目标第 2 条）。
7. 除第 5 条外，对外行为不变：
   - SSE 事件的种类、顺序与其余字段；
   - `chat.run.*` 与 `agent.run.*` 事件；
   - 取消响应点；
   - 关闭流程的释放顺序；
   - 提交的交互记录。

**非目标**：

- CPU 的选择机制，以及 actor 对应 CPU 的映射（外部 Actor Idea 1.2：后续设计）。本批只有 Alice 一个 CPU，由组合根直接注入；
- 承载接入登记的配置文件（在 A1 返工中建立）；
- 外部 harness 的驱动与 CPU 描述（能力声明、编译预算）；
- 中立的交互事件类型：交互事件仍按 Alice 现有格式透传；
- 把进程访问上下文交给 CPU（随 A1 返工）；
- Topic 按需创建、写入意图迁移与 `materialize_tasks` 的移除。

## 3. 当前状态（2026-10-01 核对）

### 3.1 执行入口

| 位置 | 现状 |
|:---|:---|
| `AgentRunService.run_agent` | 非流式：直接运行 `RunExecutor`，返回 `AgentRunResult`；异常时发布 `agent.run.failed`；被取消时不发布终态事件 |
| `AgentRunService.run_agent_stream` | 流式：经 `AgentRunStreamAdapter` 的有界队列产出事件，最后产出带运行元数据（`agent_run_id`、`frame_id`、`stream_sequence` 等）的 `done`；没有终态即结束时发布 `agent.run.failed` 并报错；终态前被关闭时发布 `agent.run.cancelled`（`close_reason: stream_closed`） |
| 路由 | `alice.public.run_agent` 与 `alice.public.run_agent_stream`，由 `alice/runtime/bridge.py` 注册；流式路由用一个 async handler 返回生成器对象 |

### 3.2 `AgentRunResult` 与两个统计字段的消费方

- `AgentRunResult` / `AgentRunStatus`：定义在 `core/protocol/models.py`。生产代码的使用方只有任务进程（`task_process.py`、`outputs.py`、`service.py`）与 Alice（`agent_run_service.py`、`runtime/runtime_events.py`）。
- `mtp_iterations` / `total_iterations`：
  - 由 Alice 从 frame 进度组装；
  - 用于 `agent.run.*` 终态事件载荷；
  - 经 `done` 事件进入 SSE；
  - 出现在 `server/models/chat.py` 与前端 `types/chat.ts` 的 `ChatDoneEvent`，前端没有读取；
  - `tests/e2e/pipeline/test_agent_loop_e2e.py` 以 `mtp_iterations` 判断是否发生了 MTP 调用。

## 4. 目标设计

### 4.1 workspace.contracts：CPU 端口与执行结果

新增 `workspace/contracts/cpu.py`，只依赖 `core`。形状如下，命名可在实施评审时调整：

```python
class CPUExecutionStatus(str, Enum):
    COMPLETED = "completed"
    CANCELLED = "cancelled"
    FAILED = "failed"


class CPUExecutionResult(BaseModel):  # frozen
    status: CPUExecutionStatus
    final_text: str
    turn_events: list[TurnEvent]
    model_used: str
    materialize_tasks: list[PendingAtomMaterializeTask]  # 写入意图实时派发实现前保留


type CPUOutput = dict[str, Any] | CPUExecutionResult


class CPUPort(Protocol):
    def execute(
        self,
        manifest: CPUInputManifest,
        *,
        generation_options: dict[str, Any] | None,
        stream: bool,
    ) -> AsyncIterator[CPUOutput]: ...
```

端口语义（契约的一部分）：

- **终态**：终态结果恰好出现一次，并且是最后一项。非流式时它是唯一一项。迭代器在没有终态结果时结束，属于协议错误，进程按失败处理。
- **交互事件**：交互事件是带 `event` 与 `data` 的字典，进程原样转交给流式交付。
- **CPU 自报的结局**：经终态结果的 `status` 表达。CPU 抛出异常，按进程失败处理。
- **取消**：进程取消正在拉取下一项的任务（用户停止），并在关闭流程中关闭迭代器。CPU 必须传播 `asyncio.CancelledError`，在迭代器关闭时释放自己创建的资源。
- **`generation_options`**：由各个 CPU 自行解释，进程原样传递。

`turn_events` 收紧为 `TurnEvent`：Alice 的 frame 进度里本来就是 `TurnEvent`（`agent_runtime/models.py`）；`AgentRunResult` 上的 `list[Any]` 是已知未收紧的类型边界（[Agent 运行时](../alice/agent-runtime.md)第 10 节）。

### 4.2 任务进程

- `TaskProcessService` 新增必填的关键字参数 `cpu: CPUPort`，由组合根注入，未注入时无法构造。
- Actor 执行阶段只剩一个循环：调用 `cpu.execute(..., stream=self._stream)`，逐项拉取：
  - 每次拉取都经 `_run_interruptible` 包装，停止请求的响应点不变；
  - 交互事件产出为 `ActorEvent`，终态结果作为执行结果；
  - 迭代器交给关闭流程，与现在 Alice 子流的处理相同。
  - 非流式与流式走同一个循环，非流式只拉取一次。
- `RunCompleted` / `RunFailed` / `RunCancelled` 与 `NonStreamingAgentOutcome` 改为携带 `CPUExecutionResult`，字段名去掉 `loop_result` / `agent_run_result` 这类 Alice 词汇。`seal_interaction` 的调用点从执行结果取字段，签名不变。
- 流式 `done` 事件：除去两个统计字段，其余字段保持现状；命令短路的 `done` 同步去掉两个字段。

### 4.3 Alice

- **统一入口**：`AgentRunService.run_agent(input_manifest, generation_options=None, *, stream=True)` 以重载区分返回类型：
  - 流式时返回事件的异步生成器，最后一项是 `done`；
  - 非流式时返回可 await 的 `CPUExecutionResult`。

  内部只有一套骨架：会话、`agent.run.*` 事件、预检索 alias 预热、提示词组装、root frame 与 `RunExecutor`。`stream` 只决定是否接入 `AgentRunStreamAdapter` 并产出交互事件。现有两条路径的终态事件语义合并为一份，差异见第 9 节。
- **路由**：合并为 `alice.public.run_agent`，增加 `stream` 参数；删除 `ALICE_RUN_AGENT_STREAM`（`RouteNames`、`GlobalRoutes`、`AliceRoutes`）。
- **端口实现**：Alice 包内新增端口实现（暂名 `AliceCPU`），经全局总线调用上面这条路由：
  - 流式时原样转交交互事件，把 `done` 的数据转换为 `CPUExecutionResult`。`done` 中的运行元数据不进入结果，现在进程同样丢弃它们。
  - 非流式时产出路由返回的结果。

  Alice 的运行时仍在路由之后，进程只持有端口对象。
- **观测**：`agent.run.*` 终态事件中的 `mtp_iterations` 与 `total_iterations` 改由 Alice 从 frame 进度取得，载荷不变。

### 4.4 组合根与测试 CPU

- `SystemAssembler` 构造 Alice 的端口实现，作为 `cpu` 注入 `TaskProcessService`。
- 测试 CPU 放在 `tests/helpers/`，实现 `CPUPort`。它可以配置：
  - 产出的交互事件；
  - 终态结果；
  - 在拉取时挂起，用于取消测试；
  - 抛出异常；
  - 不产出终态。

  它同时记录迭代器是否被关闭。任务进程的单元测试改用测试 CPU，不再用总线注册 Alice 路由替身；Alice 端口实现在 Alice 的测试中单独验证。

### 4.5 依赖与分层

- `workspace.contracts` 只依赖 `core`，由 `tests/unit/workspace/test_import_boundaries.py` 守护；
- Alice 导入 `workspace.contracts`，符合 L3 之间只导入对方 `contracts` 的规则；
- `workspace.process` 不再引用 Alice 的路由常量。

## 6. 兼容与迁移策略

- 路由、模型与参数直接修改，不保留别名或转发；所有调用方在同一批内更新。
- 前端只删除 `ChatDoneEvent` 类型中的两个字段，没有读取方。
- e2e 测试中以 `mtp_iterations` 判断 MTP 调用次数的断言，改为统计执行结果 `turn_events` 中的 MTP 调用事件。
- 回滚：一批一个提交序列，整体回退即可。

1. `workspace.contracts` 新增 CPU 端口、执行结果与状态枚举。

## 8. 测试和验收标准

测试遵循[测试设计规范](../governance/testing/test-design-standards.md)。

**任务进程（`tests/unit/workspace/process/`，以测试 CPU 替换 Alice）**：

1. 测试 CPU 跑完整个进程，总线上不注册任何 Alice 路由，流式与非流式各验证一次：
   - 进程完成，finalize 收到的交互记录来自测试 CPU 的执行结果；
   - 流式交付原样转交测试 CPU 的交互事件；
   - `done` 不含 `mtp_iterations` 与 `total_iterations`。
2. 测试 CPU 自报取消或失败：进程以相应结局结束，不调用 finalize，并请求 cleanup。
3. 测试 CPU 在拉取时挂起：Actor 阶段收到停止请求后进程以取消结束，事件数据中的阶段为 Actor 执行阶段，测试 CPU 的迭代器被关闭。
4. 测试 CPU 没有产出终态结果即结束：进程以失败结束，流式交付发出 `error`。
5. 交付方提前关闭流式交付：测试 CPU 的迭代器被关闭，租借已释放。

其余现有的进程测试改用测试 CPU，断言不变。

**Alice**：

6. 统一入口：同一段脚本化的运行，流式最后的 `done` 与非流式的结果在终态、最终回复、轮次事件与模型名上一致。`agent.run.*` 的 started 与终态事件在两种模式下都发布，终态载荷仍含两个统计字段。
7. 端口实现：
   - 流式时交互事件原样转交，`done` 被转换为执行结果；
   - 非流式时只产出执行结果；
   - 关闭端口迭代器会关闭 Alice 的事件流。
8. 公开路由形状（`tests/unit/system/contracts/test_public_routes.py`）：只有 `alice.public.run_agent` 一条执行路由，参数含 `stream`。

## 9. 风险与待决问题

| 风险 | 应对 |
|:---|:---|
| Alice 两条路径合并后，非流式被取消时也会发布 `agent.run.cancelled`。现在非流式被取消时不发布终态事件，合并后两种模式一致 | 属于观测语义的统一，不影响业务结果；在测试 6 中明确断言，收尾时写入 Alice 编排文档 |
| 非流式改为经端口迭代器拉取一次，取消路径与流式共用 | 每次拉取仍由 `_run_interruptible` 包装；现有非流式取消测试改用测试 CPU 后继续通过 |
| `turn_events` 收紧为 `TurnEvent` 后，校验可能拒绝非 `TurnEvent` 的事件 | Alice 的 frame 进度只含 `TurnEvent`；端口实现测试覆盖流式 `done` 的还原 |
| 进程阶段名 `ProcessPhase.ALICE`（值 `"alice"`）仍带有 Alice 字样，出现在取消事件的 `phase` 数据与进程状态快照中 | 本批改名为 Actor 执行阶段（值 `"actor"`）。这会改变 `chat.run.cancelled` 事件 `data.phase` 的取值；前端不读取该值，收尾时同步路由与事件文档 |

待决问题：无。端口、执行结果与 Alice 端口实现的命名可在实施评审时调整。
