# v0.7.0 计划 B：外部记忆服务与 Actor 交互契约

本计划从原 Workspace 资源体系重构计划中拆出，与[计划 A 协调入口](./v0.7.0-workspace-resource-system-and-agent-execution-boundaries.md)及其 A1–A6 子计划共同服务于 v0.7.0。A 系列建立独立于 Alice 的资源、访问、交互和 Pending 边界；B 将其交付为外部客户端可使用的记忆服务，涵盖被动对话接入、主动资源交互，以及对未来历史导入的契约适配验证。

本文状态为 planned，包含待按阶段冻结的设计。创建本文不表示外部接口、身份认证或 Actor adapter 已完成；详细字段、错误和迁移门禁在 EMS-0/1 中收敛后才能进入相关实现。

2026-09-17 修订：主动写入期间的 Pending 读取与结算解析是所有 Actor 共用的资源语义。撤回原“外部只查询任务，不提供 Pending READ/redirect”的限制；B 消费 A4 的共享能力，不克隆 Alice 工作集。完整领域规则以[A4：共享 Pending 与主动记忆写入](./v0.7.0-a4-pending-memory-intents.md)为准，本文只维护外部协议交接与验收。

## 1. 问题与定位

### 1.1 三条相近但不同的使用路线

| 路线 | 调用方需要什么 | 必须保留的差异 |
|:---|:---|:---|
| 被动记忆服务 | 外部 bot/harness 自己对话，发送已发生事件，在 user turn 开始时取得可选记忆 context | 低延迟、实时 turn 边界、buffer、flush、背压与重发 |
| 主动资源交互 | 外部 Actor 按需搜索/读取、提交写入或修订意图、观察结果 | 结构化资源引用、显式授权、提交与结果语义；无需先发一条 user 消息 |
| 历史对话导入 | 把已有消息与工具轨迹保真导入，再按策略形成记忆 | 批次、历史发生时间、来源、重复导入、分支/编辑与恢复，不应重放实时副作用 |

三条路线可以共享身份映射、资源引用、来源模型和 Patchouli 领域能力。它们不共享所有会话规则、状态机或成功条件；消息能够序列化并不能证明处理流程等价。

这三种产品模式与“Actor 主动工具调用 / adapter 自动交接”是不同维度。主动资源模式中的 search/read/write/update 可由工具触发；交互开始准备 context、完整交互结束提交记录则由 adapter 自动触发。同一检索或提交操作仍使用同一 Patchouli API，不能把普通交互提交交给模型自行决定是否调用保存工具。

### 1.2 Passive Ingress 保留自己的职责

Passive Ingress 继续表示被动对话摄入，不把所有主动操作、任务查询、历史批次和工具执行塞进其 ingressor。它是外部接入体系中的一种模式；Actor 是外部执行者，adapter 负责协议转换，connector 负责某个具体平台或格式的适配。

“与 Alice 基本相同的资源能力”指相同资源操作遵守同样的授权与领域语义，包括主动写入物化前的 Pending 读取和结算后解析。它不要求外部 Actor 采用 Alice 的 frame、CALL、PendingAtomRuntime、prompt history 或 MTP 语法，也不承诺替代外部 harness 的执行 loop。

共同引用读取由 Patchouli 处理 Pending/canonical 分派与结算跟随，B 不复制原 Alice 的 L0/L1/L2 resolver，也不要求客户端先查询 Pending 再自行查 Memory。读取结果与错误遵循 [A4 第 4.1 节](./v0.7.0-a4-pending-memory-intents.md#41-共同引用读取与-alias-resolver-归属)，B 只映射引用、授权和状态到外部协议；内部 cache hit/miss 不形成不同的外部资源语义。

Profile 定义读取与执行配置应用遵循 A2 第 1.4 节：服务提供带来源/版本的定义，不要求客户端加载该定义、采用 Alice 工具模型或接收动态 system prompt。读取 Profile 不表示配置已生效；工具返回文本也不等于 system prompt 注入。支持动态应用的具体 harness 可在后续 connector 中映射支持字段并披露部分支持/拒绝，强制限制不能落实时拒绝相应应用请求。B 的参考客户端只需验证资源读取；不具备 prompt 配置能力也不影响记忆读写与自动交接验收。

### 1.3 与愿景及版本路线的关系

[VISION](../VISION.md)中开放记忆基础设施和 Alice reference runtime 是两条互补路径。A 证明资源独立；B 用参考客户端证明对外服务可用；v0.7.1 的具体 harness connector 再证明真实工作流有价值。

完整历史导入仍在 v0.7.2；本计划用历史样例检查契约是否保留时间、来源和关联信息，不提前实现导出格式解析、批次任务、断点续跑和大规模物化。MTP RUN 可靠性与沙箱仍由 v0.7.1 执行计划承担。

## 2. 当前基线与缺口

本次拆分基线为 274d9833；实施前需刷新代码与测试清单。文档与代码不一致时记录偏差，不据文档猜测尚未存在的能力。

| 当前入口/组件 | 已有行为 | B 要处理的缺口 |
|:---|:---|:---|
| server ingest router/models | /api/v1/ingest 与 /ingest/flush；入口解析 IdentityScope，要求具体 agent_id，并拒绝 body/header 身份冲突 | 原模型主要表达消息摄入，尚非完整主动资源协议 |
| PassiveIngressService / ingressor | user 事件走 Gateway/retrieval，其他事件追加；返回可选渲染 context | 主动资源操作不应通过伪造对话事件实现 |
| accumulator / dedup / serial gate | 外部事件标识、有界进程内去重、会话串行、turn 封口和背压 | 明确新协议的关联、冲突和保留期限，不能把 TTL 去重当作永久幂等 |
| InteractionSubmissionQueue | admission 后才清空当前 turn；已有 WorkRecord、apply、drain 语义 | ingress 成功、交互应用和 Memory 物化尚不能等同为一种成功 |
| Memory 管理与检索服务 | 已有公开 CRUD/检索能力，管理读与 Actor visibility 路径分开 | 主动 Actor 不得借管理接口获得 owner bypass |
| Alice MTP / PendingAtom | 原生运行期间可 READ/WRITE/UPDATE，run 成功后投影物化任务 | A 提炼通用 Pending；B 暴露写后读取与结算解析，不要求客户端创建 Alice Runtime 或完成 Alice run |
| 历史导入 | 已有实时消息模型可作为样例输入 | 尚无完整历史批次、格式、冲突与恢复契约 |

当前 GET/CRUD 等接口不是不存在；缺的是外部 Actor 可以理解且一致使用的能力集合、交互语义和结果边界。本计划先复用正确的已有入口与领域实现，再补缺口。

## 3. 目标、非目标和独立出口

### 3.1 必须交付

1. 将实时 Passive 与主动资源操作定义为两个可独立使用的模式，共享领域资源和来源语义。
2. 提供最小主动能力集：Memory SEARCH/READ、Profile 读取、已授权 READY 附件表示读取，以及主动写入/修订、Pending 内容/状态读取、结算解析和任务结果查询。
3. 保留已有 Passive 行为和调用方兼容路径，并补齐必要的提交关联及结果观察。
4. 明确入口身份映射、资源授权、内容来源和执行者身份的区别。
5. 为操作定义版本、输入、结果、错误、去重/冲突及生命周期范围；不同操作保留各自的成功条件。
6. 提供无需 Alice 的参考客户端/协议示例与端到端验收，客户端只依赖公开接口。
7. 使用历史对话样例验证共享模型，形成供 v0.7.2 导入计划承接的缺口与非目标清单。

### 3.2 本版本不交付

- 特定厂商 harness/Discord 的生产 connector；完整 MCP、SDK 和多 transport 生态。
- 完整历史导入器、批次调度、跨重启恢复、任意格式解析及历史冲突自动解决。
- 外部 Actor 专属的 PendingAtom 状态机克隆、统一所有操作的通用任务状态机；共享 Pending 能力由 A 提供。
- 工具执行、CALL 调度、Agent loop、强沙箱、外部 prompt history 托管或跨 harness 动态 Profile/system prompt 应用框架。
- 任意公网、多租户或完整 IAM 平台；首版只面向明确的本地/受信部署边界。
- 新的 worth_saving 算法、来源定位专项编译、Research 流程、任意管理与删除权限。

### 3.3 独立验收出口

参考客户端不启动 Alice，不导入 Alice/MTP 内部模型，通过公开接口完成两条链：被动对话获得记忆支持并提交交互；主动提出写入/修订后取得 Pending 引用，物化前读回意图与状态，查询真实领域结果并经原引用解析可见的 canonical 资源。无交互提交且 Topic 无 block 时仍可主动写入；UPDATE 使用有效目标。丢弃或拒绝同样正确表达，不以“一定生成 Memory”作为成功判据。

A 的完成不等待这个客户端。B 最终验收使用 A 的真实服务；B 可以提前用边界 fake 开发协议，但不能以 fake 返回值作为跨计划集成完成证据。

## 4. 目标结构与最小能力集

```text
外部 bot / harness                 历史导入客户端（v0.7.2）
     |                                       |
实时 Passive      主动资源请求         历史批次适配
     |                 |                     |
     +---- System 对外应用服务 / 版本化协议 ----+
                       |
          System 统一 Actor Authentication 网关
          （来源认证 + Workspace 准入 → access）
                       |
             GlobalSystemBus 公开 API 路由
                       |
             Patchouli application / 领域处理
                       |
          Workspace 资源 / 交互应用 / 记忆生成
```

初期依托 System 应用层、现有 FastAPI 入口与依赖中立 contracts 实现，不因本计划提前增加第四个大型子系统。Passive ingressor 不负责主动请求分发；公共协议也不下沉到 WorkspaceRuntime。A 不再交付平行的 Workspace resource/domain port 或 Patchouli provider 层；B 经统一访问边界使用既有 application API。同一资源操作与 Alice 使用相同公开路由，管理能力则由独立 operation 授权。

外部 Actor 的实际入口是 B 提供的 connector/Actor adapter 或其 HTTP/MCP 等协议适配层。B 提供协议特定的接入证据和身份解析，调用 A1 的 System 统一 Actor Authentication 网关；网关按接入登记确认 principal/Actor，再按 Workspace Actor 记录检查准入，两项均成功才返回 `WorkspaceAccessContext`。adapter 不分别调用两个认证服务。随后经与 System、Alice 相同的 `GlobalSystemBus` 公开路由调用 Patchouli，每次动作检查 Workspace 行为白名单，资源 owner 另行授权。有效 context 可用于多个操作，认证接口不绑定单次 operation。已有 System application service 可承担调用侧封装，但同进程 adapter 也不直接调用 Patchouli application 对象、cache、store 或内部 queue。远程客户端只看到版本化 wire contract；缺口从三方共同操作归并，不为外部 Actor 新造一套资源 API。

| 能力 | B 的最小交付 | 领域限制 |
|:---|:---|:---|
| Passive event / flush | 保持旧行为，提供新协议所需关联 | 不执行外部 tool event，不触发 Alice/CALL |
| Memory search/read | 结构化引用、内容或编译视图、已有版本/来源信息 | 复用 A 的 Actor-visible read；不使用管理 bypass |
| Profile read | 映射 A2 的 AgentProfile 定义与授权语义；需要完整资源及来源时读取 AGENT_PROFILE 原子 | 不要求 ProfileSnapshot 或伪造 builtin source；读取不等于实例化 Agent、改变 caller identity 或已应用 system prompt；客户端可不采用定义 |
| Attachment read | 解析已有授权 ref、READY 检查、必要内容快照 | lease 在服务内管理，不把 Python lease 对象跨 HTTP 传递 |
| Write/update intent | 显式提交内容、目标、理由与来源引用 | Patchouli 决定生成/合并/修订/丢弃；不把日志自动当作写入命令 |
| Pending read/resolve | 登记后可读取意图与状态，结算后由同一共同读取实现解析原引用 | B 不复制分派/跟随算法；task.observe 不自动授予内容读取权 |
| Result query | 返回提交类型及真实领域结果/可用任务投影 | 查询状态不授予读取最终 Memory 的权限 |
| Future historical input | 样例、来源/时间/关联表达与不兼容项说明 | v0.7.0 不开放未实现的 import 执行端点 |

首版不增加完全通用的 resource registry。不同资源保留其必要参数与错误；同一领域规则不可在 Passive、主动操作或 connector 中分别重写。

## 5. 计划 A/B 的共同交接

共享责任及内部接口以[A 计划协调入口](./v0.7.0-workspace-resource-system-and-agent-execution-boundaries.md)、[A1 访问边界（已归档）](../archive/plans/v0.7.0-a1-workspace-access-boundary.md)、[A2 资源读取](./v0.7.0-a2-workspace-resource-reads-and-caches.md)、[A3 Session/Topic](./v0.7.0-a3-conversation-session-and-topic-projection.md)、[A4 Pending](./v0.7.0-a4-pending-memory-intents.md)和[A5 API 收敛](./v0.7.0-a5-patchouli-unified-api.md)为准。

API、总线路由、application service 与 adapter 的术语及三方行为矩阵集中在[A5 共同 API计划](./v0.7.0-a5-patchouli-unified-api.md)。B 为每项外部行为标明对应共同 API、触发者、完成信号、权限与结果映射；A2–A4 交付领域能力，A5 核对完整目录与旧 prepare/finalize 的职责接收方。B 不复制 Topic 资料获取、生成编排、Pending 结算或交互应用逻辑，也不要求客户端模拟 Alice run。

B 消费统一网关完成两项认证后签发的 `WorkspaceAccessContext`、正式资源引用、完整 MemoryAtom/列表和 AgentProfile、独立的交互与主动意图提交、共享 Pending 登记/读取/结算解析、真实任务结果和关闭协调。领域返回类型以 A2 为准；HTTP/MCP/Passive 的协议 envelope 或编译视图在 adapter 中生成，不要求 Patchouli 返回 RetrievalResponse、MemorySnapshot 或 ProfileSnapshot。A 无需先实现 ActorSubmissionEnvelope 或外部状态服务；B 无需了解 A 的缓存层次和字典。

三类调用主体的统一链路与完整示例见[A5 共同 API计划](./v0.7.0-a5-patchouli-unified-api.md)。B 的被动/主动/历史三种业务模式与三类主体不是同一分类。

交付依赖为 A1 访问基线 → [A2-P 内容版本与 Lifecycle](../archive/plans/v0.7.0-a2-pre-memory-version-and-lifecycle.md) → A2 读取/cache；A3 交互/Topic 可在 A1 后并行，A4 消费 A2/A3，再由 A5 收敛完整 API。B EMS-0 可先调查三个样例；EMS-1 按 A2–A4 的实际模型分批冻结外部 wire，EMS-2 消费 A3，EMS-3/4 消费 A2/A4，完整操作映射再核对 A5。领域计划不以 B 样例评审或外部 schema 冻结作为完成门禁。B 使用真实资源组件独立组合，不等待 A6 的全部 Alice/MTP 重排；最终生产生命周期按 A2 的关闭契约并结合 A6 的集成成果接入。发现公开契约要求 Alice run/frame/runtime 时由相应领域计划提取；`PendingAtomMaterializeTask` 可继续作为共同领域输入，B 负责 wire 转换，不要求客户端构造 Python 模型。

## 6. 身份、协议与来源

### 6.1 身份边界

区分系统接入登记确认的 `CallerPrincipal`、外部软件/connector source、本次 `ActorIdentity`、Workspace 归属以及消息说话者。认证与授权以[A1（已归档，当前事实见 Workspace 架构第 4 节）](../archive/plans/v0.7.0-a1-workspace-access-boundary.md)为唯一依据：System 统一网关内部完成来源认证与 Workspace 准入，执行动作时由公共 application 检查行为白名单，资源 owner 再执行资源访问规则。原 `Domain operation policy` 不再作为独立授权层。access 必须完整透传；一个仍有效的 context 可以用于提交和检索，但两项 operation 分别授权。失效或切换 Actor/Workspace 时重新通过统一网关，不能在 adapter 内替换 context 身份字段。

首版基于本地/受信接入登记解析调用来源和 Actor，保留现有 header/body 冲突检查；source、agent_id、user_id 字符串不能自行构成认证结果。EMS-1 冻结具体 adapter 的身份解析方式与支持的部署范围，Workspace 准入与行为许可消费 A1 的访问注册表，不另建 connector 级业务权限表。同一 principal 可以服务多个 Actor，但不能接受未经接入规则确认的身份声明。完整远程认证不在本计划，不豁免 A1 的最小接入检查及运行时授权。

输入消息中“某用户说过”属于 provenance 声明，不自动成为 authenticated Actor identity。读取结果的使用权、提交意图的权限、管理删除权限分别判断。

### 6.2 协议承载与演进

首个实现以现有 FastAPI HTTP/JSON 应用边界为承载，提供独立参考客户端，不绑定某个厂商。已满足语义的 route 可复用；新增主动操作/结果查询按明确 schema version 或新路径提供。具体 route 和字段名在 EMS-1 冻结，不在本草案冒充现有 API。

既有 /api/v1/ingest 和 /ingest/flush 保留兼容，不增加强制新字段，不静默更换响应含义。新服务用到的字段和错误应通过 schema/样例明确；后续 MCP 或 skill 只负责协议适配。

### 6.3 必须冻结的契约表

| 类别 | 必须说明的语义 |
|:---|:---|
| 请求关联 | request、source event、conversation、turn、领域 interaction、operation 的区别及稳定关联 |
| 触发与完整交互 | 区分主动工具请求和自动交接；规定完成回调、seal/flush、取消/中断的消息完整性与重复完成信号处理，不把缺少结束消息推断为成功完成 |
| 资源寻址 | scope 下的 ID/alias/ref；版本是现有事实或显式不可用，不伪造版本和精确 locator |
| 意图提交 | 操作类型、内容/修订目标、已知基版本、来源 refs、客户端去重键、何时视为明确提交 |
| Pending | 登记/物化接纳的区别、稳定引用、读取授权与可见范围、focus/状态/结算投影、保留期；不要求 Alice run/frame |
| 来源 | source、外部 ID、occurred_at 与 received_at、role、工具调用关联；未知与缺失可表达 |
| 读取响应 | 结构化资源与可选渲染 context；未读取全部资源时不能宣称全部引用均被使用 |
| 结果 | 操作种类、其阶段与领域结果、canonical refs、必要错误和查询期限 |
| 错误 | invalid/unsupported、invisible/not-found、conflict、capacity、unavailable、expired/unknown；重试条件 |
| 版本 | 旧客户端兼容、新模型差异、弃用条件与示例 |

这些不是一个所有字段都可空的通用消息包。实现时按操作分为判别模型，复用明确的公共值类型；完整字段、长度/容量限制、错误映射和响应样例是 EMS-1 的产出。

### 6.4 外部会话与 Patchouli Topic 的数据交接

B 消费[A3](./v0.7.0-a3-conversation-session-and-topic-projection.md)的 ConversationSession、演进后的 InteractionPayload/TurnEvent 和交互结果中的 Topic 路由关联契约，完整字段、状态、路由候选与结构化投影只在 A3 维护。外部会话 ID 不能直接当 topic_id 或授权身份，外部客户端不必实例化内部 Python 类型，也不必构造 AgentAction、TurnRecord、Alice run 或 Patchouli 队列 envelope。

EMS-1 的交付是这些内部语义的版本化 wire 映射：明确外部 conversation/event/turn ID 如何映射稳定引用，完成回调/flush 如何封口为 InteractionPayload，时间和来源如何保留，缺少关联/结束信号如何表达，接纳、应用与 Topic 关联如何查询。封口与逻辑提交沿用 A3 的 interaction_id，不额外要求 segment_id。EMS-2 使用 A3 的公共模型与最小内部转换，补齐 Passive 外部兼容，不重新实现 Session 存储或 Topic 投影。外部摘要/checkpoint 只表达带来源的报告，不接管 Topic canonical summary 或 harness 的 prompt history。

## 7. 三种模式的流程

### 7.1 实时被动模式

user event → 按授权可选调用共同检索 API 取得 context → Session 开放段累积 TurnEvent → assistant/tool events → seal/flush 形成 InteractionPayload → 取得提交 access → `patchouli.public.interaction.submit` 全局路由 → Patchouli application → 内部 InteractionSubmissionQueue → Topic 路由/应用与结果查询。

新服务复用 A 的资源访问能力，保持“接收实际发生事件”的语义。actor 完成外部工具调用只报告事件，不在 HiveMemory 中重执行该工具。外部 harness 默认拥有 prompt history，记忆 context 是可选输入，不自动替换其上下文。

保留会话排序、scope 漂移拒绝、admission 前不清空、失败重试复用标识、idle/manual/shutdown flush。若需改变去重 key 或乱序处理，先冻结兼容差异；既有 sequence 字段不能被误称为已经实现重排协议。

封口后由 adapter 自动交接，不要求模型主动发起提交。外部 harness 若以完成回调交付整段记录，也映射到同一交互 API；仅有零散消息或工具调用而没有可靠结束信号时，协议必须表达尚未完整或显式 flush 的边界。取消、中断、idle/shutdown flush 按原有或冻结的部分交互规则处理，不能伪装为完整成功回复。

### 7.2 主动资源模式

显式请求 → 统一 Actor Authentication 网关完成两项认证（或复用仍有效的 access）→ GlobalSystemBus 公开路由 → Patchouli application 行为授权与资源 owner 授权 → 资源结果或提交收据 → 分别授权结果查询与 canonical 读取。System-owned Asset API 沿用对应的 System application 服务，同样消费 access；不同操作不要求分别申请单次认证凭据。

主动 SEARCH/READ 不要求创建实时 conversation。主动写入是调用方明确提交的意图，不靠伪造 user 消息触发 Gateway。不能因调用 CRUD 更容易，就绕过领域生成策略或 Actor policy。

一个外部 adapter 可以同时承接工具调用和交互生命周期事件：search 工具与交互开始的自动 context 都转向 `patchouli.public.memory.retrieve`；交互完成自动转向 `patchouli.public.interaction.submit`。MCP 只提供工具协议时仍需另有完成回调、消息流或 flush 集成，才能声称支持自动交接；本版用参考 HTTP 客户端验证这个责任，不提前要求完整 MCP 或厂商 connector。

主动写入必须支持共享 Pending 的物化前读取与结算后解析，不能只返回 task_id。参考流程为“WRITE/UPDATE → Pending 引用与当前阶段 → READ Pending 得到意图/状态 → 结算 → 解析 canonical 并重新验证读取权限”。UPDATE 只有 instruction 时返回修订意图，不伪造最终正文。登记与物化提交可由一次外部调用组合，但 ACK 明确区分两者；不要求完成 Alice run 或自行维护 Pending 状态机。

交互与主动意图使用独立 application 路由方法，可由同一 service 承接。adapter 将协议参数转换成 A3 演进后的 `InteractionPayload` 或 A4 的 `PendingAtomMaterializeTask`；A4 规定读取 Topic 全部可用资料辅助生成，空 blocks 不阻断有效意图。外部无需先伪造或提交交互；需要纳入特定交互时，调用方先确认其 applied 和实际 topic_id，再主动提交。客户端失联不默认取消已接纳领域工作；取消与保留期由共同契约约束。

### 7.3 历史导入模式的设计验证

使用含用户更正、助手推测、工具结果、旧发生时间及分支标识的历史样例，检查 source/时间/关联模型可以无损表达。记录与实时模型不兼容的字段和处理边界，交给 v0.7.2 导入 Plan。

不为每条历史 user 消息自动检索当前 context，不按到达时间把旧偏好当作最新偏好，不把整个批次混入当前活动 Topic，也不因能够解析消息 schema 就声称已经完成历史导入。

## 8. 提交、状态与幂等

### 8.1 业务状态不能合并为一种“成功”

| 对象 | 权威来源 | 对外成功能说明什么 |
|:---|:---|:---|
| ingress event | 实时入口及其去重/buffer | 已接收、缓冲、重复或忽略；不代表记忆落库 |
| sealed InteractionPayload | A3 的 System Session 记录/封口结果 | 记录已封口并具有明确 completion outcome；尚不表示提交已接纳 |
| interaction submission | Patchouli application/InteractionSubmissionQueue / apply 结果 | 已接纳或已应用，assignment 在路由后可查询；不保证生成正式 Memory |
| Pending 意图 | A 的资源侧 Pending 领域状态 | 已登记内容可按权限读回，并可关联物化状态；不表示任务已接纳或 Memory 已生成 |
| memory intent work | Patchouli 生成/修改服务与实际任务记录 | 该意图处理终态及 created/updated/discarded 等实际结果 |
| canonical resource | Patchouli / A 资源读取 | 已存在且当前 caller 可读的资源 |

外部 receipt 可以统一“如何定位结果”，不能统一这些对象的状态机。结果按 operation kind 带各自 phase/outcome；WorkRecord 和领域所有者继续维护状态，query service 不通过 best-effort RuntimeEvent 推进第二套业务状态。

如需外部 ID 到领域句柄的关联记录，它只持有映射、scope 与必要去重信息；保留期、容量和缺失行为必须冻结，不能复制领域 running/succeeded 状态成为新的权威记录。

### 8.2 幂等和模糊失败

同调用方/Workspace/操作种类的去重键需绑定规范化 payload 身份。相同键相同请求在承诺窗口内定位同一提交；相同键不同内容显式 conflict。不同类型的 event、interaction 和 intent 不混用一个无类型 ID。

窗口、进程生命周期和领域幂等能力必须写入协议。接收方提交成功但响应丢失时，客户端用同一键查询或受控重试；不能生成新键盲目重放。超出保留范围返回 unknown/expired 等明确结果，不猜测此前未提交，也不自动再次写入。

首次版本不承诺跨重启 exactly-once 或通用恢复。Memory 生成包含领域副作用时遵循现有重试限制，不能因通用队列支持 retry 就开启自动重放。

### 8.3 取消、失败与读取

取消只暴露领域实际支持的范围；无法撤销已提交副作用时返回真实结果，不能把“客户端断开”写成“资源已回滚”。参数/授权失败、容量拒绝、已接纳工作失败和查询不可用分开表达。

operation 查询也需校验 scope，知道 ID 不等于有访问权。Pending 内容读取、任务观察和 canonical 读取分别授权，资源侧共享 Pending 不表示同 Workspace 的 Actor 全部可见。即使查询返回 canonical ref，READ 仍重新判断当前可见性。来源 usage 回传是调用方报告，不能把“服务返回过 ref”当作可验证的实际使用证明。

## 9. 代码落点、迁移与生命周期

优先复用 server routers/models、System 应用服务、Passive ingressor、Patchouli 领域服务和 Work Queue。公共模型放在依赖中立 contracts；客户端模型不可导入 Alice 工作集。包名由 EMS-0 冻结，先有职责再增加目录。

| 切片 | 保留路径 | 新增或调整 | 禁止的过渡方式 |
|:---|:---|:---|:---|
| 基线刻画 | 现有 Passive 请求/响应、flush 和 queue | 建立行为样例、错误和关联清单 | 先替换旧服务再寻找兼容要求 |
| A 接口接入 | A 已完成的资源依赖切换与 Passive 会话行为 | 验证 memory context 使用 A 服务，补齐外部协议映射 | 重做 A 的内部切换或在外部层增加资源 cache |
| 新主动操作 | 旧 ingest 继续服务 | 版本化资源/意图/结果接口 | 通过隐藏消息冒充主动写入 |
| 结果观察 | 领域状态所有者不变 | receipt/句柄关联与查询 adapter | 从事件推测业务成功或另建全能 TaskStore |
| 收口 | 旧客户端可继续工作 | 公开协议与参考客户端 | 在 v0.7.0 无迁移窗口删除旧 ingest |

启动时先就绪 A2 资源与 Patchouli 领域服务，再装配外部应用服务和路由；无 Alice 的装配是必要验收。停止时先停收外部请求，再 flush 实时 buffer、完成受支持提交与领域 drain，最后解绑消费者和释放资源。B 不自行关闭 A 的 store 或 Patchouli runtime。A1–A5 以独立公开路由和真实组件验证，不要求提前把未稳定接口接入生产 SystemAssembler。

新接口可在装配层关闭，旧 ingest 行为仍可独立运行。发生协议回归时停用有问题的新入口并保留已提交 work 的处理/查询所需服务，不能删除已接纳记录来“回滚”；缓存回滚和资源一致性由 A 处理。引入任何持久化 schema 前须另补迁移计划。

## 10. 实施阶段

### EMS-0：场景、边界与基线

产出：实时、主动、历史三个样例；当前 endpoint/DTO/领域入口及测试清单；能力矩阵；A/B 交接审查记录；版本非目标。
补充：逐项对照[A5 共同 API计划](./v0.7.0-a5-patchouli-unified-api.md)和[A3 Session/Topic计划](./v0.7.0-a3-conversation-session-and-topic-projection.md)，标明主动调用与自动交接、已有路由与缺口；不能以外部 Actor 为单位重新设计一套 Patchouli 业务入口。
验收：Passive 不变成万能服务；A 能独立完成，B 不依赖 Alice 私有模型；历史导入和厂商 connector 不被提前纳入。

### EMS-1：协议、身份与结果契约冻结

产出：第 6.3/6.4 节模型及样例、HTTP 路由与版本策略、可信部署/身份映射、操作结果分层、幂等窗口、错误/取消/查询范围；与[A3](./v0.7.0-a3-conversation-session-and-topic-projection.md)的 Session/InteractionPayload/TurnEvent、[A4](./v0.7.0-a4-pending-memory-intents.md)的 Pending 引用/权限、登记与提交 ACK、Topic 缺失/快照语义对齐。
补充：冻结完整交互的完成信号、自动提交与重试责任；明确 Session、封口交互及其 Topic 路由关联、使用报告及结果观察如何映射到共同 API，保留被动与主动领域操作的独立授权。
验收：从三个客户端场景可明确判断 principal 映射、Workspace admission、operation capability、资源可见性、领域结果与失败；不把 ingress accepted 当作物化；任务/receipt 查询不能仅凭 ID 越权；未关闭的关键项不进入依赖它的实现。

### EMS-2：被动模式适配与兼容

产出：复用 A3/A6 的内部 access、InteractionPayload 与公共路由切换成果（application 内部才调用 queue），补齐 Passive 的 wire 适配、旧请求/响应兼容、必要提交关联、context 呈现和降级信息；不重做 A3 的内容投影或 A6 的旧消费者迁移。
验收：旧 ingest/flush 客户端可用；不触发 Alice/MTP；去重、背压、scope 漂移和 shutdown 行为正确；结果观察由 EMS-4 完成。
自动交接验收：模型没有调用任何保存工具时，完成/封口后的交互仍经共同总线路由提交；未接纳不丢 buffer，重复结束信号不重复应用。

### EMS-3：主动资源读取与意图提交

产出：Memory/Profile/Attachment 必需读取、显式 write/update intent、Pending 引用与内容读取的公开协议适配；Pending/canonical 使用 A2/A4 同一领域解析，Profile 仅承诺定义读取。
验收：无实时会话、无交互提交且 Topic 为空时也能提出有效意图；先获得 A 的 access，再使用真实资源授权与领域路径；物化前能读回内容/状态，无权限不泄漏，附件 lease 正确释放；不复制 Pending 状态机或 alias resolver。参考客户端不提供动态 system prompt 配置能力，仍完成主动资源与交互链路；Profile 读取结果带来源版本，不冒充配置应用成功。
复用验收：主动 search 与自动 context 在相同授权/查询条件下使用同一检索 API；外部 write/update 与 Alice 使用同一主动提交语义，不把协议参数转换升级为新的生成实现。

### EMS-4：结果观察与操作生命周期

产出：分类型 receipt 查询、Pending 结算解析、领域句柄关联、重试/冲突/保留期、断连与关闭行为。
验收：延迟、丢弃、失败、重复键冲突、响应丢失、过期查询均可解释；同一 Pending 引用可解析真实领域结果，canonical 内容另行授权；mutation 触发 A 的失效路径，不依赖外部客户端收到推送才能确认终态。

### EMS-5：参考客户端、历史样例与联合验收

产出：仅调用公开接口的可运行参考客户端/示例、真实内部组件端到端链路、历史模型适配报告、A/B 联合测试。
验收：无 Alice 跑通第 3.3 节两条链；历史样例能映射到 A3 的 Session/InteractionPayload/TurnEvent 但不启动导入产品；不依赖真实厂商服务才能执行确定性测试。
联合验收：参考客户端覆盖自动 context、主动工具调用、完整交互自动提交与结果观察；与 System/Alice 对照共同总线路由、领域收据和失败语义，不以转发次数或 fake 响应代替行为证据。

### EMS-6：兼容收口与文档归档

产出：公共协议说明、调用示例、支持/不支持范围、事实文档更新与本计划归档。
验收：旧 Passive 兼容、新主动链路、观测/错误、协议版本及 A/B 交接逐项关闭；厂商 connector 留给后续计划。

EMS-0/1 可与 A 的前期设计并行；EMS-2/3 依赖 A 对应服务可用，EMS-4 依赖领域提交与结果可观察，EMS-5 必须集成真实 A。完成单阶段不等于整个 v0.7.0 完成。

## 11. 测试与观测

遵循[测试设计规范](../governance/testing/test-design-standards.md)。测试按真实协作边界分类，fake 只替换边界之外的网络、模型或时间，不用检查 re-export、私有字典或空壳转发证明完成。

| 层级 | 行为 | 必须能识别的反例 |
|:---|:---|:---|
| unit | 外部身份选择/冲突、协议判别、关联与去重冲突 | source 被当认证；同键不同内容被吞掉 |
| integration | 统一认证网关 + Passive + access + GlobalSystemBus/真实 Patchouli application + queue | context 来自独立旁路；认证失败丢 buffer；提交成功后跳过 search 行为许可检查 |
| integration | 外部工具调用与完成回调/封口均映射共同 API | 只实现 MCP 工具却声称自动交接完成；模型未保存导致交互遗漏；重复完成信号重复应用；adapter 自行拼生成规范 |
| integration | 主动读取/写入、Pending READ/resolve + A 授权/失效 | 管理 bypass 泄漏；任务查询冒充待物化内容读取；更新后返回旧缓存 |
| integration | receipt + 真实任务结果、保留期和关闭 | apply 被说成 memory materialized；重试重复副作用 |
| e2e | 公开 HTTP 入口、参考客户端、无 Alice 的两条链 | 只用 fake service 才能跑通；要求 Alice PendingAtomRuntime/frame；空 Topic 阻断有效写入；无 Pending 读取闭环 |
| compatibility | 旧 ingest/flush 的请求、响应、错误及顺序 | 新增强制字段或更换 accepted 语义 |
| 历史契约样例 | 时间/说话者/来源/分支的编码与验证 | 旧助手判断变成当前用户事实；导入样例触发实时副作用 |

现有入口样例优先从 tests/unit/system/services/passive、server ingest 相关测试和 tests/integration/system 中核对并复用；确切文件映射在 EMS-0 列出。新增 e2e 放在 tests/e2e，内部总线、application、领域与队列协作必须真实，仅将进程外 LLM、向量数据库等外部依赖替换为符合协议的确定性实现。运行命令以 pyproject.toml 与 CI 为准，真实服务/模型测试单独声明运行条件。

观测记录 mode、operation kind、request/interaction/work 关联及 scope 安全投影，区分入口接收量、领域失败、查询过期、背压、资源拒绝和 drain 结果。错误和事件不记录原始敏感内容，不以事件流完整性作为业务正确性条件。

## 12. 风险与待冻结决策

| 风险/决定 | 默认方向或约束 | 冻结阶段 |
|:---|:---|:---|
| 协议无限扩张 | 最小能力表交付，RUN/CALL、批次产品和所有 connector 排除 | EMS-0 |
| 身份字符串冒充权限 | 明确本地可信映射，资源 owner 最终重验；不宣称完整认证 | EMS-1 |
| 结果查询产生第二状态机 | 类型化查询投影，句柄映射仅作关联；不复制领域状态 | EMS-1 |
| 历史与实时流程混合 | 共享事实模型，保留独立应用编排；批次仅作设计验证 | EMS-0/1 |
| 外部 session 强制等同 Topic | 消费 A3 的交互输入与结果中的 Topic 关联；wire ID 与资源归属、Actor 身份分开 | EMS-1/2/5，与 A3 对齐 |
| write/update 借 owner CRUD 绕过策略 | 通过领域意图入口，不把管理员权限暴露为 Actor 能力 | EMS-1/3 |
| 主动写后读取只存在于 Alice | 消费 A4 的共享 Pending；登记/接纳/物化分层，读取与结算按真实授权投影 | EMS-1/3/4，与 A4 对齐 |
| 旧 ingest 兼容破坏 | 旧模式保留，新协议显式版本化；冻结新增 route/字段 | EMS-1/2 |
| 结果保留、容量与模糊失败 | 有界进程内承诺、明确 unknown/expired，不盲目重放 | EMS-1/4 |
| 对来源/实际使用作过强声明 | 报告与验证事实分开；保留已有证据，不伪造 provenance | EMS-1/5 |

以上决策是本计划分阶段产出，不要求回填成 A 的阻塞项。若某项确实改变领域归属或 A 的公开 application 契约，双方更新交接记录后推进，不通过实现细节偷偷改变公共约定。

## 13. 文档与版本收口

实现、测试、迁移、验收与代码审查完成后，按[文档治理](../DOCUMENTATION.md)将实际落地内容写入当前事实：

- System Passive/应用服务：区分实时被动、主动资源与结果查询；明确没有实现的历史模式。
- Contracts：维护请求/响应、身份选择、错误、版本、结果与幂等范围；MTP 只引用共享领域语义。
- Patchouli：说明外部意图如何进入领域处理、何时算 apply/物化及来源如何保留。
- System composition：无 Alice 的服务装配、各入口 readiness 与关闭依赖。
- Plans/ROADMAP：分别记录 A/B 完成度，B 归档后保留到事实文档的入口。

A 负责资源所有权/缓存相关 ADR 的处理，B 不提前替它宣布变更生效。B 如形成独立长期协议决策，再增加相应 ADR。两份计划可以分别收口，共同发布 v0.7.0 时必须确认两个出口；任何一份完成均不表示 v0.7.1 connector 或 v0.7.2 历史导入已经交付。
