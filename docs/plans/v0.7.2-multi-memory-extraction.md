# v0.7.2 一个话题提取多条记忆

## 1. 背景和问题

话题结算（Mode A）的 extractor 对整段话题材料只返回一份草稿，同一话题中讨论过的多项决定、事实或经验只能压进一条记忆；检索向量只由标题、类型、标签与摘要编译，正文里的次要内容检索不到（[Patchouli 生成](../patchouli/generation.md#8-当前限制)第 8 节）。2026-11-01 的离线回放中，现行单条提取在 10 个真实话题上各只留下一条记忆，其中一个话题的主线工作完全没有留下（[多条提取与查重 Idea](../ideas/settlement-multi-memory-extraction-and-dedup.md#g-1-一个话题的多条记忆怎样提取) G-1 的回放记录）。

## 2. 目标与非目标

### 2.1 目标

- Mode A 的一次提取调用输出草稿列表，每条草稿逐条查重并提交（G-1 选项 A，owner 2026-11-01）；
- 同一批草稿分配到的 alias 互不冲突；
- Librarian 的输出上限提高到 32768 token（owner 2026-11-01：16384 或更高），Mode A 的输出被截断时任务显式失败，不记为没有产出。

### 2.2 非目标

- Mode B、Mode C 与合并任务：仍各产出一条结果，写入句柄与结算语义不变；
- 查重的判定信号与阈值（G-2）；
- 同一批草稿之间互相查重；
- 价值判断规则：提示词中的价值标准保持现状，价值体系由 owner 重新设计（[ROADMAP](../ROADMAP.md#47-记忆价值体系重新设计候选)第 4.7 节）；
- 主动写入的内容被 Mode A 再提取一遍：早已接受的代价，由查重与合并收拢（[Patchouli 生成](../patchouli/generation.md#7-实时派发与交互-finalize)第 7 节）。

## 3. 当前状态（2026-11-01 核对，commit `23288e33`）

- `BaseMemoryExtractor.extract(transcript, metadata)` 按 `metadata["mode"]` 在 Mode A 与 Mode B 的提示词之间分派，两种模式都返回 `ExtractedMemoryDraft | None`；两种提示词共用同一份单条草稿的 JSON Schema。
- `MemoryGenerationEngine.process` 已经返回 `list[GenerationOutcome]`；Familiar 逐条完成提交、Artifact 与持久化，控制面逐条发布结算与合并提名。
- `AliasGenerator.generate` 只查询中期库的占用；引擎先算完全部结果，Familiar 才开始提交。
- `_complete` 只返回模型文本；输出被截断时 JSON 解析失败，Mode A 记为没有产出，任务成功结束。
- Librarian 的 `max_tokens`：`configs/config.yaml` 与 `LLMGlobalConfig` 的代码默认值都是 8192。2026-11-01 以 16384、32768、65536 向提供商各发一次极短请求，都被接受。

## 4. 进入条件

G-1 已决定为选项 A（owner，2026-11-01）；G-2 不阻塞（回放中拆开的草稿对当前库判为 SIMILAR 的只有 1/73）。依赖都是现有事实。

## 5. 目标设计

### 5.1 提取接口

`BaseMemoryExtractor` 的提取拆为两个方法，替代按 `metadata` 分派：

| 方法 | 模式 | 返回 |
|:---|:---|:---|
| `extract(transcript)` | Mode A | `list[ExtractedMemoryDraft]`；模型输出为空或无法解析时为空列表 |
| `extract_write(transcript, *, content, reason)` | Mode B | `ExtractedMemoryDraft \| None`，行为不变 |

- Mode A 的输出是 `ExtractionResult`（`memories: list[ExtractedMemoryDraft]`），它的 JSON Schema 进入 Mode A 提示词；Mode B 提示词仍使用单条草稿的 Schema。
- 整段输出按一个对象解析，任一条草稿不符合结构时整段记为没有产出，与现状的“无法解析即没有产出”一致。
- 引擎只保留 `has_value` 为真的草稿。

### 5.2 截断

- `_complete` 返回完整的 `LLMCompletion`。
- `extract` 在 `finish_reason == "length"` 时抛出 `ModelProviderError`，不重试：同一请求会再次截断。Mode A 不捕获它，任务以 `memory_generation_failed` 失败，原文仍在来源 InteractionArtifact 中。
- 其他方法不变：Mode B/C 截断后解析失败走现有 fallback，合并以 `model_output_invalid` 失败，都已是显式结果。

### 5.3 引擎与 alias

- Mode A 对每条草稿依次调用现有的查重与构造（`_dedup_and_resolve`），结果按草稿顺序拼接。
- `AliasGenerator.generate` 增加 `taken` 参数：其中的候选视为已占用。Mode A 把本批已分配的 alias 依次传入，同一批中后缀相同的草稿得到 `_2` 等消歧后缀。

### 5.4 提示词

中英文 Mode A 提示词：

- 输出改为记忆列表；
- 新增“拆分粒度”一节，内容取自回放所用的说明：
  - 每件之后会被单独查找的事写成一条；
  - 同一件事的背景、过程与结论不拆开；
  - 顺带提及的内容不单独成条；
  - 不为凑数拆分，没有值得保存的内容时输出空列表。
- 用户提示改为要求输出记忆列表。

价值标准与其余各节不变。

### 5.5 配置

- `configs/config.yaml` 的 `shared.llm.librarian.max_tokens` 与 `LLMGlobalConfig` 中 Librarian 的代码默认值都改为 32768。
- 代码默认值同时改：它是没有配置文件时的产品默认，多条提取在 8192 下会截断最长的话题。

## 6. 受影响的系统、契约和数据

- Patchouli 生成：extractor 接口、引擎 Mode A、alias 生成器、提示词；
- 配置：Librarian 的输出上限；
- 错误模型：Mode A 的截断归入提供商失败的处理；
- 无公共 route、事件、持久化结构的变化；Familiar 与控制面已按列表处理结果，不改动。

## 7. 兼容与迁移

不涉及持久化数据。已有记忆不重新提取。测试中的 extractor 替身按新接口改写。

## 10. 风险与待决问题

### 10.1 风险

- 一批草稿中途提交失败时，已提交的记忆保留而任务失败，控制面只在任务成功时提交合并提名，这批的合并因此不会发生，留下重复。中途失败只来自存储或版本记录故障，记为已知限制。
- 同一批草稿之间不互相查重；回放中同一话题内 5% 的草稿有相似度高于 0.75 的另一条。
- 合并任务的数量随记忆变细而增加：回放模拟中，25% 的草稿在其他话题中有高于 0.75 的近邻。
- 回放样本都来自同一项目的开发会话。

### 10.2 待决问题

无。
