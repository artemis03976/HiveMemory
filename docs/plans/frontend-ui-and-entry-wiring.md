# 前端 UI 优化与空入口接线

本计划改善前端五个页面的排版、配色、清晰度与交互，重新设计浅色主题，把设置页分为常用与高级两层，并把仍然只有外观的入口逐项接上。实施先在运行页样稿的设计画布上补齐其他页面的样稿，owner 定稿后再改代码；验收在打包后的桌面端中进行（[桌面客户端归档计划](../archive/plans/desktop-client.md)第 4.7 节）。

## 1. 背景和问题

2026-11-11 在开发服务器上逐页截图核对了聊天、记忆库、Agent、运行与设置五个页面：深浅两套主题，1440 与 1100 两种宽度，数据来自 debug 模式的 mock 与页面内拦截的样例对话。问题按性质分为六类：

- **浅色主题是深色主题的反转**：`:root[data-theme="light"]` 改写 `--color-white` 与整条 slate 色阶，没有自己的调色板。
  - 组件中的 53 处 `bg-black/*` 不在改写范围内，浅色下输入框、Agent 系统指令框、记忆详情正文块、表格表头与标签都成了灰块；
  - 为深色写的 200/300 级文字色（如 amber 色的代码字）在浅色底上几乎看不见；
  - 23 处硬编码的紫色光晕不随主题变化。
- **排版**：
  - 9–11px 的文字有 60 处，`uppercase` 有 25 处，层级靠小号全大写英文撑着；
  - alias 与标签被强制大写，与实际写法不符；
  - 中英混杂（Runtime、MEMORY TASKS、“SEARCH执行完毕”）；
  - 日期格式不统一（`1/16/2025` 与 `06/11, 04:16 AM` 并存）。
- **布局**：
  - 三栏没有断点；
  - Chat 右栏在“引用记忆”标签时 320px、在“Runtime”（记忆任务）标签时 440px（`WorkspaceVision.tsx`），切换标签时整体跳动；
  - 窗口 1100 宽时中间栏只剩约 280px，输入栏的“记忆预检索”几个字竖排换行。
- **聊天页**：
  - 消息列表没有自动滚动，滚动条也被隐藏：打开会话停在最早一轮，流式输出不跟随；
  - 空会话固定显示“少女祈祷中...”，看起来像在加载；
  - 消息底部显示原始 `topic_id`；
  - 被拒绝的 RUN 显示为“RUN 中断”。
- **管理页**：
  - 记忆卡片固定 `h-64` 且 `overflow-hidden`，标签换行时底部的分数与日期被截断；
  - 卡片上的生命力与置信度只有图标，没有标签；
  - 筛选与创建表单用未加样式的原生 `<select>`；
  - Agent 的模型字段是自由文本。
- **反馈与外壳**：
  - 同一错误弹出两条 toast，并压住页面标题；
  - 管理凭据失效的提示在侧栏、toast 与运行页横幅三处重复；
  - 导航栏的图标中只有主题切换带 `title`；
  - 头像是外链图片；
  - 字体从 Google Fonts 在线加载，桌面端离线时回退到系统字体。

此外有两组已登记的缺口：

- **空入口**（候选清单 D-05）：
  - 消息下方的复制、点赞与重新生成按钮；
  - 输入栏的 `#` 话题引用按钮；
  - 部分消息仍从静态 `MOCK_AGENTS` 取 Agent 名称与图标；
  - 用户头像是固定的外部图片；
  - Agent 的启用与停用只是前端字段。

  见 [Chat 视图](../frontend/chat-view.md)与[管理视图](../frontend/management-views.md)第 2.2 节。
- **设置页**（D-15）：
  - 12 个分类中 7 个（基础设施、全局网关、记忆感知、记忆生成、记忆检索、生命周期、MTP 引擎）只显示“尚未对齐”；
  - 主配置整页保存，接入与权限逐项保存；
  - “恢复默认”作用于全部分类；
  - 保存提示不区分立即生效与等待重启；
  - 离开时没有未保存提醒；
  - 切换分类有 0.5 秒的进入动画。

  后端已经返回完整配置树与 `immediate_fields`、`pending_restart`（[主配置归档计划](../archive/plans/config-overrides-and-hot-reload.md)第 4.5、4.6 节）。

### 1.1 owner 决定

- 2026-11-07（D-05）：空入口与未对齐页面逐项接上，不删除，与前端 UI 优化一起完成。
- 2026-11-09（D-15）：设置分常用与高级两层，表单与生效提示由前端 UI 工作完成。
- 2026-11-10：前端 UI 优化另写计划，在桌面计划之后。
- 2026-11-11：
  - 保留现有的东方/魔法命名与紫色霓虹风格。纯紫偏单调，可以加入樱花粉作渐变或点缀。
  - 实现之前，先在运行页样稿的设计画布上补齐其他页面的样稿，供 owner 查看并调整风格。
  - 展示效果与使用体验之间的平衡由 agent 决定。

第 4 节都是这一授权下的候选设计，可以在样稿评审与计划评审时调整；调整结果记入实施记录。

## 2. 目标与非目标

### 2.1 目标

1. **样稿先行**：
   - 在运行页样稿的画布上补齐配色板，以及聊天、记忆库、Agent 与设置页的样稿；
   - 把运行页换成新配色；
   - 深浅两套主题都画；
   - owner 定稿后才开始改代码。
2. **令牌与主题**：
   - 组件只使用语义令牌，深浅两套主题各有独立取值；
   - 紫色为主，樱花粉点缀；
   - 主题可选深色、浅色或跟随系统；
   - 字体随包发布。
3. **布局骨架**：
   - 导航提示与读屏标签；
   - 本地头像与菜单；
   - 三栏的断点与固定宽度；
   - 全局连接状态条；
   - toast 的去重与位置。
4. **页面打磨**：
   - 聊天、记忆库、Agent 与运行页的排版、文案与状态呈现；
   - 设置页按常用与高级两层重组。
5. **空入口接线**：
   - 消息的复制、反馈与重新生成；
   - `#` 话题引用；
   - Agent 的名称、图标与头像；
   - Agent 的启用与停用；
   - 设置页的 7 个分类。
6. **基本可用性**（D-07）：
   - 最小窗口宽度下布局不被挤坏；
   - 键盘可达；
   - 图标按钮有读屏标签。

### 2.2 非目标

- **界面文案的多语言**（D-12）：本计划只把文案统一为中文。
- **可分离导航栏**（D-14，v1.0 之后），以及客户端路由与深链接。
- **记忆 Pin**：它需要生命周期上的语义（是否免于衰减与归档），属于记忆核心。本计划把按钮改为禁用并说明“尚未提供”，不再弹出“施工中”。
- **Agent Profile 的模型字段改为 `ModelSelection`**（[Todo](../todo/agent-profile-model-selection.md)）：本计划只把编辑页的自由文本换成注册表选择，Profile 的字段不变。
- **MTP 执行轨迹的树形可视化与等待标语**（CI-05）。
- **运行页的功能变化**：运行页只换配色与排版。
- **把删除数据、更改数据目录从托盘移进设置页**：renderer 只用公开 API，这需要主进程桥接，另行决定。

## 3. 当前状态

- **主题**：
  - `index.css` 用 Tailwind v4 的 `@theme` 定义令牌：七曜状态色 `magic-*`、五级表面 `surface-container-*`、`primary`/`secondary`/`tertiary` 及其变体；
  - 浅色主题在 `:root[data-theme="light"]` 下改写这些令牌与 `--color-white`、slate 色阶，另以 `[data-theme="light"]` 覆盖 `glass-panel`、`ghost-border` 与滚动条；
  - 主题只有深浅两档，由 `appUiStore` 的 `theme` 持久化，从导航栏按钮切换。
- **字体**：`index.css` 第一行从 Google Fonts 引入 Manrope 与 Inter。
- **导航与外壳**：
  - `GlobalNavBar` 有五个页面图标和主题切换；
  - `App.tsx` 按 `activeTab` 渲染页面；
  - toast 由全局 store 管理，固定在顶部居中。
- **聊天页**：
  - `ChatPane` 的消息列表没有滚动逻辑；
  - `ChatMessage` 的复制、点赞、重新生成三个按钮没有 `onClick`；
  - `OmniInput` 的 `#` 按钮没有行为，`@` 提及已能选择 Agent；
  - `ChatRequest`（`server/models/chat.py`）没有话题字段，话题由 Gateway 的话题路由决定。话题路由在用户消息为空、或话题路由模型失败时，续接上一轮所在的候选话题（`gateway/workflow/topology.py`）。
- **引用记忆**：
  - `memory_refs` 事件只在流式过程中下发，不写入会话记录；
  - 引用记忆面板中逐条的 👍/👎 已接到 `POST /api/v1/memories/{id}/feedback`。
- **Agent**：
  - `AgentProfile` 没有启用字段，前端 `toPayload()` 不发送 `status`；
  - Chat 的 Agent 选择器列出全部 Profile。
- **设置页**：`SettingsPanel` 有 12 个分类，其中 7 个在 `UNALIGNED_CATEGORIES` 中；各字段的生效方式已由配置接口给出。
- **桌面端**：
  - 窗口默认 1440 宽，没有最小尺寸；
  - 启动页是 `desktop/src/starting.html`，自带样式。

## 4. 目标设计

### 4.1 样稿

- **位置**：沿用运行页样稿所在的设计画布（目前只有一张 1440×900 的可交互运行页）。每个页面一张画板，深浅主题各一张，并排摆放。
- **画板**：
  1. **配色与组件板**：
     - 两套主题的色板、渐变与字号阶梯；
     - 按钮、输入框、选择框、徽标、卡片、toast 与连接状态条。
  2. **聊天页**：
     - 有历史的会话（含 MTP 卡片与子 Agent）；
     - 流式进行中；
     - 空会话；
     - 另加一张 1100 宽的窄窗口布局。
  3. **记忆库**：网格、记忆详情与短期话题池。
  4. **Agent 页**。
  5. **设置页**：常用与高级各一张。
  6. **运行页**：换成新配色。
- **内容**：
  - 用接近真实的样例数据（与截图时的样例对话一致），不用占位文字；
  - 画板以静态为主，聊天页的“回到最新”与设置页的未保存栏可以交互。
- **评审**：
  - owner 在画布上评论或直接修改；
  - agent 按意见调整后，再请 owner 确认；
  - 定稿后，配色板上的取值就是第 4.3 节令牌的取值。

### 4.2 视觉方向

- **主色与点缀**：
  - 紫色仍是主色，用于选中、焦点与主要操作，樱花粉是第二强调色；
  - 紫到粉的渐变只用在少数焦点上：品牌标记、导航当前项的指示、每个视图里最主要的一个按钮、页面主标题的装饰线；
  - 大面积的背景与卡片保持中性，不铺渐变。
- **颜色只表示状态**（沿用[运行页](../frontend/run-view.md)的规则）：
  - 七曜色继续表示进行中、完成、失败与警告，樱花粉不表示任何状态；
  - 现在的失败色 `magic-fire`（`hsl(340 80% 60%)`）与樱花粉色相相近，改为偏橙的红（取值以样稿为准），使“失败”不会被看成装饰；
  - 记忆的类型是例外：记忆图书馆与引用记忆卡片中，类型用七曜色的图标块表示（图标着色，底为同色的浅底，类型名是中性文字），卡片背景与边框不带类型色；状态始终是圆点加文字，两者靠形状区分。类型色是独立的一组令牌，反思保留原来偏粉的红，不与新的失败色混淆。
- **深色**：
  - 保留近黑偏紫的底色；
  - 表面分三级，边框与分隔线用独立令牌；
  - 正文与次要文字对底色的对比度至少 4.5:1，弱文字（标签、时间）至少 3:1；
  - 光晕收进一个令牌，只用在当前项与主要按钮上。
- **浅色**：
  - 独立的调色板，不由深色反转而来；
  - 底色是带一点薰衣草色的白，表面是白与浅紫灰；
  - 主色与樱花粉都取更深的一档，保证白底上的对比度；
  - 状态色取 600–700 档；
  - 不用光晕，改用轻阴影区分层级。
- **东方元素**：
  - 保留现有命名，以及“少女祈祷中...”这类文案，但只用在标题、加载与空状态这样的位置；
  - 操作按钮、表单标签与错误提示用直白的说法；
  - 必要时风格化名称作标题、直白说明作副标题，例如“帕秋莉”一栏下写明“记忆的检索与生成”。

### 4.3 设计令牌与字体

- **令牌**：沿用现有名称，补上缺少的语义。
  - 保留：`surface-container-*`（表面层级）、`primary`（主色）、`magic-*`（状态色）。
  - 新增：
    - 正文、次要与弱三级文字色；
    - 常规与加重两级边框；
    - 樱花粉 `accent`；
    - 品牌渐变；
    - 遮罩，替代 `bg-black/*`；
    - 光晕。
  - 每个令牌在深浅两套主题下各有取值。
- **组件改写**：
  - 组件中的 `bg-black/*`、`text-white`、`text-slate-*`、`border-white/*` 以及硬编码的颜色与光晕，全部改为令牌；
  - 改写完成后，删除浅色主题对 `--color-white` 与 slate 色阶的改写，两种写法不并存。
- **字号**：
  - 阶梯为 12、13、14、16、20、24、32px，正文 14px，最小 12px；
  - 层级靠字重与颜色区分，不用 `uppercase`；
  - 等宽字体只用于标识符、代码与日志，并原样显示大小写。
- **日期**：
  - 今天只显示时分，今年显示月日与时分，更早的显示完整日期；
  - 列表中的近期时间用相对时间（“3 分钟前”），悬停显示完整时间。
- **字体**：
  - Manrope 与 Inter 以 npm 包随前端构建打包（都是 OFL 许可），删除 Google Fonts 的引入；
  - 中文回退到系统字体（Microsoft YaHei UI、PingFang SC、Noto Sans SC），等宽用 Cascadia Mono、Consolas。
- **主题选项**：
  - 可选深色、浅色或跟随系统；新安装默认跟随系统，已经保存为深色或浅色的保持不变；
  - 跟随系统时监听 `prefers-color-scheme`，桌面端由 Electron 按 Windows 的设置给出；
  - 头像菜单与设置页的外观一节都可以切换。
- **自定义背景**（D-13 的剩余部分）：
  - 外观一节里可以选择一张本地图片作为主区域背景，并调节遮罩浓度；
  - 图片只存在本机的浏览器存储（IndexedDB）中，不上传后端；
  - 读取失败时回到默认背景；
  - 面板与卡片先用不透明的表面令牌；毛玻璃效果是为了让自定义背景透出，与自定义背景一起实现。

### 4.4 布局骨架

- **导航栏**：
  - 每个图标都有悬停或键盘聚焦时出现的提示，并带 `aria-label`；
  - 当前项用品牌渐变的竖条指示。
- **头像**：
  - 换成本地的默认头像（品牌标记）；
  - 点击打开菜单，菜单中是主题选择与“外观设置”入口；
  - 没有账户系统，不显示用户名。
- **三栏**：
  - 中间栏最小 560px；右栏固定 360px，不再随标签变宽；
  - 窗口宽度放不下三栏时，右栏改为可开合的抽屉，从右侧覆盖在中间栏上；再窄时，会话列表也收为抽屉；
  - 桌面端窗口设置最小尺寸 1024×640。
- **页面头部**：各页统一为标题加一行说明，右侧放本页的操作。
- **连接状态条**：
  - 后端连不上或管理凭据失效时，主区域顶部出现一条状态条，写明原因与处理办法；
  - 各页面的局部空状态只说“数据暂不可用”，不再各自重复原因。
- **toast**：
  - 放在右上角、页面头部之下，不压住标题；
  - 相同文字在显示期间只出现一次；
  - 成功提示 2 秒后消失，错误提示停留 6 秒并可手动关闭。

### 4.5 聊天页

- **滚动**：
  - 打开会话时定位到最新一轮；
  - 停在底部时，新消息与流式输出自动跟随；
  - 用户向上翻时不再跟随，底部出现“回到最新”按钮，并标出新增的消息数；
  - 滚动条可见（细样式）。
- **空状态**：
  - 没有选中会话或会话为空时，显示欢迎区：当前 Agent、记忆预检索开关的状态与几条示例问题；
  - “少女祈祷中...”只在确实在加载历史时显示。
- **消息**：
  - 用户消息改为紧凑的气泡；
  - 助手的正文不再包在带边框的大卡片里，只有 MTP 与子 Agent 卡片带框；
  - MTP 卡片的动词徽标保留协议名（SEARCH、READ……），说明改为中文（“检索完成，命中 4 条”），标识符原样显示；
  - 被拒绝的操作写出原因（“RUN 被拒：只能运行代码片段”），不再显示“中断”。
- **话题**：
  - 消息底部显示话题标题（取自话题列表），标题不可得时显示“未命名话题”；
  - 点击跳到记忆库的短期话题池，并定位到这个话题。
- **引用记忆面板**：分数写明是“相关度”，生命力与置信度带文字标签。
- **模型配置**：覆盖开关关闭时，直接列出当前生效的值（来自 Agent 与模型定义），不再只是灰掉滑块。

### 4.6 记忆库与 Agent 页

- **记忆卡片**：
  - 类型用带颜色的图标块表示（见第 4.2 节），旁边是类型名与别名；
  - 高度随内容，正文限制行数，底部的指标与日期始终可见；
  - 指标带标签（“生命力 92”“置信度 42%”），悬停说明含义；
  - 标签原样显示大小写。
- **表单控件**：
  - 原生 `<select>` 保留它的键盘与读屏行为，按令牌统一样式（去掉系统外观，加上下拉箭头）；
  - 不引入组件库。
- **记忆详情**：
  - 保持两栏：头部是类型图标块、标题、类型名与别名（可复制）、摘要；左侧是记忆内容，右侧是分组的元数据栏（元数据、时间线、来源、标签）；
  - 元数据中的 ID 可复制，置信度与生命力带短条与悬停说明，时间按统一格式；
  - 右上角是编辑、Pin、删除与关闭，都有悬停提示，删除与其余按钮隔开；Pin 禁用，并提示“尚未提供”。
- **短期话题池**：显示标题、摘要、块数与相对时间。
- **Agent 页**：
  - 模型字段改为从模型注册表中选择，保存的仍是 `model_name`；
  - 注册表里没有当前值时，显示这个值并标注“不在注册表中”；
  - 启用开关见第 4.8 节。

### 4.7 设置页（D-15）

- **结构**：左侧导航分三组。
  - **常用**：一页，按[主配置归档计划](../archive/plans/config-overrides-and-hot-reload.md)第 4.5 节“常用设置”的分组（模型、记忆、对话、附件、系统）排成若干小节，另加外观一节（主题与自定义背景）。
  - **高级**：一页，按同一节“高级设置”的分组排列；存储地址与集合名只读展示。
  - **管理**：提供商凭证、模型注册表、接入与权限三个分类保持现有的独立页面。
- **取代的分类**：
  - 原来的通用设置、内部引擎与 7 个未对齐分类，由常用与高级两页取代；
  - 每个设置项都绑定到真实的配置字段，“尚未对齐”提示删除。
- **每一项**：
  - 直白的名称、一行说明，以及生效标记“立即生效”或“重启后生效”，取自配置接口的 `immediate_fields`；
  - 保存后，`pending_restart` 中的项显示“等待重启”，页面顶部汇总“N 项设置等待重启”。
- **保存**：
  - 常用与高级两页有改动时，底部出现保存栏（放弃、保存）；
  - 有未保存的改动时，离开页面或切换分类前先提示；
  - “恢复默认”移到每个小节，只恢复这一小节的字段，并需要二次确认。
- **命名**：小节标题保留风格化名称（如帕秋莉、小恶魔），旁边写明它控制什么；具体文案在样稿中确定。
- **动画**：删除切换分类时的进入动画。

### 4.8 空入口接线（D-05）

| 入口 | 行为 | 涉及 |
|:---|:---|:---|
| 消息的复制 | 复制这条回复的 Markdown 原文，提示“已复制” | 前端 |
| 消息的 👍/👎 | 对这一轮预检索命中的记忆逐条记录反馈，沿用 `POST /api/v1/memories/{id}/feedback`。只在本页知道这一轮命中了哪些记忆时显示（当前页面中完成的轮次）；从会话历史加载的轮次不显示 | 前端 |
| 重新生成 | 只出现在最后一条回复上：以同一 Agent，把这一轮的用户消息作为新的一轮再发送一次，原来的一轮保留在历史中（会话原文不删改）。原轮次的附件不随之重发，按钮提示写明这一点；流式进行中不可用 | 前端 |
| `#` 话题引用 | 输入 `#` 或点击按钮，弹出短期话题池中的话题，可按标题筛选；选中后在输入框上方显示话题标签，可以移除。请求带上 `topic_id`，Gateway 的话题路由直接取这个话题，不调用话题路由模型。话题已不在候选话题中（已结算或被驱逐）时，这一轮在 Gateway 阶段以结构化错误失败、不提交，页面提示重新选择；这个拒绝不是话题路由失败，不进入续接上一轮的兜底 | `ChatRequest`、任务进程交给 Gateway 的输入、Gateway 话题路由、错误模型、前端 |
| Agent 的名称、图标与头像 | 消息与选择器中的 Agent 名称、图标都取自 Profile 列表；不在列表中的 Agent 显示默认图标与 `agent_id`；`MOCK_AGENTS` 只留给 debug 模式 | 前端 |
| Agent 的启用与停用 | `AgentProfile` 增加 `enabled`，缺省为启用，已存的 Profile 读作启用。Agent 页的开关保存它；Chat 的选择器与 `@` 提及只列出启用的 Agent。以停用的 Profile 发起对话时，Profile 解析以 `ProfileResolutionError` 拒绝，原因为 `profile_disabled` | `core.models.agent`、Profile 解析、Agent 管理接口、前端 |
| 用户头像 | 见第 4.4 节 | 前端 |
| 设置页的 7 个分类 | 见第 4.7 节 | 前端 |

`enabled` 只表示这个 Profile 能否用于对话，不是操作权限：Agent 的操作权限仍只由 Workspace 访问登记表达；plugin 模式的 harness 不使用 Profile，不受影响。

## 8. 风险与待决问题

- **改动面大**：第 2 步会改到几乎所有组件。缓解：每一步合并前，在两套主题、两种宽度下截图并与样稿对照；截图脚本放在本机临时目录，不进仓库。
- **樱花粉与失败色混淆**：缓解见第 4.2 节，失败色改为偏橙的红，粉色不表示状态。
- **消息反馈只覆盖当前页面中的轮次**：预检索命中不写入会话记录，从历史加载的轮次无法得知命中了哪些记忆。要覆盖历史轮次，需要把每一轮的命中写进会话记录，这是另一项后端改动，本计划不做。
- **`#` 话题引用被拒绝**：选择话题与发送之间，话题可能被结算。选择器只列短期话题池中的话题；被拒绝时提示重新选择，不自动改为路由，避免这一轮悄悄落到别的话题上。
- **待决**：没有阻塞问题。可以在评审时调整的有：
  - 断点与右栏宽度；
  - 头像菜单的内容；
  - 消息反馈的语义；
  - 重新生成是否带上原附件；
  - 自定义背景是否放在这一计划中。
