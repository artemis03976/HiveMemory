# v0.8.0 生成的记忆指向交互轮次：事件记下模型响应，记忆引用到段

> 状态：Planned（2026-11-18）。v0.8.0 的第二个方向“生成的记忆指向交互轮次”的计划，排在主被动记忆的复核之前；设计依据见[写入链路 Idea](../ideas/memory-flow-write-path.md)第 5 节。

## 1. 背景和问题

被动结算下的复核与它要用的判定格式，都要求记忆能指回具体的交互：判定要指出依据在哪几段，复核要看到写入与更新发生在哪里（owner，2026-11-18）。现在记忆只指向整份话题快照：

- 原始记录有坐标：`TurnRecord` 有 `turn_id`，每个 `TurnEvent` 有 `sequence`，交互快照逐轮保留它们；
- 坐标丢在中间：生成材料的 `GenerationTurn` 没有 `turn_id`，渲染为序数 `[Turn 1]`、`[Turn 2]`，事件没有编号；模型输出的草稿没有来源字段；记忆的 `ArtifactRef` 指向整份交互快照；
- 一次模型响应的边界没有记录：Claude Code 连接器读到每次 API 响应的 `message.id`，只用于去重；Alice 的 `iteration` 只出现在调用标识里。

一轮中常有几十上百次工具调用（日常实例去重后的 1,076 轮中，每轮事件 P90 为 72 个，最多 460 个），只引用到轮次时，同一轮产出的多条记忆全都指向同一处，没有区分度；直接引用事件，模型又要在几十个条目里挑。思考块撑不起边界：owner 最近 6 个 Claude Code 会话中只有 4%～8% 的响应带思考正文。模型响应的边界总是存在，一次响应常常并行发出多个调用（15%～35% 的响应有 2 个以上）。

## 2. 目标与非目标

### 2.1 目标

1. 原始记录中的每个由模型产生的事件，记下它来自本轮第几次模型响应（owner，2026-11-18）。
2. 段由事件派生、不保存：连续的响应合成一段，供材料与引用使用；切段以原始交互记录为准，生成材料只是视图（owner，2026-11-18）。
3. 被动提取、主动写入与修订的模型在输出中引用段；代码把合格的引用换算为轮次标识加事件序号区间，随这一版记忆的版本记录保存。
4. 回放脚本能在带响应序号的轮次上重放生成，统计引用是否合格、多次运行是否一致，用于确定切段参数与验收。

### 2.2 非目标

- **读取方**：第一个读取方是下一个方向的复核（owner，2026-11-18）。本计划只写下引用，落地时没有生产读取方，这是 owner 同意的例外：生成时模型引用了哪几段，事后无法重建。管理页、MCP 的读取与前端都不读，会话 HTTP 接口与前端类型不增加响应序号。
- **主动写入的锚点**：WRITE、UPDATE 事件自身的位置。Alice 一侧可以事后从 `produced_aliases` 推出，外部 harness 一侧 Import Bus 不接受 `produced_aliases`；两者都留给复核方向。
- **在材料中渲染写入与更新**：属于复核的输入（写入链路 Idea 第 3.1 节）。
- **已有数据**：不回填。已有轮次没有响应序号，整轮作为一段；已有记忆仍只指向整份快照。
- **合并与手动编辑**：合并没有交互材料，手动编辑没有模型，两者的版本记录都不带引用；合并的版本记录以被吸收记忆的 Artifact 引用为来源（`source_artifacts`），来源经此追溯。
- **折叠的轮次**：被动材料中已折叠的轮次只以话题状态摘要出现，不能被引用。

## 3. 当前状态（2026-11-18 核对）

- **事件**：`TurnEvent`（`core/models/interaction.py`）为 `frozen`、`extra="forbid"`，可选字段按 `_EVENT_OPTIONAL_FIELDS` 只允许出现在 `tool_call` 上；`validate_turn_events` 只校验序号 0 的用户消息、序号严格递增、没有第二条用户消息、调用标识唯一。`InteractionPayload` 构造时调用它。封口 `seal_interaction` 在给了回复正文却没有助手正文事件时补一条，Alice 总会写出助手正文，Import Bus 不传回复正文，因此生产中不触发。
- **写出方**：
  - Alice：全部非用户事件在 `agent_runtime/loop.py` 构造，`iteration` 在每次生成前加一，在每个构造点可用；同一次生成的正文与调用属于同一个 iteration。Alice 不产生思考与子 Agent 消息事件。
  - Claude Code（`connector/claude_code/reader.py`）：每个助手内容块都能取得 `message.id`（缺失时退回条目的 `uuid`）；同一条 API 消息分成多个条目写入、按消息标识与块位置去重。子 Agent 消息来自用户条目，没有消息标识。
  - pi（`node/pi/turns.js`）：每个助手条目就是一次模型响应，正文、思考与调用块在同一个条目中。
  - dsh（`node/dsh/turns.js`）：`assistant/message`、`tool/call`、`tool/result` 都带 `step`，读取器没有使用；仓库中的样例全为 `step: 0`，它是否按轮、从几开始没有确认。
  - Codex（`connector/codex/reader.py`）：只读 `event_msg` 与 `item_completed`，条目只带自身标识，没有响应边界；并行调用按完成顺序写出。
- **Import Bus**：`ImportedTurnEvent` 为 `extra="forbid"`，`to_turn_event` 逐字段转写；连接器把 413 与 422 当作这一轮被拒绝，写下拒绝记录并前移游标。
- **持久化的编码**：交互提交 `InteractionSubmissionCodec` v7 与生成队列信封 1.2 都要求解码后重新编码与原载荷相同。交互提交队列只驻留于进程内；生成队列的工作在关闭时保存、下次启动读回，已有 1.1 的读回适配器。
- **生成材料**：`GenerationTranscriptBuilder.build_context` 收到带 `turn_id` 与事件的 `LogicalBlock`，转成 `GenerationTurn` 时丢弃两者；`render_turn_material` 同时供 token 估算与接力摘要使用。被动结算的材料是话题的工作视图（已折叠的轮次只留摘要），主动写入与修订的材料是工作视图中最近的 5 轮，不含发出写入的这一轮。
- **模型输出**：被动与主动写入的输出格式由 `ExtractedMemoryDraft` 的 JSON Schema 自动生成；修订与合并的格式在提示词中手写（`i18n/prompts.py`，中英文各一份）。被动输出中任一草稿不合格，整份输出作废；主动写入输出不合格时退回由写入内容组成的草稿；修订不合格时退回追加。
- **版本记录**：每个内容版本写一份 `MemoryVersionArtifact`（`extra="ignore"`），`source_artifacts` 含这次生成捕获的交互快照；新建时另写 `MemoryCreationArtifact`。版本记录不进入记忆投影：管理接口的 `MemoryResponse` 与 MCP 的读取都不包含 Artifact 引用。

## 4. 进入条件

阻塞问题已决定（owner，2026-11-18，写入链路 Idea 第 5 节）：先于复核实施；粒度按模型响应记录；切段与引用以原始交互记录为准；轮次标记只供记忆生成使用，由复核读取。

## 5. 目标设计

### 5.1 事件的响应序号

`TurnEvent` 新增可选整数 `response_index`：本轮第几次模型响应，从 1 开始。

- 只出现在 `assistant_message`、`thought` 与 `tool_call` 上；用户消息与子 Agent 消息不带。
- 一轮之内全有或全无：只要有一个事件带它，全部助手正文、思考与调用都带；带的事件中，它随序号单调不减。由 `validate_turn_events` 校验，违反时整轮拒绝。
- 写出方：
  - Alice 取 `iteration`；
  - Claude Code 按 `message.id` 在本轮首次出现的顺序编号；
  - pi 每个助手条目一次；
  - dsh 取 `step`，实施前用 owner 本机的 dsh 会话日志核对它的含义，确认不了就不填；
  - Codex 不填，整轮作为一段。
- 封口补写的助手正文取本轮最后一个响应序号；本轮没有响应序号时不带。
- Import Bus 的 `ImportedTurnEvent` 与 `to_turn_event` 增加这个字段；会话 HTTP 接口与前端不增加。

### 5.2 段

段由一轮的事件按确定规则推出，读取时计算、不保存：

- 带正文或思考正文的响应开启新段，其余响应并入当前段；一段超过上限（初值 8 次响应）时在响应边界上再切；
- 不带响应序号的子 Agent 消息并入其后的段，位于末尾时并入最后一段；
- 没有响应序号的轮次（已有数据、Codex）整轮一段；
- 每段对应一个事件序号区间，标签为“轮次在材料中的位置.段号”，例如 `2.3`。

切段函数是感知层的纯函数，输入只有一轮的事件。上限以第 8.3 节的回放确定。

### 5.3 生成材料与模型输出

- `GenerationTurn` 带上 `turn_id` 与各段（标签、条目范围、事件序号区间），在 `build_context` 中由原始事件得到；`build_transcript` 在每段之前印出段标签。`render_turn_material` 不变，token 估算、接力摘要与历史转写都不带标签。
- `ExtractedMemoryDraft` 与 `RevisionResult` 新增 `source_segments`：引用的段标签列表，可以为空。被动与主动写入的提示词由 Schema 自动带上这个字段；修订的 JSON 格式在中英文提示词中手写补上；三类提示词都说明段标签的含义与“只引用支撑这条记忆的段”。
- 引用的容错：格式不对的引用在解析时丢弃，不让整份被动输出作废；材料中不存在的标签丢弃；退回草稿与追加修订不带引用。
- 引擎把合格的标签换算为 `CitedSegment(turn_id, first_sequence, last_sequence)`，经 `GenerationOutcome` 交给提交。

### 5.4 存储

- `MemoryVersionArtifact` 新增 `cited_segments`：这一版记忆引用的段，默认为空。被动新建、主动写入新建与修订的版本写入；查重命中而没有新版本（TOUCH）时不保存；合并与手动编辑为空。
- 被引用的轮次就在同一份版本记录 `source_artifacts` 指向的交互快照中，`turn_id` 跨快照唯一，引用不依赖取自哪份快照。
- 引用不进入 `ArtifactRef`、记忆原子与 Qdrant 载荷，不出现在管理接口与 MCP 的返回中。

### 5.5 持久化的编码

- 交互提交编码升到 v8，只注册当前布局（队列只驻留于进程内）。
- 生成队列信封升到 1.3；1.2 保存的工作经读回适配器补齐缺失的字段后按 1.3 严格解码，照常执行、不带引用。1.1 的读回适配器保留。

### 5.6 回放

`scripts/memory_replay.py` 新增一种输入：带事件的轮次。切段参数与验收都在它上面跑：

- 来源一：开发实例或日常实例的交互快照（只读），已有数据整轮一段。
- 来源二：用新的 Claude Code 读取器重新读取 owner 本机的 Claude Code 会话记录（JSONL 中保留了 `message.id`），得到带响应序号的轮次，不经过服务端。
- 统计每轮段数的分布、引用的合格率与多次运行的一致性。

结果写到调用方给出的目录，不写任何实例的数据根。

## 7. 兼容与迁移

- **升级顺序**：Import Bus 拒绝不认识的字段，连接器把 422 当作这一轮被拒绝并前移游标，新连接器对旧服务端会永久丢失这些轮次。服务端必须先于连接器升级；实施时核对安装包怎样更新各 harness 的插件，并在验收中确认新连接器只在新服务端启动之后才开始提交。
- **旧连接器对新服务端**：不带响应序号的轮次照常接受，整轮一段。
- **已有数据**：交互快照中的事件以字典保存，旧快照没有这个键；版本记录 `extra="ignore"`，新旧代码都能读。回退到旧版本时，新版本记录多出的键被忽略。
- **持久化的工作**：生成队列中 1.2 的工作读回后执行（第 5.5 节）；交互提交队列不跨重启。
- **已有记忆**：不回填。

### 8.3 回放与实测

- **切段参数**：在第 5.6 节来源二的轮次上，统计每轮段数与每段响应数的分布，确定每段的响应上限；同一批轮次重放被动提取 3 次，报告引用的合格率与一致性，并抽查引用是否指向支撑内容的段。
- **开发实例**：Alice 真实对话中一轮带多次生成，交互快照中的事件带响应序号；话题结算后，新记忆的版本记录带引用，换算回的事件区间与记忆内容对应（抽查）。
- **日常实例**：owner 按第 7 节的顺序安装新版本后，新导入的 Claude Code 轮次带响应序号，结算出的记忆版本记录带引用；Codex 轮次不带响应序号，整轮一段；没有被拒绝的轮次。

## 9. 风险与待决问题

- **模型引用的准确性**：没有标准答案，只能测合格率与一致性，再人工抽查；引用不准时，复核读到的依据会偏。这是本计划验收的主要不确定性。
- **材料变长**：段标签增加材料长度；一轮切得很碎时（已有数据中按思考切最多到 133 段）标签更多。上限与“思考正文开启新段”是否保留，以回放结果为准（候选，可在计划评审时调整）。
- **dsh 与 Codex**：dsh 的 `step` 含义待核对；Codex 没有响应边界，它的轮次只能整轮一段。若 Codex 的会话记录中有可靠的每次请求标记，另开 Todo。
- **修订是否引用**（候选）：修订的材料只有最近 5 轮且不含发出更新的这一轮，引用可能经常为空；仍然保留字段，使每个内容版本的来源形态一致。
- **字段名**：`response_index`、`source_segments`、`cited_segments`、`CitedSegment` 为候选命名，可在计划评审时调整。

### 11.1 实施中取的默认值（不是 owner 决定）

- 响应序号只校验从 1 起与单调不减，不要求连续：pi 每条助手消息占一个序号，没有写出事件的消息留下空号；Claude Code 只给写出了事件的消息编号，序号连续。

- 段标签写作 `[Segment x.y]`；渲染不出条目的段（例如只有写入调用的响应）照样印标签，不另设分支。

- 引用的容错：只保留去掉首尾空白后形如 `\d+\.\d+` 的字符串，字段不是列表时为空；材料中不存在的标签丢弃并记 INFO 日志。
