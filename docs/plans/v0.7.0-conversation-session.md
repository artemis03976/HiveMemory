# v0.7.0 会话：Alice 改用会话上下文

> **文档状态**：Active。阶段一已完成审查与验证；继续按阶段实施。

本计划新增 workspace 的会话资源（ConversationSession），让 Alice 的对话上下文来自会话而不是 Gateway 路由到的 Topic，并让前端回归会话模型。Topic 只继续承担记忆生成的接入材料。范围只到“Alice 先改用新体系”：面向外部 harness 的模型演进、流式同步与会话持久化都不在本计划。

设计依据：

- [外部会话与 Topic 投影 Idea](../ideas/external-session-and-topic-projection.md)：0.1 会话模型与 Topic 池（owner，2026-09-28）、0.2 计划范围与会话上下文（owner，2026-10-15）、0.3 会话计划的候选设计；
- [第五代架构 Idea](../ideas/fifth-generation-architecture.md) 3.4 库内与库外、3.9 上下文与记忆材料分离；[ADR-0006](../architecture/decisions/0006-memory-library-custody-criteria-and-independence-contract.md)：会话是库外的工作状态；
- 当前事实：[Workspace 架构](../architecture/workspace.md)第 4.3–4.5、5.4 节，[System 应用服务](../system/application-services.md)第 3、4 节，[子系统契约](../contracts/subsystem-contracts.md)第 4 节，[感知与短期话题](../patchouli/perception.md)；
- 已归档：[写入意图实时派发](../archive/plans/v0.7.0-intent-inflight-dispatch.md)（写入与进程结局解耦，本计划沿用）；[Chat Run 取消重构最小闭环](../archive/plans/chat-run-cancellation-unified.md)：用户停止只经 `Task.cancel()` 与原生 `CancelledError`，不引入取消 token、Event 或轮询（当前事实见 [System 应用服务](../system/application-services.md)第 4 节、[Alice 编排](../alice/orchestration.md)），本计划保留这一基线；
- [Chat Run 生命周期后续候选 Idea](../ideas/chat-run-lifecycle-follow-ups.md)：第 6 节候选 D（取消时的文本契约）由本计划吸收，第 3.4 节已复现的断连丢失结算由本计划修复。

## 1. 背景和问题

- **Alice 的上下文来自路由到的 Topic**：每轮的历史是 Gateway 路由到的 Topic 的 `state_summary` 与最近 5 个 block。Topic 池在 Workspace 内共享，路由一变上下文就跟着变，一个 Topic 里还交错着其他对话的内容；这与外部 harness 自带会话的模型不一致，也让前缀几乎无法命中 KV cache。
- **Gateway 也把 Topic 当对话上下文**：查询理解读取路由到的 Topic 的最近若干 block，重复输入检测读取它的最后一个 block。Topic 不再对应某一个对话之后，单轮消息中缺失的指代会按其他对话的内容消解。
- **没有会话资源**：HTTP chat 请求体的 `session_id` 只是兼容接收、不使用；前端不持久化消息，后端没有读取对话历史的接口，“新建”“恢复”无从实现。
- **被取消的一轮哪里都接不上**：只有 completed 的进程提交交互记录；被取消的一轮在前端已经显示了部分回复，但 Alice 的下一轮与 Patchouli 都看不到它。
- **前端以“当前 Topic”为中心**：左栏是 Topic 列表，`topic_info` 事件设置当前 Topic，done 事件回传话题池。

## 2. 目标与非目标

### 2.1 目标

1. **会话资源**：workspace 共享设施新增会话服务，会话属于 Workspace、不属于某个 agent，只在进程内保存，容量用尽时显式拒绝。
2. **会话操作**：新建、列表、重命名、加载历史、删除，经 root API 与 HTTP 管理路由提供；不设 actor 操作。
3. **chat 请求绑定会话**：请求携带 `session_id`，缺少时自动新建；注册入口校验会话属于目标 Workspace，同一会话同时只允许一个进程；每次请求各自选择 agent，会话内可以随时切换。
4. **全量会话上下文**：进程把会话的全量历史放进 CPU 输入清单，Alice 由会话历史组装提示词，不截断；Topic 的内容不再进入 Alice 的提示词。
5. **Gateway 取得会话上下文**：Gateway 照旧取得全部活跃话题的列表（含各话题的状态摘要与最后一轮），另外取得当前会话的最近 N 轮，用于话题路由与查询理解中的指代消解；重复输入检测改为比较当前会话的上一轮。
6. **有输出的轮次都记入会话**：completed，以及有输出的 cancelled 与 failed 轮次都记入会话并带结局，同时以相应结局提交给 Patchouli；没有输出就结束的轮次不记入、不提交。
7. **停止时交回部分输出**：用户停止 Actor 阶段时，取消方式不变；CPU 在收尾时把已经产生的输出（包括已流式发出、尚未成为完整一轮的文字）组装为 cancelled 终态结果交给进程，由进程封口、写入会话并提交。
8. **话题标注**：`topic_info` 改为 done 事件中的本轮话题标注，并记入会话的该轮；prepare 不再返回话题内容与话题池。
9. **前端回归会话模型**：左栏为会话列表，取消“当前 Topic”，Topic 池移到记忆面板。

### 2.2 非目标

- 面向外部 harness 的模型演进：TurnEvent 的新 kind 与来源字段、`InteractionPayload` 的会话与顺序字段、外部事件的封口与迟到处理（v0.7.1 controller 模式的计划）。
- 流式同步、交互被接纳后即关闭进程（任务进程 Idea 2.1）、话题是否预建与 Profile 的解析时点：话题仍预建，cleanup 路由保留，finalize 仍等到交互 applied 才返回。
- 会话持久化：重启后会话随其他短期状态消失，之后单独建立计划。
- Alice 的会话压缩与 `/compact`：在本计划之后单独一份计划；本计划期间长会话可能超出模型窗口。
- Gateway 的会话提示（提议恢复已有会话或新开会话）、编辑与回退。
- Passive Ingress 的会话键与 Import Bus；会话 ID 进入 Patchouli。

## 3. 实施前状态（2026-10-15 核对）

- **chat 请求**（`server/models/chat.py`、`server/routers/chat.py`）：`ChatRequest.session_id` 兼容接收、不使用；server 生成 `process_id` 后经注册入口 `TaskProcessService.register_process` 认证并登记进程，`ProcessRequest` 没有会话字段。SSE 首个事件只携带 `process_id`。
- **prepare**（`patchouli/service.py`）：按 Gateway 决定预建或刷新话题，再读取话题池（`TOPIC_LIST_ACTIVE`）与话题内容（`TOPIC_GET`），放入 `PreparedAgentRun.pool_topics` 与 `topic_context`；两者都注明在 ConversationSession 一批之前暂时保留。
- **CPU 输入**（`workspace/contracts/process.py`）：`CPUInputManifest.topic_context` 同样暂时保留；`topic_id` 用于根帧挂载与观测。Alice 把它转为 `AgentRunContext.topic_context`，`prompts/assembler.py` 以 `state_summary` 进入系统提示词、以 `recent_blocks(5)` 经 `HistoryTranscriptBuilder` 生成历史消息，其他 agent 的回复带 `[From: agent_id]` 前缀。
- **Gateway**：`gateway.public.process` 只接收消息、scope、入口模式与超时；话题菜单（`gateway/topic_context.py`）包含各话题的标题、状态摘要与最后一轮对话；话题路由只看消息与菜单；查询理解读取路由到的话题最近 `context_block_limit` 个 block（`engines/gateway/query_understanding.py`），重复输入检测读取其最后一个 block（`gateway/analysis/resolver.py`）。
- **停止**（`workspace/process/table.py`、`runner.py`）：`request_stop` 直接取消当前阶段的 task；Actor 阶段被取消时进程得到 `RunCancelled`，没有 CPU 终态结果，不封口、不提交，预建的空话题由 cleanup 清理。Alice 的执行层在取消时把 run 收尾为 CANCELLED（`alice/orchestration/run_executor.py`），但输出流已被关闭，结果交不回进程。
- **流式文字**（`agent_runtime/execution/loop.py`）：一次 LLM 调用的 token 在流出时立即发给前端，要等这次调用拿到最终块才写入 `frame.progress`；在回复流到一半时停止，已流出的文字不在 Alice 的记录中（chat-run Idea 候选 D 指出的同一问题）。
- **断连丢失结算**（chat-run Idea 第 3.4 节，已复现）：进程先进入 FINALIZE、产出 `finalizing` 事件，再调用 finalize；断开恰好落在这个产出点时，关闭流程执行 cleanup，已完成的一轮丢失。
- **封口与提交**：`seal_interaction` 只在 completed 时调用；`InteractionPayload` 没有结局字段，`InteractionSubmission` codec 版本为 4；`TurnRecord` 没有结局字段。
- **输出投影**（`workspace/process/outputs.py`）：CPU 分配后产出 `topic_info`（话题 id、是否新建、话题池）与 `memory_refs`；completed 的 done 事件携带结算后的话题池。
- **前端**：`chatStore` 的 `partialize` 不保存消息；`currentTopicId` 由 `topic_info` 设置；左栏 `ContextSidebar` 显示 Topic 列表，`TopBar` 显示当前 Topic 的标题与 token。
- **存储与关闭**：只有中期记忆与 Artifact 跨重启保留；`WorkspaceAssetStore` 由组合根装配并在关闭时最后清理（`system/system.py`）。

## 4. 目标设计

### 4.1 会话资源与会话服务

- 新增 workspace 共享设施中的会话服务（目录与类名在实施评审时确定，例如 `workspace/sessions/`），由组合根装配并持有，与 `WorkspaceRuntime`、`WorkspaceAssetStore` 同级；不导入 `process`，进程与 root API 都经它访问会话。
- **会话**：会话 id、归属（`WorkspaceIdentity`）、标题、创建与更新时间、有序的轮次列表。会话属于 Workspace，不记录 owner agent。
- **轮次**：进程 id（即 `interaction_id`）、执行该轮的 agent（取自进程的 `ExecutionLabels`，只用于历史渲染与展示，不参与授权）、封口的 `InteractionPayload`（含结局，见 4.6）、本轮所在的 Topic、写入时间。会话不复制第二份正文。
- **容量**：每个 Workspace 的会话数与每个会话的轮数各有上限（配置项见 4.9），用尽时新建会话或注册进程显式拒绝，不淘汰既有会话或轮次。
- **并发**：会话持有至多一个运行中的进程。注册入口在同步段认领，进程关闭时释放；认领与释放都不跨越 await。
- **关闭**：System 关闭时在进程表关闭之后清空会话服务；清空后的读写显式失败。
- 删除会话不级联 Topic 与 Memory；正在运行进程的会话不能删除。

### 4.2 会话操作与 HTTP

- root API 新增会话管理（例如 `workspace/capability/root/session.py`）：新建、列表、重命名、读取历史、删除，以 `authorize_root` 授权；`system` 的访问记录照旧不配置 operation。
- server 新增会话路由（路径在实施评审时确定），经认证网关取得 root 访问后调用 root API；错误沿用结构化域错误：会话不存在或不属于目标 Workspace、会话忙、容量用尽（错误类型与码在实施评审时确定，并写入错误模型）。
- 标题默认取首条消息的截断，新建时可以为空，首轮写入后补全；可以重命名。
- 历史读取返回全部轮次（会话只在进程内且有轮数上限），每轮包含用户消息、回复文本、轮次事件、结局、agent 与所在 Topic。

### 4.3 chat 请求与注册入口

- `ChatRequest.session_id` 改为实际使用：注册入口在认证通过后、登记进程之前认领会话。会话不存在、不属于目标 Workspace 或正在运行其他进程时拒绝，不创建进程；缺少 `session_id` 时新建会话并认领。
- `ProcessRequest` 新增会话 id；SSE 首个事件同时携带 `process_id` 与 `session_id`，非流式结果同样返回 `session_id`。
- 进程关闭时（任何结局）释放会话的认领；释放放在注册入口的关闭收口中，与 context 失效、进程注销同处。
- 每次请求各自选择 agent；注册入口不校验 agent 与会话中已有轮次的一致性。

### 4.4 CPU 输入与 Alice 提示词

- 进程在 CPU 分配时读取会话的全量轮次，作为只读快照放进 `CPUInputManifest`（字段名在实施评审时确定）；删除 `CPUInputManifest.topic_context`，保留 `topic_id` 用于根帧挂载与观测。
- `AgentRunContext` 以会话历史取代 `topic_context`。提示词组装：
  - 系统提示词不再包含 Topic 的 `state_summary`；记忆、附件与 persona 部分不变；
  - 历史消息由会话轮次生成：`HistoryTranscriptBuilder` 改为消费会话轮次的 `turn_events`（无事件时回退到回复文本），其他 agent 的回复继续带身份前缀；
  - cancelled 与 failed 的轮次附带中断或失败的说明（中英文案在实施评审时确定），让下一轮知道该轮没有正常结束。
- 全量，不截断。超出模型窗口时本轮按 CPU 失败结束，由压缩计划解决。
- 会话中的内容对后续轮次的任何 agent 可见，不按 agent 过滤；agent 的可见性只约束对资源的直接访问。

### 4.5 Gateway

- `gateway.public.process` 新增当前会话最近 N 轮的参数，类型为 CPU 中立的只读值（每轮的用户消息与回复文本，放在 `core.protocol.gateway` 或 Gateway contracts，实施评审确定）；进程在 Gateway 阶段从会话读取后传入，Gateway 不读取会话。
- 话题路由：提示词在话题菜单之外加入会话的最近 N 轮，用于定位缺失上下文指代的单轮消息；话题菜单的内容不变。
- 查询理解：同样加入会话的最近 N 轮；继续读取路由到的话题最近若干 block，作为话题背景。
- 重复输入检测：比较当前会话的上一轮用户消息。
- 被动入口（`PASSIVE_MEMORY`）不传会话，行为不变。
- 这 N 轮只用于分析，不进入 `GatewayDecision`，也不随交互提交。

### 4.6 写入会话与停止

**一轮的收尾顺序**（拿到 CPU 终态结果之后：正常结束时来自输出流的最后一项，停止时来自结果槽）：

| 步骤 | 内容 |
|:---|:---|
| 1 | 关闭 CPU 输出流，撤销全部线程 context（不变） |
| 2 | 判断是否有输出：终态结果含有至少一个轮次事件或非空回复文本 |
| 3 | 有输出：封口 `InteractionPayload`，结局取 CPU 终态（completed、cancelled、failed） |
| 4 | 同步写入会话（不跨越 await） |
| 5 | 进入 finalize，以该结局提交给 Patchouli；进入后拒绝停止（不变） |
| 6 | 交出终态产出，done 事件携带本轮所在的 Topic |

- 没有输出（Gateway 或 prepare 阶段停止、CPU 尚未产出即结束、进程异常、客户端断开）：不封口、不写入、不提交，关闭流程照旧清理预建的空话题。前端把用户消息放回输入框（4.8）。

**停止时交回部分输出**：

- **取消方式不变**：用户停止仍由 `request_stop` 取消当前阶段的 task，下游只传播原生 `CancelledError`；不引入停止信号、取消 token、Event、等待或超时，停止延迟与现在相同。
- **结果槽**：`CPUPort.execute` 改为返回一个 run 句柄（类型放在 `workspace.contracts`，名称在实施评审时确定），除输出流外带一个终态结果槽。CPU 在取消的收尾中（重新抛出 `CancelledError` 之前，只做同步操作）把 cancelled 终态结果写入结果槽；句柄只暴露 CPU 中立的 `CPUExecutionResult`，不让 `FrameExecutionResult`、执行器终态或进程控制类型越过边界。进程在 Actor 阶段的取消分支读取结果槽：有输出时按上表收尾，为空时按没有输出处理。
- **Alice**：
  - agent 循环在 LLM 流式输出时把已发给前端的文字累积在 frame 上，这次调用正常结束时清空；收到 `CancelledError` 时把累积的文字记为一条未完成的 `assistant_message` 再上抛；
  - 正在执行的工具调用沿用现有收尾，已记录但没有结果的工具调用作为不完整动作保留在轮次事件中；
  - `_abort_cancelled_run` 收尾为 CANCELLED 后，运行服务按 `_assemble_execution_result` 组装 cancelled 结果并写入结果槽；结果槽由 CPU 驱动经 Alice 的运行路由传入，与 `submit_operation` 相同；
  - 非流式运行没有流出的文字，部分输出只有已完成的迭代；
  - 停止发生在 CALL 子帧执行中时，子 agent 已流出的文字属于子帧、尚未回填到根帧，根帧只把这次 CALL 记为不完整动作。
- **测试 CPU**（`tests/helpers/cpu.py`）同步实现结果槽。
- **外部执行单元**（v0.7.1，不在本计划）：驱动在自己的收尾中把 `CancelledError` 翻译为外部协议的取消（例如 ACP 的 `session/cancel`），等对方以 cancelled 结束后写入结果槽；协作式取消只存在于驱动与外部进程之间，驱动自带等待上限。
- **done 事件的文本**（吸收 chat-run Idea 候选 D）：有输出的 cancelled 的 done 携带后端组装的回复文本，与前端已显示的内容一致；没有输出时 done 不携带 `final_text`，前端保留当前内容，不以空字符串覆盖。
- **断连丢失结算**（修复 chat-run Idea 第 3.4 节）：进程进入 FINALIZE 之后，交付方提前关闭不再导致 cleanup，已封口的交互照常提交；实现方式在实施评审时从该节的选项中确定。被取消的轮次现在也经过 finalize，这个窗口会更常出现。
- **结局字段**：`InteractionPayload` 新增结局（completed、cancelled、failed，默认 completed），`InteractionSubmission` codec 升为 5；`TurnRecord` 记录结局，Patchouli 与 completed 同样处理，生成材料的转写注明中断或失败。
- 写入意图不受影响：派发与结局无关（沿用实时派发的语义）。
- `chat.run.cancelled` 与 `chat.run.failed` 事件在有输出时晚于 finalize 发出；进程结局语义不变。

### 4.7 话题标注与话题池

- 删除 CPU 分配后的 `topic_info` 事件；done 事件新增本轮所在的 Topic（有输出的三种结局），并记入会话的该轮。
- 删除 `PreparedAgentRun.topic_context` 与 `pool_topics`；prepare 不再读取话题池与话题内容。

- `memory_refs` 事件不变。

## 6. 兼容与迁移策略

- 进程内替换，不涉及持久化数据：会话、短期 Topic 与提交队列都在进程内；`InteractionPayload` 新增字段带默认值，`InteractionSubmission` codec 版本递增。
- **HTTP**：`session_id` 由“兼容接收、不使用”变为实际使用；缺少时自动新建会话，不破坏现有调用方。SSE 的 `topic_info` 删除、done 的 `pool_topics` 删除并新增话题标注，仓库内只有前端消费，随阶段四一并修改。
- **既有 Topic**：升级后不把已有 Topic 的历史转换为会话（不编造会话）；新会话从空上下文开始，Topic 照旧作为记忆材料。
- **CPU 端口**：返回值改为 run 句柄，只影响 Alice 与测试 CPU，在同一阶段修改；取消方式不变。
- **语义变化**：被取消或失败但有输出的一轮现在会进入 Patchouli 并参与记忆生成；停止后要等 finalize 完成才结束。

## 7. 实施阶段

每个阶段结束时全量后端测试通过、可单独审查。

## 8. 测试和验收标准

按[测试设计规范](../governance/testing/test-design-standards.md)分类。会话服务、注册入口、任务进程、Gateway workflow、Patchouli 感知与 Alice 提示词使用真实对象，外部 LLM 与存储使用既有替身。

1. 会话的新建、列表、重命名、读取历史与删除经 root API 生效；非 `system` 的 actor 被拒绝；其他 Workspace 的会话不可读写。
2. 会话数或轮数达到上限时新建会话或注册进程显式拒绝，既有会话与轮次不被淘汰；关闭后读写显式失败。
3. chat 请求缺少 `session_id` 时新建会话，首个事件与非流式结果携带它；携带不存在或属于其他 Workspace 的 `session_id` 时拒绝且不创建进程。
4. 同一会话已有进程运行时，第二个请求被拒绝；进程以任何结局关闭后，会话可再次使用；运行中的会话不能删除。
5. completed 的一轮在 finalize 之前写入会话，记录进程 id、agent、交互记录与结局；同一会话内切换 agent，两轮都写入同一会话。
6. CPU 输入清单携带会话的全量轮次，不含 Topic 内容；Alice 的提示词历史与会话轮次一致，系统提示词不含 Topic 状态；其他 agent 的回复带身份前缀。
7. 两个会话交错写入同一 Topic 时，各自的下一轮只看到本会话的历史。
8. Gateway 收到当前会话的最近 N 轮（N 取自配置）；只靠上一轮才能理解的单轮消息，路由与改写使用该上下文；话题菜单内容不变；重复输入检测比较会话的上一轮；N 轮不出现在 `GatewayDecision` 与交互记录中。
9. prepare 不再读取话题内容，`PreparedAgentRun` 没有 `topic_context`。
10. Actor 阶段停止：进程从结果槽读到 cancelled 终态与部分输出，部分输出包含停止前已经流式发出的文字；进程封口、写入会话并以 cancelled 提交，Patchouli 的 block 记录结局，预建话题不被清理；有输出时 done 携带与前端已显示内容一致的文本。
11. 停止仍只经 `Task.cancel()`：下游收到原生 `CancelledError`，不出现停止信号或等待；Gateway 阶段停止、结果槽为空、没有输出的结束与客户端断开不写入会话、不提交，预建空话题照旧清理，done 不携带 `final_text`。
12. CPU 以 failed 结束且有输出时同样写入会话并以 failed 提交；进程异常不写入。停止发生在 CALL 子帧中时，根帧把这次 CALL 记为不完整动作。
13. 下一轮的提示词中，cancelled 与 failed 的轮次带说明；生成材料的转写注明结局。
14. `InteractionSubmission` codec 5 的往返与旧版本的拒绝规则；进入 finalize 后停止请求仍返回 `already_finalizing`。
15. 交付方恰好在 `finalizing` 事件处关闭流时，已封口的交互照常提交，不执行 cleanup（chat-run Idea 第 3.4 节的复现用例改为通过）。
16. done 事件携带本轮所在的 Topic 且与会话中该轮一致；不再有 `topic_info` 事件与 `pool_topics`。
17. 确定性 HTTP chat E2E：新建会话、两轮对话、回复流到一半时停止后继续发消息，第三轮的提示词包含被中断的一轮及其已流出的文字，Patchouli 收到三份交互且结局正确；读取历史与前端渲染所需字段一致。
18. 前端 `npm run lint` 与 `npm run build` 通过。

## 9. 风险与待决问题

| 风险或问题 | 处理 |
|:---|:---|
| 全量上下文在压缩计划完成前可能超出模型窗口 | owner 已接受（Idea 0.2）；本轮按 CPU 失败结束，用户可新建会话；压缩计划紧随其后 |

| 客户端断开时部分输出丢失 | 交付与进程生命周期仍绑定在同一个流上，独立任务与输出通道属于 chat-run Idea 候选 A，不在本计划；保持现状 |
| 停止发生在 CALL 子帧中时子 agent 的半截输出不进入会话 | 已知限制；根帧记录不完整的 CALL 动作 |

| 停止后要等 finalize（交互 applied）才结束 | 前端照旧显示 finalizing；“交互被接纳后即关闭进程”不在本计划 |
| 被中断或失败的回复可能不完整或有误，进入记忆材料 | 结局随 block 与生成转写一起标注 |
| agent 的私有记忆经共享会话被其他 agent 看到 | 候选设计已接受（Idea 0.3）：可见性只约束对资源的直接访问 |
| 会话忙导致的拒绝 | 前端在 finalizing 期间已禁止发送；多标签页同时发送时显式报错 |
| 实施命名（会话服务、模型字段、路由路径、错误码、配置项、run 句柄与结果槽） | 实施评审时确定并记入本计划 |
