# ADR-0006：记忆库的归属判据与独立工作契约

## Context

v0.7.0 期间，记忆库（Patchouli）与其外侧之间的边界标准多次更替，每一次都因判据本身的缺陷而失效：

| 判据 | 失效类别 |
|:---|:---|
| “当时只有 Alice 消费” | 偶然事实：消费者集合一变化即失效 |
| “谁需要 Workspace key” | 派生量：寻址需求是归属决定的后果，不是原因 |
| “派生自什么、谁改变其有效性” | 机制局部最优：以缓存一致性机制裁决所有权，把 Actor 的工作状态拽入记忆库 |

共同的教训有两条。第一，描述性判据（谁在消费、数据流向谁）会随系统描述的变化而失效。第二，机制问题不能裁决所有权问题：缓存一致性、失效覆盖、当前性是机制需求，应当由契约承接，而不是由所有权迁移承接。

本决定于 2026-09-23 作为 v0.7.0 边界宪章的原则部分采纳。2026-09-27 宪章拆分时，原则部分移入本 ADR；宪章中针对具体状态（缓存、写入意图、会话记录等）的归属裁定不属于本决定。

## Decision

### 1. 归属判据

1. **管护权（主判据）**：状态归谁，由过线动作决定。库已接收、进入其管护的素材与资产归记忆库；仍在 Actor 手中、尚未被记忆库接收的工作状态不归记忆库。过线动作有明确的名字：材料的过线是**封口 + 提交**，写入意图的过线是**物化**（settlement 回流为注销）。临时性不作为判据，它是“未被接收”的后果而不是原因：Topic 同样是临时的，但已被库接收，所以归库。
2. **迁移约束**：存量迁移不得给记忆库增加任何迁移前不属于它的领域内容，也不得削弱其既有能力；迁移前已属于记忆库的内容不动。
3. **用途（新增状态的判据）**：为记忆流水线自身运转而存在的状态（canonical 资产、版本历史、接入素材、生命周期）归记忆库；为 Actor 干活而存在的状态（写入意图的追踪、热读视图、挂载资产、引用解析）不归记忆库；谁都不服务的进程骨架（bus、queue、scheduler、registry、EventBus）是共享基础设施。
4. **工作产物规则（决断规则）**：两侧都能主张用途时，问它是谁的即时工作产物。由 Actor 组成、需要同步读回的状态是 Actor 的工作产物；只做异步消费的一方是加工者，不因消费而取得所有权。追踪跟着干活的人走，不跟着加工车间走。

这组判据是工程承诺，不是被发现的事实。推翻它的方式是举出第 5 节证伪条件中的实例，而不是提出新的偏好。

### 2. 记忆库的角色

记忆库是接收提交、加工生成、存储并演化记忆资产的 canonical 知识机构，拥有完整的库内流水线：接入 → 生成 → 存储 → 生命周期 → 检索。

它与外侧的分割按角色执行，不按资源垄断：两侧都有自己的资源。记忆库的资源是已接收的素材与 canonical 资产（Topic 素材、MemoryAtom、Artifact、版本历史）。

### 3. 独立工作契约

> **独立工作**：任何一侧在与另一侧的连接断开时，必须仍能启动并完整履行自身名下的职责；由此产生的能力缺口必须以显式错误或显式状态呈现，不得以静默的过期成功替代。

独立工作不是独立部署（系统仍是单进程组合根）、不是独立数据（canonical 资产只存在于库）、不是零集成（过线契约照常存在且必须可靠）、也不是职责对等（两侧义务不对称，不互相补位）。它由三条可检验的性质构成：

1. **职责完整性**：断开时自身职责清单仍可履行；
2. **降级显式性**：缺口以明确的错误或状态呈现，绝不伪装成功；
3. **组合无序性**：装配与启动顺序不要求另一侧先存在、先健康。

记忆库一侧的义务（库外一侧缺席或不可用时必须全部成立）：

1. 库内全流水线可运行：提交接收 → generation 物化 → canonical 存储 → reinforcement/gardening/archive/revive → 检索；
2. canonical 写入的成功不以任何库外缓存的失效确认为前提；
3. settlement 照常产生并留痕于库侧事实，不等待库外确认；
4. canonical 点读、alias 批读、语义检索与 Profile 解析对任何调用方照常服务；
5. 库对外发布的通知在没有接收方时不改变任何库内业务结果。

记忆库禁止：持有缓存、写入意图登记、alias resolver、会话记录或任何授权结论缓存；假设读侧存在需要库来维护的缓存；以库外接收方的失败为由回滚已经成立的 canonical 提交。

库外一侧在库不可达时同样要履行自身职责并显式降级，例如冷读返回明确错误，而不是以过期条目伪装新鲜的成功。库外各项状态由谁持有、如何降级，不由本决定裁定。

### 4. 断开测试

独立工作契约以断开测试作为机械守卫：

- **库模式**：不注册任何库外接收方，独立组装记忆库，跑通提交 → 生成 → 存储 → 生命周期 → 检索全链路；断言 canonical 提交成功、通知空投不影响提交结果、settlement 留痕、读取路由可用；
- **库外模式**：注入“库不可达”，断言库外一侧的职责降级存活、缺口显式失败，全过程不出现静默的过期成功；
- 测试只允许注入不可达，不得通过 mock 库内部状态来通过。

### 5. 证伪条件

观察到以下任一实例，本决定即告失效，必须另立 ADR 重新裁定；不以偏好或美学理由重开：

1. 某项库外状态的正确性必须同步依赖库内部事实，且无法通过过线契约表达；
2. 断开测试无法写成不依赖 mock 库内部的可执行测试；
3. 出现一类 Actor，其接入必须理解库内部结构，而不能只消费能力面；
4. 工作产物规则在真实的新状态上无法给出单侧裁决，且两侧的用途论证同样有力；
5. 独立工作义务中的任一条与已落地的 Memory 版本与 lifecycle 语义冲突。

## Consequences

- 记忆库的读路径保持 storage-shaped，不因读侧存在缓存而增加维护职责；库外状态的当前性由其所有者通过过线契约（冷读、通知等）自行保证。
- 本决定只回答“是否归记忆库”。库外状态（写入意图、缓存、会话记录、引用解析等）由网络共享设施还是任务进程持有，由相应设计另行决定。
- 采纳时记忆库内没有缓存、写入意图登记或会话记录；Actor 执行路径的派生缓存与 `PendingAtomRuntime` 位于 Alice（见 [Alice](../../alice/README.md)）。
- 断开测试尚未实现。
- 修改判据须以第 5 节的证伪实例为依据，另立 ADR 替代本决定。

## Alternatives

- Context 表中的三种判据：分别因偶然事实、派生量与机制局部最优而被拒绝。
- 以缓存一致性、失效覆盖等机制需求决定所有权：被拒绝，机制需求由契约承接。
- 以临时性作为判据：被拒绝，临时性是未被接收的后果。
