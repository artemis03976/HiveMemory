# v0.7.3 话题内主动写入优先

> 状态：Archived（2026-11-03，PR #176）。当前事实见 [Patchouli 生成](../../patchouli/generation.md#42-本话题的主动写入)第 4.2 节；实施记录见第 11 节。这是过渡措施，不代表主动写入优先是更好的选择（owner，2026-11-03），之后的方向见[统一的交互记忆](../../ideas/unified-interaction-memory.md)。以下为计划原文，相对链接已随归档改正。

## 1. 背景和问题

执行者经记忆工具主动写入的内容，会在话题结算时被 Mode A 从同一份材料里重新推导出来，查重判为相似后合并进主动写入的记忆。合并按新旧定主次，被动草稿总是较新，于是成为骨架，把 agent 有意精简掉的风险清单、行号与未决问题带回记忆。同一轮里 agent 有意分开写的几条记忆，也会在写入时因相似度越过阈值而被合并。证据见[收敛 Idea](../ideas/generation-source-convergence.md) 第 2 节：只含调研的四个话题中，19 条主动写入被 Mode A 全部复现；被动草稿并入本话题主动写入的合并 17 次成功、3 次失败；4 个仓库中 3 个出现同一轮主动写入之间的合并。

owner 2026-11-03 决定以"话题内主动写入优先"处理（Idea 第 3.3 节）：提示词约束 Mode A 的两种做法经离线回放否定（Idea 第 3.2 节）。

## 2. 目标与非目标

### 2.1 目标

- 话题结算时，被动草稿查重命中本话题主动写入结算到的记忆，丢弃这条草稿，不新建、不触碰、不提名合并；
- 主动写入查重为相似、命中的是本话题主动写入结算到的记忆时，照常新建，不提名合并。

### 2.2 非目标

- 不改材料渲染、提取与 Mode B 的提示词、合并提示词与合并语义；
- 不改查重的判定信号与阈值（[查重 Todo](../../todo/generation-dedup-decision-signal.md)）；
- 不处理低于相似下限的重复草稿，也不处理跨话题的查重与合并；
- 不持久化话题与记忆的对应关系。

## 3. 当前状态（2026-11-03 核对，commit `575d626d`）

- **查重**：`GenerationEngine._dedup_and_resolve` 对 Mode A 的每条草稿与 Mode B 的草稿做 dense top-1 查重。IDENTICAL 只触碰已有记忆；SIMILAR 新建并提名合并（策略不同或任一方是 Profile 时不提名）；DISTINCT 新建。来源（主动写入或被动提取）不参与判断（[生成](../../patchouli/generation.md#4-查重与合并)第 4 节）。
- **生成请求**：`GenerationRequest` 携带材料与写入、更新或合并的焦点，不携带话题；话题只在任务规格 `MemoryGenerationTaskSpec.topic_id` 中，WRITE、UPDATE 为派发话题，SETTLE 为结算的话题，MERGE 沿用原任务的话题。
- **结算**：控制器在任务成功后 `_publish_settlements` 发布写入意图的结算，结算带正式记忆的标识（CREATED、MERGED、TOUCHED、UPDATED），之后提交合并提名。
- **执行**：控制器经本地路由 `GENERATION_EXECUTE_SPEC` 把任务规格交给 `MemoryGenerationFamiliar.execute`，队列并发为 2。

## 4. 进入条件

Idea 第 3 节已决定（owner，2026-11-03），依赖都是现有事实。

## 5. 目标设计

### 5.1 本话题主动写入结算到的记忆

控制器在进程内按话题保存一份记忆标识的集合：

- **写入**：发布写入意图的结算时，把结算带的正式记忆标识加入任务话题的集合，四种结算（CREATED、MERGED、TOUCHED、UPDATED）都加入。WRITE 新建后被合并时，合并任务发布的 MERGED 结算带保留的那条记忆，同样加入，合并任务沿用原任务的话题。
- **读取**：控制器执行 WRITE 与 SETTLE 任务时，把该话题当前的集合放进生成请求（`GenerationRequest` 新增字段，默认为空）。读取发生在执行时，不在接纳时：同一话题先后派发的写入，前一条结算后，后一条执行时才能看到。
- **清除**：执行 SETTLE 任务时取出并删除该话题的集合。话题结算后不再接收写入。
- 同一个事件循环内，读写之间没有 `await`，不需要锁。

这是新增的进程内状态。它不持久化：进程正常关闭时 shutdown 结算会先用上它；进程崩溃或话题未经结算被删除时，集合随进程丢失或留到重启，退回现行行为。

### 5.2 Mode A

查重结果为 IDENTICAL 或 SIMILAR，且命中的已有记忆在请求的集合中时，这条草稿不产出结果，记一行日志（草稿标题、命中的记忆与相似度）。其余草稿照常处理。同一批的草稿全部被丢弃时，任务照常成功，没有新记忆；来源 InteractionArtifact 照常保存。

### 5.3 Mode B

查重结果为 SIMILAR 且命中的记忆在集合中时，照常新建，不提名合并。IDENTICAL 照常只触碰：同一轮写了两次相同的内容，触碰仍然正确。

### 5.4 不变的部分

- 被动提取照常运行，写入没有覆盖的事实照常进入记忆；
- 跨话题的查重、合并提名与合并语义不变；
- Mode C 不查重，不受影响；
- 结算事件、任务快照与任务 API 不变。

## 6. 受影响的系统、契约和数据

- **Patchouli 生成**：`GenerationRequest` 新增一个字段，只在 Patchouli 内部的本地路由中传递；`GenerationEngine` 的查重分支；控制器新增按话题的集合。
- **公开契约、事件与持久化数据**：不变。

## 7. 兼容与迁移

没有持久化变化。部署前驻留的话题在旧进程关闭时按现行行为结算；新进程从空集合开始，之后的写入与结算按新规则。

## 8. 测试和验收标准

### 8.3 回放与实测

## 9. 风险与待决问题

- 被动草稿里比主动写入更细的内容随草稿一起丢弃。这是"执行者决定什么重要"的直接结果；agent 想补充时应当用 UPDATE。
- 话题落位错误时（[跨会话落位 Todo](../../todo/cross-conversation-topic-placement.md)），另一段对话里与这些写入相似的草稿也会被丢弃。
- 低于相似下限的重复仍会新建（Idea 第 3.2 节的 Gliding Horse 收尾门）。

没有待决问题。

## 11. 实施记录

**实现**（2026-11-03，分支 `feat/topic-active-write-precedence`）：

- `GenerationRequest` 新增 `topic_write_memory_ids`（默认为空）。`GenerationEngine._dedup_and_resolve` 新增两个参数：Mode A 以 `dropped_on_hit` 传入，IDENTICAL 或 SIMILAR 命中其中的记忆时丢弃草稿并记一行日志（记忆 ID、判断与相似度，不记标题，按[日志写法](../../governance/observability/logs-and-events.md)第 2.2 节）；Mode B 以 `kept_apart_from` 传入，SIMILAR 命中时不提名合并。
- 控制器按话题保存集合。与第 5.1 节的一处偏差：集合在执行 handler 中数据面返回后立即记录，而不是在任务终态之后的 finalize 中记录。生成 lane 不按话题排序、并发为 2，finalize 晚于同话题下一个任务开始执行时，后者会读不到前一条写入；在 handler 中记录把这个窗口缩到"结算开始时同话题写入仍在执行"。WRITE 读取不清除，SETTLE 取出并清除，UPDATE 与 MERGE 不读取。

**测试**：按第 8.1 节写入归属层的现有文件：

- `tests/unit/engines/generation/test_engine.py`：Mode A 三条草稿（相似与相同命中集合中的记忆、相似命中集合外的记忆），只剩最后一条新建并提名；Mode B 在既有"何时提名合并"的参数化用例中加入命中集合的情形；
- `tests/unit/patchouli/control/test_memory_generation_controller.py`：两个话题上依次执行 WRITE、UPDATE、WRITE 与 SETTLE，核对每次执行收到的集合；
- `tests/integration/patchouli/test_memory_generation_pipeline.py`：真实的 coordinator、控制器、Familiar、生成引擎与查重器，只有提取器是替身；先写入、后结算时任务只有 WRITE 与 SETTLE，库中只有写入的一条；
- 分别临时去掉丢弃判断、不把集合放进请求、去掉不提名判断，对应用例失败。

**离线回放**（第 8.3 节，2026-11-03）：以生产引擎、生产提取器（`deepseek/deepseek-chat`）与当前 Qdrant（只读）处理收敛 Idea 第 3.2 节的五个话题，各 1 次。集合由两份证据包的 lineage 还原：本话题 WRITE 新建的记忆、吸收过写入的保留记忆，以及 UPDATE 的目标。

| SME 第二轮主话题 | 6 | 5 | 1：命中 `fact_sme_storage_persistence`（0.857），它不在还原的集合中 |
| SME 记忆动力学追问 | 1 | 1 | 0 |

- 丢弃的 24 条人工核对都是本话题写入的复述。
- 保留的两条命中集合外的记忆，原因是还原条件与当时不同：当时的结算会记下合并改指的记忆，当前库中又多了事后的重复本。这不是实现的问题。
- 这次运行没有产出写入之外的新草稿；这类草稿命中集合外的记忆或判为 DISTINCT，照常新建，由引擎单元测试覆盖。
- 回放脚本是临时脚本，与结果一起保存在本地证据目录。
