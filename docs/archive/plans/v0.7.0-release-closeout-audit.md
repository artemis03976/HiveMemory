# v0.7.0 版本收尾审计

本记录冻结 2026-10-19 的版本范围、版本目标判定、收尾分支的修复、遗留事项与验证结果。核对基线为 `76f10e57`：master `bf2fb7ff`（已包含 PR #100–#134）之上，收尾分支 `release/v0.7.0` 的三个提交，加上本次升版与文档收尾。当前实现从[项目总览](../../PROJECT.md)与 [Workspace 文档包](../../workspace/README.md)进入，后续开发顺序从 [ROADMAP](../../ROADMAP.md) 进入。

v0.7.0 内容收尾完成，Python 规范版本、运行时版本与前端包版本统一为 `0.7.0`。发布标签定为 `v0.7.0`，合并后创建；本次没有创建 tag，也没有推送或发布产物。下文的“通过”只指所列的验证边界。

## 1. 范围与版本目标

范围（owner，2026-09-27）：项目完全演进到 Workspace 网络与任务进程架构，使 workspace 体系在项目架构中稳定存在。首条迁移流程是 Alice 的 chat 链路，验收口径是 Alice 在新架构下跑通、各流程协作无误，之后的 adapter 不需要再大改系统拓扑。v0.7.0 不为外部 Actor 所需的基建作承诺。

版本目标（owner，2026-09-28）逐条判定：

| 目标 | 判定 | 依据 |
|:---|:---|:---|
| (1) Patchouli 的公开路由既不产出、也不接收 Alice 专属的类型 | 达成 | Patchouli 源码不导入 `alice` 与 `agent_runtime`，`patchouli/contracts` 只依赖 core 与自身；prepare 只做话题与检索，finalize 接收 `PreparedAgentRun` 与任务进程封口的 `InteractionPayload`，不再接收 `AgentRunResult`（[结算阶段的中立输入](./v0.7.0-task-process-finalize-neutral-input.md)）。反方向上，Alice 不引用 Patchouli 路由，由 `test_access_boundaries.py::test_alice_resource_operations_do_not_reference_patchouli_routes` 守护 |
| (2) 非 Alice 的 CPU（测试替身即可）能跑完整个任务进程，不改动进程与入口的代码 | 达成 | 任务进程只经组合根注入的 `CPUPort` 调用 CPU。`tests/helpers/cpu.py` 的 `ScriptedCPU` 跑通流式与非流式进程（`tests/unit/workspace/process/test_cpu_port.py`），也在 HTTP 系统验收中替代 Alice，驱动真实的 Patchouli/Gateway 组合（`tests/e2e/system/test_chat_session.py`、`test_chat_mtp_operations.py`） |
| (3) 取消与清理都经过进程容器 | 达成（按 2026-10-13 修订的口径） | 用户停止经 `TaskProcessService.cancel_process`，交付方离开以给定原因请求停止，进程只在自己的 task 中收尾；系统停止经 `shutdown()` 依次停止、等待、硬取消。Patchouli 的 cleanup 路由在 workspace 中只有 `TaskProcessRunner.close` 一个调用方（`workspace/process/runner.py:557`），只补偿 prepare 预建且仍为空的话题。原计划随 Topic 按需创建移除该路由；2026-10-13 决定保留话题预建，路由作为补偿保留 |
| (4) 命令、主动请求与被动请求经同一入口注册 | 达成（被动请求按 Q-6 排除） | chat 与命令都经 `register_process` 登记为任务进程。命令只解析，产生“暂不可用”的命令终态，v0.7.0 内的内置命令不可用。被动请求按 [Q-6](../../ideas/task-process-table-and-registration-entry.md#26-被动请求q-6)（owner，2026-10-01）这一阶段不考虑，仍经 `PassiveIngressService`，不经注册入口 |

## 8. 保留限制

- 任务进程表、会话与压缩检查点、写入意图登记、读取视图缓存、WorkspaceAsset working set 与本地 Work Queue 都是进程内状态，不承诺跨重启恢复；持久化的 Memory、Artifact 与这些运行态的保证不同。
- 内置命令在 v0.7.0 不可用；被动请求不经注册入口。
- 真实 LLM 下的会话压缩摘要质量、延迟与成本没有评估；浏览器界面没有人工验收；没有对存量用户数据重新执行迁移。
- 开发库中留有真实环境验收写入的测试记忆、话题与会话；会话随后端重启消失，记忆与话题需要手动清理。
- 访问登记只有文件形式，Agent 操作白名单不支持运行时编辑，归入配置热更新（Unscheduled）。
