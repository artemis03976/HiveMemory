# v0.8.0 版本收尾审计

本记录冻结 2026-11-21 的版本范围、版本目标判定、收尾分支的改动、遗留事项与验证结果。核对基线为 master `042195e2`（v0.7.3 标签之后的 PR #180–#237），加上收尾分支 `release/v0.8.0` 的升版与文档改动。

v0.8.0 内容收尾完成，Python 规范版本、运行时版本与前端包版本统一为 `0.8.0`。发布标签定为 `v0.8.0`，合并后创建；本记录写成时没有创建 tag，也没有发布产物。下文的“通过”只指所列的验证边界。

## 1. 版本目标与判定

版本目标：生成核心的升级，即类型的更迭与 Patchouli 馆长 agent。v0.8 重新设计记忆从短期到中期的流转，顺序是生成核心的升级、被动生成、主动写入（[v0.8 总纲](../../ideas/memory-flow-short-to-mid-term.md)第 4.1 节）。owner 于 2026-11-21 决定以已经完成的方向收尾发版：被动生成的“写什么”仍在孵化，阻塞它的是缺少判断写得对不对的信号，不在 v0.8.0 中等它。

| 方向 | 判定 | 依据 |
|:---|:---|:---|
| 记忆类型的收敛 | 达成 | 去掉 WORK_IN_PROGRESS，CODE_SNIPPET 与 URL_RESOURCE 并入资源记忆，RUN 不再运行记忆；已有记忆按 owner 逐条决定迁移（PR #225） |
| AgentProfileStore | 达成 | Agent Profile 移出中期库，改为全局的 Profile 文件并热重载，可用 agent 的列表固定载入提示词（PR #226） |
| 生成的记忆指向交互轮次 | 达成 | 事件记下来自本轮第几次模型响应，段由事件派生，记忆的版本记录引用段（PR #228） |
| 馆长 agent | 达成，日常实例已启用 | 话题结算可选馆长，与一次性生成并存为用户选项（PR #231）；日常实例自 2026-11-20 起以馆长结算 |
| 写入时的更新 | 达成，日常实例已生效 | 馆长修订、主动 UPDATE 与合并改用编辑集，提交前按同一条基础变化规则重放，合并依次执行并沿吸收关系改指（PR #236）；2026-11-21 重装后的第一次馆长结算修订了 2 条已有记忆、没有新建 |
| 试验场第一版 | 达成 | 隔离的试验实例与 HaluMem 评测；第一次评测在 Medium 的 5 个用户上对照了两种结算方式（PR #234，结果见[评测集 Idea](../../ideas/memory-evaluation-benchmarks.md#6-首个评测切片)第 6 节） |

总纲第 4.2 节的评判方式仍是候选：单轮的“不交记忆税”没有对照，长程的人工介入量与留存率没有在新机制上复测。编辑集改动之后的第二次完整评测按 owner 要求中止（成本），没有对照数字。

## 7. 保留限制

- 日常实例运行的安装包版本号仍是 0.7.3；合并后重新打包安装，窗口标题与 `/health` 才显示 0.8.0。
- 馆长换成 deepseek-flash 之后的两次结算各有 1–2 步输出无法解析为动作，此前 deepseek-chat 的 6 次结算没有出现；样本还少。
- 合并的吸收关系、本话题主动写入的记录、任务进程表、会话与压缩检查点、读取视图缓存、WorkspaceAsset working set 与本地 Work Queue 仍是进程内状态，不承诺跨重启恢复（写入意图登记、未执行的生成工作与已结束任务的历史在正常关闭时写盘）。
- 馆长不提名合并，一次性生成留下的相近记忆不会被它合并；修订以追加为主时，摘要与标签可能不跟着改，新内容只在正文里。
- 浏览器界面没有人工验收；E2E 没有运行（第 5 节）。
