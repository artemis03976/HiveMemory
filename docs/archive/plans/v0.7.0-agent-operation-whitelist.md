# v0.7.0 Agent 操作白名单

> **文档状态**：Archived（2026-10-11）。三个阶段均已完成实现、验收与 code review，事实文档已按最终代码更新。阶段一至三提交为 `991f54c`、`27cba45`、`0c660f8`，审查修复为 `bb3ce09`；本次文档收尾保留在工作区供审阅。本文保存当时的设计、风险和验收证据，当前接口以 [MTP 契约](../../contracts/mtp.md#4-权限)第 4 节、[Workspace 架构](../../architecture/workspace.md)第 4.2、4.5 节与 [System 配置](../../system/configuration.md)为准；不表示 v0.7.0 已发布。

本计划让 Workspace 访问登记中的 actor 操作白名单成为 agent 权限的唯一来源：删除 Agent Profile 的 `allowed_mtp_verbs` 与 `allowed_sys_tools`，任务进程在 CPU 分配时把本进程 actor 的操作集合交给 CPU，Alice 把它翻译为 MTP 动词，用于提示词与 frame 执行策略；授权仍只在 actor API 逐次执行。系统工具不设权限，子 agent 继承父 agent 的操作集合。白名单的运行时编辑不在本计划内。

设计依据：

- commit `6add90f` 版本的《Workspace 网络与任务进程架构》Idea 15.4：白名单为 actor 操作全集、按 (user, workspace, agent) 记录、系统工具不设权限、OMNI_DOLL 默认全部操作、同一名单翻译为 MTP 与 MCP 工具列表；2026-10-10 能力层分层之后的三项决定（白名单留在访问登记；运行时编辑并入配置热更新；执行线程层之前子 agent 继承父 agent 的操作权限）；
- commit `a384688` 版本的执行单元 Idea T-3 的 2026-10-10 决定（子线程独立权限留给执行线程层）；
- [外部 Actor Idea](../../ideas/external-actor-registration-and-runtime-access.md#34-操作适配器的定义与边界) 3.4（MCP 工具列表属于 v0.7.1 的操作适配器）；
- 当前事实：[Workspace 架构](../../architecture/workspace.md#45-三个调用面actor-apiroot-api-与任务进程的阶段调用)第 4.2、4.5 节，[子系统契约](../../contracts/subsystem-contracts.md#46-操作请求与线程-context)第 4 节，[MTP 契约](../../contracts/mtp.md)；已归档的[能力层分层计划](./v0.7.0-capability-surface-split.md)。

## 1. 背景和问题

能力层分层之后，agent 的权限仍由两套数据共同决定（总 Idea 15.4 的“拆分后的过渡状态”）：

- 访问登记的 actor 操作白名单由 actor API 逐次检查，对任何经操作入口的 actor 生效；
- Agent Profile 的 `allowed_mtp_verbs` 与 `allowed_sys_tools` 由 Alice 检查（frame 执行策略、MTP runtime、提示词组装），只对 Alice 有意义，对不经 MTP 的外部 Actor 没有定义；权限也因此附着在一条记忆原子上。

两处都通过才执行，读者无法从任何一处看出 agent 实际能做什么。能力层分层后 actor 操作已与 MTP 动词对齐，同一份名单可以同时驱动授权与提示词，Profile 不必再承载权限。

## 2. 目标与非目标

### 2.1 目标

1. **唯一来源**：访问登记的 actor 操作白名单是 agent 权限的唯一来源；删除 Profile 的两个 allow 字段、OMNI_DOLL 的两份显式列表，以及 Alice 中基于它们的检查。
2. **交给 CPU**：任务进程在 CPU 分配时以阶段授权读取本进程 actor 的操作集合，写入 `CPUInputManifest`；该集合只用于提示词与执行策略，不授予权限。
3. **Alice 的翻译**：Alice 把操作集合翻译为 MTP 动词，主 frame 的提示词与 `FrameExecutionPolicy` 都由它生成；系统工具不设权限。
4. **子 agent 继承**：CALL 子帧的执行策略与提示词使用父 frame 的动词集合并去掉 CALL；被调用方 Profile 只提供 persona、模型与语言。
5. **前端与周边**：前端移除 MTP 动词与系统工具开关；注入脚本、前端模板等不再写入两个字段。

### 2.2 非目标

- 白名单的运行时编辑（含前端开关）：并入[ROADMAP](../../ROADMAP.md)的“配置热更新”（2026-10-10 决定）；本计划之后修改白名单仍需改 `workspace_actors.yaml` 并重启。
- 外部 harness 的 MCP 工具列表（v0.7.1 的操作适配器）。
- 执行线程层：子线程独立的认证、白名单与派生授权（执行单元 Idea T-3）。
- 系统工具的权限、RUN 目标是否可执行改由 workspace 判断（状态 map 的 `run-target-check`）、附件读取的 actor 操作。

## 3. 当前状态（2026-10-10 核对）

- **访问登记**（`workspace/registry.py`，`configs/workspace_actors.yaml`）：键为 (owner, workspace, user, agent)，省略 agent 的用户级记录覆盖所有具体 Agent，精确记录优先；默认登记的用户级记录持有六项 actor 操作；保留的 `system` 不得配置 operation。登记在运行实例内不可变。actor API 每次请求以 `authorize_operation` 即时查询。
- **Profile 字段**（`core/models/agent.py`）：`allowed_mtp_verbs`、`allowed_sys_tools` 为三态（`None` 全部允许、`[]` 全部禁止、列表为白名单），配套 `is_verb_allowed`、`is_tool_allowed`；`OMNI_DOLL_PROFILE` 显式列出六个动词与五个系统工具。`AgentProfile` 不禁止多余字段：从 `agent_config` 解析时，未知键被忽略。
- **Alice 的三处使用**：
  - `FrameExecutionPolicy.from_profile`：主 frame 由 `AgentRunService._create_root_frame` 按主 Profile 构造；CALL 子帧由 `CallCoordinator` 按被调用方 Profile 构造并拒绝 CALL；
  - `KoakumaRuntime._check_verb_permission` 先查 frame 执行策略、再查 Profile；`_check_tool_permission` 按 Profile 检查 `sys_*`；
  - `PromptAssembler._build_mtp_prompt` 按 Profile 渲染动词教学与系统工具菜单（主 agent 用主 Profile，子 agent 用被调用方 Profile 并去掉 CALL）。
- **RUN**：`sys_*` 系统工具在 Alice 本地执行，不提交请求；记忆中的用户态工具提交 `ResolveRunTargetRequest`，由 actor API 检查 `memory.run`。
- **输入清单**：`CPUInputManifest` 不含任何权限信息；Alice 由它构造 `AgentRunContext`（`core/protocol/models.py`）。
- **写入 Profile 的位置**：`scripts/inject_profiles.py` 的两个内置图纸；前端 `PermissionsSection`（动词开关）与 `ToolsSection`（系统工具开关）经 root API 写入 `agent_config`，`types/agent.ts`、`services/agentApi.ts`、`hooks/useAgentManagement.ts`、`constants/agents.ts` 携带两个字段。HTTP 的 `agent_config` 是自由字典，不校验键。
- **依赖 Profile 限制的文档**：[MealAssistant 产品规格](../../applications/MealAssistantProductSpec.md)用 `allowed_sys_tools: ["sys_clock"]` 只开放时钟。

## 4. 目标设计

### 4.1 唯一来源

- agent 的权限只由访问登记表达：精确记录优先，其次是用户级记录；`system` 没有 actor 操作。OMNI_DOLL 的“全部 actor 操作”由默认登记的用户级记录实现，内置 Profile 不再携带权限。
- Profile 只描述 persona、模型、temperature、top_p 与语言。
- 授权点不变：actor API 逐次检查白名单；输入清单中的操作集合只用于提示词与执行策略，不能作为授权依据。

### 4.2 进程把操作集合交给 CPU

- 操作授权者新增一个只供任务进程使用的查询：与 `authorize_stage` 相同地兑现 context、确认准入并检查目标与 owner，然后返回访问记录中的 actor 操作集合（方法名在实施评审时确定）。架构测试把它的调用面限定在 `workspace.process`，与阶段授权相同。
- `CPUAllocator.allocate` 在组装清单前执行该查询，`CPUInputManifest` 新增操作集合字段（`frozenset[WorkspaceOperation]`，字段名在实施评审时确定）。清单仍不携带访问 context、`IdentityScope` 或任何身份。
- 该集合是 CPU 分配时的快照；登记在运行实例内不可变，快照与 actor API 的即时检查一致。配置热更新落地时再处理快照与即时检查之间的差异（第 9 节）。

### 4.3 Alice 的翻译

操作集合到 MTP 动词的翻译属于 Alice 一侧（MCP 的翻译属于 v0.7.1 的外部适配器）：

| actor 操作 | MTP 动词 |
|:---|:---|
| `memory.read` | READ |
| `memory.search` | SEARCH |
| `memory.write` | WRITE |
| `memory.update` | UPDATE |
| `agent.call` | CALL |
| `memory.run` | RUN 的记忆目标 |
| —（系统工具不设权限） | RUN 的 `sys_*` |

- RUN 始终可用，因为系统工具不设权限；没有 `memory.run` 时，RUN 的记忆目标由 actor API 拒绝，沿用 `mtp.permission.verb_denied` 的映射。
- `FrameExecutionPolicy` 改为由动词集合构造（取代 `from_profile`）。主 frame 使用清单翻译出的集合；运行上下文携带该集合（`AgentRunContext` 新增对应字段，或由 Alice 在构造 run 时从清单取得，实施时确定）。
- `KoakumaRuntime._check_verb_permission` 只检查 frame 执行策略；`_check_tool_permission` 删除，所有已注册的 `sys_*` 对所有 agent 可用。
- 提示词按 frame 的动词集合渲染动词教学，系统工具菜单渲染全部系统工具。

### 4.4 子 agent 继承父 agent 的操作集合

- CALL 子帧的执行策略取父 frame 的动词集合并去掉 CALL；子 agent 的提示词按同一集合渲染。被调用方 Profile 不再收窄或扩大权限。
- 资源操作本就以主线程凭据授权（[Workspace 架构](../../architecture/workspace.md#54-写入意图线程-context-与操作入口)第 5.4 节），继承后提示词、执行策略与实际授权一致。子线程独立的权限属于执行线程层。

### 4.5 Profile 模型、数据与入口

- 删除 `AgentProfile.allowed_mtp_verbs`、`allowed_sys_tools` 及配套方法，删除 `OMNI_DOLL_ALLOWED_MTP_VERBS`、`OMNI_DOLL_ALLOWED_SYS_TOOLS`；`PayloadLayer.agent_config` 的字段说明同步更新。
- 已存 Profile 的 `agent_config` 可能仍带两个键：解析时忽略，不做数据迁移；HTTP 的 `agent_config` 仍是自由字典，旧客户端写入的两个键同样被忽略、不报错。
- `scripts/inject_profiles.py` 的内置图纸不再写入两个键。

### 4.6 前端

- Agent 编辑器移除 `PermissionsSection` 与 `ToolsSection`，`types/agent.ts`、`services/agentApi.ts`、`hooks/useAgentManagement.ts`、`constants/agents.ts` 删除对应字段；配置热更新落地前，前端不提供权限编辑。

## 6. 兼容与迁移策略

- 进程内替换，不做数据迁移。
- 权限可能变宽：Profile 中收窄过动词或系统工具的 agent，在本计划后按访问登记执行（默认用户级记录为全部六项），系统工具不再能按 agent 限制。[System 配置](../../system/configuration.md)补充升级说明：需要收窄的部署，应在 `workspace_actors.yaml` 为该 agent 增加精确记录。
- CALL 子 agent 不再按被调用方 Profile 收窄，与父 agent 的操作集合一致。
- 前端在配置热更新前没有权限编辑入口；[MealAssistant 产品规格](../../applications/MealAssistantProductSpec.md)中只开放时钟的限制无法再表达，随本计划改写为现状并标注依赖系统工具权限。

## 7. 实施阶段

三个阶段依次实施，每个阶段结束时全量后端测试通过、可单独审查。

**阶段一：workspace 把操作集合交给 CPU**

1. 操作授权者新增操作集合查询，架构测试限定其调用面；
2. `CPUInputManifest` 新增操作集合字段，`CPUAllocator` 写入；
3. Alice 暂不读取该字段，行为不变。

验收：第 8 节 1–2 项。

**阶段二：Alice 改用操作集合，删除 Profile 权限**

1. 操作集合到 MTP 动词的翻译；执行策略由动词集合构造，主 frame 使用清单集合，CALL 子帧继承父 frame；
2. MTP runtime 与提示词改用 frame 的动词集合，删除系统工具检查；
3. 删除 Profile 的两个字段、配套方法与 OMNI_DOLL 两份列表；更新注入脚本。

验收：第 8 节 3–8 项。

**阶段三：前端与收尾**

1. 前端移除两个开关及相关字段；
2. 晋升事实文档、归档本计划。

验收：第 8 节 9–10 项；全量门槛、确定性 HTTP E2E 与前端检查通过。

## 8. 测试和验收标准

按[测试设计规范](../../governance/testing/test-design-standards.md)分类；授权者、任务进程与 Alice 使用真实对象，外部 LLM 与存储使用既有替身。

1. 输入清单的操作集合等于本进程 actor 的访问记录：精确记录优先于用户级记录；空白名单得到空集合；清单不含访问 context 或身份。
2. 操作集合查询只在 `workspace.process` 中调用（架构测试）；准入失效或目标不符时与阶段授权同样拒绝。
3. 主 agent 的提示词只列出操作集合翻译出的动词（RUN 始终在列），系统工具菜单列出全部系统工具，与 Profile 内容无关。
4. 操作集合之外的动词在 frame 执行策略处以 `mtp.permission.verb_denied` 拒绝，且不向操作入口提交请求。
5. 空白名单的 agent 仍可用 RUN 执行 `sys_*`；没有 `memory.run` 时 RUN 的记忆目标由 actor API 拒绝。
6. 没有 `agent.call` 时，CALL 不出现在提示词中并被拒绝；CALL 子帧的动词集合等于父 frame 的集合去掉 CALL，与被调用方 Profile 无关。
7. `agent_config` 带旧键的 Profile 正常解析，旧键对提示词与执行策略没有影响；`AgentProfile` 不再有两个字段（结构测试）。
8. 确定性 HTTP chat E2E：访问登记只授予 READ 与 SEARCH 的 agent，提示词不含 WRITE；模型输出 WRITE 时得到 `verb_denied`，写入意图登记中没有新记录。
9. 前端 `npm run lint` 与 `npm run build` 通过，Agent 编辑器不再出现动词与系统工具开关。
10. 结构：生产代码中不再引用 `allowed_mtp_verbs`、`allowed_sys_tools`、`is_verb_allowed`、`is_tool_allowed` 与 OMNI_DOLL 的两份列表。

## 9. 风险与待决问题

| 风险或问题 | 处理 |
|:---|:---|
| 依赖 Profile 收窄的 agent 权限变宽，且系统工具不再能按 agent 限制 | 2026-10-10 的既定语义；第 6 节升级说明；系统工具执行安全仍按[身份与执行安全治理](../../governance/security/identity-and-execution-safety.md)的 S3 跟踪 |
| 清单中的操作集合被误当成授权依据 | 字段说明与契约写明只用于提示词与执行策略；actor API 的即时检查不变；查询调用面由架构测试限定 |
| 快照与即时检查在配置热更新后可能不一致 | 当前登记不可变；配置热更新的计划需处理快照刷新或以即时检查为准，提示词多列的动词最多得到 `verb_denied` |
