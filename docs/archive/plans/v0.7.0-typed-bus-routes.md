# v0.7.0 总线路由类型化与 mypy 门禁

> **文档状态**：Archived（2026-10-12）。三阶段实现、迁移、验收与 code review 均已完成，当前事实由[运行时机制](../../components/runtime-and-bus.md)、[公开路由与事件](../../contracts/routes-and-events.md)和[子系统公共契约](../../contracts/subsystem-contracts.md)承接。本文件保留实施方案与验收记录；不表示 v0.7.0 已发布。原 Todo“总线路由的类型化与静态签名检查”删除前最后版本见 commit `8faa0b7`。

本计划把总线 route 从字符串常量改为携带签名的类型化对象，由提供方 contracts 同时声明 route 名与签名，mypy 检查全部注册与调用点；CI 新增按锁定依赖运行的 mypy 门禁。总线的运行时调用语义不变。

设计依据：

- 当前事实：[运行时机制](../../components/runtime-and-bus.md)第 1 节（总线语义与运行时参数检查）、[公开路由与事件](../../contracts/routes-and-events.md)、[子系统公共契约](../../contracts/subsystem-contracts.md)第 4.4 节（Alice 统一执行入口）；
- 代码：`components/bus/async_bus.py`、`components/bus/arguments.py`、各子系统 contracts 中的 route 类、`tests/unit/architecture/test_package_layers.py`；
- owner 决定：2026-10-04，本事项与 mypy 错误修复分支一同完成；2026-10-12，route 由提供方 contracts 持有名称与签名并删除 core 的 `GlobalRoutes` / `RouteNames`，Alice 的执行 route 按流式与非流式拆分，CI 新增按 `uv.lock` 安装依赖的门禁 job，mypy 只覆盖 `src`。

## 1. 背景和问题

`AsyncSystemBus.request(route, *args, **kwargs)` 以 `handler(*args, **kwargs)` 直接调用；route 是字符串常量，调用点与 handler 签名之间没有静态约束，全靠人工保持一致。全局总线与各子系统本地总线都继承这一调用方式。

- **2026-09-12（W1 附件）**：调用方向 prepare route 传 `attachments=`，handler 的形参名为 `selected_attachments=`，运行时才以 `TypeError` 暴露。Chat 流单元测试为该 route 注册了 `**kwargs` 替身，prepare 层测试直接调用 handler，两条链在“总线绑定真实 handler”这一接缝上没有交叉验证。
- **2026-10-04（身份第二批）**：Patchouli 本地 route 的参数从 `identity_scope` 整体改为 `belong_to` / `from_actor`，其中 7 个调用点按位置传入归属；按位置传入错误类型（例如仍传 `IdentityScope`）时不会报错，handler 可能把它当作字典键或比较对象静默使用（见[已归档的第二批计划](v0.7.0-identity-access-batch-2.md)）。

2026-10-04 起，总线在调用 handler 前按其签名与类型标注只校验、不转换参数，不符时抛出 `RouteArgumentError`。它覆盖所有总线，但只在请求实际发生时生效：只有被测试或运行实际走到的调用点才会被检查，handler 签名改变后旧调用点要到运行时才失败。

此外，总线 `request` 返回 `Any`，是 `mypy src` 剩余 38 个错误（全部为 `no-any-return`）的唯一来源；CI 至今不运行 mypy。

## 2. 目标与非目标

### 2.1 目标

1. 全局总线与各子系统本地总线的 route 都是类型化对象，`register` 与 `request` 只接受类型化 route，mypy 检查参数名、数量、类型与返回值；
2. route 的名称与签名由提供方 contracts 声明一次，删除 core 的 `GlobalRoutes` 与 `RouteNames`；
3. Alice 的执行 route 拆分为非流式与流式两条，各有确定的返回类型；
4. `mypy src` 为 0 错误，并由 CI 按 `uv.lock` 安装依赖的门禁 job 持续检查；第 1 节的两类漂移由门禁中的类型回归样例证明会失败。

### 2.2 非目标

- 不改变总线的运行时调用语义：仍是直接调用，不转换参数、不注入默认值；运行时参数检查保留，作为 mypy 之外的兜底；
- Pub/Sub 事件不类型化，事件常量仍在 core；
- mypy 不覆盖 `tests/`，测试中的 route 替身由运行时参数检查兜底（owner，2026-10-12：覆盖测试过于严格且无意义，不另留待办）；原 Todo 中“替身也要满足 route 的签名类型”的约束随之取消；
- 除 Alice 执行 route 的拆分外，不新增、删除或重命名 route，不改变 HTTP 接口。

## 3. 实施前状态（2026-10-12 核对）

- **总线**：`register(route: str, handler: Callable[..., Awaitable[Any]])`、`request(route: str, *args: Any, **kwargs: Any) -> Any`；`unregister`、`list_routes`、`list_unresolved_routes` 以字符串为键。
- **route 常量**：core 的 `RouteNames` 是全局 route 字符串的唯一来源；调用方使用 core 的 `GlobalRoutes`，提供方注册使用各自 contracts 中的 `PatchouliRoutes`（27 条）、`GatewayPublicRoutes`（1 条）、`AliceRoutes`（1 条）；本地 route 为 `PatchouliLocalRoutes`（34 条）与 `GatewayLocalRoutes`（1 条），只在各自子系统内使用。
- **注册**：Patchouli 的全局 route 与本地 route 分别经 `PatchouliBridge` 和 `build_patchouli_route_bindings` 的 `(route, handler)` 绑定表注册（27 与 34 条）；Gateway 的全局与本地 route 各 1 条；Alice 以 `(*args, **kwargs)` 代理注册执行 route。
- **调用**：src 中 74 处 `request`（`GlobalRoutes` 30 处、Patchouli 本地 41 处、`PatchouliRoutes` 2 处、`BusCanonicalReadBackend._request` 的字符串转发 1 处）；测试中引用 `GlobalRoutes` 415 处、`PatchouliLocalRoutes` 155 处。
- **分层约束**：全局 route 的签名包含 L3 类型，如 `PreparedAgentRun`、`MemoryGenerationTask`、`TopicSettleResult`（`patchouli.contracts`），`CPUInputManifest`、`OperationSubmitter`、`CPUExecutionResult`（`workspace.contracts`）。分层测试同样扫描 `TYPE_CHECKING` 导入，因此带签名的 route 不能声明在 core。
- **契约之外的类型**：`MemoryIntent`、`MemoryIntentSubmissionResult` 位于 `patchouli.application`，`InteractionSubmissionResult` 位于 `patchouli.control`；对应的两条全局 route 在 src 中没有调用方，仅被集成测试使用。
- **Alice 执行 route**：`AgentRunService.run_agent` 按 `stream` 返回事件的异步生成器或可 await 的 `CPUExecutionResult`，单个返回类型无法表达。
- **CI**：只运行 pytest、ruff 与 black；以 `pip install -e ".[dev]"` 安装，pydantic、qdrant-client、litellm 等运行依赖只有下界约束，而 mypy 结果依赖这些库自带的类型标注。

2026-10-12 以项目锁定的 mypy 2.3.1 验证了第 4 节的形状：`Route` 作为 `str` 子类在运行时与原字符串相等、可哈希、可作字典键；handler 签名漂移、按位置传入错误类型、关键字名不符、对仅关键字参数按位置传值，以及绑定表中的漂移均在静态检查时报错，返回类型按签名推断；装饰器声明在模块级与类体内均不触发 `empty-body`。

## 4. 目标设计

### 4.1 Route 原语

core 提供依赖中立的泛型原语：`Route` 是 `str` 的子类，携带只用于静态检查的签名 `Route[P, R]`；`route(name)` 装饰器把一个只声明签名的异步函数变为 `Route` 实例：

```python
class PatchouliRoutes:
    @route("patchouli.public.memory.get")
    async def MEMORY_GET(
        memory_id: UUID | str,
        *,
        identity_scope: IdentityScope,
        refresh_vitality: bool = True,
    ) -> MemoryAtom | None:
        raise NotImplementedError  # 只声明签名
```

运行时 `Route` 就是 route 名字符串，总线内部的注册表、`list_routes`、日志与以字符串比较 route 的代码不受影响。原语不引用任何业务类型，因而可以位于 core。

### 4.2 声明归属

- route 的名称与签名由**提供方 contracts** 声明一次：`patchouli.contracts`（公开与本地）、`gateway.contracts`（公开与本地）、`alice.contracts`（公开）；
- 签名只引用 core 与本子系统 contracts 中的类型；本地 route 的签名可在 `TYPE_CHECKING` 下引用本子系统内部类型（同一子系统内，不构成跨子系统依赖）；
- `MemoryIntent`、`MemoryIntentSubmissionResult` 与 `InteractionSubmissionResult` 移入 `patchouli.contracts`，原位置不保留兼容导出；
- 调用方从提供方 contracts 导入 route：L3 子系统之间经对方 contracts（分层规则已允许），System 与 server 直接导入；
- 删除 core 的 `RouteNames` 与 `GlobalRoutes`；事件常量仍在 core。

### 4.3 总线 API

```python
def register(self, route: Route[P, R], handler: Callable[P, Awaitable[R]]) -> None: ...
async def request(self, route: Route[P, R], *args: P.args, **kwargs: P.kwargs) -> R: ...
```

`unregister`、`list_routes` 与 `list_unresolved_routes` 继续以字符串处理（`Route` 即字符串）。运行时参数检查不变。实施期间可为 `register` / `request` 保留接受字符串的过渡重载，最后阶段删除。

### 4.4 绑定表

绑定表的每一项在构造处检查：`RouteBinding.of(route, handler)` 要求 handler 满足 route 签名，之后以擦除类型存储，由总线逐项注册。Patchouli 的全局与本地绑定表、Gateway 的本地绑定改用它；单条注册直接调用 `register`。

### 4.5 Alice 执行 route 的拆分

- `AliceRoutes.RUN_AGENT`（沿用 `alice.public.run_agent`）：非流式，返回 `CPUExecutionResult`；
- `AliceRoutes.RUN_AGENT_STREAM`（新增）：流式，返回交互事件的异步生成器，最后一项为 `done`；
- 两条 route 的其余参数相同（`input_manifest`、`submit_operation`、`generation_options`）；是否流式由所选 route 决定，route 签名中不再有 `stream` 参数；
- 拆分只发生在 route 层：`AliceRoutes` 的两条声明、AliceBridge 的两个 route handler，以及 `AliceCPU` 按是否流式选择 route。Alice 侧的方法不变：`AgentRunService.run_agent` 仍是唯一执行入口，保留 `stream` 参数与按 `Literal[True]` / `Literal[False]` 区分返回类型的 overload；两个 handler 分别以 `stream=True` / `stream=False` 调用它，删除现有的 `(*args, **kwargs)` 代理。

执行骨架与取消语义不变：流式与非流式仍运行同一套骨架，消费者关闭事件流时 Alice 取消并 join 自己创建的 runner。

### 4.6 转发辅助

以 route 为参数转发请求的辅助函数（当前为 `BusCanonicalReadBackend._request`）按 `Route[P, R]` 与 `P.args` / `P.kwargs` 泛型化，不再接受字符串。

### 4.7 mypy 门禁

- CI 新增 typecheck job：以 `uv sync --frozen --extra dev` 按 `uv.lock` 安装，运行 `mypy src`；现有 pytest 与 lint job 不变；
- 类型回归样例：一个专用文件集中写出第 1 节两类漂移与第 4 节各类误用，每处以精确错误码的 `# type: ignore[...]` 标注，并以 `--warn-unused-ignores` 检查；某处不再报错时 ignore 变为未使用，门禁失败。该文件只服务门禁，不属于测试套件，也不被 pytest 收集。

| 数据与持久化 | 无变化 |

## 6. 兼容与迁移策略

- route 名字符串除新增的流式 route 外均不变，`Route` 在运行时等于原字符串，日志、观测与以字符串注册的测试替身行为不变；
- 测试迁移按映射表机械完成：`GlobalRoutes.GATEWAY_PROCESS` → `GatewayPublicRoutes.PROCESS`，`GlobalRoutes.PATCHOULI_<X>` → `PatchouliRoutes.<X>`，`GlobalRoutes.ALICE_RUN_AGENT` → 按调用的 `stream` 实参改为 `AliceRoutes.RUN_AGENT` 或 `RUN_AGENT_STREAM`，并同步调整导入；
- Alice 执行 route 只有进程内调用方（`AliceCPU`），没有外部消费者，拆分不需要兼容期；
- 不保留 `GlobalRoutes` / `RouteNames` 的兼容别名，避免出现第二个 route 名称来源。

## 7. 实施阶段

三个阶段依次实施，每个阶段结束时全量后端测试通过，`mypy src` 的错误数不增加，可单独审查。

**阶段一：原语、总线 API 与 Patchouli 本地 route**

1. core 的 route 原语；总线 `register` / `request` 的类型化签名（保留字符串过渡重载）；绑定表辅助；
2. `PatchouliLocalRoutes` 改为类型化声明，本地绑定表与 Patchouli 内部调用点改用类型化 route；
3. Gateway 本地 route 与本地绑定同步改造。

验收：第 8 节 3、4 项中涉及本地 route 的部分。

**阶段二：全局 route 与调用方迁移**

1. `PatchouliRoutes`、`GatewayPublicRoutes`、`AliceRoutes` 改为类型化声明；3 个模型移入 `patchouli.contracts`；
2. Alice 执行 route 拆分，AliceBridge 与 `AliceCPU` 更新；
3. src 调用方与转发辅助改用提供方 contracts 的类型化 route；测试按映射表迁移；
4. 删除 core 的 `RouteNames` 与 `GlobalRoutes`。

验收：第 8 节 3–7 项。

**阶段三：门禁与收尾**

1. 删除字符串过渡重载，`mypy src` 为 0 错误；
2. 类型回归样例与 CI typecheck job；
3. 晋升事实文档、归档本计划。

验收：第 8 节全部项；全量门槛通过。

## 8. 测试和验收标准

按[测试设计规范](../../governance/testing/test-design-standards.md)分类；总线与 handler 使用真实对象，外部 LLM 与存储使用既有替身。

1. 在按 `uv.lock` 安装的环境中，`mypy src` 为 0 错误。
2. 类型回归样例在 `--warn-unused-ignores` 下通过，且每处误用都由对应错误码捕获：handler 与 route 签名不符时注册报错；按位置把 `IdentityScope` 传给 `WorkspaceIdentity` 形参报错；关键字名不符报错；对仅关键字参数按位置传值报错；以普通字符串调用 `register` / `request` 报错；`request` 的返回类型与 route 声明一致。
3. 每条 route 的名称与迁移前一致（新增的流式 route 除外）；总线按 route 注册、请求与卸载的运行时行为不变，运行时参数检查仍对字符串替身生效。
4. 绑定表中 handler 与 route 不符时在构造处报错（类型回归样例覆盖）；Patchouli 与 Gateway 的全部 route 在挂载后可请求、卸载后不可请求。
5. Alice：非流式 route 返回 `CPUExecutionResult`；流式 route 返回事件流且最后一项为 `done`；关闭事件流时 Alice 的 runner 被取消并 join；`AliceCPU` 的流式与非流式路径行为与拆分前一致；`AgentRunService.run_agent` 的签名与行为不变，直接调用它的既有测试无需修改。
6. 分层测试通过：core 不导入任何子系统，route 声明只依赖 core 与本子系统 contracts（本地 route 的 `TYPE_CHECKING` 导入限于本子系统）。
7. 结构：src 与 tests 中不再引用 `RouteNames`、`GlobalRoutes` 与 `core.contracts.route_names`；总线之外没有以 `Callable[..., Any]` 注册 handler 的代码。
8. CI typecheck job 以 `uv sync --frozen` 安装依赖并运行 `mypy src` 与类型回归样例。

```bash

```

## 9. 风险与待决问题

| 风险或问题 | 处理 |
|:---|:---|
| route 签名与 handler 签名各写一份，维护成本上升 | 这是契约与实现的分离；二者的一致性由 mypy 在注册处强制，不一致即门禁失败 |
| 绑定表中的签名漂移报错信息不如直接调用直观（ParamSpec 推断失败） | 仍会失败；类型回归样例固定这一行为，必要时改为逐条 `register` |
| 测试替身不受静态检查 | owner 决定 mypy 只覆盖 `src`；替身仍受运行时参数检查约束 |
| 测试迁移涉及约 570 处引用 | 按第 6 节映射表机械迁移，与 src 迁移同一阶段完成并跑全量测试 |
| CI 引入 uv | typecheck job 单独使用 uv，锁定 uv 与 setup action 的版本；其他 job 不受影响 |
