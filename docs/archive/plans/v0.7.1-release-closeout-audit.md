# v0.7.1 版本收尾审计

本记录冻结 2026-10-30 的版本范围、版本目标判定、收尾分支的改动、遗留事项与验证结果。核对基线为 master `7e489918`（v0.7.0 发布之后的 PR #136–#147），加上收尾分支 `release/v0.7.1` 的升版与文档收尾。当前实现从[项目总览](../../PROJECT.md)进入，plugin 模式的两条路径分别见 [Import Bus](../../system/import-bus.md) 与 [MCP 记忆访问](../../contracts/mcp.md)。

v0.7.1 内容收尾完成，Python 规范版本、运行时版本与前端包版本统一为 `0.7.1`。发布标签定为 `v0.7.1`，合并后创建；本次没有创建 tag，也没有推送或发布产物。下文的“通过”只指所列的验证边界。

## 1. 版本目标与判定

版本目标（owner，2026-10-20）：plugin 模式的真实外部 harness 接入，首个接入的 harness 为 Claude Code。同日先定的 controller 模式目标改为 plugin 模式，controller 模式退回候选方向。规模控制（owner，2026-10-20）：版本期间不新增只服务 controller 模式的机制，每份计划写明它针对的已观察问题或待验证的核心假设。

ROADMAP 第 4.4 节的验收逐条判定：

| 验收 | 判定 | 依据 |
|:---|:---|:---|
| 用户在 Claude Code 中的对话回流进入记忆生成，形成的记忆来源可查 | 达成 | 2026-10-27 至 10-28 的 3 个 Claude Code 会话共导入 31 轮，形成 5 个话题，生成 5 条记忆；各话题落盘的记忆创建 Artifact 保存了当时交给提取模型的材料，2026-10-29 据此逐段对账（[生成材料的筛选与截断](../todo/generation-material-filtering-and-truncation.md)的证据一节） |
| Claude Code 在之后的会话中检索并实际使用这些记忆 | 达成，检索效果有已知限制 | 记忆访问计划实测（[阶段五](./v0.7.1-memory-access-mcp.md)第 3 项）：agent 主动调用检索与读取，被读取的正式记忆 `access_count` 增加；本次收尾的 Claude Code 会话中，检索命中此前 Claude Code 会话经对话回流形成的记忆（如 2026-10-29 的生成链路诊断、记忆访问的决定），读取全文后作为历史证据与仓库文档核对使用。首个观察样本因决定发生在接入之前、正文不进检索索引而未命中，根本原因是一次话题结算至多产出一条记忆，记为 [Patchouli 生成](../../patchouli/generation.md#8-当前限制)的已知限制 |
| 记忆访问经能力层逐次授权，越权与跨 Workspace 的访问被拒绝 | 达成 | 记忆访问计划实测第 4–6 项：错误或缺少凭据返回 `invalid_credential`，移出白名单后返回 `operation_not_allowed`，跨 Workspace 返回 `request.workspace_not_found`，以 server 的 principal 经 MCP 接入返回 `adapter_mismatch`；归属层测试见 [MCP 记忆访问](../../contracts/mcp.md#9-代码与测试入口)第 9 节 |
| HiveMemory 不可用时不阻塞 Claude Code 的工作，并明确披露失败 | 达成 | 记忆访问计划实测第 8 项：HiveMemory 停止时 Claude Code 照常工作，恢复后工具可用；连接器的 hook 无论成败都以 0 退出，失败只进日志并保留游标等待补发（[Import Bus](../../system/import-bus.md#82-hooks)第 8.2、8.5 节） |

仅采集日志、仅发送事件，或者只有回流、只有读取的情况都不存在：两条路径共用 Claude Code 自己的接入登记 `harness:claude-code`，在同一个插件中提供。

## 7. 保留限制

- plugin 模式的已知限制分别写在 [Import Bus](../../system/import-bus.md#10-已知限制)第 10 节与 [MCP 记忆访问](../../contracts/mcp.md#8-已知限制)第 8 节：交互查重依赖提交队列的进程内记录，服务重启或超出保留窗口后重发会形成重复交互；请求头中的用户身份不做证明，接入凭据是本地共享密钥，修改经重启生效；回声标记依赖 Claude Code 的工具调用命名；连接器依赖未公开承诺的会话记录格式，只在 Linux（WSL）上验证过。
- 任务进程表、会话与压缩检查点、写入意图登记、读取视图缓存、WorkspaceAsset working set 与本地 Work Queue 仍是进程内状态，不承诺跨重启恢复。
- 模型空闲卸载后的重新加载期间，同一进程的其他请求最长等待约 1～3.7 秒。
- 记忆质量的长期表现（查重、生成粒度、每轮上限）只有插件 2026-10-27 安装以来几天的真实样本，结论见第 4 节的 Todo，没有形成量化评估。
- E2E 中 `test_agent_loop_python_repl_computes` 依赖模型选择调用工具，本次 11 次运行中失败 4 次；浏览器界面没有人工验收。
- 开发库中留有真实使用与验收写入的记忆、话题与交互 Artifact。
