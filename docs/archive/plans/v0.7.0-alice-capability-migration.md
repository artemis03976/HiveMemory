# v0.7.0 Alice 的能力层调用迁移

> **文档状态**：Archived（2026-10-09）。三个阶段均已完成实现、迁移、验收与 code review，事实文档已按最终代码更新。阶段一、二提交为 `7c28c3c`、`f8dccad`；阶段三与本次文档收尾保留在工作区供审阅。本文保存当时的设计、风险和验收证据，当前接口以 Workspace、Contracts 与 Alice 文档为准；不表示 v0.7.0 已发布。

本计划完成 Alice 能力层调用迁移的收窄范围，分三个阶段：先以操作请求与 workspace 的单一操作入口取代第 1 步建立的进程操作通道；再把 Alice 仍直连 Patchouli 的 SEARCH、引用记录与 CALL 目标 Profile 改经能力层；最后删除 CPU 的过渡执行身份。完成后，Alice 不再请求任何 Patchouli 公开路由，`IdentityScope` 不再进入 Alice。

设计依据：

- [执行单元 Idea](../../ideas/execution-unit-thread-and-environment.md#t-9-操作请求与-workspace-的操作入口) T-9 及其计划前的补充决定（2026-10-08、2026-10-09）：操作适配器只产出操作请求、由 CPU 经单一操作入口提交；请求与能力方法一一对应；每个线程一份执行凭据；凭据的形态与兑现位置；前提 4–6；T-1b；
- [总 Idea](../../ideas/workspace-network-task-process-architecture.md)：7.1.6（in-process 的 workspace server API，不新开总线路由）；15.4（正式操作列表留给 Profile 权限计划）；15.5 的重新划分与 2026-10-09 的计划范围决定；P-12b（引用记录是引用读取的自动副作用）；
- [身份与访问体系 Idea](../../ideas/identity-and-access-model.md#i-9-cpu-在过渡期的身份) I-9 及其“删除之后”（观测标签、执行凭据与访问 context 分开）；I-8（进程句柄按对象身份判定有效）；
- [外部 Actor Idea](../../ideas/external-actor-registration-and-runtime-access.md#34-操作适配器的定义与边界) 3.4（操作适配器的定义；适配器可持有会话到进程的对应关系）；
- 已归档的[写入意图登记与读取缓存失效计划](v0.7.0-intent-registry-and-read-cache.md)与当前事实文档、代码。

## 1. 背景和问题

写入意图迁移第 1 步让 Alice 的 WRITE、UPDATE、READ、RUN 与 CALL 的 `context_refs` 经进程操作通道进入能力层。owner 随后指出这一形态有结构问题（执行单元 Idea T-9）：

- **通道是按进程临时创建的集成对象**：`TaskProcessRunner` 在每个进程的 Actor 阶段创建 `ProcessOperationChannel` 并注入 `CPUPort.execute`，为此持有 `MemoryApplicationService`；能力服务不应进入 runner。
- **调用面随能力增长而膨胀**：`ProcessOperations` 每增加一种能力就要同时增加端口与通道的方法，会回到早期 Patchouli 一个门面代理全部 API 的状态。R-2 已经为撤回意图加了第四个方法。
- **绑定与调用面混在一起**：目标 workspace 在创建时固定；关闭时只能取消调用方的整个任务，因为副作用发生前无法再检查一次绑定。

同时，Alice 仍有三条绕过能力层的路径，靠 CPU 的过渡执行身份（I-9）运行，均没有 operation 授权：

- MTP SEARCH 直接请求 Patchouli 检索路由；
- READ、RUN 交付原子后直接请求 Patchouli 记录引用；
- CALL 目标 Profile 经 Alice 自己的 resolver 请求 Patchouli，并缓存在一个从不失效的 Alice 本地缓存中。

## 2. 目标与非目标

### 2.1 目标

1. **操作请求与单一操作入口**（阶段一）：`workspace.contracts` 定义操作请求模型、执行凭据类型、入口协议与 CPU 一侧的提交函数协议；workspace 提供唯一的操作入口，按请求类型分派到能力方法。请求与能力方法一一对应。
2. **执行凭据**（阶段一）：任务进程为主线程签发执行凭据并在关闭时同步吊销；入口把凭据兑现为访问 context 后调用能力方法，能力方法的签名不变。runner 不再持有任何能力服务。
3. **CPU 端口与 Alice 改用提交函数**（阶段一）：`CPUPort.execute` 以执行凭据取代 `operations` 参数；Alice 的 CPU 驱动持有操作入口，为每次执行构造绑定凭据的提交函数；MTP 与 CALL 编排只构造请求、提交并映射结果。删除 `ProcessOperations` 与 `ProcessOperationChannel`。
4. **SEARCH 经能力层**（阶段二）：MTP SEARCH 提交检索请求，由能力层 `retrieve`（`resource.search`）执行。
5. **引用记录成为引用读取的自动副作用**（阶段二）：能力层的引用读取向 agent 交付正式原子时自动记录引用；Alice 不再记录引用。
6. **CALL 目标 Profile 经能力层**（阶段二）：CALL 编排提交 Profile 读取请求，由能力层 `get_agent_profile`（`profile.read`）执行；删除 Alice 的 Profile resolver 与缓存。
7. **删除过渡执行身份**（阶段三）：CPU 输入清单以观测标签取代 `IdentityScope`；Alice 内部的 `IdentityScope` 全部移除；删除 `cpu_execution_identity`。

### 2.2 非目标

- 正式的操作列表（分类与命名的重写）：留给 Agent Profile 权限并入 operation 控制的计划（总 Idea 15.4，owner 2026-10-09）。本计划的请求名称只求与能力方法对应。
- Profile 的 `allowed_mtp_verbs` / `allowed_sys_tools` 并入 operation 控制：同上，MTP 动词检查仍在 Alice 内。
- 执行线程层：子线程的独立凭据、派生经过进程、派生授权（执行单元 Idea T-1a、T-2a、T-3）。本计划中子线程继续共用主线程凭据。
- HTTP 管理侧改为请求模型（T-9 设计第 3 点：暂不迁移）。
- 显式的目标 workspace（T-5b）与跨 workspace 访问。
- 外部执行单元与 MCP 操作适配器（v0.7.1）。
- 写入意图迁移第 2 步。

## 3. 实施前状态（2026-10-09 核对）

以下为建立计划时核对的起始基线；阶段一、二落地结果分别见第 11、12 节。

- **进程操作通道**：`workspace.contracts.ProcessOperations` 有四个方法（提交 WRITE、提交 UPDATE、撤回意图、解析引用）。`TaskProcessRunner` 在 Actor 阶段为每个进程创建 `ProcessOperationChannel`（绑定访问 context、注册目标与 process_id），存入工作集并作为 `CPUPort.execute(manifest, *, operations, generation_options, stream)` 的参数交给 CPU；关闭时置空 context 并取消在途调用方任务。runner 构造时接收 `MemoryApplicationService`（`workspace/process/runner.py`、`workspace/process/operations.py`）。
- **Alice 的接收路径**：`AliceCPU` 只持有全局总线，经 `alice.public.run_agent` 路由把 `operations` 交给 `AgentRunService`；root frame 持有端口，单帧循环写入每条 `MTPExecutionContext`，CALL 子帧继承调用方的端口（`alice/application/cpu.py`、`agent_run_service.py`、`call_coordinator.py`）。
- **Alice 仍直连 Patchouli**（均使用输入清单中的过渡 `IdentityScope`，没有 operation 授权）：
  - SEARCH：Koakuma 经全局总线请求 `PATCHOULI_MEMORY_RETRIEVE`，MTP filter 解析为 `QueryFilters`，`top_k` 取默认 5（`agent_runtime/mtp/runtime.py`）；
  - 引用记录：READ（来源 `mtp.read`）与 RUN（`mtp.run`）交付原子后请求 `PATCHOULI_RECORD_MEMORY_CITATION`，失败只记日志；CALL 的 `context_refs` 不记录；
  - CALL 目标 Profile：`AgentProfileResolver` 经 Alice local bus 请求 `PATCHOULI_GET_AGENT_PROFILE`，以调用方身份解析，结果存入按完整坐标分区的 `AgentProfileCache`；该缓存没有失效事件与 TTL（`alice/runtime/profile_resolver.py`、`profile_cache.py`）；
  - `AliceBridge` 为上述三条路由提供 local bus 代理（`alice/runtime/bridge.py`）。
- **过渡执行身份**：`CPUAllocator.allocate` 以 `cpu_execution_identity(access, target_workspace)` 组装 `CPUInputManifest.identity_scope`（只做目标与 owner 检查）。Alice 内部的用途：`AgentRunContext.identity_scope`（提示词的 `current_agent_id`）；`RuntimeScope.identity_scope`（frame 与 `MTPExecutionContext` 的 `identity_scope` / `identity` 派生、子帧 scope）；流式输出的 `agent_id` 回退；运行事件的 `agent_id`、`workspace_id` 标签（`agent_run_service.py`）。架构测试把 `cpu_execution_identity` 的调用面限定在 CPU 分配（`tests/unit/architecture/test_access_boundaries.py`）。
- **观测标签的先例**：注册入口创建进程时，以通过认证的注册声明绑定一次 `workspace_id` / `agent_id` 观测标签，此后不变（`workspace/process/events.py`、`service.py`，I-8）。
- **可用的能力方法**：`MemoryApplicationService.retrieve`（`resource.search`，经读取视图检索并在代次未变时预热原子缓存，`top_k` 默认 5）、`resolve_references`（`resource.read`）、`submit_write_intent` / `submit_update_intent` / `cancel_intents`（`memory_intent.submit`）；`AgentApplicationService.get_agent_profile`（`profile.read`，经 workspace `ProfileResolver`，其缓存随 canonical 变更事件失效；未指定或 `default` / `omni_doll` 返回内置 Profile）。UPDATE 的基础解析在能力层内部直接使用读取视图，不经 `resolve_references`。
- **访问登记**：默认用户级记录持有 `resource.read`、`resource.search`、`profile.read`、`memory_intent.submit` 等（`configs/workspace_actors.yaml`）。
- **装配顺序**：`AliceSystem`（内部构造 `AliceCPU(global_bus)`）在 `_build_subsystems` 中构建，早于 `_build_services` 中的能力服务与 runner（`system/assembler.py`）。
- **导入约束**：workspace 中 process 以外的模块不得导入 process；`workspace.contracts` 只依赖 core；`intents`、`cache`、`resolution` 不得导入能力层（`tests/unit/workspace/test_import_boundaries.py`）。

## 4. 目标设计

### 4.1 操作请求与单一操作入口

- **请求模型**：放在 `workspace.contracts`，只依赖 core。每个请求类型是冻结模型，并声明自己的结果类型（泛型基类，例如 `OperationRequest[R]`），使入口与提交函数保持静态类型。本计划的请求类型（名称在实施评审时确定）：

| 请求 | 能力方法 | operation | 结果 |
|:---|:---|:---|:---|
| 提交 WRITE（`focus`） | `MemoryApplicationService.submit_write_intent` | `memory_intent.submit` | `PendingAtom` |
| 提交 UPDATE（`base_alias`、`instruction`、`content`） | `submit_update_intent` | `memory_intent.submit` | `PendingAtom` |
| 撤回意图（`aliases`） | `cancel_intents` | `memory_intent.submit` | 实际撤回的 alias |
| 解析引用（`aliases`） | `resolve_references` | `resource.read` | 逐项 `ReferenceResolution` |
| 检索（`query`、`filters`、`top_k`） | `retrieve` | `resource.search` | `MemoryAtom` 列表 |
| 读取 Agent Profile（`agent_alias`） | `AgentApplicationService.get_agent_profile` | `profile.read` | `AgentProfile` |

- **入口**：协议在 `workspace.contracts`，只有一个泛型方法 `execute(request, *, credential) -> R`；实现放在 `workspace.capability`，持有能力服务，内部是一张“请求类型 → 能力方法”的分派表，每项只做一次调用。入口不持有业务状态，不实现领域语义；未知请求类型是程序错误（`TypeError`）。
- **提交函数**：`workspace.contracts` 定义 CPU 一侧的提交函数协议（一次调用：请求 → 结果）。CPU 驱动以入口与凭据构造它；操作适配器（MTP handler、CALL 编排）只持有提交函数，不持有能力层、入口或身份。
- **process_id 与目标**：只有意图类请求需要 `process_id`，由入口从凭据绑定中取得；目标 workspace 一律取凭据绑定的注册目标，请求不携带目标（T-5a）。

### 4.2 执行凭据

- **形态**：`workspace.contracts` 中的不透明类型，没有公开字段，按对象身份判定有效，不可序列化为身份数据，不写入记录、事件或输入清单。
- **凭据表**：新的 workspace 共享设施（模块位置在实施评审时确定），记录“凭据 → (访问 context, 目标 workspace, process_id)”。它不得导入能力层或 process：process 写入、入口读取，从而不引入 capability → process 的依赖。导入约束测试随之覆盖该设施。
- **签发与吊销**：runner 在进入 Actor 阶段时为主线程签发凭据；关闭流程在原先关闭通道的同一同步步骤中吊销凭据，与取消未认领意图、释放租借一起先于任何 await。凭据吊销与访问 context 的失效分开：context 仍由注册入口在关闭之后使其失效。
- **兑现**：入口按凭据取得绑定；凭据未知或已吊销时抛出 contracts 中的错误（取代 `ProcessOperationsClosedError`，名称在实施评审时确定）。能力方法照常对还原出的访问 context 做逐次授权。

### 4.3 关闭与副作用的时序

- 入口在分派前检查凭据。
- 能力方法若在副作用之前有 await（当前只有 UPDATE：先冷读基础原子，再登记），入口在方法返回后、同一同步段内再检查一次凭据；若期间已被吊销，立即撤回刚登记的意图（登记的按 alias 撤回）并抛出吊销错误。协程返回到入口之间没有挂起点，因此不存在“关闭已取消 PENDING、随后又登记新意图”的窗口。这取代现在“关闭时取消调用方任务”的做法。
- 只读请求在吊销时已在途的，照常完成，结果由已关闭的 CPU 丢弃。

### 4.4 CPU 端口与 Alice 一侧

- `CPUPort.execute(manifest, *, credential, generation_options, stream)`：`operations` 参数由凭据取代；凭据是独立参数，不进入冻结的输入清单（T-4a 的理由不变）。
- **装配**：组合根先构建能力服务与操作入口，再构建子系统；`AliceSystem` 在构造时接收操作入口并交给 `AliceCPU`。runner 不再接收 `MemoryApplicationService`。
- **AliceCPU**：每次执行以“入口 + 本次凭据”构造提交函数，经 `alice.public.run_agent` 路由以提交函数取代原 `operations` 参数。
- **Alice 内部**：root frame、`MTPExecutionContext` 与 CALL 子帧持有提交函数（取代端口）；子帧继续共用主线程的提交函数。MTP WRITE、UPDATE、READ、RUN 与 CALL 的 `context_refs` 构造对应请求并提交；结果与错误映射保持现状（pending 基础 → `mtp.update.pending_not_updatable`，不存在或不可见 → `alias_not_found`，`OperationDeniedError` → `mtp.permission.verb_denied`）。CALL 子帧未成功结束时撤回意图改为提交撤回请求。ACK 别名清单与 frame 产物不变。
- **删除**：`ProcessOperations`、`ProcessOperationChannel`、工作集中的通道字段。

### 4.5 剩余路径迁移

- **SEARCH**：Koakuma 把 query 与解析后的 filter 构造为检索请求并提交，由能力层 `retrieve` 执行；filter 解析与结果编译仍在 Alice（协议翻译）。行为变化：检索结果在代次未变时预热 workspace 原子缓存；SEARCH 首次受 `resource.search` 授权。
- **引用记录**（P-12b）：`MemoryApplicationService.resolve_references` 在解析完成后、返回前，为本次交付给 agent 的正式原子自动记录引用：
  - 范围：结果为 `atom`，或结算 redirect 且带有可读原子；同一请求内按 memory id 去重；pending、failed、discarded、not_found 与无可读目标的 redirect 不记录；缓存命中同样记录（这是副作用必须放在 workspace 一侧的原因）；
  - 触发方：所有经引用读取交付原子的调用，即 READ、RUN 与 CALL 的 `context_refs`（CALL 是新增的触发点，owner 2026-10-09）；UPDATE 的基础解析不经此方法，不记录；
  - 实现：以授权点得到的 `IdentityScope` 请求现有的 `PATCHOULI_RECORD_MEMORY_CITATION` 路由；失败只记日志，不改变读取结果，`CancelledError` 照常传播；来源标签统一为一个 workspace 读取来源（取值在实施评审时确定），不再区分 `mtp.read` / `mtp.run`；
  - 不设请求类型，也不设 operation；Alice 删除自己的引用记录。R-1 之后引用记录产生的生命周期 patch 不使读取视图失效。
- **CALL 目标 Profile**：`CallContextProvider` 提交 Profile 读取请求，以主线程凭据经 `profile.read` 解析（子线程独立身份留给执行线程层）。删除 `AgentProfileResolver`、`AgentProfileCache` 及 `AliceRuntime` 中对它的持有与清理；Profile 改由 workspace 按 canonical 变更失效的 `ProfileCache` 承担。内置 Profile 的返回规则由能力层沿用；缺失、不可见或配置损坏照旧映射为 CALL 的准备失败响应。
- **Alice 不再请求 Patchouli**：`AliceBridge` 删除三条 Patchouli 路由代理；Koakuma 不再为 SEARCH 与引用记录持有全局总线（若无其他用途则移除该依赖）。

### 4.6 删除过渡执行身份

- **观测标签**：`CPUInputManifest.identity_scope` 改为观测标签（agent_id、workspace_id 字符串，模型名称在实施评审时确定），取自注册入口绑定的同一组标签，不参与任何授权。
- **Alice 内部**：`AgentRunContext`、`RuntimeScope`、`MTPExecutionContext` 与 frame 去掉 `IdentityScope` 及其 `identity` 派生；提示词的 `current_agent_id`、流式输出与运行事件改用观测标签；子帧沿用父帧的标签，展示用的 agent 仍优先取 Profile alias。
- **授权者**：删除 `WorkspaceOperationAuthorizer.cpu_execution_identity` 及其调用面测试；新增架构测试：`alice` 与 `agent_runtime` 不导入 `IdentityScope`，也不请求任何 `PATCHOULI_*` 公开路由。

## 5. 受影响的系统、契约和数据

| 范围 | 变化 |
|:---|:---|

## 6. 兼容与迁移策略

- 进程内的替换，不跨重启、不涉及持久化数据；每个阶段一次性切换，不保留新旧两套通道。
- 默认访问登记已持有 `resource.search` 与 `profile.read`。自定义过访问登记、缺少这两项的部署，升级后 SEARCH 与 CALL 将以 `mtp.permission.verb_denied` 被拒绝；System 配置文档补充升级注意。
- `alice.public.run_agent` 只有 `AliceCPU` 一个调用方，与端口签名同批修改。

## 8. 测试和验收标准

按 [测试设计规范](../../governance/testing/test-design-standards.md) 分类；凭据、入口与能力层优先使用真实对象，外部 LLM 与存储用既有替身。

1. 入口对每种请求恰好调用对应的能力方法一次，并以凭据绑定的 context、目标与 process_id 调用；未知请求类型抛 `TypeError`。
2. 未知或已吊销的凭据被拒绝，且不产生登记、缓存或引用记录副作用。
3. 缺少对应 operation 时以 `OperationDeniedError` 拒绝，且没有副作用（逐请求类型参数化）。
4. 进程关闭同步吊销凭据：关闭后任何请求被拒绝；关闭时正在冷读基础原子的 UPDATE 返回后不留下 PENDING 意图，且不取消调用方任务。
5. completed 认领、取消与失败时取消 PENDING、子帧未成功结束时撤回，行为与第 1 步一致（沿用并迁移现有集成测试）。
6. 子帧与主线程共用提交函数，意图的发起者为主线程 actor。
7. runner 与 `workspace.process` 不导入能力服务；凭据表不导入能力层或 process；contracts 只依赖 core。
8. SEARCH 经入口与 `resource.search`：结果与 filter、`top_k` 语义与迁移前一致；代次未变时预热原子缓存，随后的 READ 命中缓存。
9. 引用读取为交付的正式原子各记录一次引用（同请求内去重），覆盖 atom、带可读原子的 redirect 与缓存命中；pending、failed、discarded、not_found 与无可读目标的 redirect 不记录。
10. READ、RUN 与 CALL 的 `context_refs` 均触发引用记录；UPDATE 的基础解析不触发。
11. 引用记录失败只记日志，读取结果不变；取消照常传播。
12. CALL 目标 Profile 经 `profile.read`：缺少该 operation 时 CALL 以准备失败响应结束；Profile 源原子经管理入口修改后，下一次 CALL 读到新配置。
13. 内置 Profile（未指定、`default`、`omni_doll`）的 CALL 行为不变。
14. 输入清单不含 `IdentityScope`；提示词 `current_agent_id` 与运行事件的 `agent_id` / `workspace_id` 使用注册时绑定的标签；流式 frame 展示按第 4.6 节优先使用 Profile 的 Agent 标识、缺省时回退到标签，不改变操作发起者。
15. 架构测试：`alice` 与 `agent_runtime` 不导入 `IdentityScope`、不请求 `PATCHOULI_*` 公开路由；`cpu_execution_identity` 不再存在。
16. 确定性 HTTP E2E：一次 chat 内依次 SEARCH、READ、WRITE、CALL（带 `context_refs`），终态正确，意图被认领，引用被记录。
