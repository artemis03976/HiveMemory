# v0.7.3 主动写入沿用 agent 的标题

> 状态：Archived（2026-11-03，PR #178）。当前事实见 [Patchouli 生成](../../patchouli/generation.md#32-mode-b主动-write)第 3.2 节与 [MCP 记忆访问](../../contracts/mcp.md#3-工具)第 3 节；实施记录见第 11 节。以下为计划原文，相对链接已随归档改正。

## 1. 背景和问题

agent 经 WRITE 提交的标题在生成时被丢弃。dsh 调研的 17 条写入（dsh-agent-soul 与 EverOS）没有一条沿用 agent 的标题，全部被改写为"主体：要素清单"的形式，agent 写成判断句的结论随之丢失，其中 4 条还加上了"已知代价""可靠性缺口"一类字眼（[收敛 Idea](../../ideas/generation-source-convergence.md#26-生成丢掉了-agent-写的标题)第 2.6 节）。检索只比较标题、类型、标签与摘要，标题是一条记忆能否被找到的主要依据；使用手册 skill 要求 agent 把标题写成"具体、可检索、带关键名词的判断句"，生成却把它重写了。

按[统一的交互记忆](../../ideas/unified-interaction-memory.md)第 3.2 节的设想，Patchouli 的权威在记录（归属、证据与一致性）而不在措辞；改写第一当事人拟定的标题，正是越权到了措辞上。

owner 2026-11-03 决定：Mode B 沿用 agent 写的标题（收敛 Idea 第 3.3 节）。离线回放中，提示词加入 agent 的标题与沿用规则后，17 条都原样沿用（Idea 第 3.2 节）。

## 2. 目标与非目标

### 2.1 目标

- Mode B 把 agent 拟定的标题交给模型，模型沿用它，只在它与草稿内容不符、或缺少让人检索到它的关键名词时修改；
- MCP 写入工具的说明与使用手册 skill 如实告诉 agent：标题会被沿用。

### 2.2 非目标

- 不改摘要、标签与正文的生成方式；
- 不改合并对标题的改写（合并提示词照常综合两条记忆的标题）；
- 不改 Mode C（UPDATE 不携带标题）与 Mode A；
- 不在代码中强制保留标题：是否修改由模型按规则判断，系统不比较模型输出与 agent 标题；
- dsh 插件中的 skill 副本由 owner 重新复制，不在本计划中修改。

## 3. 当前状态（2026-11-03 核对，commit `7569a952`）

- **入口**：`WriteFocus` 有 `title`（可空）。MCP `memory_write` 的 `title` 参数与 Alice MTP WRITE 的 `title="..."` 都写入它。
- **Mode B**：`MemoryGenerationEngine._process_mode_b` 调用 `extractor.extract_write(transcript, content=focus.content, reason=focus.reason)`，不传标题。只有提取失败走 fallback 时，`_build_fallback_draft` 才用 `focus.title`（缺省时取正文前 50 字）。
- **提示词**：`i18n/prompts.py` 的 `write` 提示词（中、英两份）。用户提示词只有"草稿内容""保存理由"与背景对话，系统提示词没有关于标题的规则。
- **接口**：`BaseMemoryExtractor.extract_write` 的签名是 `(transcript, *, content, reason)`，默认实现返回 None，`NoOpMemoryExtractor` 沿用它；三处测试替身按这个签名实现，分别在 `tests/unit/engines/generation/test_alias.py`、`tests/integration/patchouli/test_settlement_identity.py` 与 `tests/integration/system/test_memory_task_access_api.py`。
- **说明**：MCP 的写入说明是"title 简短概括"，参数说明是"简短的标题"；skill 第 5 节写"正式记忆的标题、摘要与标签由生成重新撰写，与你写的不完全相同是正常的"。
- **长度**：草稿标题在模型输出解析时截断到 `MEMORY_TITLE_MAX_LENGTH`（200 字）；agent 的标题没有长度限制，沿用后同样受这一截断约束。

## 4. 进入条件

Idea 第 3.3 节已决定（owner，2026-11-03）；回放已验证提示词措辞（Idea 第 3.2 节）。依赖都是现有事实，不依赖其他计划。

## 5. 目标设计

### 5.1 传递

- `extract_write` 新增关键字参数 `title: str | None`；`_process_mode_b` 传入 `focus.title`。
- `BaseMemoryExtractor` 的签名与默认实现同步，测试替身随之修改。
- fallback 草稿不变，仍优先用 `focus.title`。

### 5.2 提示词

中、英两份 `write` 提示词同步修改，措辞以回放所用的版本为起点：

- **用户提示词**：在"草稿内容"之前加入"Agent 拟定的标题"；没有标题时写"未提供"。"未提供"像保存理由的空值一样，作为提示词文本在 i18n 中定义。
- **系统提示词**：加入一节"标题"："Agent 拟定了标题时沿用它，不改写措辞；只有它与草稿内容不符，或缺少让人检索到它的关键名词（项目、组件、工具名）时才修改，修改时保留原标题的判断与表述。"

### 5.3 对 agent 的说明

- **MCP 写入工具**：写入说明中的"title 简短概括"改为说明标题会被沿用、应当写成具体可检索的判断句；参数说明随之修改。
- **使用手册 skill**：第 5 节"怎样写"的开头一句与"写入之后"中关于标题的一条改写：标题沿用 agent 写的，只在与正文不符或缺少检索名词时修改；摘要与标签由生成撰写。

### 5.4 不变的部分

Mode A、Mode C、合并、fallback、查重与结算都不变。

## 6. 受影响的系统、契约和数据

- **Patchouli 生成**：提取器接口、Mode B 的提示词与引擎调用；
- **MCP 契约**：`memory_write` 的工具说明与参数说明文字，参数与返回不变；
- **使用手册 skill**：Claude Code 插件中的 skill 文本；
- **数据**：无。已有记忆的标题不变，只影响之后的写入。

## 7. 兼容与迁移

没有持久化与 API 变化。插件需要重新加载才能看到新的 skill 文本与工具说明，后端重启后新提示词生效。

### 8.3 回放与实测

- **离线回放**：以生产提取器（`patchouli.llm` 解析的模型）重放 Idea 第 3.2 节的 17 条写入，统计沿用、改写与改写的理由；改写只应出现在标题与内容不符或缺少关键名词时。
- **日常使用**：下一批经 dsh 或 Claude Code 的写入，正式记忆的标题与 agent 的标题一致或只补了关键名词。实测依赖自然发生的写入，不作为归档条件。

## 9. 风险与待决问题

- 模型遵从是概率性的：回放 17/17，规则仍可能被个别输出忽略；系统不做强制比较（非目标）。
- agent 的标题写得含糊时（例如"今天的排查"），规则允许补关键名词，但仍以 agent 的表述为基础；标题质量主要靠 skill 的写法要求。
- 合并会重新综合两条记忆的标题；跨话题的合并仍可能改掉 agent 的标题（同一话题内的主动写入已不再互相合并）。

没有待决问题。
