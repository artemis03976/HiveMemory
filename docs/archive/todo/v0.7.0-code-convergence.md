## 2. 结构冗余与死代码（P2）

### 2.1 写入意图状态机中已不产生的 PENDING 与无人使用的辅助（已完成）

**已完成（2026-10-18）**：实时派发之后登记直接进入 MATERIALIZING，删除了不再产生的 `PendingAtomStatus.PENDING` 及从它出发的迁移，`is_in_flight` 只剩 MATERIALIZING；删除无人使用的 `PendingAtomSnapshot`、`PendingAtomMaterializeTask.from_pending_atom`、`allowed_transitions` 与从不抛出的 `InvalidStateTransition`（登记对晚到或重复的结算按规则忽略）。编译器测试改用 MATERIALIZING 构造在途意图。[数据模型](../../architecture/data-model.md)、[PendingAtom](../../alice/pending-atom.md)与 [MTP 契约](../../contracts/mtp.md)不再称 PENDING/EXPIRED 为“兼容”枚举，改为说明 EXPIRED 保留、当前不产生。证据：`core/models/pending.py`、`core/models/__init__.py` 与 `tests/unit/engines/memory_compiler/`。

EXPIRED 不属于本条：它是设计中的永久终态，SETTLED、FAILED、CANCELLED 都可以迁入，`is_terminal` 按此定义。它原先由 run 结束触发（上一轮结束的意图标为 EXPIRED，见[写入意图登记归档计划](../plans/v0.7.0-intent-registry-and-read-cache.md)），登记与任务进程解耦后触发点不复存在，结算后的句柄暂时保留到重启。`EXPIRED` 枚举与迁入它的边、引用解析结果的 `"expired"` 种类，以及 READ、RUN 与编译器中的对应分支和文案都保留；过期机制由[写入意图后续方向 Idea](../../ideas/pending-intent-migration.md)第 3 节跟踪，读取视图目前把 EXPIRED 与 CANCELLED 按不存在交付、编译器中终态写入意图的渲染分支走不到，这两点也记在该节，随过期机制一并决定。

### 2.2 主动生成的单元素批量与三次表示转换（已完成）
