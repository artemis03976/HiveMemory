# 统一的交互记忆：轨迹、断言与整理

## 0. 文档性质

本文记录一个尚未排期的方向：用同一套记忆架构，把任何形式的交互整理成记忆资产。它不描述当前行为，也不代表排期。当前的生成设计见 [Patchouli 生成](../patchouli/generation.md)与[感知与短期话题](../patchouli/perception.md)；v0.7.3 的过渡措施与证据见已归档的[主动写入与被动提取的收敛](../archive/ideas/generation-source-convergence.md)。

## 1. 出发点（owner，2026-11-03）

- 项目的起点是 Mode A：从对话中被动整理记忆。
- 只做对话式记忆不够。现在的 agent 不是一来一回的简单交互，而是像 CPU 一样长程运行，只把"中断"暴露给用户；agent 的主动能力很强，作为第一当事人，它有权与记忆库充分交互。
- 两种形式不是不能兼容，理应有一种统一的记忆架构，把任意形式的交互记忆资产化。
- v0.7.3 的"话题内主动写入优先"是想到更好的办法之前的过渡措施，不代表主动写入优先是更好的选择。

## 2. 现状

### 2.1 三层的成熟度

| 层 | 现状 |
|:---|:---|
| 轨迹 | 项目一贯的短期记忆机制与证据基础：从最初的感知层，演化到话题路由、轮次事件原子化、logical block 与全交互轨迹的保存（话题按顺序保存全部交互记录，结算时冻结为来源 InteractionArtifact） |
| 整理 | "唯一写入者"是核心原则：记忆写入都经 Patchouli 的再生成，Patchouli 永远是记忆的权威。前提是 LLM 的输出不可信，必须经第三方整理或审计之后才能入库 |
| 断言 | 最薄弱：记忆的来源信息缺失，看不出一条记忆是谁断言的；生成依赖专门定义的模式（Mode A、B、C 与合并任务各有一套） |

### 2.2 两种形式为什么冲突

原因在结构上，证据见收敛 Idea 第 2 节：

1. **两个互不知情的写入者**：Mode A 与 Mode B 各自产出正式记忆，只在查重时靠向量相似度事后对账。用提示词让一方知道另一方，回放证明不可靠（收敛 Idea 第 3.2 节）。
2. **两个时间尺度**：主动写入立即生成，被动提取等话题结算，同一件事在两个时刻、两种上下文里各被整理一次。
3. **记忆不记录是谁说的**：第一当事人的断言与旁观者的推断地位相同，合并只能按新旧定主次。

"话题内主动写入优先"借话题边界给第 3 点打补丁；话题边界与"两条草稿是不是同一个断言"并没有关系。

## 3. 设想

### 3.1 轨迹、断言、整理

- **轨迹**：发生过的一切，不论形式：用户消息、agent 输出、工具调用、记忆操作。一来一回的对话与长程 run 都是轨迹，用户的介入是轨迹里的一次中断。
- **断言**：候选记忆只有一种类型，带三样东西：谁断言的、在轨迹中的证据位置、事情发生的时间。"谁断言的"至少分两个维度：说话者（用户或 agent）与显式程度（主动写入，或从对话中提取）。agent 的 WRITE 是第一当事人带着意图的断言，被动提取产出推断的断言；Mode A、B 不再是两条生成管线，而是断言的两种来源。
- **整理**：唯一写入者把断言变成正式记忆，规则按断言的属性而不是生成模式：
  - 推断的断言与第一当事人的断言讲同一件事时，挂为后者的佐证，不改写它；
  - 推断出第一当事人没写的事实，照常成为记忆；
  - 第一当事人的断言之间不互相合并，除非显式 UPDATE；
  - 偏好与决定以用户本人的陈述为准；会变化的事实按发生时间而不是生成时间判断新旧。

纯对话的轨迹没有主动写入，只有推断的断言，退化为今天的 Mode A；长程 agent 的轨迹两类断言都有。对话式记忆评测（如 LoCoMo）测的是前一半，agent 工作记忆的自有评测测后一半。

### 3.2 主观与客观

agent 的记忆是主观的，作为资产又要客观。设想的化解：资产的客观在于**归属与证据可查**，不在于内容中立。"某 agent 在某时依据某段证据断言了 X"本身是客观的记录，哪怕 X 是判断、决定或经验。

Patchouli 的权威据此落在记录上：谁说的、何时、依据什么、与其他记录是否一致或冲突，而不在措辞上。"LLM 输出不可信"要求的审计是核对归属、证据与冲突，不是用自己的话重写；Mode B 丢掉 agent 拟定的标题（收敛 Idea 第 2.6 节）就是越权到了措辞。关于世界的事实需要证据；决定、偏好与经验作为带归属的记录，本身就是客观的。

### 3.3 消费水位（owner 设想）

维护一条时间线：主动或被动任一方式触发生成时，到当前为止的全部交互原子事件作为这次生成的材料，并且**不再**作为下一次触发的材料。每个事件只被消费一次，两个时间尺度的问题随之消失，每次整理的区间也成为断言的证据位置。owner 指出了三个问题，初步分析如下：

1. **需要流式接收事件轨迹**：按轨迹坐标而不是时钟切分，多数情况下不需要流式。
   - MCP 的写入与更新已带 `turn`，服务端由它推导的交互标识与这一轮导入时相同（[MCP 记忆访问](../contracts/mcp.md#6-连接器调用名轮次信息与回声标记)第 6 节）；写入在轮内的位置，可以在这一轮导入时由工具结果中含其 pending alias 的那个 `tool_call` 事件确定。
   - 触发与切分因此分开：写入时照常 ACK 并登记 pending，切点等轨迹到达后落定，这次写入的正式记忆要等这一轮结束才生成。
   - 一轮跑几个小时的长程 agent 仍然需要流式接收或轮内分段（[Turn 内上下文折叠](./long-running-agent-intra-turn-context-folding.md)）。
2. **并发写入擦除时间线的竞态**：只有"消费到现在"在处理时求值才会竞态。
   - 切点是一个会话轨迹中的位置，区间由相邻切点决定，与处理顺序无关；Import Bus 已按外部会话串行，切点在导入时登记。
   - 时间线按会话划分：并发的不同会话之间只有时间戳，没有可消费的先后。
   - 同一轮里的多次写入合成一个切点，在同一次整理中作为几条第一当事人的断言，同轮写入互相合并的问题在结构上不再出现。
3. **收尾那轮复述"之前做了什么"**：水位解决不了，复述是新的事件、旧的内容。水位给它划出可判定的范围：第 k 段整理时，把本会话此前各段的断言清单（带编号）交给它，每条候选标注与清单的关系，由系统按标注确定性地处置。第 4 节的回放验证这一点。

切点登记与"每段只消费一次"必须持久化，这与已接纳的交互扛住崩溃是同一件事（[耐久性与故障恢复](../governance/reliability/durability-and-recovery.md)）。

## 4. 验证：对照断言清单标注（离线回放，2026-11-03）

**样本**：与收敛 Idea 第 3.2 节相同的五个话题，输入是结算时的来源 InteractionArtifact。

**方法**：

- 断言清单取话题中 WRITE、UPDATE 事件的原始参数，即 agent 自己写的标题与正文，按出现顺序编号 L1、L2……；材料中的写入渲染为一行 `WRITE: L3「标题」`。
- 提取的系统提示词加入清单规则，要求每条草稿标注它与清单的关系（new、restates、revises、contradicts）与对应编号，并明确"不要为了避免重复而省略"。其余沿用生产的材料渲染、提示词、提取模型（`deepseek/deepseek-chat`）与解析。
- 每个话题 3 次，共 15 次，全部解析成功；每条草稿与清单逐条比较 dense 余弦，辅助人工核对。
- 回放脚本是临时脚本，不在仓库中，与结果一起保存在本地证据目录。

**结果**：共 65 条草稿；"复述"指人工核对为与清单中某一条讲同一件事。

| 话题（清单条数） | 复述的草稿与标注 | 其他草稿 |
|:---|:---|:---|
| SME 第二轮主话题（8） | 3 次都只复述 L8 一条，3 次都标为 new（余弦 0.737～0.739） | 1 条报告版本的记录，标 new |
| SME 记忆动力学追问（1） | 3 次都复述 L1，都标 restates L1 | 无 |
| Gliding Horse（4） | 无 | 13 条，都标 new：清单主题（未接线层、5W2H、复杂度分级、向量引擎）的审计细节，以及测试失败、凭据卫生、配置与代码矛盾等清单之外的发现 |
| EverOS（8） | 2 次各复述 8 条，16 条都标 restates，编号正确（余弦 0.844～0.928） | 另 1 次不复述，产出 8 条清单主题的审计细节，都标 revises（余弦 0.60～0.71） |
| 混合话题（14） | 19 条都标 restates，编号正确；其中 2 条指向同一条记忆的 UPDATE | 2 条标 new：一条工作进度；一条是 dsh 工作区写入被拒的 `icacls` 根因，即 Mode A 的独有贡献，3 次中出现 1 次 |

**结论**：

- **复述基本能被标出**：41 条复述标对 38 条。漏标的 3 条是同一条复述，3 次都标为 new。
- **兜底只能有限补救**：在清单范围内比较余弦，标对的复述最低 0.768，漏标的在 0.737～0.739，其余草稿最高 0.714。阈值取 0.73 在这批样本上能补上漏标，但余量很窄：SME 调研的几条不同的主动写入之间就在 0.714～0.724（[查重 Todo](../todo/generation-dedup-decision-signal.md)）。
- **没有吞掉新事实**：清单之外的事实没有一条被标成复述；`icacls` 那条出现时标为 new。它只在 1 次中出现，是提取本身的波动，现行规则同样如此。
- **与其他做法相比**：
  - C 让模型照常复述，复述与新内容无从区分；
  - C2 要求模型省略复述，漏出来的复述同样无从区分；
  - 标注让复述可以被确定性地处置，并对应到具体的断言；
  - 按话题结算到的记忆判定的过渡措施（E），按生产查重估算能挡住 21 条中的 20 条，效果相当，但它不知道对应哪条断言，也只在话题之内有效；
  - 标注只针对 Mode A，不覆盖 E 的另一半：同一话题的主动写入之间不合并。
- **新暴露的问题**：Gliding Horse 与 EverOS 的一次运行，产出了清单主题的审计细节（行号、缺陷、矛盾），这正是 agent 按 skill 有意精简掉的内容。它们被标为 new 或 revises；如果按 revises 并入第一当事人的断言，就又回到被动提取改写主动写入的问题。怎么处置取决于第 5 节第一项。

## 5. 主要未知项

1. **第一当事人"没写"算不算判断**。上面的审计细节说明，被动提取会系统地补回 agent 有意精简的内容。如果第一当事人对"写什么"也有权威，推断出的新细节是否要尊重它的不写？可能的处置有三种：丢弃；作为推断的断言另立一条，与第一当事人的断言关联但不并入；挂为佐证。现在也没有办法表达"看过、决定不记"。
2. **第一当事人的断言什么时候成为正式记忆**：立即生成，其他 harness 马上能检索到，但之后的整理要再来一次；或者挂起到切点，与推断的断言一起整理，只整理一次、上下文完整，但长程 run 期间只能按 alias 读到 pending。
